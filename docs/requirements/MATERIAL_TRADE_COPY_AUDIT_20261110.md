# 本人素材和交易：提供范围及未覆盖部分

依据[28号第一节](../sources/contracts-20261029/extracted/28.md)原文：“在 App 内查看/导出个人资料、数字人资产、订单与授权记录；可申请机器可读副本。”本表是实施核查，不是甲方要求公开全部数据库字段。

|核查对象|此前已有|本轮查实及处理|仍需注意|
|---|---|---|---|
|supply_assets本人素材/作品|编号、类型、字节数、内容摘要、状态；受控原件字节校验|补创建时间；补严格元数据接口结构；错误账号/类别/不存在的游标拒绝|不包含存储路径、上传人或请求哈希；其他purpose未因此全部核完|
|artist_asset_links|素材归属本人，上传可由机构代办|新增artist_person_id仅本人关联；无本人关联为null，不泄露他人档案|机构代办记录不变成个人所有，null不等于文件无主；不导出acting_party_id|
|trade_records订单|本人买卖单、金额、分期、已收/已退及冻结条款副本|补订单创建时间、已存取消原因；无原因返回null|创建时间不是支付/签署时间；ORDER来源报价关联尚未单列，特殊商品JSON仍须按实际订单继续核|
|trade_records付款/退款|金额、分配、状态、模拟/正式、退款原因及创建时间|补付款原有截止时间；退款不伪造截止；非法日期拒绝|期限不延长原付款权利；标题/时窗原始数值尚未另列；回执原件另核|
|trade_journal|收退款方向、金额、币种、时间和来源关联|复核与原付款/退款金额、归属匹配；差异拒绝输出可信汇总|不把流水时间当供应商到账时间；provider_reference及原始渠道证明按具体申请另核，不作永久拒绝依据|
|删除/撤权|下载前后重核状态与访问限制|补删除中/已删除元数据合法状态与不可下载反例|保留记录不等于原件仍可用；无假恢复或新增保留期限|

流程补全：为使用户知道“哪份素材、何时上传、哪个本人档案、哪笔订单为何取消、付款原定何时截止”，兼容增加上述字段；不改收费、取消、支付、授权或留存规则。内部字段默认不直接提供，不意味着所有渠道回执都可省略；涉及第三方和真实供应商时仍需具体办理。

JSON核心键的逐项归类见[字段底册](PERSONAL_COPY_FIELD_AUDIT_20261110.json)的json_review_20261110。仅核本批类型和核心流程，不能把一个data_json列称为已审完全部业务内容。16表范围115列是核查范围，不是需求分母；1092列尚未核查，也不是1092个未开发功能。
