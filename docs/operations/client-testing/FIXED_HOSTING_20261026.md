## 为什么不能直接把昨天的工具挂几天

现有故事、艺人和制作隔离脚本约60分钟自动结束，并在退出时删除各自的随机测试库；部分登录记录仅两小时有效，示例报价也有业务有效期。测试网关又核对隔离资料状态及期限。因此只延长网页链接、修改一个超时时间或循环重建资料，都会出现业务数据消失、登录失效或当天提交次日找不到的问题。

固定环境必须采用独立初始化和运行步骤：首次只建一次合成资料；正常停止或重启不重新灌数据、不删除数据库；登录过期后重新验证身份，继续读取同一批记录。报价/订单等真正的业务期限仍照原规则运行，不能为了测试常驻而把所有业务期限自动延长。

## 已完成的备份工具怎样使用

准备人员先停止问题工作台，保留原记录与邀请；不要同时运行批次准备命令。执行node scripts/client-testing/backup.cjs backup <批次>，输出加密备份文件名及条目数。备份保存在.local/client-backups，密钥单独保存在.local/client-backup-key.bin；两者都不入Git、不放在网站可下载目录。正式测试服务器的访问权限和离机保管还需配置，不能把本机文件权限当成远端已经保护完毕。

node scripts/client-testing/backup.cjs verify <文件名>可检查解密及记录关系；node scripts/client-testing/backup.cjs restore <文件名> <新批次>恢复到一个不存在的新目录，拒绝覆盖原批次。恢复不启动网站、不恢复业务数据库、不修改当前会话指向。若有RESTORE_INCOMPLETE标记，准备和问题工作台会拒绝该批次；负责人检查失败原因后再处理，不直接删原记录。

更换机器时，需要通过私密渠道分别保管和转移加密备份与密钥。丢失密钥将无法恢复；请不要只复制备份包。业务数据库、业务文件及其版本对应关系需要另做备份和恢复演练，尚未实现。本工具不自动删除备份，也不擅自确定甲方真实反馈的保留期限。

独立验证：node --test scripts/client-testing/portal.test.cjs scripts/client-testing/backup.test.cjs。实际本机恢复证据见docs/testing/evidence/client-fixed-hosting-20261026/BACKUP_RESTORE.json。新增代码当前只保存本地，待固定环境形成可独立验收成果后按阶段集中推送，不改PR37已受测提交。
