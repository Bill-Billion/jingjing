# 甲方模拟测试资料的备份和恢复

用于本机合成资料，不是生产备份工具。后端负责人 chengcongcong222执行；甲方和前端无需手工启动。演示版连续测试前先保留订单、私有影片和反馈，再冻结构建。

新增 `scripts/client-testing/business-backup.cjs`，只接受已标记的本机隔离库和对应目录。备份先取得与业务服务相同的运行锁，服务尚在用或存在未核查的旧锁就拒绝；不擅自停止会话。数据库与全部私有文件一起加密，密钥只存本机忽略目录。恢复只创建随机新库和新目录，不覆盖原库。

运行需要指定 `JX_MYSQL_TEST_ENV_FILE`（本机test配置）、`JX_MYSQL_EXE` 和 `JX_MYSQLDUMP_EXE`（本机MySQL工具绝对路径），不读取生产.env，不把口令放命令行。示例中的名称替换为本轮实际随机库名，不能选旧甲方正在使用的库：

```text
node scripts/client-testing/business-backup.cjs backup <已停止的合成库名>
node scripts/client-testing/business-backup.cjs verify <返回的jxdb文件名>
node scripts/client-testing/business-backup.cjs restore <返回的jxdb文件名>
```

反馈另用原 `backup.cjs` 加密备份并恢复到新的反馈批次。业务备份不冒称已包含反馈。原网页反馈批次、访问有效期与构建清单在实际切换时一起核对，不因恢复自动延期或启用公网。

一键隔离演练 `business-backup-drill.cjs <本轮新建合成库名> <新证据文件>`：拒绝正在使用的资料→备份→恢复到新库→逐表逐行摘要核对→逐私有文件核对→验证原库不变→未完成恢复禁止启动→启动恢复库→实际下载原已付款影片→恢复同订单反馈→停止临时服务。两份数据库保留，访问文件清理；旧人工环境不动。

本机演练已通过9项检查：179表、131附件完整一致，恢复后原已付款视频可读取，反馈编号和订单引用保留。首次导入因Windows MySQL客户端无法读取中文绝对配置路径失败；后改为受控工作目录下的相对配置文件并用私有标准输入文件导入，复验通过。原始失败保留。失败恢复目录有 `RESTORE_INCOMPLETE`，运行时明确拒绝启动；不能删标记当成功。

限制：只支持本机指定MySQL测试账号、事务表及现有私有文件格式；最多256MiB解压内容，超出即明确失败，不截断。备份密钥与归档需一起保管；当前仍仅本机副本，不声称跨机器灾备。备份前停止业务写入，MySQL导出使用一致性事务；不得由另一工具同时改库。恢复/回退与最终App及网页产物一起发布的完整第18组检查仍待完成，不因为这9项通过自动定版。
