# 甲方怎样在浏览器测试并反馈

2026-10-25。本轮先把队友PR36复审合入，再准备浏览器测试辅助工具。共同版本为integration/767d2ffc；本侧新增工具在worktrees/client-testing，分支core/client-browser-testing-20261025。工具的上传、检查和最终状态以本文件末尾补记为准。

## 甲方将拿到什么

一个HTTPS测试链接，以及单独发给每位测试人的邀请码。进入后选择本次业务路线，按页面说明操作。需要机构或运营身份时，由负责人提供对应邀请；不使用一个万能账号绕过业务权限。试用邀请只是隔离测试身份，不是实名或正式机构资质。

页面上的“反馈当前问题”可以随时打开。选择功能出错、流程看不懂、与需求不符或改进建议，填写发生了什么和希望怎样，可添加确认过内容的PNG/JPEG截图。反馈不会离开正在填写的业务页面，返回后可以继续操作。浏览器刷新仍可能丢失未保存的业务表单，应先按业务页面保存。

系统保存反馈编号、当前测试身份、页面位置、测试版本、设备信息及自愿填写的关联记录编号。没有自动采集表单正文、密码、验证码、私人故事全文或完整操作录像。详情中的路由仅保留允许的业务编号参数；无法识别的位置仍可通过截图和描述补充。

“我的问题与进度”只显示该邀请码对应测试人的反馈。工作人员可以统一查看、要求补充、记录复现、修复并交回甲方复测；工作人员不能代甲方确认解决。与需求不符或改进建议仍须另行评估，不自动修改产品规则。

每条路线可记录“已走通”“卡住了”“能走通但需调整”。这记录的是测试人的结论，不替代正式验收或法律、财务审批。

## 谁接着做什么

本侧负责准备新一轮隔离资料、邀请码、浏览器构建、检查入口，处理问题及记录证据。甲方按角色操作、反馈并复测；建议前端伙伴处理页面体验问题，本侧处理服务器逻辑与环境，具体反馈收到后再分配，不代伙伴认领。

先开放故事提交、受理、报价等清晰的小范围路线；跑顺后再逐条加入制作、现货及其他业务。甲方应使用虚构文字和测试图片，勿填写真实身份、私人故事或真实银行卡。

临时方式建议每次约定不超过55分钟，由本侧重建资料并开启访问，结束关闭。现有隔离资料脚本60分钟自动清理，不能把它当作连续几天的稳定测试环境。连续多日测试须独立测试服务器、固定域名、专用数据库、备份与账号管理，不应简单延长本机临时脚本。

## 记录如何保留

反馈和流程结果保存在本机私有目录.local/client-feedback/<批次>/records，业务资料到期清理不会删除这些记录。相同批次下重新准备测试沿用测试人的记录身份。工作人员可在业务服务关闭后单独启动问题处理工作台，查看与导出原记录；这个工作台不提供业务操作权限。服务重启需重新输入邀请码。

不要把邀请码、运行配置、问题原文或截图整包上传Git。本仓库只保存合成验证证据。页面导出包含问题、处理历史和测试结果，不含截图二进制；原截图仍随私有记录保留。真实验收批次的保留时间由项目负责人确认，本工具不擅自定时删除甲方反馈。
