# 让甲方能测更多业务：当前范围与扩充顺序

2026-10-26用户指出，目前主要只能走指定故事路径，要求完善其他路径。本侧已核对页面、测试脚本和此前缺项；不能把所有菜单直接放开后，要求甲方自己找账号、填内部编号或猜流程。

本阶段先补艺人本人和受托机构：本人在手机页面建立数字人档案，机构从工作台读取同一档案；公开目录及独立审核入口也检查。已有故事和反馈不重建。本地分支core/client-route-expansion-20261026基于b26c3ad2，依赖待审PR37；当前未代队友审阅。实际公网切换与交付另记。

## 为什么此前很多路径无法完整测试

1. 原邀请码只绑定故事客户，不是艺人、制作方、机构管理人或审核人；打开其他菜单不自动取得其他身份权限。
2. 其他业务已有模拟脚本，但多数一小时后删库，附件还在进程内存里。长期开放会导致次日记录或文件消失。
3. 不同模拟资料组使用不同账号和数据库。故事组的客户不是制作组的客户，不能把两个组的订单编号硬接起来，冒称同一订单全流程。
4. 实名、真实支付、电子签、长期模型和OSS等仍有外部条件；测试必须标明模拟状态，不能放开一个“直接标已付”的正式接口。
5. 页面入口检查与完成一条业务不同。仍要逐项验证保存、换岗继续、权限拒绝、取消/退款及历史记录。

## 本轮实现与验证

- 持续测试新增艺人组，沿用严格限定的本机测试库和环境标记；原故事格式兼容，未放开所有业务接口。
- 附件使用独立私有目录保存，文件名取存储标识的摘要，避免把标识当作路径；不得越目录、跟随链接文件或写超大文件。正常停止后档案与附件一起保留，原短会话仍删自己的库。
- 机构邀请固定使用机构主体；本人、机构和审核各自绑定原测试账号。真实实名调用、短信、长期模型仍不开放。
- 15项工具检查、9项数据库/附件/授权重启检查通过；4个页面入口读取通过；4项实际浏览器检查通过，覆盖本人新建、原页读回、机构查看同一记录和无外部资源/脚本异常。
- 本轮早期自动化脚本误把权限隐藏404预期为403、误用授权记录接口读取形象档案，并使用了不正确的按钮和长列表定位。已按实际API/页面纠正测试，未为通过检查放松权限或改变产品流程。成功证据见docs/testing/evidence/client-routes-20261026。

## 合作方式与顺序

本侧负责模拟资料、数据与附件保留、按岗位的操作说明、完整流程检查及发现问题后的修复。本轮没有修改正式App/Vue或业务API，队友无需为这批测试配置重做页面；建议队友审阅邀请和资料边界，按具体反馈修页面，未代认领。

先让甲方使用故事及艺人/机构路线；下一批优先制作交付，再现成视频，随后通告/试镜/商单，其余积分、共创与运营服务分批补。每条路线都要给出“用哪个身份、从哪里开始、上一岗怎样交给下一岗、做到什么算成功”。尽量减少手填编号；确实仍需编号时由测试工具给出明确样例，不让甲方猜。

用户可从导航自由查看已有页面，但只有已准备并验证的路线才能记为本轮可验收。这里不把当前九个测试入口写成九条完整业务；故事与艺人资料仍为两组独立账号，尚未打通从一个新故事直接走到制作交付的完整订单。其他路线本轮未开放，不需要因此重做已经验证的基础页面。
