# 安卓模拟测试与人工接手

本侧按2026-10-21授权，先在电脑上的安卓虚拟手机测试、修复和记录，再交给双方人工测试。基于共同版本 integration 5fba043，工作目录 worktrees/android-test，分支 core/v5-android-functional-test。没有调用真实短信、付款或生产资料。

## 本轮实际结果

安卓虚拟手机已经配置好，并实际安装运行测试包。三个原生业务场景通过，保存13张实际截图；静态检查无问题。当前成果可供双方开始第一条业务线的人工检查，不能称整个V5已验收。

|检查层次|本轮结果|能证明什么|
|---|---|---|

|补充后端检查|197项通过|成长榜单、共创、兑换抽奖、参演发行、隐私请求和余额规则；分别为24/26/34/35/46/32项|
|页面与工具回归|导航及故事52项、报价11项、工具7项通过|已有页面行为和文件权限修改没有破坏对应检查；这些数量不可相加当成不同业务数量|

报价首次确认生成订单在前一轮原生场景中单独通过；那一轮整体因身份测试定位方式失败。修正定位方式后，最后全组复测读取已确认报价并打开同一订单，核实实收0、未签署。不是声称最后一轮又新建订单。完整证据见[结果目录](evidence/android-functional-20261021/README.md)。

## 当前执行顺序

1. 本侧安装安卓工具、创建虚拟手机，解决本地打包差异。
2. 本侧用真实安卓页面连接本机隔离数据库，检查五入口、故事填写、身份切换及已有业务。缺页面如实登记。
3. 本侧逐条线核对模拟资料和后端规则，记录通过、缺口与不能测的原因。
4. 修复复测后集中交付；双方再实际操作，重点确认页面是否好理解、操作是否顺手。正式外部服务仍单独验收。

## 本机配置

工具位于工作区 .local/tools：Java 17、Android SDK、Android 15/API35 x86_64 虚拟手机 JX_API35。虚拟化加速已经实际通过检查；不需要重启。全部镜像和安装内容在D盘，未上传Git。

J:映射工作区，K:映射本轮Flutter项目，避开Windows中文构建路径；脚本会检查占用，不覆盖别人的映射。只修改子进程环境；本机代理只供下载依赖，构建限制两项并发、2GB Java堆。跨盘Kotlin增量缓存关闭，项目正式运行逻辑不受影响。

在本轮仓库目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android-local.ps1 -Action status
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android-local.ps1 -Action start
# 人工需要看见手机窗口时，先停止本项目虚拟手机，再带 -Visible 启动。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android-local.ps1 -Action stop
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android-local.ps1 -Action start -Visible
```

模拟资料由 `node scripts/joint-test-data.cjs start story` 生成，须先按[隔离测试说明](JOINT_TEST_20261022.md)启动本地MySQL并设置测试配置路径。该命令返回本轮access_file，账号只用于随机隔离数据库、约一小时失效，不需要找甲方要验证码。不要把access.json或安装包发给甲方当正式服务。

```powershell
# 用实际返回的路径替换下面占位符；不要复制旧会话。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android-local.ps1 -Action test -AccessFile <本轮access.json>
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android-local.ps1 -Action preview -AccessFile <本轮access.json>
```

自动测试截图位于本轮仓库 .local/android-runtime/screenshots；复核后的证据另放 docs/testing/evidence/android-functional-20261021。人工预览带“本机模拟测试”标记，使用正常业务页面及真实本地接口，但登录注入合成测试会话，不代表真实短信验收。关闭模拟资料须使用对应stop文件或quit命令，清除本轮数据库和会话；随后关闭虚拟手机。

## 双方人工测试怎么接手

先由本侧重开本机模拟资料和可见安卓窗口；你和队友可以通过现有远程桌面操作，无需把手机用USB接到服务器，也无需真实验证码。当前测试会话结束后关闭，人工开始前重新生成，不能用旧安装包里的过期账号。

|顺序|实际操作|预期结果|负责人|
|---|---|---|---|
|1|逐个打开广场、试镜、通告、消息、我的，再进入设置并返回|导航不乱跳；尚未开放的功能清楚说明状态|双方人工操作，本侧记录|
|2|进入我的身份，在个人和测试机构之间来回切四次|每次只变一次，清楚显示当前身份；机构不自动获准所有业务|双方人工操作，本侧复现问题|
|3|切回个人，填写故事，先保存，再重新打开并提交|草稿能找回，提交后明确谁来处理；必填不完整不能提交|双方人工操作|
|4|查看已审核测试报价，核对价格和条款，确认并查看订单|底部能找到下一步；订单仍未付款、未签署；再次打开是同一订单|双方人工操作，本侧核对账与权限|
|5|配合运营网页补件、受理、报价和独立复核|不同角色各做自己的工作，用户能看懂下一步；网页按上轮指南启动|双方共同操作；本侧准备各角色资料|

模拟机构尚未通过正式资质审核；选择机构身份不代表审核通过。截图里的100.01元等数值仅用于测试，不能作为正式定价。

随后建议队友先补真人/机构受托、制作交付的新页面，再依次接现货、通告/试镜、钱包、共创/权益等；这是建议顺序，未替队友认领。本侧继续提供各状态资料、查接口和修复。外部支付、OSS、真实签署、真实设备相机/文件选择及性能需要另外验收。

## 已发现并处理的问题

|问题|处理|复验结果|
|---|---|---|
|已确认报价的订单入口在长页面深处，不容易找到|改为固定在底部，保留服务器两种已有订单编号位置及原约定提示|实际安卓查回同一订单；新回归检查底部可点且不会重复确认|
|正式包缺证书时回退调试签名|缺正式证书保持未签名|实际Gradle报告debug=debug、release=null；正式签名仍待证书|
|本地构建缺少file_picker插件兼容处理|从一次性远端打包脚本移到统一构建配置|本地APK构建并安装运行成功|
|正式包资源允许公网HTTP例外|正式资源只允许HTTPS，本机HTTP只放调试资源|检查源码与实际调试APK资源；未构建正式包|
|本机构建内存不足、跨盘缓存失败|限制并发和Java堆，关闭本机跨盘Kotlin增量缓存|构建通过；不修改产品业务规则|
|软件图形环境调试断开、截图大数据传输不稳定|本地测试使用软件渲染，将截图保存至应用目录后按PNG拉取|全组三场景通过，13张PNG；不据此评价性能|
|测试故事账号只有个人身份，无法查切换|增加归属本人的合成机构，补只读成员/邀请接口|四次原生切换稳定，故事资料21项复验通过|
|Windows测试配置再次写入时权限设置失败|只更新访问权限，不写审计/所有者权限|首次和重复保护回归通过；权限仍仅当前账号|
|旧原生测试还是旧导航，不能证明当前V5|新增五入口与故事/报价当前原生测试；保留旧iOS历史|三场景通过；没有声称本轮测过iOS|

重要共享改动涉及正式签名与网络配置，须由队友实际检查后进入共同版本。本侧测试、上传或远端检查通过，不等于已获另一方审阅；实时上传与合并状态见[当前进展](../status/CORE_CURRENT.md)。
