## 本机怎么启动、重置和检查

先按已有 `scripts/local-mysql.cjs` 准备独立MySQL测试环境。`JX_MYSQL_TEST_ENV_FILE` 指向本机忽略上传的测试配置；启动器严格核验本机33316端口、测试账号及jx_dev，不接受生产配置。不要将配置、access.json、编译了合成会话的App或数据库上传Git。

```powershell
# 本开发机的现有配置；队友机器应使用自己的测试配置路径。
# 本轮结束已移除临时J盘符；本开发机重开时先恢复以下映射和测试MySQL。
subst J: 'D:\ccc\博士资料\7.项目\2026-晶晶日上'
$env:LOCAL_MYSQL_ROOT='J:\worktrees\full-flow'
$env:LOCAL_MYSQL_HOME='J:\worktrees\core\.local\mysql\mysql-8.4.11-winx64'
node ../full-flow/scripts/local-mysql.cjs start
$env:JX_MYSQL_TEST_ENV_FILE='J:\worktrees\full-flow\.local\mysql\runtime\test-env.json'
node scripts/joint-test-data.cjs check
node scripts/joint-test-data.cjs start story
```

`check`逐组建库、检查接口并清理；结果在`.local/joint-test-data/CHECK_RESULTS.json`。也可`check artists`单独检查。`start story`启动一组供人工操作，打印本机地址和access_file位置，不打印会话口令。access.json里是本次生成的买家、受理人、报价人、独立复核人、无关用户等账号（各组不同）。使用已有本机测试入口注入合成会话，不调用真实短信。

停止时在启动终端输入`quit`，或写入启动结果所示stop_file。等待状态变为STOPPED再重开；重新启动即生成新库和新账号，不覆盖原库。每组最多开放60分钟，仅监听127.0.0.1。本轮结束会关掉服务，明天需重新启动，不能使用今天的过期会话。

## 前两轮页面的复现方式

1. 后端启动`start story`，记下打印的base_url及access_file。
2. 页面工作树中设置`CUSTOMIZATION_ACCESS_FILE`为该access.json绝对路径，执行`node scripts/prepare-r01-app-fixture.cjs`。只生成被Git忽略的合成会话配置。
3. 运营网页目录设置`VITE_BACKEND_ORIGIN`为base_url去掉`/api/v1`后的地址，运行`npm run dev:runner -- --host 127.0.0.1 --port 5173 --strictPort`。
4. App目录使用已有Flutter环境运行：`flutter build web --no-pub --target=test/support/r01_browser_main.dart --dart-define-from-file=.local/r01-browser-defines.json --output=.local/joint-web`。将该目录仅在127.0.0.1:5000提供静态访问。这个入口有本机限制，不是发行包。
5. 用`scripts/v5-r01-app-browser-check.mjs`走第一轮，再把结果文件中的request_id设置为`CUSTOMIZATION_REQUEST_ID`运行`scripts/v5-r02-frontend-browser-check.mjs`。Windows设置`CHROME_PATH`为本机Edge可执行文件。结果路径由`CUSTOMIZATION_EVIDENCE_DIR`指定。

真实页面证据与本轮最终测试数量见[本轮记录](../tasks/records/CORE-v5-test-readiness-20261021.md)。App网页检查不能替代原生安卓手机验收。
