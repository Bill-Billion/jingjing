# 三类私有依据：受限提示与主动恢复

本轮承接 [后端跨模块交接](../backend-cross-closure-20261104/REPORT.md) 的前端复验，属于原第4、11、17组的局部工作。服务器此前已修商单、发行、财务原文件入口的权限检查；本轮不重复更改后端。组合起点 PR39 `90dc1c2aa1f16520da1a6d03702e8b66e057c64c` 包含 `dcf410ae` 和同事 `9f3ad878`；这两笔之后至该起点仅有协作资料修改。本批最终提交及检查以实际 PR 精确 SHA 为准。

## 发现、原因与修正

- **App 财务**：先成功读取，再遇服务器返回 `409 CONTENT_RESTRICTED` 时，原成功提示仍在，容易把上次读取误认为本次成功。修复前组件回归实测复现；现在每次开始读取清旧提示和错误，限制明确提示、解除后须主动点击。保存中身份变化后不显示成功；系统保存失败不冒称成功。
- **网页财务独立核验**：同一证明先读取成功、随后再次读取返回409，页面原有“已读”仍在，审核决定可能仍可选择通过。修复前对真实 `FinanceView` 的组件测试复现（预期不可提交、实际仍可提交）；现在发起重读时先移除该证明的已读状态、清旧提示并回收本页文件地址，只有取得本次文件才重新允许已读条件成立。没有调用真实审核或支付。
- **商单、发行、财务的受限提示**：已有通用409并不说明资料受限；现将 `CONTENT_RESTRICTED` 翻译为“材料当前受到限制，暂不能读取。限制解除后可重新读取。” 无权身份仍走403/404原有清理与权限提示，不显示他人的限制信息。
- 这些措施不能自动得知用户曾读过的文件后来被限制：若未再次读取，页面没有后台推送可主动发现变化。本批没有改变财务审核服务端规则；已下载到设备或交给系统保存的文件也无法由页面远程收回。需要另一方结合审核规则决定是否须在提交时服务端重新核查。
