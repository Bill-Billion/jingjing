## Android 原生登录与失效（本批修改后）

Android 模拟器以真实登录页面、真实 localhost 账号 API 和隔离 MySQL 运行 `scripts/tonight-login-native-check.mjs`；短信适配器为合成，不发送真实短信。登录 UI 没有注入令牌：模拟不可用先返回 503，原挑战核对不可恢复、冷却期再次请求 429；随后另一合成号码登录成功，返回原充值页且没有自动发出充值写入。新用户无账本时 `WALLET_NOT_FOUND` 原被误报为无权，已修改充值页显示先阅读规则及开户；修前／修后原生截图和组件红绿记录均在 `native/`。

测试再通过隔离 API 撤销当前合成会话，Android 刷新返回 401 并清除私有状态。原公共身份门只显示“选择身份”，未说明失效；现明确显示“登录状态已过期”和重新登录，保留 `/wallet/recharge` 返回路径，且不自动继续提交。`native/red-result.json` 是修前 401 实际失败，`native/result.json` 和 `native/execution.log` 为修后操作与清理；`wallet-final.log` 为 11 项钱包组件回归。测试的短信失败与成功使用不同合成号码；未等待同一号码冷却后再次发送，也未覆盖所有业务页。受测版本为上述基线加本地修改，精确源文件摘要见结果。

App 受影响的 account、navigation、stock、wallet、auditions、cocreation、redemption 和 engagement 组件回归在本批公共门修改后 320 项通过（后来仅改钱包未开户提示并单独跑 11 项）；这些不是 Android 六条完整路线通过。

格式化测试文件后，以本批最终受测 App 源码再次执行原生登录检查，结果与源码摘要见 `native/final-source-result.json`：登录返回原业务页未自动写入，撤销会话后清除私有状态。短信及账号仍为本机合成测试，测试库和转发已清理。
