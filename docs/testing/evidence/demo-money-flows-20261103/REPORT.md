## 过程中排除的测试问题

1. 初稿脚本期望新付款为 CREATED，实际启动模拟渠道后正确状态为 PENDING。修正断言，没有改业务代码。
2. Playwright 的媒体响应 `body()` 返回空数组，不能单独作为空文件证据。随后读取页面真实 Blob 并与直连接口交叉核验，两者均等于上传原文件。保留初次失败记录，未当成产品缺陷。
3. 试镜拒单已自动建立退款，初稿脚本却继续申请第二笔退款。页面禁用重复申请符合预期。最终沿拒单返回的 `refund_id` 打开原退款，完成独立审核、执行和核实。
4. 现货售后编号是自动选中的下拉框，初稿用了文本框 fill。改为核对已选编号后继续，未手工修改页面数据。
5. 一次未处理的 Playwright 等待异常使测试进程退出；只清理该次进程编号 26152 创建的随机数据库，范围和结果见 crash-cleanup.json。后续修正等待异常捕获，最终两条链正常退出并自动清库。

attempt 文件是以上测试脚本纠正前的历史结果，不能与最终同单编号混用。最终结果以 results.json 和两个 *-result.json 为准。
