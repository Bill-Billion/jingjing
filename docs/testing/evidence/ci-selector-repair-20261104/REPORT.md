# 商单选择入口及新版艺人形象兼容复验

本轮基于 PR39 `39cd1fd3` 加本地修复。属于今晚计划第4条商单、第10条机构艺人的组合复验，不是新增业务范围，也不代表18组或151条整体验收完成。

## 依据和本轮前后变化

[今晚计划](../../../collaboration/client-complete-20261028/TONIGHT_EXECUTION_20261104.md)明确：“可以选择商品/服务/艺人/机构，必要规则及授权齐备。不要求甲方复制内部编号，不靠开发者改库解锁流程。”本轮修复是该办理要求的测试补全与已有数据兼容，不增加合同条件或放宽业务授权。

1. 远端原浏览器检查仍把“选艺人”当文本框填写，实际页面已改为受控选择。改为从当前机构可见的已审核公开艺人中选择，并检查未选不能提交、发送对应公开展示编号。
2. 增加正常资料前提后，发现真实缺陷：新版艺人形象的材料在LOOK/VOICE记录，AVATAR自身材料数组为空；网页和App仍强制旧数组至少1项，导致新形象不能被商单页面读取，甚至整页选项拒绝。现按服务器实际格式区分：旧形象仍至少1份材料；新版必须同时有有效真人编号、明确归档状态、长期模型未启用且供应商引用为空。不修改权利审核、材料权限或后端商单资格。
3. 公开邀请合成资料通过正常艺人创建、模拟成人核验、本人明确公开授权、独立审核、L1和免费托管、公开展示审核完成；不是SQL强改已审核。运营授权和规则是隔离夹具前提，不能将它们声称为页面办理。
4. 同批4份旧脚本已修改：PR17网页/App、PR39商业新约定、六项交接。PR17默认截图改存`.local`，显式归档使用本轮路径，历史截图未覆盖。

## 可重复命令

在仓库根目录设置本机隔离配置和浏览器路径（不含密钥）：

```powershell
$env:JX_MYSQL_TEST_ENV_FILE='J:\worktrees\full-flow\.local\mysql\runtime\test-env.json'
$env:CHROME_PATH='C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
$env:JX_BROWSER_EVIDENCE_DIR='.local/pr17-current-evidence'
node scripts/run-ui-browser-check.cjs 17 --built
node scripts/pr39-commercial-contract-browser-check.mjs
node scripts/pr39-six-handover-check.mjs --web-only
```

顺序运行，避免多个浏览器和构建同时耗尽内存。六项脚本不带`--web-only`仍保留既有原生完整流程；仅在明确可以使用安卓设备时运行，不能把网页模式的NOT_RUN当原生通过。
