## 真实阻断与修复

修复前，收入约定的“实际受益主体”下拉只列项目所属方、当前本人和已确认艺人，未包含原已审参演合同中的平台方；因此无法按既定90/10合成收益条款填写平台份额。浏览器失败项目61a0ed81-b113-4e90-a7e6-06d70e3fc859，证据 [修复前结果](red-income-platform-missing.json)及 [实际页面结构](red-income-platform-missing.html)。这是一项已实际复现的页面资料来源缺口，不是接口付款失败。

按主负责人授权修复：src/business/references.ts 的参演party_id分支改为读取本项目所属主体、已确认候选人及本项目已审核参演合同的实际各方；src/business/participationParties.ts完成合并、责任名称显示、全部分页读取、重复游标及外项目拒绝、账号和办理主体核验、读取结束时项目版本再核对。没有全库搜索主体，不要求客户输入UUID，不改变合同、比例或艺人报酬；候选项也不代表自动获得收益。

新测试 tools/test-participation-income-options.mjs 纳入既有 test:business，5项覆盖正常平台候选与未审排除、外项目、重复游标、项目版本变化及权限拒绝。完整 test:business 通过，类型检查通过，独立构建成功。见 [业务检查](business-tests.log)、[类型检查](type-check.log)、[构建](build.log)。这是让既有收入约定能够从页面正常填写的“流程补全”，不是甲方新增分红要求。原需求与固定片酬原文沿用 [第一批报告](../../REPORT.md)所列20261029合同出处；90/10仅是本测试明确会签的合成条款，不是平台默认。
