## 需求原文与测试补全

来源：[甲方合同包《晶钻抽奖规则》“二、制作金”](../../../sources/contracts-20261029/extracted/22.md)。原文：

> 仅可用于真人承制的定制影视作品（人生主角定制片及做剧），不能用于数字人创建、托管、样片；

> 订单退款时，已用制作金不返还、不顺延；

> 除抽奖外，设置固定兑换区：可用晶钻明码兑换部分制作金（50/100/200/500 元，兑换价为面额×120 晶钻，即 6000–60000 晶钻），用户无需赌概率也可获取。

本轮选固定兑换的 50 元制作金，消耗 6000 晶钻，绑定人工定制服务规格。500 元门槛和 50 元面额来自该文档列出的制作金档位；注册 12000 晶钻、签到 100 晶钻仅是合成测试参数，不作为甲方正式奖励规则。

“同日重复签到不能重复发放”“未付款取消释放原券、不再额外返兑换晶钻”属于流程补全检查，不能冒称上述条文逐字规定。已用券退款不返券属于原文明确要求。当前 30%–40%–30% 付款按既有最新定制代码验证，本报告没有另行决定付款比例。

## 实际操作结果

全部业务按钮由 Edge 无头浏览器操作，连接真实本机隔离 MySQL 服务；不是请求拦截假返回。最终运行从全新库重新完整开始，第一轮结果独立保存在 `first-run/`，最终结果在 `final-run/`，不拼接不同订单当作一条链。

| # | 页面操作与预期 | 最终实际结果 |
|---|---|---|
| 1 | 阅读有效规则并开户；只获得合成注册奖励 | 可用晶钻 12000，现金余额 0 |
| 2 | 本人明确签到 | 可用晶钻增至 12100 |
| 3 | 刷新重新签到，不能重复奖励 | 仍为 12100 |
| 4 | 读取已审库存，明确兑换 50 元制作金 | 新券可用，扣 6000，剩 6100 |
| 5 | 在原报价选券，核对后建立订单 | 原报价 500 元，抵扣 50 元，应付 450 元；分期 135/180/135 元 |
| 6 | 原订单建立首付款、渠道模拟成功后页面核实 | 首款 135 元到账，原券核销；没有实际资金往来 |
| 7 | 买家申请原款退款→独立审核→执行→渠道模拟成功→买家核实 | 退 135 元，现金净额 0；原券仍已使用，晶钻仍为 6100，没有把券额退成现金 |
| 8 | 另兑换一券→另一个新报价下单→未付款取消 | 第二订单取消，原券从锁定恢复可用；晶钻仍为 100，没有再返兑换花掉的 6000 |

最终运行记录了 13 个过程检查点（含 1 个前置资料点、2 个外部支付模拟点）及 108 次浏览器 API 响应。这些数字不是功能总数，也不是 151 条正式标准的通过数。
