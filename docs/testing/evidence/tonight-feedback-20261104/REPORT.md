# 2026-11-04 反馈页面的隐私与失败恢复

关联今晚公共交互及原测试反馈要求的局部证据，不改变 151 条正式状态。受测基于 `b0ed887871ea07f8dcaf2c5e4258042a99d7b82c` 加本批本地反馈工具修改；`result.json` 记录确切源文件 SHA-256、时间及清理状态。Chrome 在 390 像素视口运行本机隔离测试门户，iframe 内是明确标识的合成表单夹具，不是实际业务 App；没有调用真实服务。

- 修复前实际复现：业务路由含 `orderId` 和合成 `token` 查询值时，反馈弹窗显示该 token，并在 POST 内容中发送；证据为 `red-result.json` 的 `context_exposed_secret`、`request_exposed_secret`。服务端在保存时已有过滤，但不足以阻止浏览器显示或传输。
- 修复：免邀请码体验和原邀请测试两种页面在展示及提交前按服务端同一允许列表过滤路由参数；保留允许的业务编号，剔除 token 等未列参数，服务端过滤继续保留。此项仅约束自动关联的路由，不承诺识别用户自行写入描述或截图中的全部敏感内容。更换已冻结测试门户文件后必须按既有流程准备新构建清单及候选，不覆盖或自动延长已有会话。
- 修复后，实际浏览器分别验证两种门户的显示和发送均不含合成 token，保留业务编号。自由体验模式额外模拟服务端已存储但响应丢失：反馈及业务夹具草稿仍在，恢复使用同一键和内容，最终仅一条反馈；重新加载后原访客仍可读。证据为 `result.json` 和截图。测试没有验证真实业务 iframe 表单或生产环境。
- `portal-api.log` 为20项独立本机 API/存储自动检查，覆盖隔离、去重、权限、截图与重启恢复；它不是浏览器或整条业务验收。
