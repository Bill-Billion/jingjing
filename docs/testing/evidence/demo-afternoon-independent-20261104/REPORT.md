## 修复前的真实阻断

同一房间已由10名不同本人实际确认参加，截止核定为 `READY`，首期模拟付款已到账记账。制作方进入 `/production/orders/{orderId}/fulfillment-new` 并填写有效剧本、负责账号、用途、地域和依据后：

1. 勾选“本项目使用可识别的真人或数字人”，页面强制要求手填出演人，空名单时提交按钮禁用。
2. 不勾选则能够发送请求，但服务器返回 `400 / COCREATION_CAST_MANAGED_BY_ROOM`。
3. 原服务器要求 `uses_identifiable_people: true`、空 `cast`，再从房间读取已确认授权；网页没有表达这种情况。不是人数不足、未付款或授权未完成。

证据：[勾选后禁用](before-fix/cocreation-co-cast-empty-disabled.png)、[实际请求被拒](before-fix/cocreation-co-cast-unchecked-rejected.png)、[原始结果](before-fix/cocreation-result.json)。该脚本将“重现已知错误”作为断言成功，所以结果 `failures: []` 和退出0只表示复现符合预期，**不表示修复前产品可用**。后续接口制作成功保留为分层诊断，不能代替失败的网页流程。

修复仅涉及网页 `src/views/DeliveryView.vue`：合法共创房间显示明确说明与返回房间链接，隐藏手填出演人；请求使用上述原有服务器格式。普通私人定制仍采用原来可识别人物/逐人授权输入，未改变后端权限或付款规则。
