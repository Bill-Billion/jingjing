## 业务验证与模拟边界

- 123个场景宽度使用真实隔离服务返回的合成测试账号/业务记录；浏览器记录的业务请求全部为GET。真实API与生产账号是不同概念。
- `11-pools-closed` 的3个宽度显式将一次 `GET /redemption/pools` 替换为空信封，仅验证24A关闭界面；不能据此证明当前服务没有已发布活动。记录的 `evidenceKind` 为 `VISUAL_STATE_STUB`。
- `12-preferences-on` 只切换两个真实控件，检查 `aria-checked=true`，**未保存**；不能证明服务器偏好已经改变。选项选择后的4个表单也只展开真实数据，未提交、上传或替换授权。
- 浏览器截图没有执行支付、签署、上传、审批、投票、兑奖、邀请、取消、退款、明确收件或保存偏好。root建立隔离fixture的操作单独记录，不混为浏览器业务验收。
- 新增状态测试覆盖成功空结果与失败区别、月冠军异议门槛、城市传入目录、钱包规则匹配及不匹配分支。共创与新增状态末次定向回归12例通过；其它本域定向测试与静态检查详见需求报告。正式App测试范围以现有CI的明确目录命令为准，历史V15视觉套件没有被算成通过。

审图证明位于 `corrected/review/REVIEWED_CONTACTS_390.json` 与 `final/review/REVIEWED_CONTACTS_{390,320,768}.json`，记录实际拼板和源图SHA256。主任务最后复验与其它域证据由上级总索引合并。
