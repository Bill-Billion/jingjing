1逐项开发动作

C1改逻辑

打开首屏＝艺人广场 ＋ 左上角地理位置

现状
冷启动落 Tab1"首页（短视频信息流）"，艺人广场在 Tab2。
改为
冷启动默认进艺人广场（龙虎榜）；底部 Tab 顺序固定为 艺人广场 / 视频商品 / 线下试镜 / 剧集 / 我的；广场左上角加位置选择器（定位授权 ＋ 可手动切城市 / 商圈），榜单与货架按所选位置过滤；不做全国混合大市场。
前端
初始路由改 /plaza；新增 LocationPicker、RankBoardList；原信息流页改名"视频商品"、移到 Tab2。
后端
GET /plaza/rankings?geoId=&type=、GET /plaza/artists?geoId=&…；位置字典 geo_nodes；榜单按 geo 分区计算。
验收
冷启动首屏即广场；切换位置后榜单 / 货架随之变化；拒绝定位时须手动选城市，不展示全国混合榜。
C2改逻辑

交通费并入固定出场费一口价

现状
固定出场费 ＋ 交通费凭票实报实销、交通费不抽成、不入分账（F2 口径）。
改为
艺人只设一个固定出场费总价（已含交通），类似"包邮"；商品页只展示一个价；平台按含交通总价计入 22% 佣金基数，下单按总价支付。废止交通费单列 / 报销 / 不抽逻辑。
前端
试镜服务编辑 / 详情去掉交通费字段，改单字段 fixedFee（提示"已含交通"）；下单金额＝fixedFee。
后端·数据
试镜商品 / 邀约 price=fixedFee，分账按 22%；表中去掉 transport_fee，保留 fixed_fee。
验收
全链路无独立交通费；分账按总价计算、多方分账各列合计＝100%。
C3改逻辑

剧集 Tab＝演出记录 ＋ 参与 / 评选 / 兑换商城

现状
剧集 Tab 以剧目上架、播放观看为主。
改为
两大区：① 演出记录（剧目 / 剧本介绍、进度条、演员名录、出演记录、成片）；② 参与中心（抽奖 / 摇奖池、积分 / 等级兑换、评选 / 月冠军）。
后端
POST /drama/lottery、POST /drama/exchange、POST /drama/vote、GET /drama/:id/records。
数据
lottery_pools / lottery_tickets / reward_items / exchange_records / contests / contest_votes / drama_cast / drama_progress。
验收
中奖可获得对应角色名额；积分兑换实时扣减留痕；评选产生称号；演出记录完整可查。
N1新增

"主角光环"真实信息认证

现状
仅有视频认证、出品认证。
改为
新增"点亮主角光环"＝真实信息认证（类似"金牌讲师"、闲鱼"擦亮"），与等级无关；通过后榜单 / 推荐曝光加权、档案卡展示光环标识。
前后端
认证中心加入口；POST /verify/halo 通过写 halo_verifications；榜单 / 推荐权重增加 halo 因子。
数据
halo_verifications(user_id, materials, status, verified_at)。
验收
未点亮无加权；点亮后标识与排名加权生效，且与等级完全解耦。
N2新增

真人试镜取样 → 数字人造型底板

现状
试镜交付 6 照 / 1 视频，未与数字人资产打通。
改为
试镜为"真人试到数字人"：演厨师着厨师装、演骑马带骑马装备；取样的妆造 / 装备 / 真人影像入库成为该数字人造型底板与 AIG 排剧底层框架；不接受后期把造型 P 到数字人上。
前后端
交付物可"设为数字人造型底板"；POST /assets/baseplate 关联 digital_assets.id，AIG 任务引用底板。
数据
audition_baseplates(id, asset_id, audition_id, look_tags, files, owner_id)；digital_assets.baseplate_id。
验收
试镜素材可成为底板并被排剧引用；底板归艺人；无底板时 AIG 提示先取样。
S1细化

星探 → 一期轻量"邀约意向卡"

现状
数字人合拍四步流程，入口位置未定（评审中明确"还没想好放哪"）。
改为
入口固定在艺人详情页右上"星探邀约"；未下单前出品人填结构化意向卡（拍摄目的 ＋ 内容，可附数字人合影 / 打招呼短视频）；艺人同意 / 拒绝，同意才转洽谈 / 下单；无自由文字私信。
后端·数据
POST /scout/intent（状态 pending / accepted / rejected）；accepted 一键转试镜邀约 / 商单；scout_invites 改名 scout_intent_cards。
验收
未下单可发卡、可被拒绝；同意后才进入下单；全程无开放 IM。
S2细化

"企业代下单"→ 企业 / 团体代下单

改为
明确为企业行政 / 经办人代表企业批量采购（节日祝福、开业祝贺等）；审核经办人 / 法定代表人代表权，发票开企业。
前后端·数据
下单流程支持"为企业 / 团体代下单"（企业、经办人、用途）；订单关联 enterprise_id / operator_id / order_scene；新增 enterprise_representations。
验收
代下单订单企业信息完整、发票抬头为企业、代表权过审。
S3细化

商品 / 榜单 / 客服 / 成年 等细节

  • 未解锁态统一称"黑内容"：整黑画面 ＋ 产品名 ＋ 未解锁图标 ＋ 价格，不再用"黑框"表述；付费后解锁可看、可下载。
  • 榜单六维：等级、新人、好评 ＋ 销量、人气、复购，均按 geo 分区；权重＝成交 ＋ 评分 ＋ 复购 ＋ 活跃 ＋ 合规，违规降权。
  • 客服按节点出现：艺人客服 / 私人联系方式在点过购买 / 解锁后出现（试镜为接单 ＋ 付款后）；此前仅平台通用咨询入口。
  • 成年声明：为他人制作时制作方勾选"已成年声明"；为未成年人制作仍须监护人授权。

3订单 / 履约状态机改动

  • 新增"出品人确认履约"节点：艺人交付后进入待出品人确认，须出品人在 APP 点确认 → 已清分；不允许跳过确认。
  • 超时兜底：出品人逾期未确认，系统到时自动确认并清分（保护艺人、防恶意不确认）；时限后台可配。
  • 意向卡状态：pending → accepted（可一键转订单）/ rejected / expired。
履约认定不以最终是否被录用为条件：艺人按约到场、完成与所选角色一致的试镜即具备履约条件，待出品人确认后清分。

4明确不变（不要重复开发 / 不要回退）

  • 平台定位与口号"晶晶日上，做自己的人生主角"、五类角色、一人多身份合一；
  • 不进场选身份、统一入口；分佣比例 18%（样片 / 数字商品）/ 22%（商单 / 线下），供给侧默认艺人 80% / MCN 20%；
  • 自营 / 增值类口径、足额纳税测算、清分 T+1 / 状态机 / 尾差由平台承担；
  • 持牌清分、不设资金池、不二清；数字人资产归个人；CMS / 比例后台可配；角色级鉴权；
  • 剧本提供方自助门户本期不开放，但端口与角色提前预留。

6.2 后端服务 / 引擎与关键接口

  • HaloService：提交 → 机审（实名 / 活体）→ 人审（L2/L3）→ 到期复核 / 金光环月度复核 / 造假封禁。
  • GrowthEngine（事件驱动、幂等）：监听 order.completed（数字商品 1 / 试镜 3 / 商单 5 分）、review.added（五星 +1、图文 +2、视频 +2）、复购 +2、order.refunded（扣回并 −5）、违规处罚；重算 level 与 gp_90d。
  • RankService：按 geo ＋ type 计算；分项先在同 geo 内归一化到 0–100，再加权；好评用贝叶斯修正（先验 C=10、m=4.0，<10 条不上榜）；新号 7 天冷启动、复购需 ≥20 买家；写 rank_snapshots。
  • PointsService：账户 / 流水 / 批次 FIFO 过期；消费返晶钻在售后期结束才入账，退款按比例扣回；全部幂等 + 事务、余额不可为负。
  • LotteryService：按 odds 加权抽取，校验库存 / 光环资格 / 日上限；角色名额只发"参选 / 试镜资格"，不直接出演；全程留痕。
  • ContestService：投票每日上限、异常票剔除；总分＝官方 .6 ＋ 榜单 .2 ＋ 投票 .2。
  • 风控：同设备 / 同支付账户高频自买、秒退、刷票刷好评 → 剔除量、降权 / 封禁，留日志。

6.6 验收标准

  • 未点亮光环不可上架、不进榜；L1/L2/L3 曝光与榜单系数按配置生效，且与等级完全解耦；
  • GP 计分幂等（重复消息不重复加）、退款正确扣回、90 天保级自动降级；
  • 榜单按 geo 隔离、好评贝叶斯防小样本、新号 7 天冷启动、复购 20 买家门槛生效；
  • 晶钻余额不为负、退款扣回、过期 FIFO；抽奖概率 / 库存 / 资格正确、投票每日上限生效；
