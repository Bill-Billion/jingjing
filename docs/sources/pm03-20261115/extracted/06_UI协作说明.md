# UI协作说明

## 目标

在前端已完成的页面重塑基础上统一视觉，支持本轮业务接入，不再另外规划一套产品。设计稿、页面实现、接口接通和业务验证分别记录。

## 优先交付

先确定字体层级、颜色、图标、按钮、表单、选择器、卡片、列表、弹窗和消息提示。每个组件至少区分正常、加载、空数据、字段错误、不可操作、成功和失败；是否展示某种状态由实际业务决定。

首批支持视频商品详情、许可、付款状态、已购/下载、通告卡片、发布表单、审核/投稿结果。随后按定制试镜、机构隐私、共创与权益、发行收入顺序提前一批。

UI可与接入并行。非关键图标、字体细节没有最终确定时，使用已有组件继续接接口；定稿后统一替换。状态含义和必要错误提醒不能留空。

## 交付清单

组件和页面版本、资源名称与格式、字号/间距规则、适配范围、交互状态、已定/待定说明，以及字体图标的使用许可依据。生产文件不附无授权字体；不要将图片中的字当作不可编辑按钮。

## 不能代替的决定

不决定谁能发布、如何收费、何时解锁、是否自动验收、退款金额、授权用途或分成比例。这些以有效需求和后端结果为准。设计与当前规则不符时先指出冲突，不让前端照着漂亮但错误的流程实现。

## 验证

前端每完成一批实际操作后检查可读性、层级、控件状态和一致性。影响理解/误付款/误授权/可访问性的缺陷优先处理；普通美化集中调整，不阻断其他功能接入。
