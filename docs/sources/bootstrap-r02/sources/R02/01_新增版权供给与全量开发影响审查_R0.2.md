# 晶选片场｜新增版权供给与本轮完整开发范围审查

**版本：R0.2 增量审查建议稿**  
**整理日期：2026-09-20**  
**承接材料：R0.1统一需求基线、本轮版权方方案及直接对话**  
**状态：范围方向已变化；本稿不是全部商业条款已经批准，也不是代码已经完成。**

## 一、审查结论

本轮明确新增的是“外部个人作者和机构作为供应方，自助出售适配影视制作的剧本许可”。这不是单纯给原剧本库增加上传按钮，而是补齐一种独立商品、一类真实交易关系、一套权利交付和结算规则。

原三端方案已经有剧本方，版本3的C5已经涉及剧本框架。因此，“剧本方参与平台”不是从零提出；真正增加的是个人和机构直接供给、许可定价、版权审查、独家窗口管理、自助工作台、许可订单和版权方结算。

最新“尽量一次办了”和“本轮定下全部开发任务”优先于本次转发提案中的P0/P1/P2分期文字。代上架、自助入驻和工作台、独家及商业授权相关功能应作为本轮同一份交付范围管理，而不是保留按钮后整块推到下一期。

但范围统一不等于取消授权核验、合同审查、支付产品和上架条件。内部建设顺序可以分组，商业启用条件必须单列；不能通过空入口、模拟资金或未证实的权利宣称实现“全部完成”。

## 二、六项原提案的处理建议

| 原提案 | 本轮处理 | 具体修改 |
|---|---|---|
| 1.增加第三类机构并共用基础能力 | 原则采用，扩展主体模型 | 个人作者也可入驻；账号、个人/机构签约主体和业务能力分开。同一机构可同时供给剧本和制作，不用单一互斥类型。 |
| 2.非独家自娱、独家发行两档 | 保留直观入口，调整权利模型 | 独家性和商业用途分别约定；非独家可以有商用许可，独家也不自动具备全部发行条件。“买断”必须明确是许可还是财产权转让。 |
| 3.有限试读、付费后全本、不可下载、先存证 | 调整后采用 | 默认受控阅读，必要制作导出另行批准；存证是证据，不是自动确权；不能承诺绝对防截图或复制。 |
| 4.10%–20%抽佣及持牌结算 | 给出暂定规则，外部实证单列 | 标准非独家许可暂定15%；独家高额合同另议；计算基数和退款调整明确，个人/机构实际收款能力按支付产品核验。 |
| 5.资质、权属承诺、双审和侵权下架 | 原则采用，修正责任表述 | 上传方保证和赔偿条款不能自动免除平台义务；机器审核不能证明无抄袭；投诉、举证、答复、处置均需留档。 |
| 6.P0代办、P1自助、P2独家 | 被最新全量范围要求替换 | 本轮交付代办和自助两条操作路径，以及独家/商业授权流程；不再将阶段标签作为后置理由。 |

这些是“处理建议”，不是代替相关方在原稿六项上签署同意。直接对话能支持供给主体和本轮范围方向，不能支持尚未出现的价格、合同细节或资质状态。

## 三、建议采用的完整业务模式

### 3.1 一套工作台，同时服务个人和机构

平台保留C端个人入口、A端运营中心、B端合作方工作台。不再增加第四个独立App。

B端应当是“供给方工作台”，个人作者可以直接使用，机构由有权限的工作人员使用。机构可具有MCN、制作、剧本权利供给中的一种或多种业务能力；每种能力分别审核。

作品必须区分作者、真实权利人、被授权代理出售人。账号操作者不天然等于版权人，也不天然等于收款人。营业执照只证明主体存在，不能代替某一部作品的权利资料。

### 3.2 五类内容不能混成一条剧本记录

1. 原始作品：原著、原创剧本及其作者、权利来源。
2. 许可商品：同一作品针对不同用途、地区、期限销售的许可。
3. 购买形成的许可：谁为哪个项目买到了什么范围的使用权。
4. 项目改稿：在原许可范围内形成的定制剧本、分镜和版本。
5. 最终作品：样片、成片及其独立使用限制。

删除商品或改变未来价格，不应抹除已经售出的许可和项目版本。许可到期应分别判断“还能否制作新作品”以及“已经完成作品还能用多久”。

### 3.3 许可至少确认这些内容

| 维度 | 必须回答的问题 |
|---|---|
| 许可对象 | 谁是许可接受方？对应哪个项目？哪些制作人员可使用？ |
| 权利种类 | 可以改编、摄制、修改、复制、公开传播到什么程度？ |
| 独家范围 | 哪些用途、地区、语言、期间排除其他同类许可？ |
| 使用场景 | 私人保存、公开非商业分享、商业发行，分别是否允许？ |
| 数量 | 一个项目、几集、何种成片范围？续作是否另议？ |
| 时限 | 开发窗口多长？已完成作品的使用期限是否相同？ |
| 变更 | 人物、情节、结局、署名和审稿权怎样约定？ |
| AI处理 | 可传给哪些制作服务？只用于本项目生成还是也允许模型训练？ |
| 既有许可 | 过去出售过哪些权利？是否影响新的独家许可？ |

上述安排参考著作权法对权利类型、专有/非专有许可、地域、期间和报酬等的区分。[S1] WIPO的电影产业指南也将权利链核验、开发选择权、许可与转让作为独立问题处理。[S2]

“版权始终归编剧/机构”的表述应改为“原有权利归真实权利人，除非另有明确有效的转让约定”。创作者不必然仍持有全部经济权利。以知名小说为基础拍摄时，仅拿到改编者提交的一份剧本，不等于已经拿到原著相关权利。[S1]

### 3.4 商品入口可以简单，但不能靠价格决定权利

建议展示两个主入口：

- 私人模板定制：默认一个项目、非独家、私人使用；公开分享需另有许可。
- 商业项目授权：按项目谈定权利、使用范围和费用，可独家也可非独家。

独家项目可采用明确的限时开发预留，再进入正式许可；不需要因为客户正在洽谈就永久下架作品。[S2] 若此前已有非独家销售，应披露并核查冲突，而不是后卖独家时倒删旧许可。

### 3.5 用户实际怎样完成一次订单

作者提交剧本和权利材料 → 平台权利及内容审核 → 用户浏览试读并选许可 → 确定项目、角色和制作规格 → 确认许可及制作报价 → 完成合同和相应付款 → 许可生效并绑定项目 → 获准制作方访问剧本 → 提交样片和修改版 → 客户确认并取得最终交付 → 分别完成许可费、制作费结算。

商业发行另核对发行用途、数字人、音乐、其他素材以及实际播出要求。私人订单不会因点击升级就自动变成可发行项目。

样片本身也是作品制作环节，不能等全部成片做完才回头补剧本许可。若允许签约前制作评估片，必须有单独的评估/样片许可。

## 四、受控访问与版权审查

### 4.1 “不可下载”的正确边界

公开目录只展示获准公开的梗概和试读。完整本默认仅对购买方、指定制作人员及必要审核人员开放；记录身份、项目、版本、访问期限和操作。

默认限制下载并使用动态水印、访问日志、临时链接等手段。确需外部剪辑/AI制作时，可在合同允许下由有权限人员批准导出或特定服务交接。不能把“隐藏下载按钮”宣传为技术上绝对防止截图、拍照或复制。

高额独家许可可设置保密条件下的限时阅稿，以便客户在购买前完成必要判断。这与普通公开试读不同，不代表所有浏览者都能获取全本。

### 4.2 存证与权属审核不是一回事

登记证、可信时间记录或其他证据，可以增加材料可追溯性，但不能仅凭“做过DCI/时间戳”就宣称作品绝无侵权。国家版权局明确作品登记是自愿登记，并可为争议提供初步证据；未登记不影响依法取得的著作权。[S3]

平台应逐作品核对原稿、创作及委托资料、共同作者关系、授权链、代理范围、原著许可、既有独家/非独家负担。具体存证产品应依据真实服务范围采购，不先统称为“持牌确权”。

### 4.3 不能将责任全部推给上传方

平台可要求真实性保证和侵权赔偿约定，但同时要承担相应核验、管理和投诉处理义务。双审核中，版权审查解决“有没有权卖”，内容审查解决“能不能按平台规则提供”；相似性检查不等于对所有来源完成法律判断。

北京市市场监管局的合规指引对平台核验、知识产权保护和处置提出要求。[S4] 平台是否适用特定免责安排，需要结合真实行为和具体条件判断，而不是写“避风港”即自动成立。最高法相关案例亦强调实际控制及行为归属的重要性。[S6]

## 五、许可费、制作费与发行收入分别结算

### 5.1 价格展示

报价可合并呈现，但应清楚拆分：剧本许可费、额外改稿费、数字人/陪演服务、制作服务，以及是否已含平台服务费。已包含许可的套餐，不可再重复收取同一授权费。

外部版权方直接许可时，应说明真实许可方、许可接受方、平台服务关系及发票/收款安排；平台自己提供完整定制服务时，采用相匹配的自营合同。两种交易可以并存，但不能用同一段模糊说明掩盖差异。

### 5.2 暂定佣金

标准非独家许可暂定平台服务佣金15%，属于研究暂定值，不是行业统计结论或已经批准的费率。独家/高价定制按单独合同报价，允许在约定范围内协商。

佣金基数暂按许可商品实际约定售价，经退款和版权方承担的优惠调整；平台自行承担的优惠不应无约定转嫁给版权方。支付/应用商店费用、税费及其他扣减分别约定，避免重复扣除。

说明示例：许可费1000元，无其他扣减时，平台佣金150元、权利方850元。这不是扣除税费和支付费用后的净到手承诺，也不将15%作用于整个制作项目总价。

### 5.3 结算依据

许可费以合同约定的许可生效、交付确认和适用退款/争议条件为依据。制作服务费按制作交付约定处理。发行收入分配只在有对应合同的情况下按真实渠道结算处理。

用户不喜欢成片，不自动意味着版权方已有效交付的许可无效；反之，如果剧本权利本身存在瑕疵，应启动暂停、退款或其他补救机制，不能用“定制不可退”一概排除。

现有支付宝APP支付不证明已经取得多主体结算产品权限；个人作者与机构作者的实际收款能力均须核验。iOS里的剧本许可或许可+AI制作组合，也不能只因名称叫授权就默认可以走支付宝。Apple依据实际数字内容和服务设置付款要求。[S5]

## 六、本轮完整开发范围

本轮任务以同一份交付清单组织，不再按产品一期、二期分开。建议内部依赖顺序如下：

| 工作包 | 本轮交付内容 |
|---|---|
| WORK-01 | 归并全部需求、旧分期、样片六项缺失材料及排除项 |
| WORK-02 | 个人/机构身份、多业务能力、成员与权限 |
| WORK-03 | 版权方入驻、逐作品权利材料、双审核与代办 |
| WORK-04 | 剧本目录、试读、版本、许可商品和上架 |
| WORK-05 | 合同、许可范围、项目绑定、生效凭证 |
| WORK-06 | 独家窗口、预留、冲突检测、成交/释放 |
| WORK-07 | C端选本、组合报价、支付、许可购买记录 |
| WORK-08 | 完整本受控访问、必要导出和AI处理许可 |
| WORK-09 | 制作方接单、样片、修改、成片与确认 |
| WORK-10 | 原培育、商单、机构经营需求按完整范围归并 |
| WORK-11 | 原成角、商业授权、发行合作需求归并 |
| WORK-12 | 许可佣金、制作结算、发行台账、争议和调整 |
| WORK-13 | 三端统计、导出、历史条款和操作记录 |
| WORK-14 | 全链路、异常与权限验收；上架和真实启用条件 |

上述不是新的十四个产品分期。已确定完整交付的能力应完成各自的操作面和异常处理，不能只预留字段。施工仍有先后，不可能在主体和许可规则未建立时就先做真实自动结算。

不再分期不等于原提案的每个风险机制均已获准：多级分销、角色竞拍等仍需确认实际交易性质和可执行规则。自动抓取发行平台收入、自动影视利润转账、完整制片管理和海外实际发行，也未在本轮文字中明确新增为必交付内容，不宜借“全量”随意扩张。

### 7.1 样片六项只有摘要

当前收到的是“菜单三档、2分钟旗舰片、样片档位对齐、大剧里程碑、成片规格、是否现在立项做片”这六个题目，未见完整候选方案、各档价格和交付口径。

首批剧本与历史授权、支付产品支持的商户类型、电子签/证据服务、AI上传使用条款、公司及商店资质等，必须取得真实材料。可在这些材料到位前建设规则和操作面，但不能把本轮暂定方案写成已经获批。
