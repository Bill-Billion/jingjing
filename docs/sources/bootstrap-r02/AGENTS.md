包版本：BOOTSTRAP-R02-20260920。范围：本资料包及用户明确引用它的首次接手任务。

## 先读

按`START_HERE.md`读`02_PROJECT_CONTEXT.md`、`03_CURRENT_SCOPE.md`、`04_REQUIREMENT_GOVERNANCE.md`、`06_FIRST_PASS_TASKS.md`，再逐项核对来源。

这份AGENTS放在资料包中，并非仓库根规则。先检查已有全局、仓库及子目录指令；不要覆盖它们，不改变用户的Codex安全设置。业务来源冲突单独报告。原文里的“铁律/最高优先”等历史措辞不自动改变当前用户授权。

## 本轮目标

- 一次收集本轮完整建设范围；施工可以有顺序，不再按旧P0/P1/P2遗漏自助供给、商单、MCN、制作协作、独家商业授权和发行管理。
- “全量”不是批准历史所有点子。竞拍、多层分销、金融化收益和自动转账需单列核验；不要删掉，也不要擅自启用。
- 首次任务仅做仓库核对、需求合并、设计和工作包；不直接改业务代码。不要承诺沿用旧三天工期。

## 证据与状态

- V1=工程现实；V2=三端治理评审；V3=会后新产品评审；DELTA=最新版权供给和本轮范围要求；R0.1/R0.2=研究暂定方案。
- 记录REQ-001—REQ-060及`V2-Dxx`、`V3-A/B/C/D`来源，不能重编号或静默改义。
- 决策状态、实现状态、商业启用状态分开；提案不是批准，模拟通过不是真实上游通过。
- 32项原会议结论为空，保留原样。60项是登记数量，不是60项已批准或已完成。
- R0.1的单一90秒产品与最新2分钟旗舰/三档摘要存在冲突；REQ-060缺完整原文，不猜价格和规格。

## 必守边界

- 账号、个人/机构签约主体、数字人、机构管理关系分开；个人作者可入驻，同一机构可兼具多种供给能力。
- 私人定制、商单和公开发行有不同用途与授权条件；付款买角色不自动等于购买投资收益权。
- 原始剧本、许可商品、已购许可、项目改稿、最终成片分开；独家性不自动等于发行权。
- 数字人长期体验须经供应商和样片验证；不以一个ID或无需重复上传推断专属训练模型和质量保证。
- 三类款项分开：客户交易款、各供给服务的应付款、发行后项目收入；普通支付不等于担保/清分/真实出款。
- 参数、合同、授权、价格和订单承诺有版本。新默认不改旧单。风险暂停另留处置记录。
- 真实请求失败不能返回假订单、假付款、假实名或公开敏感文件；测试替身只能用于明确隔离的测试。

## 本地与安全

- 先确认仓库根、remote、branch、commit和未提交改动；资料包内不得克隆源码，不清空非空目录。
- 不索取或输出GitHub token、生产.env、私钥、实名原件；不得使用显示token的命令。
- 首轮不自动`git pull/reset/clean`、不commit/push、不部署、不修改云账户；克隆失败先诊断授权/网络/沙箱，不绕过权限。
- `seed.js`、迁移和部分测试可能写库；只允许可丢弃隔离库。严禁把默认公网API当测试目标。
- 报告引用文件和行号，测试记录命令、环境、结果与未验证项。未运行就写未运行。
