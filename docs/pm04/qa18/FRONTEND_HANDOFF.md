## 首批 G01 / G02 的具体标准与最小复现

完整原预期和所有场景以 [151项源展开](../../testing/evidence/pm04-g1-discovery-20261125-01/PROVISIONAL_MATRIX.csv)为准，不能因本表摘要省略反例。API-only标准可以用后端证据核查；以下条款明确要求App/Web，不能由API代签。

|标准|前端应执行的端/场景|最小复现与必须核对|
|---|---|---|
|TASK-01|App、Web各 normal / reverse|全新无旧商品卖家读取本人的有效规则和逐人同意；创建现货→独立权利/内容审核→公开。另用试镜艺人读取规则→创建方案→独审→公开可约。分别撤回/停用授权或规则，再读/提交必须拒绝；待审不能公开，自审拒绝，原键不能重复创建。保留两业务各自ID及版本。|
|E2E-01|App、Web各 normal / reverse / unauthorized / duplicate / state_change / recovery|同商品/订单从许可确认、下单、未知付款、原键核对、实际文件保存到独审退款；报价变化用旧摘要必须报错并重读，不自动接受新价。切账号与撤权后不可读取旧私有内容，未知付款不能下载。退款金额和KEEP/REVOKE由独审逐案决定，两种分支用关联新单避免污染。|
|E2E-03|App、Web各上述6场景|同试镜方案/预约：未付款不能接单或开聊；核款后由艺人接拒，拒绝/超时走实际退款。约定材料、授权、实际读取、收件/验收分开；改价报错后重读，不按旧价预订。|
|TASK-02|App、Web各 normal / reverse|艺人本人明确脸声/销售/展示用途并同意；机构员工选择同一真人与委托提交。换人、错用途、撤回本人同意、撤销员工权限分别验证拒绝；经营委托不能代签人格授权。旧资产/订单主体不转移。|
|E2E-04|App、Web各上述6场景|同通告/投稿/客服工单/商单，感兴趣不自动聊天或授予角色；重复回复不多开工单，普通成年实名发布不额外强加星探门槛。|
|E2E-10|App、Web各上述6场景|原有机构互认及委托下的样片/商单成交→换绑/解约→旧单退款/结算，保留原机构/推荐/佣金快照；不增加“MCN带艺人入驻”冷启动步骤。|
