- 复用共用资料准备器，但**每个状态改变、退款、注销或释放都使用独立可追溯记录**；同链多角色使用同一原记录，不为凑覆盖把旧环境、不同数据库和不同付款拼接。

## 3. 缺陷分级、定责和协作

|等级|定义|处理顺序|
|---|---|---|
|P0|权限越权、敏感资料泄露、漏控未成年收费、钱账重复/丢失/错误授权、不可恢复数据损坏|相关链立即停止、保留证据、先修复再重试；其他隔离独立链可继续|
|P1|原需求主流程无法完成、跨端原请求恢复错误、合同或退款金额/状态错误|本批集中修，修完立即专项回归，再纳入整批回归|
|P2|非核心状态/布局/操作障碍、过时定位器/夹具、测试环境准备缺口|记录后继续下一组；集中分域处理，不挤占P0/P1|
|P3|非阻断说明、轻微显示/文案|汇总修复和复验，原要求该条仍不可无证据跳过|

**定责严格依证据**：

- 后端 `BACKEND`：真实隔离HTTP、数据库、权限/钱账与OpenAPI契约缺陷；后端Codex修复并交接口、源SHA、原记录及专项日志。
- 前端 `FRONTEND`：在后端合法响应下Flutter/Vue页面显示、选择、原请求缓存、导航/下载问题；Bill-Billion核对真实控件及重现后修复，并自行签认前端CURRENT。
- 测试与环境 `TEST/ENV`：脚本旧定位器、无效测试前置、FFmpeg/超时/身份夹具问题；不得为了绿灯削弱合法权限、静默修改预期或跳过业务断言。
- 需求解释 `PRODUCT`：原文确有冲突或现行版本缺决定；只能记录 `DECISION_PENDING` 并标来源，不得擅改用户冻结的要求。
- `EXTERNAL`：真实服务、银行或设备、资质/业务签收；登记阻断和负责人，不拿模拟伪装真服务。

缺陷记录使用统一 `QA18-0001...` 标识，字段至少包含 `group_id, acceptance_ids, e2e_id?, severity, category, owner, exact_revisions, environment_id, original_record_id, actor, operation_key_digest, expected, actual, reproducible_command, error_code, proof_path, proof_sha256, fix_commit, targeted_retest, full_regression, reviewer, state`。**只有同根因问题合并缺陷单；不得把多个独立问题打包为“已修”。**

流程：机测失败 → 后端负责人判断原范围与复现证据 → 指向前端/后端/环境/决策/外部 → 指派负责人在本侧分支小补丁 → 原案/同规则专项复验 → 必需横向回归 → 下一轮冻结候选统一扫。禁止后端代前端提交代码或代其宣布通过；不频繁追逐不存在的接口或改产品规则。
