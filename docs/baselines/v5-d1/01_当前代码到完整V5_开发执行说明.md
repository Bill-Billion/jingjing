## 4. 五项直接改变施工安排的修正
### 4.1 导航是代码迁移，不是原型里的“保持不变”
远端app_shell.dart仍使用首页/入戏/培育/成角/我的。V5要求广场/试镜/通告/消息/我的。需一并迁移页面归属、返回、登录直达、旧地址、未知路由、导航测试和AGENTS旧导航段，不能只改标签。[CODE-01、CODE-05]
### 4.2 分账必须分版本改两个层次
当前gigs/policy把MCN费用从平台佣金扣，settlement/source也按同一口径校验。V5先从成交额提取18%/22%平台佣金，再对供给侧余款按艺人80%/MCN20%分。

100元、有MCN、无推荐人的回归目标：样片＝平台18元＋MCN16.40元＋艺人65.60元；商单/试镜＝平台22元＋MCN15.60元＋艺人62.40元。存在推荐人时，7.2%/6.6%从平台佣金中支出，不能再次扣艺人份额。上述是来源规则的算术例，不是税后到账承诺。

新算法、财务来源校验、合同快照和退款尾差必须共同升级。旧单按原版本重放，不给旧记录静默追加V5比例。[CODE-02、CODE-03；V5 §3.2—3.3]
### 4.3 人工制作只扩展，不重建
现有production已有订单行、受派人、独立审查、剧本/样片/粗剪/成片版本、反馈与受控交付。新增的是品类、故事卡、补件、档期、共创个人片段和对应业务规则。V5列出的production_jobs/custom_orders是业务对象提示，不代表必须与现有系统再建一套订单和制作事实。[CODE-04]
### 4.4 现货与定制分两条链
现货：商品与许可说明 → 下单付款 → 受信核验 → 一次发放已购权益 → 播放/受控下载。

定制：故事草稿 → 资料提交/补件 → 报价合同 → 约定付款 → 人工制作 → 版本反馈 → 最终验收与成果。

现货不填故事卡、不等制作；定制资料提交不意味着已付款或获准开工。角色授权、主理人数字资产与买方已购成片许可分别记录。[V5 §2.1、2.3、2.12]
### 4.5 新账本与消息不能借旧名字冒充
现有finance余额是供应方应付，不是客户充值余额。储值、可用晶钻、累计成长、制作金券与供应方应收分别有来源和流水。旧通知和对象留言不等于订单会话；必须另有单向意向、客服转单、条件开聊、冻结、归档和反越权。[SRC-REVIEW L74—100]
