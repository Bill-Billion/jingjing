## 本轮复查与修复

已有接口和后端汇入[第9份统一待审申请](https://github.com/Bill-Billion/jingjing/pull/9)，解决队友需要自己拼多层分支的问题；原提交与证据保留。账号权限规则现在可独立测试，旧接口测试按需加载，基础测试不再写死建表文件数量，拼错测试模块名会明确失败。另修复崩溃恢复测试对机器速度的依赖：先确认保存编号，再明确模拟过期，正式保护逻辑不变。

本机全套129项通过、1项缺脱敏旧库跳过；独立权限规则6项通过。接口格式和示例320项检查通过。真实数据库分组结果和审查限制见[本轮记录](../tasks/records/REVIEW-20260922.md)。GitHub代码复验及合并申请检查已通过，结果见文末。未声称队友检查通过、未合入或上线。

队友获取代码、检查以及可先做的页面工作，统一看[交接入口](../collaboration/REVIEW_AND_HANDOFF.md)。目前内部账号流程仍需接可信登录和公开接口，不能把接口草案当成已可调用服务。

## 下一步谁做什么

1. **本侧继续账号权限接入。** MySQL内部身份和邀请流程已测；接下来接可信登录、完善公开接口和页面联调，以及停用/成员管理入口。之后推进规则版本与合同留存。成员身份不自动授予商业合作或收款权。逐项状态见[14个问题](LEGACY_ISSUES.md)，不把整组提前报完成。
2. **队友继续App和网页起步。** 运行已有App、记录构建结果，整理五入口，搭建运营/合作方网页；实际接手时登记，不把建议分工写成已认领。
3. **双方从统一待审入口检查已上传的代码。** 数据格式和MySQL基础先处理，随后后台任务、自动检查、外部服务基础及本轮旧问题修复；涉及共同规则的改动经另一方实际检查后才进入共同版本。
4. **继续准备旧数据迁移。** 可先做工具与样例，真实数量、金额、关联对账需要明确提供的脱敏旧库。缺样本不阻断其它开发。
