# 第三轮交接：真人、数字人与机构受托经营

2026-10-16。本侧在 `core/v5-r03-artists-assets` 实现第三轮后端，完整入口继承第二轮 `dd31ef8`。当前验证及上传结果见[本侧进度](../status/CORE_CURRENT.md)；本文不代替远端发布证据。队友是否开始第1—2轮页面仍待本人确认，本轮页面未代认领、未审阅或验收。

## 现在能办什么事

本人建立真人档案 → 核对实名服务结果 → 建立该人的一个或多个数字人 → 分别提交形象/声音使用同意 → 独立审核 → 保存造型和声音版本。机构只有在已有合作关系被艺人接受、本人另行确认代办范围后，才可代传材料、管理数字人或提交展示申请。所有权始终归真人本人。

同一真人首次创建服务、每个数字人的托管服务、收费认证审核分别下单，继续使用原有商品、报价、订单、付款和退款。报价锁定服务内容，确认后保存当时规则及合同内容；订单确认不等于签署或付款。第三方未启用时仍明确显示不可用。

|具体事情|本侧已提供的后端能力|页面伙伴怎样接、怎样算通过|
|---|---|---|
|我的真人与数字人|本人档案、受信实名结果、同人多形象、逐版造型/声音|先选具体真人和数字人，再操作；不能把切换个人/机构当成换所有权；不得自己提交“已实名”|
|本人授权与资料|按脸/声音、用途、使用方、地区及期限记录；独立审核；私有上传与受控下载|明确“只存私人档案”和“允许公开展示/重新生成”的区别；保存、提交、批准分别显示|
|机构管理艺人|基于已接受合作关系的逐项委托、有效期、本人撤回；机构名单|机构只看获托艺人；本人资料上传后仍归本人；代办权限不包含代签、替本人授权和修改佣金|
|认证|免费L1、关联同一笔审核费用的L2申请；补件、审核、异议、有效期|付钱不显示审核通过；补件回到原申请，不再买一笔；原拒绝结果不会因提交异议自动改写|

|公开供给|指定预览、独立公开同意、内容审核、城市/标签筛选；试镜展示单独开关|公开目录只显示批准的资料；关闭试镜展示不等于退出全部展示；无权/到期后不能继续下载预览|

数字人档案交付记录保存造型/声音版本、材料引用及校验值，由有权且独立的人员确认；这是内部档案的结果，**不是长期模型训练成功**。长期模型仍未启用，不能在页面标“可调用真人模型”。私人档案、已制作作品、历史许可也不能因停托管而一起删除。

## 本轮明确不能宣称完成的部分

- **儿童实际处理：用户已确认暂不开。** 保留单独的监护规则需求；不接收儿童实际素材、不建模、不公开。监护人流程和年龄规则仍需甲方补充，不以勾选代替依据。
- **L3认证：需要第9轮的真实成交、评价和违规事实。** 当前不可购买对应审核，不能人工填几个数字就升级。完整成长、月度复核和榜单仍按第9轮安排。
- **自动续费扣款没有启用。** 当前可单独开启/关闭续托管提醒；续期另建明确订单。提醒开关不是扣款授权。正式自动续费需要对应渠道签约、扣款与取消的实际接入和验收。
- **真实实名、长期模型、真实存储和收退款各自核验。** 本轮只用隔离库、内存文件及合成服务回执，没有给真实用户核验、收费或建模。服务方开通不等于代码自动启用。
- **页面、浏览器、安装包和真机尚未验收；队友尚未审阅；尚未自动合入或部署。** 本轮不代替前端完成页面。旧SQLite迁移仍缺脱敏样本。

## 双方怎样协作

本侧负责服务器、数据库、权限、订单衔接、测试资料和联调修复。队友负责App“我的艺人/数字人”、认证与服务购买、机构受托名单，以及运营审核页面；具体接手由队友确认。

建议按以下顺序接页面：

1. 本人档案、服务状态、数字人列表；先保证登录、返回和选中对象稳定，不因身份切换不断跳页。
2. 私有资料、本人同意、版本列表；所有表单清楚写出“谁的资料、替谁办事、允许什么用途”。
3. 机构名单和获托操作；没有委托就显示原因，不自动把机构下所有人都当可操作。
4. 运营收件、查看指定证据、补件、独立审核；不同岗位不要共用一个“管理员万能按钮”。
5. 认证和创建/托管订单；展示服务器给出的服务和原订单，不建立前端独立付款状态。
6. 公开目录和指定预览；用本人/机构/陌生人三个账号各走一遍撤回前后行为。

双方都从完整分支获取依赖。先保存本地改动再 `git fetch origin`；新页面分支可从 `origin/core/v5-r03-artists-assets` 建立，已有分支先比较整合，不重置覆盖。第二轮及旧PR23尚未合入共同版本，不能只拉integration就声称已取得本轮接口。查看本轮净差异可比较 `dd31ef8...core/v5-r03-artists-assets`。

到集中交付点统一上传；共享接口、数据库和授权规则仍须队友实际审阅。本轮延续前两轮交接方式，不再新建一份与旧申请重复的串联合并申请。上传、另一方检查、进入共同版本和正式启用分别记。

## 接口怎么调用

[统一接口文件](../../contracts/openapi.yaml)版本 `0.16.0-rc.1`，新增30个艺人相关操作。接口前缀 `/api/v1/artists`；已有交易入口仍为 `/api/v1/trade`。完整字段与错误以该文件为准，[合成示例](../../contracts/examples/platform.json)可用于对照。

|用途|主要入口|谁操作|
|---|---|---|
|查看外部服务和已审商品|GET `/services`|登录账号，不带机构身份头|
|真人建立、查找、详情|POST/GET `/people`；GET `/people/{person_id}`|本人；列表/详情可由获托机构查看|
|数字人/造型声音|POST `/people/{person_id}/avatars`、`/variants`|本人或有对应代办权限的机构|
|实名结果|POST `/people/{person_id}/identity`|仅本人；传服务会话引用，不传自称通过的结果|
|本人同意与机构委托|POST `/people/{person_id}/consents`、`/delegations`|仅本人|
|找回记录|GET `/people/{person_id}/records?kind=...`、`/records/{record_id}`|按当前权限；个人和机构可见范围不同|
|认证与公开申请|POST `/people/{person_id}/halos`、`/listings`|认证仅本人；公开申请可按委托代办|
|运营收件和审核|GET `/reviews?kind=...`；POST `/people/{person_id}/records/{record_id}/reviews`|对应审核岗位，不带机构身份头；拒绝自审|
|补件、撤回、异议|POST `/people/{person_id}/records/{record_id}/supplements`、`/withdrawals`、`/appeals`|本人；异议不自动改变原裁决|
|服务下单前请求|POST `/people/{person_id}/services`|本人选择已审商品与数字人；真人首次创建不能重复占用|
|服务进度、退款核对|GET `/people/{person_id}/services/{record_id}`；POST其下`/sync`、`/cancel`、`/reminder`|本人；修改须检查当前状态|
|交付和失败记录|POST `/people/{person_id}/services/{record_id}/results`|独立服务复核岗位；未付款不可交付|
|私有文件|POST `/people/{person_id}/assets`；GET `/assets/{asset_id}`、`/content`|本人或获托的材料管理人；证据不自动对机构公开|
|公开目录及预览|GET `/catalog`、`/catalog/{listing_id}/assets/{asset_id}/content`|登录账号；每次下载重新检查展示授权和托管|

请求头：普通主体操作携带 `X-Acting-Party`；账号级和运营操作不要自动带它。所有修改使用 `Idempotency-Key`；对已有记录审核、补件、撤回、取消、提醒和结果操作还带 `If-Match: "当前版本号"`。并发冲突保留用户输入，重新读取后处理；不能换请求键掩盖未知结果。

身份列表是实际归属/受托关系；不能只根据页面选中了机构就认为机构有权。机构暂限有效负责人代办，完整员工分派仍在第9轮。

新商品增加 `AVATAR_CREATION`、`AVATAR_HOSTING`、`HALO_REVIEW`，使用自己的 `specification.service`，不再填写假样片/成片秒数。创建按真人首次、托管按数字人月、审核按申请；本轮来源对应60元/29元/月/10元审核费，正式价格、重试次数、期限、交付内容均随已审商品版本明示，不给未知次数自动补默认值。创建失败退款必须跟随原交易退款结果。

平台报价选择 `artist_service_source.service_id`，只允许对应一个服务商品、数量1、一次明确付款；审批和用户确认仍走原trade接口。服务请求、正式订单和实际付款是三个状态。新报价冻结原规则原文，后改规则不改旧单。

新增配置 `ARTIST_PLATFORM_MERCHANT_PARTY_ID` 指向经核实的平台签约机构；空值不提供可订服务。不因设置此项就标记实名、支付、存储或长期模型可用。岗位权限由已有维护工具显式赋予，不能从HTTP自授。

兼容影响：原故事和旧交易接口保留；一旦账号已建立新真人档案，其新数字人/人像素材必须用本轮入口，旧接口返回 `USE_ARTIST_AVATAR_FLOW` / `USE_ARTIST_MATERIAL_FLOW`。V5制作必须关联真人，不把旧未核验档案自动升级；旧订单历史不改写。队友需要接新页面与新商品结构，不能继续调用旧创建入口。

$env:JX_MYSQL_TEST_ENV_FILE=(Resolve-Path '.local/mysql/runtime/test-env.json').Path

队友把页面API地址指向输出地址，用访问文件中的对应测试账号接入。先用本人/机构/陌生人三类账号复现权限，不必等待真实服务。结束按输出停止文件、Ctrl+C或60分钟自动退出，工具仅清理本次库和凭据。
