# 第1轮接口交接：用户交故事，运营收到并开始受理

本侧已实现并测试“保存故事、正式提交、运营受理”的后端。前端伙伴现在可以接页面、用同一批合成资料检查流程。**这次是接口和测试资料的交接，不代表 App 页面已完成、双方已审阅，或整轮已经验收。**

本轮面向普通买家：不用先创建数字人、不用先成为星探。用户从“把我的故事拍成片”进入，选品类，填写故事，没写完可以保存；以后从“我的”找回继续。正式提交后看到“平台待查看”；有受理权限的运营人员看到同一份提交，点击“开始受理”。提交或受理都不会收钱、创建制作任务或表示授权已通过。

需求依据与后续范围继续使用[完整需求对照](../reviews/v5-d1-intake/00_READ_FIRST.md)、[十二轮安排](../reviews/v5-d1-intake/07_ROUND_PLAN.md)和[首两轮原施工说明](../reviews/v5-d1-intake/08_FIRST_ROUND_HANDOFF.md)。原施工说明中“接口尚未实现”是施工前状态；本文件说明本次实际接口结果，没有把后续补件、报价或完整附件处理提前计入完成。

## 现在谁可以做什么

|工作|负责人及当前进展|接下来怎样检查|
|---|---|---|
|故事字段、保存、提交和受理规则|本侧负责，代码已写好并经过专项检查|继续处理审阅和页面联调发现的问题|
|App 入口、动态表单、草稿列表和状态提示|前端伙伴负责，具体人员尚待队友本人认领；未宣称页面已完成|普通买家能自己找到入口；保存后返回不丢内容；清空后不恢复旧值；提交失败能知道哪项没填|
|运营待受理列表和详情|前端伙伴负责，尚未代认领|列表能找到用户刚提交的需求；打开的是提交版本；受理后显示操作人和时间|
|双方共用接口、权限和数据库变化|本侧已提供实现、接口文件和测试资料，等待队友实际检查|队友按本文件运行检查并提出修改，不能用辅助模型审阅代替另一方确认|
|真实业务启用|未启用|真实品类模板、岗位人员、附件条件和页面验收完成后，再按项目发布规则处理|

页面先接这一条小流程，无需等待第2轮全部报价功能。本侧下一步接“补哪些资料、用户如何重提、报价对应哪一版故事”，再引用既有交易系统形成未付款订单；没有新建另一套订单账。

## 怎样判断第1轮真的走通

双方用下方同一套合成资料完成：买家保存未完成的故事 → 返回后继续 → 正式提交 → 运营从列表找到并受理 → 买家能看到当前状态。再检查另一买家不能查看、旧页面版本不能覆盖新内容、重复点击不重复提交、必填附件未具备时明确不能提交。

后端验证和页面操作分别记录。只有接口通过时写“后端可交接”；App 和运营网页实际走通、队友检查过以后，才评定完整用户流程。当前没有新的安卓安装包验收结果。

## 八项已实现的接口

以下路径均以 `/api/v1` 开头。完整字段、返回格式和错误定义以[接口文件](../../contracts/openapi.yaml)为准；页面只通过这些接口协作，不直接读取数据库或导入服务器内部函数。

|用户动作|接口|返回或效果|
|---|---|---|
|查看已发布的品类和问题|`GET /customization-categories`|每类当前最高已发布版本及提交是否可用；空库返回空列表|
|建立草稿|`POST /customization-requests`|传 `template_version_id` 和 `answers`；返回需求详情和初始版本|
|找回自己在当前身份下的需求|`GET /customization-requests`|分页摘要，不含故事正文或完整表单|
|查看一份需求|`GET /customization-requests/{id}`|本人读自己的需求；有专属岗位的运营可读正式提交版本|
|保存草稿|`PATCH /customization-requests/{id}`|传完整 `answers` 替换原答案，只能修改草稿|
|正式提交|`POST /customization-requests/{id}/submissions`|正文为 `{}`；按绑定的模板校验并保存不可改写的提交版本|
|运营查看已提交需求|`GET /operations/customization-requests`|可筛选待受理或受理中，不显示未提交草稿|
|运营开始受理|`POST /operations/customization-requests/{id}/intake`|正文为 `{}`；记录受理人和时间，不是报价批准或开工|

界面可以把 `DRAFT / SUBMITTED / INTAKE` 显示为“草稿 / 平台待查看 / 受理中”。可操作按钮参考返回的 `allowed_actions`：`READ / SAVE / SUBMIT / INTAKE`。返回中的版本仍必须用于下一次修改；按钮显示不是权限凭据。

详情包括答案、绑定的模板和正式提交快照；列表仅给需求标识、品类名称、状态、版本、提交及受理时间等摘要。客户端不能写付款状态、审核结果、操作者或任意未在模板中声明的答案。

## 页面接入时必须一致的处理

**登录与操作身份。** 沿用已有登录会话，每个接口都要 `Authorization: Bearer <当前会话>`。买家创建、列表、保存、提交及读取本人需求时传 `X-Acting-Party`。目录接口不传这个头；运营列表、受理接口也不传。运营读取正式需求详情时同样省略它，并由服务器检查专属岗位。不要将全局拦截器强制附加的机构身份带入运营操作。

**保存是整份答案替换。** `PATCH` 的正文为 `{ "answers": { ... } }`，不是只发送发生改变的单个字段。草稿可以缺项，空字符串会保留；删掉某个键表示这次保存不再包含该答案。不要把空值替换成上次缓存值。选择题只能使用模板里的选项。

**防止两次修改互相覆盖。** 保存、正式提交、受理要带 `If-Match: "<object_version>"`，包括双引号。版本过旧返回 **412**，应重新读取当前数据，保留用户未保存的输入并提示核对，不能自动覆盖。没有版本返回 428。

**防止重试变成两次操作。** 每次创建、保存、提交、受理都要带独立的 `Idempotency-Key`，推荐 UUID；同一次操作遇到断网或未知结果，应使用原来的键、原正文和原版本重试，返回原结果。真正开始新操作才使用新键。原键对应不同内容返回 **409**；已提交后再保存、已经受理后再受理等状态冲突也返回 409，应按具体错误码重新读取和提示，不能统一当成“再试一次”。如果收到 `COMMIT_OUTCOME_UNKNOWN`，先查询当前需求，必要时重试原请求，不换键造新记录。

**校验错误。** 缺必填或无效选项等返回 `CUSTOMIZATION_VALIDATION_FAILED`，字段提示在 `error.details`，例如 `answers.story / REQUIRED`。按固定原因显示提示，保留原输入；类型错误、未声明字段和不支持的附件值会被拒绝。模板最多40个字段，文本单项最多12,000个字符且可有更小的模板限制；答案总计不超过48 KiB，HTTP JSON正文不超过64 KiB。

**模板和历史内容。** 新发布模板不会修改已有草稿和正式提交。页面继续使用需求详情里的 `template_snapshot`，不要每次打开都用目录最新模板覆盖旧问题。每个正式提交保存当时的模板和答案；运营开始受理不改写用户原话。

**分页。** 列表支持 `limit`（1—100，默认20）、`current_status` 和 `cursor`。沿用返回的 `next_cursor` 原值；切换账号、操作身份、状态筛选或买家/运营列表后应从第一页重新加载，不能复用上一个范围的游标。

## 权限、空目录和附件边界

- 当前有效成员只能读写自己创建的需求，机构负责人也不会自动看到另一成员的私密草稿。切换为机构身份不会把个人草稿转为机构需求；已撤销成员权限的人不能通过旧请求重放取回内容。
- 运营要有 `CUSTOMIZATION_INTAKE` 岗位，只能访问正式提交；无此岗位的人不能以省略操作身份的方式获得运营权限。岗位撤销、账号冻结等会在后续读取及重放时重新检查。
- 发布模板使用独立的 `CUSTOMIZATION_TEMPLATE_PUBLISH` 维护权限，本轮没有公开发布模板的 HTTP 接口。空目录表示尚未发布可用模板，页面应说明当前不可选；不得自行补出正式价目、问卷或已批准商品。
- 本轮是文字流程。含必填私有附件的模板返回 `submission_available=false`、`unavailable_reason=ATTACHMENT_SUBMISSION_NOT_READY`，可以保存文字草稿，但正式提交会被阻止。不能用公开 URL、别人的材料编号或“上传成功”提示绕过。即使附件可选，本轮也不接受实际附件值。
- 受理权限不等于商户报价权、本人形象授权、实名通过或制作开工。后续步骤需要各自的真实条件，不能用本轮状态代替。

## 前端伙伴怎样在自己的电脑运行同一批资料

先准备仓库锁定依赖和项目专用的隔离 MySQL；启动方法见[MySQL 本地环境说明](../../晶晶日上工程交接包/01_源码/backend_server/docs/MYSQL_FOUNDATION.md)。不要复用真实业务库。下面在各自仓库根目录执行，路径由本机实际文件解析，不需要复制别人的口令：

```powershell
$env:JX_MYSQL_TEST_ENV_FILE=(Resolve-Path '.local/mysql/runtime/test-env.json').Path
node scripts/customization-sandbox.cjs
```

工具只接受本机 `127.0.0.1:33316` 的专用测试配置，创建本次随机测试库和随机 loopback HTTP 端口。启动输出提供 `base_url`、`access_file` 和 `stop_file`；从本机 `access_file` 读取临时会话和对象编号即可接现有测试客户端，不增加新的登录方式、不发短信。

|合成资料|用途|
|---|---|
|4个账号：买家甲、另一买家、收件员、模板维护员|验证本人办理、他人拒绝和运营受理；维护员用于初始化模板|
|3个模板：家庭故事、人生片段、必填附件场景|验证不同品类有不同问题，以及附件未具备时不能假提交|
|2份需求：未完成草稿、已提交待受理|页面打开即可操作，不用手动改数据库造状态|

所有资料都是合成的；模板不是甲方批准的商品，不填真实身份、私人故事或真实材料。每个人在本机运行会生成自己的临时会话，不需要互相发送 token。`access.json` 只放 `.local`，不上传 Git、不贴到聊天或日志。

工具只开放本次故事接口、本人资料和状态检查；短信发送、其他业务接口及外部网络均被限制。前端网页可使用本机5173或5000端口；换用其他开发端口时先明确调整本地允许来源，不关闭浏览器权限检查。不将此工具开放到公网。

停止方式任选一种：运行窗口按 `Ctrl+C`；标准输入发送 `quit`；在另一终端创建启动输出指定的 `stop_file`。也会在60分钟后自动停止。正常清理会关闭服务、删除本次随机库和临时会话文件；对应 `status.json` 记录真实结果。如为 `CLEANUP_FAILED`，按 `failed_steps` 排查，不能把清理失败说成已经删除。重新运行会建立新资料，不保留上次故事。

工具入口：[customization-sandbox.cjs](../../scripts/customization-sandbox.cjs)。它是页面联调工具，不是正式部署脚本。
