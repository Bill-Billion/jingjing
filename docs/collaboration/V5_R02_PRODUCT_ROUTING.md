# 新版商品怎样进入正确的交易流程

2026-10-16，本侧继续第二轮，在core/v5-r02-story-quote上从2d4070a实施。当前批次本地保存，未上传、未获队友审阅、未合入或启用。它依赖同分支上一批故事报价代码，不能单独拿到旧integration上使用。整轮仍剩分账、财务和页面验收。

## 这次解决什么

以前只有报价带了故事编号才执行定制检查，漏传时可能走旧通用报价。现在商品本身记录所属规则版本和类型，与商品规格一同独立审核，再原样保存到报价、订单及合同。页面只提供商品编号；服务器从已经批准的商品读取分类，不能让页面自行选择跳过检查。

|商品|现在可以做什么|不能据此声称什么|
|---|---|---|
|私人故事定制|平台按当前受理故事报价、独立复核、买方确认未付款订单；缺故事引用直接拒绝|还不能真实收款、签署或开工|
|人工样片、现货视频、商业合作、试镜|可登记商品类型并审核规格；现阶段新V5报价统一返回流程尚未实现|不代表这些新版成交流程已经完成；旧业务保持自身规则|
|旧商品与历史交易|保留原记录、已发报价、价格、分期和合同；旧商品可另建带分类的新版本|不能把新版本覆盖到旧订单；旧价旧承诺不能被重新计算|

新旧分类不能混在一张报价里；不同新分类也不能混用。已标V5的规格修订时必须保持版本和类型，不能删分类降回旧流程或改成另一类产品。确需不同商品应建立新的规格，经原有独立复核；没有扩大任何人的发布或审批权限。

## 双方现在怎样配合

本侧已修改服务器、接口定义、自动测试及合成资料。前端伙伴实际接手仍待本人确认；阶段集中同步前，不把这些本地修改当作队友已经收到。

前端可继续已上传的第一轮故事与运营受理页面。拿到第二轮集中版本后，商品编辑页需填写分类，报价页选已批准商品；报价详情及订单说明展示固定下来的类型。旧记录缺少分类应显示历史商品，不能猜成私人定制。遇到缺故事、混合分类、流程未实现等错误，保留填写内容并说明需要返回哪一步，不自动换成旧商品或重试旧接口。

本批没有修改App/Vue页面。服务器检查通过不代表页面、手机或双方协作已验收。

## 接口变化与启用方式

候选接口版本0.14.0-rc.2，仍是175项操作。新增TradeProductProfile；商品请求、商品记录、报价明细、订单内报价明细增加可选product_profile：

```json
{"version":"V5","type":"PRIVATE_CUSTOMIZATION"}
```

类型代码：私人定制PRIVATE_CUSTOMIZATION；人工样片MANUAL_SAMPLE；现货视频STOCK_VIDEO；商业合作COMMERCIAL；试镜AUDITION。未列类型不自动归到“其他”。这些是当前trade规格分类，不是整个产品的会员、充值、订阅分类已经全部实现。

|服务器设置|实际效果|
|---|---|
|TRADE_REQUIRE_V5_PRODUCTS=true|所有新建规格必须分类，所有新建报价不得使用未分类旧规格。旧商品要继续新售，须创建并审核分类后的新版本；尚未接好的V5流程明确拒绝报价|
|未设置或false|仅保留旧业务过渡能力。已经标记V5的商品仍强制分流；关联故事的报价也必须使用V5定制规格。此状态不能作为V5正式开放依据|
|其他值，包括空字符串或拼错|启动配置报错，不能悄悄当false|

开关只约束新建规格和新建报价，不撤销此前已发报价、不改变历史订单。此前成功请求使用相同请求键、相同正文重试，仍返回原记录而不会创建新单；权限仍重新检查。正式切换前应盘点并由业务审核存量未成交报价，不以本开关代替撤销决定。跨越不同服务器实例时配置必须一致，不能一部分开一部分关。本批没有部署、没有改真实环境配置或发布正式商品。

接口结构允许旧记录缺省，新建时是否必须填写由上述服务器设置约束。已有客户端不受字段删除影响；开启V5后旧客户端继续发未分类新商品/新报价将得到409，需先更新后台商品维护与报价页面。这是有意的规则变化，不是无影响升级。

常见错误：PRODUCT_PROFILE_REQUIRED需先审核新版商品；CUSTOMIZATION_SOURCE_REQUIRED需回到已受理故事；MIXED_PRODUCT_PROFILES需分别报价；PRODUCT_PROFILE_CANNOT_CHANGE不可改历史商品类型；PRODUCT_FLOW_NOT_IMPLEMENTED对应新版流程尚未实现。真实定制收款仍由上一批的CUSTOMIZATION_PAYMENT_RULES_PENDING阻断。
