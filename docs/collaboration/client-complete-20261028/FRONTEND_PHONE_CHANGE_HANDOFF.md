# 换手机号：前端接入与验收

2026-10-30。后端负责人 **chengcongcong222** 已提供接口；前端负责人 **Bill-Billion** 接 App 和本人网页。用户负责转发，本次说明是否收到、是否开始接入尚未确认。沿用 PR39，不新增合并申请。

## 用户应怎样办

从账号设置进入，说明“换的是登录号码，原账号、订单、作品和机构关系保留”。这项操作属于登录账号，不随个人／机构身份切换，不传机构身份头。

1. 提醒用户近期重新登录验证身份。进入申请时，服务器要求最近 10 分钟内完成短信登录；旧自动登录会话也必须重新验证，不能由页面直接修改账号手机字段。
2. 用户输入旧、新号码，发起申请。依次向旧号码、新号码发独立验证码并核验，不复用普通登录验证码；新号码已属于另一账号时，提示不可使用，不自动合并账号。
3. 两次核验都通过后，展示两个脱敏号码，让本人确认更换。确认成功即退出全部旧登录，跳到新号码登录。
4. 新号码重新登录后继续原账号。若确认时断网、随后旧登录失效，提示用新号码登录并查询最近换号结果，不反复提交确认或创建新账号。
5. 旧号码无法收验证码时进入现有客服工单，说明需要人工核查；本批没有“客服直接换绑”接口，也不能承诺仅提交工单就一定找回。

## 同版依赖与接口

整体接口 **0.31.12-rc.1**，数据库追加 **0188—0192**。不修改原迁移，不需要改其他业务页面的账号标识。历史账号保留原标识；新注册账号采用与手机号无关的标识，防止原号码释放后注册者继承旧账号。

所有路径以下列前缀开始：`/api/v1/me/phone-changes`。均需本人 Bearer 登录；拒绝 `X-Acting-Party`。返回 `meta/data`，不包含验证码和完整号码。

|步骤|请求|页面要点|
|---|---|---|
|发起|POST 前缀；`{old_phone,new_phone}`|传 `Idempotency-Key`；重复点击保留原键|
|恢复进度|GET `/current`；GET `/{change_id}`|`current.data.request` 可为空；进行中的申请优先返回|
|发码|POST `/{change_id}/challenges`；`{side:"OLD"或"NEW"}`|按步骤发码；不自动重发|
|核验|POST `/{change_id}/verifications`；`{side,challenge_id,code}`|用对应步骤返回的 challenge 编号；失败后读取剩余次数|
|确认|POST `/{change_id}/confirmation`；`{}`|仅 READY 可确认；成功后清理旧登录|
|取消|POST `/{change_id}/cancellation`；`{}`|仅未完成申请可取消，不影响原号码|

除发起外，所有 POST 都传 `If-Match: "当前 object_version"` 和 `Idempotency-Key`。重试同一请求保留同一键、内容和版本；内容变化或新操作使用新键。412 后重新读取状态，不能盲目覆盖。

状态顺序：`AWAITING_OLD → AWAITING_NEW → READY → COMPLETED`；另外有 `CANCELLED`、`EXPIRED`。申请有效 15 分钟，本轮暂定安全参数见任务记录。`can_continue=false` 时不能继续当前申请；不同设备不能接管验证中的申请。原申请过期后重新发起，不自动替用户取消另一个设备的操作。

`requires_relogin` 只在确认成功的原会话返回 true；用新号码重新登录再读取完成结果时为 false，避免反复跳登录。`challenges` 含各侧最近验证码状态、剩余尝试次数、到期与下次可发时间；倒计时以服务器时间信息为依据。

## 错误必须说清楚

|服务器提示|对用户怎样说明|
|---|---|
|RECENT_LOGIN_REQUIRED|请先重新登录验证身份，再更换号码|
|PHONE_CHANGE_BINDING_CHANGED|旧号码与当前账号绑定不符，请核对|
|PHONE_CHANGE_TARGET_UNAVAILABLE|新号码已有账号，不能直接合并或覆盖|
|PHONE_CHANGE_ALREADY_ACTIVE / SESSION_MISMATCH|已有另一笔或另一设备的换号申请，请查看进度或等待过期|
|INVALID_PHONE_CHANGE_CODE|验证码不正确；保留页面并读取剩余次数，不把它当登录失效|
|PHONE_CHANGE_CHALLENGE_UNAVAILABLE|验证码过期、耗尽或不属于这一步，请按服务器状态重新获取|
|SMS_NOT_READY / PHONE_CHANGE_SMS_UNAVAILABLE|发送结果未确认或服务不可用；先查当前进度，不自动重发|
|RATE_LIMITED|按服务器限制等待，不能换请求键绕过|
|PHONE_CHANGE_NOT_ACTIVE|申请已结束或过期，请重新查看状态|

## 前端怎样自验

用本批隔离资料，同一账号依次完成：原订单下载 → 发起换号 → 旧号验证 → 新号验证 → 确认 → 旧登录失效 → 新号登录 → 原订单、工单、发票仍可查。再测：重复点击、错误验证码、断网恢复、不同设备／账号、号码被占用、过期和取消。旧号码重新注册不得读取原订单。

本地短信只写被 Git 忽略的 `phone-codes.json`，不是实际短信；停止测试会删除。准备与检查脚本见[模拟资料和完整流程记录](../../testing/COMPLETE_FLOWS_20261030.md)。不要将测试号码、验证码或自动登录能力放进正式服务。前端返回同版提交、实际办理记录及尚未完成项，后端再组合复测。
