## 明早优先检查和之后的可见顺序

1. **先审当前成果与计划**：打开产品总览、财务接法和本轮证据；明确局部已通过、缺页面和真实服务边界。
2. **实际操作优先顺序**：现货商用购买/下载/退款 → 人工视频两种版权及30/40/30 → IP买断/分红及失败恢复 → 现有商单/机构/换号。后端在用户开始时准备最新隔离资料和环境，不沿用过期登录、不预先开放公网。
3. **新页面到一批验一批**：交接/时限/直推/注销，再监护/侵权/日对账；每批问题归双方负责人。
4. **全业务收口**：按12路线完成共创、权益、抽奖、余额、成长、隐私、参演发行；[151条队列](../../testing/ACCEPTANCE_WORK_QUEUE_20261102.md)逐项补足并实际审阅，不能靠数字批量改状态。
5. **固定测试版**：同版构建、数据和反馈备份/恢复、回滚保留订单、剩余问题说明齐备后，申请阶段审阅合入；再由用户/甲方人工验收。
6. **真实上线准备**：昆山短信→身份/签署/审核→正式支付退款清分对账，按资料逐项启用；OSS最后。模拟验收和真实上线两份结果分开。

当前没有“只需等反馈”的整段空档。后端可持续做上述测试、修复和证据整理；某个接口或页面发现实际缺口，归回原18组，注明来源和完成标准，不临时创造新阶段。
