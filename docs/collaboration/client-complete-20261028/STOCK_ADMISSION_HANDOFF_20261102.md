## 用户应该看到什么

- 艺人进入上架页，先看到实名认证、L1记录、主角光环人工审核分别是否满足；不只显示“权限不足”。只付了审核费或正在补件不等于通过。
- 机构先选具体艺人，再查该艺人的资格和授权；多人作品逐人检查。不能用机构成员或另一艺人的认证替代。
- 缺少资格时允许看说明和已买订单，禁止提交新上架；指向既有认证入口。不要虚构审核成功、扣费成功或新的付费认证产品。
- 已公开但认证失效的商品不能继续新购；卖家仍能查看和处理自己的记录。买家原订单继续按快照履行，不能在已购页套用卖家新准入条件而禁掉下载。
- 新订单在付款前资格失效，应显示暂停新交易及联系处理；旧未付款订单按原准入及原付款期限继续，但授权撤回、商品下架、争议等仍可能阻断。

## 已提供的接口

`GET /api/v1/stock/seller-eligibility?person_id=<真人ID>`，登录并传当前`X-Acting-Party`。只允许本人或具有该真人上架委托的机构查询。返回：

| 字段 | 页面用途 |
| --- | --- |
| person_id、seller_party_id | 结果必须与当前艺人/身份匹配；切换后清空，拦截旧请求回写 |
| identity_verified | 当前成年人实名核验是否有效；未成年人实际处理继续关闭 |
| l1_verified | 现有一级认证记录及实名是否有效 |
| manual_review_approved | 主角光环人工审核是否已通过且在有效期内 |
| eligible | 仅表示上述资格满足，不代表媒体/权利审核通过或可以直接售卖 |
| blocking_reasons | 缺项代码：ARTIST_IDENTITY_REQUIRED、STOCK_L1_REQUIRED、STOCK_HALO_REVIEW_REQUIRED |
| policy_version | 本批为CONTRACT_20261029，来自新合同准入规则 |

提交、审核、公开展示、购买和新订单付款均重新查真实状态，页面不能以缓存的eligible绕过。机构权限、逐人肖像/声音授权、媒体审查仍单独核验。

现货提交`qualification.minimum_halo_level`兼容旧客户端传1或新客户端传2，但服务器对新记录固定保存2，`source_ref`保存新合同来源。**读回结果可能为2，旧记录可能为1**；更新App与网页数据类型和提示，不用这个客户端字段决定放行。新购买返回可选`seller_admission_policy`；旧购买可能没有，不能因此报错。

试镜保持`AUDITION_L2_REQUIRED`错误码供兼容，页面解释为“需有效的主角光环人工审核”。服务器现已拒绝尚未生效的认证；不要新增要求客户购买更高等级的含糊文案。

## 同版验收顺序

1. 合成L1卖家、人工审核待审：查询显示缺人工审核，直接提交也被拦截。
2. 人工审核通过：文件/逐人授权/独立内容权利审核通过后，公开可购；旧请求传1不能把新记录降级。
3. 待审、拒绝、撤销、过期、未来生效的人工认证分别拦截；切换本人/机构不得显示上一艺人的资格。
4. 机构有委托可查对应艺人，无委托不能读取；多人作品中任何一人缺资格不能用其他人认证替代。
5. 已公开商品失去认证后停止新购；新未付款订单付款被拦截；历史未付款订单保留原约定，已付款下载及合同不变。
6. 授权真正撤回仍须停止受影响访问，不能把“旧订单保留”误用为绕过肖像授权。

模拟资料由`test/helpers/stock-seed.cjs`集中准备：包含明确标记的合成二级审核记录，可在独立测试库切换待审/失效状态。此记录不是人工真实审定。`scripts/stock-sandbox.cjs`等沿用该资料构造；本轮未重置甲方网站、未自动新增真实认证。页面完成后后端准备同版可播放资料并主测。
