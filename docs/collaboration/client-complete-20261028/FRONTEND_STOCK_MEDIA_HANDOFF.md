# 前端下一步：现货显示真实封面与时长

这是原第5组后续接线，不新增需求。后端 chengcongcong222提供，前端 Bill-Billion接App与网页；由用户通知，新接线尚未代确认。当前完整分支仍为PR39的 `core/full-business-closure-20261028`，接口0.31.5-rc.1、迁移0167，需获取完整组合代码。上传事实看[本轮记录](../../tasks/records/CORE-stock-media-20261029.md)。

你已完成的主肖像、媒体类型、历史保留及上传离开提示都保留，不重做。此次只接现货卡片和详情。

|用户要看到什么|调用与字段|页面处理|
|---|---|---|
|完整作品和预览各多长|`GET /api/v1/stock/catalog/{record_id}/media`；`duration_ms`完整作品，`preview_duration_ms`预览，单位毫秒|分别标注，不把预览时长当商品完整时长；失败显示暂不可读取，不写0秒或默认值|
|真正的作品封面|同一回复的`cover`有类型、大小、SHA256、尺寸、来源及首帧时间；再读`GET /api/v1/stock/catalog/{record_id}/cover`取得JPEG|核对大小、摘要再解码展示，不拼公开对象地址；保留完整画面。读取封面与清单不一致时清图、重读，不显示旧图|
|授权变化及时生效|两接口只带登录凭证，不带`X-Acting-Party`；回复均不缓存到浏览器持久层|换作品/版本/身份、401/403/404/409及撤回/下架时立即清旧对象URL、旧时长；迟到回复不能恢复旧内容|
|处理失败能理解|格式不支持409；工具缺失、处理繁忙、文件损坏等503；权限照原规则拒绝|给出“封面或时长暂不可读取”和手动重试；原预览播放独立可用时仍能使用，不能不断自动请求或假显示成功|

媒体回复还含`listing_id/listing_version/source_sha256/preview_sha256/preview_width/preview_height`。`source_sha256`是完整作品摘要，**不是公开下载完整片的权限**；公开封面仅来源于 `REVIEWED_PREVIEW`，本批`frame_ms=0`，无手填封面/上传自定义封面入口。`cover`为`media_type/byte_size/content_sha256/width/height/frame_ms/source`。旧列表格式未变，按可见卡片加载，不把所有页同时发起处理；列表不是新的批量媒体接口。

后端复用配置`MEDIA_FFMPEG`与`MEDIA_FFPROBE`的绝对路径，未配置明确返回不可用；真实服务配置由后端负责。原视频在存储中不改写，进程内只缓存最多16张受控封面5分钟，每次仍重查权限和原文件。进程重启会重算，不能把缓存当永久文件链接。

验收用同一条新审核作品：完整片与预览片时长不同、封面来自预览；下架后不能继续读封面；换新版本须重新审核并清旧图；损坏/无配置显示失败；退出、换身份和迟到响应清理。后端现货50项与综合964通过是后端证据，新页面仍须双方按同版接通复测。
