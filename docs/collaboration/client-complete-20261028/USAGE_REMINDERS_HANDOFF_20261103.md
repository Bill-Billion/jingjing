# 让“定时休息”真正生效：前端接入与验收

后端负责人 **chengcongcong222**；前端负责人 **Bill-Billion**。本批属于原第4/14/16/17组，当前接口 **0.31.25-rc.1**、数据库 **0207**。沿原PR39集中交付；未合入共同版本或部署。前端六项合同已交付，本任务是在原偏好页和App/网页前台生命周期中补执行，不重做六项页面。

## 为什么做，依据是什么

[37号合同材料“使用时长管理与防沉迷”](../../sources/contracts-20261029/extracted/37.md)原文：“提供使用时长统计、休息提醒、夜间提醒；用户可开启\"定时休息\"\"夜间免打扰\"。”此前 `rest_reminder_minutes` 仅存设置，没有统一的服务端计时结果。本批补休息提醒这一部分；夜间提醒/免打扰、真实营销推送和高频消费确认仍单列，不能称整条已完成。

## 用户应该如何操作

在已有偏好页开启定时休息，选择现有15—240分钟间隔；页面前台使用时显示今天累计使用估计。达到设置时间，显示“已连续使用一段时间，建议休息”。按钮写“知道了”，不写“已完成休息”。关掉功能后不再报告使用状态，当前统计清零；重新开启从零开始。

原 `GET/PATCH /api/v1/privacy/preferences` 不变。账号本人设置，不随机构身份改变；不得传 `X-Acting-Party`。切账号须停止旧计时器、清空旧统计并拒绝旧响应回写。

## 可调用接口

|接口|作用|页面处理|
|---|---|---|
|GET `/api/v1/privacy/usage`|读本人统计和当前提醒|登录后或返回前台先读取；不会因为读取而计入新时长|
|POST `/api/v1/privacy/usage/pulse`，空对象|报告当前仍在前台，由服务器计算时间|仅页面可见且已开启时每30秒一次；不传时间、时长、身份或用户ID。隐藏、锁屏/后台、退出时停止；断线不补发积压心跳|
|POST `/api/v1/privacy/usage/acknowledge`，空对象|本人确认看到了提醒|携带当前使用状态的If-Match和独立请求键；返回`acknowledged: true`后重新GET，不能把返回当已休息|

使用结果包含 `object_version`、`enabled`、北京时间日期、`day_seconds`、`reminder_seconds`、`rest_due`、距下次提醒的秒数和服务器时间。确认前暂停当前页面心跳；另一设备使版本变化时，412后重读并让用户确认当前提示，不静默重放。响应丢失时沿原请求键恢复确认；若功能已关闭或账号失效，先刷新最新状态，旧成功结果不能恢复计时。

心跳是服务端时间采样，**不属于付款等业务指令**，不接受客户端时间，也不保存每30秒一条永久请求记录。因此不要求请求键、不承诺重试返回旧快照；并发只累计同一段真实经过的服务器时间一次。普通业务写入和提醒确认仍保留原来的请求恢复要求。401退出，503显示“统计暂不可用”，不能显示为0或伪称已提醒。

确认返回409 `REST_REMINDER_NOT_DUE`时，表示提醒已因离开、设置变化或其他设备确认而不再到期，重新读取并关闭过时提示，不反复提交。请求键冲突沿既有恢复流程处理，不能换键把旧动作重放。

## 暂定实施口径与限制

- 30秒报告、超过90秒无报告视为离开，为实施建议；离开期间不累积，下一次报告重新开始连续计时。它是前台报告的使用估计，不是操作系统屏幕时长证明，也不用于绕过监护、年龄或支付限制。
- 精度限制：短于90秒的后台暂停与网络延迟无法仅凭报告间隔区分，可能被估入；关闭页面前最后不足一个报告周期的使用也可能漏计。因此界面必须写“使用时长估计”，不能承诺精确屏幕时间或把它用于强制未成年管控。需要精确前后台区间时须另补设备会话协议，不能把本批宣称为已完成。
- 多设备共用本人账号状态，重叠区间不重复计算。跨北京时间午夜只重置当日累计，连续使用和提醒仍可跨日。
- 改变休息间隔会重新计时。关闭功能时清除当前统计；账号实际注销时删除统计行。只保留最近一日累计与当前状态，下一次跨日读/写呈现新日，不保存页面内容、浏览轨迹或每天历史清单。提醒确认只保存必要请求恢复结果，不存当时统计快照。
- 提醒是建议休息，不阻断合同、退款、申诉和其他必要办理；确认只重置提醒计时，不证明真实休息。
- 当前没有已启用的外部营销推送发送器；站内必要业务通知保持可查，不因营销关闭而吞掉合同、退款或隐私答复。后续接外部推送前必须落实关闭、免打扰与发送前复核，不能仅保存字段。

## 验收条件

未开启不产生统计；开启后实际前台使用达到设置时间出现提示；短时重复请求不重复计时；后台超过90秒后重新从连续0开始；跨日只保留新日累计；改间隔/关闭立即一致；旧版本不能确认新提醒；旧请求可恢复但不自动重放其他业务；其他账号无法读取。后端隔离测试以合成记录调整时间验证边界，生产没有修改时钟的接口；前端人工验证至少一条真实15分钟场景。
