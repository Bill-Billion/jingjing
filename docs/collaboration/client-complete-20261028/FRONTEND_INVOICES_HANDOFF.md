# 让用户从原订单申请开票、跟进处理并领取票据

后端负责人 **chengcongcong222**；前端负责人 **Bill-Billion**。接口候选 **0.31.11-rc.1**，数据库迁移至 **0187**，仍集中交付PR39。用户负责转发；本说明不代表前端已接手本次增量。上传及最终检查以CURRENT和本批记录为准。

目标是完成原第12组。用户从已付款订单进入，填写抬头和所需金额，按通知补资料、查看审核、领取获准文件；运营在网页独立处理。真实发票默认关闭，甲方模拟测试得到的只能是醒目标注的模拟凭证。本批没有新增版权、税务代办或自动报税产品。

## 前端现在接什么

1. 原订单提供“申请开票／开票进度”，本人中心提供申请清单。先查可申请金额，展示已核实支付、已退款、待退款、其他申请占用；金额单位为分，不能把订单标价、优惠券、未支付尾款当实付。
2. 个人抬头填写名称，`tax_id`为null；单位抬头填写名称与税号。本轮只做格式和必填检查，不在页面宣称税务真实性已校验。不额外收集无使用依据的邮箱、手机号或银行账户。
3. 当前购买身份是申请所有方：个人订单用个人身份，机构订单用机构有效负责人身份。切身份清旧详情、历史及文件；本人其他机构的附件不能混入当前申请。
4. 申请、补件和撤回都保留原请求编号；返回结果未知时，先用原内容和原编号重试并查状态，不能换编号重复占金额。修改带当前版本；版本冲突先刷新，不自动覆盖运营新处理。
5. 运营网页分“受理／录入”和“票据核准”。两者须单独授权，录入者不能批准自己录入的文件，购买方成员也不能审自己的申请。无权限不显示处理按钮，但不得把前端隐藏当服务端授权。
6. 未核准文件仅工作人员可见。本人领取只认票据列表中的`ISSUED`或`SUPERSEDED`，后者写“历史票据，已有更正”，不要冒充当前有效票据。文件通过登录受控下载，不能拼公开URL。
7. `requires_correction=true`表示已出票金额超过退款后当前可开金额，展示“订单退款变化，需人工核对更正”。旧文件不能删除或覆盖。更正结果为0时明确“已作金额归零更正”，不是“给用户退了一笔钱”；退款仍走原订单。

## 可调用接口

统一前缀`/api/v1/invoices`。所有请求须登录。用户接口带`X-Acting-Party`；运营接口不带此头。所有写请求带`Idempotency-Key`，动作另带`If-Match: "当前版本"`。

|用途|方法与路径|主要返回或请求|
|---|---|---|
|原订单可申请额度|GET `/orders/{order_id}/eligibility`|已收、已退、待退、已占用、当前可申请；无现金时环境为null|
|提交申请|POST `/requests`|`order_id, amount_minor, header, text, asset_ids`|
|本人／机构申请清单|GET `/requests`|`cursor, limit(1—50), status`；列表带原订单编号|
|申请详情|GET `/requests/{invoice_id}`|状态、版本、抬头、金额及更正提示|
|处理历史|GET `/requests/{invoice_id}/history`|cursor为处理版本号；补件不会删旧材料|
|票据清单|GET `/requests/{invoice_id}/documents`|cursor为UUID；包含当前与历史获准票据|
|本人操作|POST `/requests/{invoice_id}/actions`|补件、撤回、请求更正；见下表|
|下载申请材料|GET `/requests/{invoice_id}/assets/{asset_id}/content`|原文件字节，私有下载|
|下载票据|GET `/requests/{invoice_id}/documents/{document_id}/content`|模拟文字凭证或经人工核准的PDF|
|运营办理|上述`/requests...`前加`/operations`|运营列表／详情／历史／票据／动作／两种下载；无运营创建申请接口|

所有动作都传`action,text`，正文不能附带与当前动作无关的字段。

|操作人|action|额外字段与办理结果|
|---|---|---|
|申请方|SUPPLEMENT|仅待补资料时传`header,asset_ids`，重新进入待审核|
|申请方|WITHDRAW|出具前可撤回，释放占用；已出具不可撤回|
|申请方或受理员|REQUEST_CORRECTION|已出具后请求更正，保留原文件和金额占用|
|受理员|REQUEST_INFO / APPROVE / REJECT|要求补资料／批准录入／拒绝；拒绝释放占用|
|受理员|RECORD_DOCUMENT|传`document`，进入等待另一人复核；不是已经出票|
|另一位核准员|VERIFY_DOCUMENT / REJECT_DOCUMENT|批准成为当前票据／拒绝此次文件；拒绝文件不等于拒绝整份申请|

`document`字段：`amount_minor,reference,issued_at,asset_id,header`。日期为UTC标准字符串；首次金额和抬头须与申请一致。更正金额不能增加，可归零；如仍需补开差额，应走另一份经过金额核对的新申请。模拟时`asset_id=null`，由服务器生成“模拟凭证，非真实发票”；正式人工模式须上传本人有权访问的`application/pdf`，并通过另一工作人员核准。

申请材料通过现有私有上传接口，使用`REVIEW_EVIDENCE`或`RIGHTS_EVIDENCE`，最多8份。申请人上传至当前购买身份；工作人员上传至自己拥有管理权限的身份。正式材料不能用模拟文件代替。下载后端会再次核对权限及文件校验值；下载中撤权也不能返回文件。

## 页面状态与失败处理

|后端状态／错误|页面说法与下一步|
|---|---|
|REQUESTED / NEEDS_INFO|待审核／待补资料，展示处理历史和原说明|
|APPROVED / DOCUMENT_REVIEW|申请已批准，待录入票据／票据待另一人复核；本人不能提前领取|
|ISSUED / CORRECTION_REQUESTED|票据可领取／更正处理中；模拟环境始终带模拟标识|
|REJECTED / WITHDRAWN|申请被拒绝／本人已撤回；不自动重提|
|INVOICE_AMOUNT_UNAVAILABLE|额度有变化，刷新原订单的支付、退款和占用情况|
|VERSION_CONFLICT|记录已更新，刷新后由用户决定，不自动覆盖|
|IDEMPOTENCY_CONFLICT|原编号内容不一致，保留原内容供核对，不循环换编号|
|INVOICE_ISSUER_NOT_READY / INVOICE_SANDBOX_DISABLED|出票条件尚未启用，不能弹成功|
|INVOICE_ISSUER_CHANGED|出票方配置变更，拒绝旧待核文件后重新录入并复核|
|INVOICE_OPERATOR_FORBIDDEN / SELF_REVIEW_FORBIDDEN|无办理权限／须另一获准人员复核|
|INVOICE_DOCUMENT_NOT_FOUND / CONTENT_RESTRICTED|当前无权领取或材料受限，清旧文件，不尝试公开链接|
|SERVICE_UNAVAILABLE|暂不能核实金额或文件，保留原请求等待核对；不要显示0元或成功|

开票更新沿现有订单通知返回原订单，通知中不含税号、抬头或文件。前端从原订单再进入开票，不能把通用通知视为票据下载授权。

## 同版联调怎么验

使用PR39同一提交，先执行迁移，使用随机隔离数据库、合成账号与文件。现有自动脚本`node scripts/test-mysql.js invoices`能自建并清理资料；只连接已经确认的本机测试数据库，不留下真实账号。长期页面模拟资料在第16组统一准备，不把本次自动测试用的短期编号作为永久测试账号。

1. 同一订单：未付款查额度0→模拟付款→申请→运营要求补资料→本人补件→运营批准→录入模拟票据→另一人核准→本人领取。历史材料和文件内容逐项核对。
2. 同时重复同一申请只留一份；另一个编号申请不能超额。操作失败后仍能按原编号恢复；旧版本操作被拒绝。
3. 出具前撤回释放额度；已核准后不能撤回。已出票订单退款，旧票据保留、显示更正；另录归零更正并独立核准，原文件标历史。
4. 购买方、机构外成员、无权工作人员、录入者自行核准全部拦截。切身份和下载中撤权清理旧资料。
5. 正式出票配置未开时清楚显示未启用；真实PDF分支只用隔离合成文件验证，不能报告为甲方正式发票已经可用。

本批不要求修改数据库细节或服务器内部函数。前端提交时给实际代码版本、同一订单／申请／票据编号、每一步预期和实际结果；后端再做组合复核。页面接入、另一方审阅、共同版本合入和甲方网站更新仍分别登记。
