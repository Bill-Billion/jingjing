## 这一轮办成什么

用户填故事 → 平台指出缺项 → 用户补充重提 → 平台签约主体按该版故事报价 → 另一个有权人员复核 → 用户确认 → 一笔未付款、未签署订单。重复点击或断网重试不新增订单；后改故事、价格、规则不改旧订单承诺。

用户已确认由平台签约主体报价。报价人须同时具备机构负责人和故事受理权限；普通收件员不能自动报价或复核自己的报价。外部制作机构暂不直接读私人故事。

按[原十二轮计划](../reviews/v5-d1-intake/07_ROUND_PLAN.md)，本轮终点是未付款订单。付款/制作第4轮，现货第5轮，试镜第7轮，推荐归因第9轮；全量税票渠道核验按后续对应轮次。此前CURRENT把这些全列为第二轮阻塞不准确，本次纠正，未删除后续任务。

## 队友按什么顺序接页面

|页面与顺序|本侧已提供|队友需要做什么、怎样验收|
|---|---|---|
|1. 用户补资料|补件清单、草稿、重提、历史|逐项展示要求；保存再开不丢；区分保存/提交；冲突保留输入|
|2. 运营受理与补件|正式版本读取、受理、补件操作|看到同一正式版本，列明缺项；重提后重新查看，不自动判合格|
|3. 平台报价|故事、商品与已批准约定关联|从需求进入报价，说明代表哪个机构；无权不能报价，不手填故事编号|
|4. 独立复核|权限与独立复核|另一个有权人员复核；普通受理员不能冒充复核员；显示拒绝原因|
|5. 用户确认及订单|需求内报价列表、详情、确认、原trade订单|从我的需求找到报价；看清规格价格条款；确认进入同一未付款未签署订单|
|6. 财务查看|固定约定、来源校验、只读试算|显示服务器结果，区分试算/账面应付/可打款/已到账|

队友负责App和运营网页，待本人接手；本侧负责服务器、规则、数据库、合成资料及后端联调修复。本批未改App/Vue，页面只通过统一接口协作。

## 接口和兼容

[统一接口](../../contracts/openapi.yaml)版本0.15.0-rc.1，共176操作/306结构。具体接法依次见[补件](V5_R02_SUPPLEMENTS.md)、[报价/订单](V5_R02_PLATFORM_QUOTES.md)、[商品分流](V5_R02_PRODUCT_ROUTING.md)、[定制财务](V5_R02_CUSTOMIZATION_FINANCE.md)。分批文件中的未上传/剩余工作是历史状态，当前以本交接和CURRENT为准。

买家操作携带当前身份，运营账号级操作不自动带机构头。修改带原对象版本和请求键，未知结果保持原请求核对，不换键重建。补件保存使用上下文顶层object_version。

新增GET `/api/v1/finance/marketplace-preview?rule_id=...&supplier_party_id=...&net_minor=10000`，可传relation_id。仅财务复核岗位可用，不带操作主体头。整数分金额，比例由已批准生效规则提供，不能自行传入。返回PREVIEW_ONLY_NOT_ORDER_OR_PAYABLE，仅试算，不产生订单、账目、合同或付款。

V5总纲§3及分账规格§7要求先分平台佣金与供给收入，再从供给收入分MCN；推荐额出自平台份额。18%/22%测试例子不设为所有商品默认。新MCN条款可显式传v5_terms={version:'V5',supply_share_bps:2000}，范围10%—30%；明确选V5且省略比例才默认20%。旧commission_bps不转换，新旧关系各保原含义。

关系须艺人本人接受，时间、能力和证据有效。唯一有效关系自动采用；同时存在多条有效关系时拒绝试算，先核对并处理关系冲突，不能用指定其中一条来绕过，也不因漏传关系规避分成。系统确认不冒充外部电子签。冻结的关系及比例不随以后换绑/终止改写。

财务每条明细只选旧shares或新allocation一种，新规则必须匹配订单分类、收款人、原规则及比例。实付扣退款计算、尾差归平台、重复核对不重复记账。旧算法保留，自营定制不能套撮合分账。

新撮合商品尚无正式报价/收银入口，内部来源匹配用构造订单验证。正比例推荐仅计算已测，真实归因未实现，待第9轮。撮合出款明确阻止；财务条件增加可选business_gate说明原因。试算不等于可付款。
