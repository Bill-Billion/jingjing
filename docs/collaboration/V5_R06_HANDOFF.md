本阶段共12轮。本轮本侧负责后端；队友负责App和运营网页。本机检查、上传、远端检查、双方审阅、合入与正式启用的实际状态统一看[当前进度](../status/CORE_CURRENT.md)。本文件不代表页面或正式服务已经完成。

## 用户可以怎样办成一件事

|使用者|开始做什么|接下来会发生什么|
|---|---|---|
|有发布资格的出品人或机构|按剧、商演、商单、活动、招募填写通告；平台官方通告另走运营权限|独立审核后公开；超时、下架或发布资格失效后停止新投稿|
|真人艺人或获明确委托的MCN|选择具体真人、数字人和本次接收方授权，投递形象/模卡、想演角色或自己做剧的意向|先审核内容与附件，再单向送达；MCN不能凭机构身份代替任何艺人授权|
|普通实名成年买家|在已有公开展示授权的艺人处发送结构化邀约意向|只发送一张意向卡，不能直接给艺人开私聊或取得出演权|
|接收方|选择感兴趣或婉拒|感兴趣只生成一次客服待办；婉拒结束；二者都不代表付款、签约或授角|
|客服|核对双方、具体数字人及报价版本，关联已经审核的原商单报价|买家继续走原报价确认接口，形成未付款订单；订单仍要依原支付与履约规则处理|

投稿会保存实际人物、数字人、授权、规则及截止时间。授权撤回、MCN失权、未成年人、过期投稿和失效通告不得继续撮合。已经成立的订单保留原合同，不用撤回投稿去伪造订单取消或退款。

## 实际接口和调用次序

统一格式见 [OpenAPI](../../contracts/openapi.yaml)，版本0.19.0-rc.1。新增16个操作均为服务器实际实现，不是静态示例。请求使用已有登录凭据；代表个人/机构操作时带对应身份；修改须附读取到的版本和一次操作标识，重复发送同一次操作不重复生成记录。

|事情|接口（前缀 `/api/v1/notices`）|注意事项|
|---|---|---|
|规则|GET `/rules`；POST `/rules`；POST `/records/{id}/reviews`|独立审核；未知商业参数不提供默认正式值|
|机构资质|POST `/qualifications`|只针对本机构和明确通告类型；附外部资质证据，经独立审核|
|资格事实|POST `/facts`；POST `/records/{id}/reviews`|仅财务权限；录入与复核为不同人；外部回单来源与文件指纹防重复。不是充值接口|
|资格查询|GET `/eligibility?rule_id=...`|返回能发哪些类型和不能发的原因；前端不自行按数字推断|
|发布与浏览|POST `/announcements`；GET `/catalog`；GET `/catalog/{id}`|剧/商演/商单/活动/招募/官方各有字段；不让每类都填到场设备；浏览不暴露审核凭据|
|单向投递|POST `/submissions`|选择PROFILE/ROLE/CREATE_DRAMA/INVITATION；绑定具体人物，不通过切换全局头像代选|
|我的及运营待办|GET `/records?kind=...`；GET `/records/{id}`|同一地址按当前真实权限返回；CASE是客服待办，SUBMISSION是投稿|
|回复与撤回|POST `/submissions/{id}/decision`；POST `/records/{id}/close`|感兴趣/婉拒不可当作交易完成；过期按服务器时间拒绝；不提供自由聊天|
|客服关联|POST `/cases/{id}/quote`|仅客服；已审原报价、双方和具体数字人一致，版本准确且未过期|
|私有附件|GET `/records/{id}/materials/{asset_id}`|读取前后检查当前权限，校验文件字节；错误不能回退公开链接|

通知继续走原 `/operations/notifications`，新业务分类为NOTICES。原通用评论接口不允许对通告/投稿/客服记录开聊天。操作员权限新增NOTICE_REVIEW、NOTICE_SUPPORT、NOTICE_OFFICIAL；它们不能由App自选或充值授予。

新增人物委托动作SUBMIT_COOPERATION和本人同意用途COOPERATION_SUBMISSION。旧授权不会自动获得新用途。给某出品方投递前，需本人声明并审核该接收方的投稿用途授权；这不授予制作、商业出演或公开发行权限。买家意向卡只引用有公开展示授权的艺人，不能上传他人的新形象冒充本人同意。

客服关联仅复用原商单报价，不创建第二套订单。旧商单报价/合同继续保留原费率；新正式商业条件必须由原交易规则配置审核，本轮合成报价的金额与费率不作正式产品建议。MCN可受托投递；机构代签非标参演和完整多方会签仍按第12轮范围处理，不借投稿授权代替商用授权。

## 发布资格做到哪里、哪里仍不能正式使用

- 普通实名仅证明身份，不等于有权发布通告。机构须独立审核证据并列明准许类型；官方必须专门运营权限。
- 星探最低资格使用经过独立财务复核的充值/消费成长事实和发布规则计算。充值不发消费积分；一次大额充值不购买多年或高级别；六级须后续专门资质复核，当前不自动授予。实际余额账户、充值通道、消费积分账仍属第8轮，本轮没有开放真实充值。
- 外部资金事实录入是人工核验通道：必须真实核对托管方回单、本人、金额、时间和来源；一人不能录入后自己批准，不能凭口头声称或合成文件开启正式资格。它不增加钱包余额，不证明支付服务可用，不代替持牌通道。退款事实出现先暂停资格，退款后的完整恢复商业规则在第8轮确认处理。
- 用户2026-10-19已确认：一级商单/招募、三级活动；机构另审资质，官方仅平台运营。代码拒绝低于这一约定的规则；隔离样例不导入正式环境。剧/商演等类型的具体权限也通过明确发布规则登记，不从名称猜权限。机构范围须实际审核。
- 文字会拦截明显联系方式和站外付款引导；图片/视频及规避写法仍必须人工审核。程序没有宣称能自动识别所有违规内容。
- 未接真实OSS、未验证真实回单、未部署、未进行页面或手机验收。原有儿童限制保留。无人审阅的机构或没有可信资金事实的星探不会因为测试通过就能正式发布。

## 队友怎样取得可测试资料

在已有Node依赖与本机MySQL隔离配置的完整工作树运行：

```powershell
$env:JX_MYSQL_TEST_ENV_FILE='本机隔离配置文件的绝对路径'
node scripts/notices-sandbox.cjs
```

脚本只接受本机专用测试配置，临时建随机隔离库，只监听127.0.0.1，禁止外网服务调用；60分钟后或停止时删库及删除临时访问凭据。终端只输出本机文件路径，不输出令牌。访问文件位于被Git忽略的 `.local/notices-sandbox/<本次目录>/access.json`，不得上传或复制进页面代码。

生成8类场景：已发布通告、待审核投稿、已发送投稿、已婉拒、感兴趣待客服、已撤回、已过期、已关联报价。账户包括艺人、出品人、审核员和无关用户；全部为合成资料。

```powershell
node scripts/notices-sandbox-smoke.cjs .local/notices-sandbox/<本次目录>
node scripts/backend-check.cjs notices
```

前一命令检查12步接口行为并自动关闭资料服务；后一命令单独验证本模块，不调用真实短信、充值、支付或OSS。完整回归用 `node scripts/backend-check.cjs all`。接口实际返回另用 `scripts/validate_contract.py --runtime-fixtures .local/notices-http-fixtures.json` 核对。

页面需要的正常与异常数据可直接重新生成；临时合成服务不是共享线上环境。要在手机远程访问或部署仍另行安排，不能复用历史一次性开放授权。
