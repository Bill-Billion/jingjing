## 从干净目录获取与检查

先保留自己原目录的修改，在已有仓库执行以下命令。目录和本地分支已存在时换未使用名称，不清空原目录。阶段分支上传后才可执行获取命令。

```text
git status --short
git fetch origin
git worktree add -b ux/stage-1-review ../jingjing-stage-1 origin/core/stage-1-foundation-handoff
```

进入新目录，使用Node22.19.0、Python3.10或以上版本。只检查规则和资料，不需要安装服务器依赖或启动数据库：

```text
node scripts/backend-check.cjs party-unit
python scripts/collaboration_check.py
```

检查接口格式（Windows；Linux把Scripts/python.exe替换为bin/python）：

```text
python -m venv .local/contract-venv
.local/contract-venv/Scripts/python.exe -m pip install -r contracts/requirements-lock.txt
.local/contract-venv/Scripts/python.exe scripts/validate_contract.py
```

完整服务器检查：先在晶晶日上工程交接包/01_源码/backend_server执行`npm ci --no-audit --no-fund`。Windows本地测试还需自行下载、解压官方MySQL8.4.11至仓库.local/mysql/mysql-8.4.11-winx64，或用LOCAL_MYSQL_HOME指定安装目录；工具不会自动安装MySQL。中文路径的盘符映射、启动/停止方法详见[数据库说明](../../晶晶日上工程交接包/01_源码/backend_server/docs/MYSQL_FOUNDATION.md)。不要借用正式数据库或覆盖已有数据库目录。

启动隔离实例后，在仓库根执行PowerShell命令：

```powershell
$env:JX_MYSQL_TEST_ENV_FILE=(Resolve-Path '.local/mysql/runtime/test-env.json').Path
node scripts/backend-check.cjs all
```

成功应看到数据库16、后台任务21、外部服务21、账号18、旧问题31及全套129通过/1跳过（本阶段代码的预期，未来增测试会变化）。分组有重叠。唯一跳过的是缺脱敏旧库，不能说真实数据迁移通过。结束后停止本机实例，再确认端口关闭并撤销自己创建的盘符映射。Linux干净环境的完整复验由GitHub工作流提供；现有ci-mysql工具仅供GitHub运行，不假称任意电脑都能一键启动。

**不要用npm start验证新业务已经可用。** 旧app.js尚未整体迁到MySQL，正式模式会拒绝旧SQLite入口；后台真实业务处理器同样未启用。本阶段可复验的入口是上述规则、格式和隔离数据库检查。
