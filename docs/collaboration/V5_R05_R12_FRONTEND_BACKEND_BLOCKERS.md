# 第5—12轮前端：后端尚需补齐的事项

2026-10-22。当前共同版本 `integration/2608ef7`，接口文件 `0.30.1-rc.1`。用户已明确选择“继续制作5—12轮，单列后端阻断”。以下是实际代码、隔离接口和页面接线的结果，不把“已有路由”写成全部业务已完成。Experience完成可接页面及失败保护，Core修复服务器后再验证受影响的动作；没有代Core认领或代同事审阅。

## 会直接阻止办理或影响权限的事项

|事情|现有证据和影响|Core最小补齐及复验|
|---|---|---|
|原故事的创意追加报价（承接第四轮）|`R04-CORE-01`：合法原冻结故事追加仍返回409 `CUSTOMIZATION_ORDER_EXISTS`，报价创建、复核、确认、绑定的来源检查未整体区分追加与首次重复下单。详见第四轮报告。|沿原故事修复完整追加链；覆盖已冻结原故事的合法追加、过期/撤销工单、重复首次下单和最终绑定。前端不克隆故事绕过。|
|消费者充值和托管付款|钱包 `recharge()` 明确抛503 `CUSTODY_PROVIDER_NOT_CONNECTED`；trade provider也缺托管适配。隔离验证余额不变，页面不显示充值或付款成功。|完成适配及受信核对，再验证未知结果、原请求恢复、预留释放和退款原批次。真实服务是否启用单独验收。|
|MCN员工收入范围|`engagement/mcn.js` 的看板仅将 `assignments` 按员工过滤；`relations`、`orders`、总应计仍读取全机构，而员工授权带 `person_ids`。前端已隐藏员工的机构总额及无明确受派依据的订单。此隐藏不构成后端权限修复。|服务端依有效员工授权、艺人范围和受派业务过滤关系、订单及合计，返回明确范围依据；用至少两个艺人、不同员工和不同订单验证交叉读取、撤权与旧页刷新。当前单艺人零商单资料只证明该账号受派事项可读。|
|独立客服首次进入商单会话|客服未加入时GET messages返回403 `COMMERCIAL_SUPPORT_NOT_ASSIGNED`，而JOIN需要当前会话If-Match；现页面没有客服可读的首次待办/摘要版本。App请求客服及加入后的处理可办，但不能从买方读取冒充客服已读。|补独立客服待办/受控摘要及版本；验证首次加入、作者/交易参与者不可充当独立客服、已被其他客服认领与412重新核对。本批后续隐藏/冻结使用明确标注的隔离夹具预加入，初次UI加入仍不算通过。|
|从公开艺人直接发送试镜邀请|公开艺人目录未返回本次邀请可用的目标主体及本人公开同意引用，而通告INVITATION提交要求二者。个人资料编号不能代替主体编号，机构也不能读取他人私有同意列表。|提供权限内可用的邀约上下文或专用邀约入口，明确接收方和适用同意；验证本人授权变更、撤回、无关机构和重复邀请。已有合法上下文的流程保留。|
|首次办理时缺安全的规则/服务方选择|现货上架、试镜方案、付费参演/改约等需要适用的governance规则；普通调用者没有对应的生效规则目录。共创首次发起也缺可选制作方目录。绑定在旧记录中的快照不能自动冒充本次有效规则。|提供按业务、调用身份和生效状态过滤的只读选择上下文，保留真实版号与适用范围，并在写入时重新校验。现货/试镜/参演/共创各自验证首次办理与停用规则；不要借无关业务规则。|
|成长与推荐的首次规则、已公开档案找回|普通调用者缺当前生效engagement规则目录、自己的RANK_PROFILE找回入口；公开快照只能证明历史采用规则。影响首次推荐来源、指定成长同步，以及曝光绑定后重启找回。运营的queue不等于普通人的规则目录。|补权限内有效规则和本人公开档案读取；验证非本人读取、规则停用、公开撤回，以及重启后绑定。页面只从本次实际返回或合法已读记录取引用。|
|钱包待审规则的独立读取|GET wallet/rules只返回有效规则，缺待审记录和其版本；wallet/records不接受RULE。另一位审核人无法靠现有公开入口读取本次待审原文再审核。|补独立运营待办/详情及版本读取，验证作者不能自审、审核人必须先读同一版、412后重新确认。前端没有手填编号/版号伪装已审。|
|原券预留在重启后的恢复|接口提供grant checkout和hold release，却没有本人读取既有hold详情及版本的GET。当前会话保留原请求、原体、原版本；已获结果可确认或释放，不能靠换键猜测。丢失会话且grant已HELD时无法安全重建原预留内容。|补本人hold读取或grant中的可核对预留摘要/版本。覆盖提交后丢回复、刷新/重启、过期、已绑定订单、撤销订单和他人读取；保留原幂等重放。|
|隐私分类执行与留存依据的选择|更正、具体清理/留存及media任务需要适用政策引用；普通权限内缺安全政策目录，已批准执行摘要也缺更正后的完整展示名/变更原文。已有查询/副本/申请/答复/异议/模型逐项撤回删除可按各自接口办理。|补可读且按动作/类别过滤的政策依据；独立复核后执行，不能让普通人填规则UUID或把发起请求显示为完成删除。|

## 代码和正式服务仍须分别验收

- 本人副本现覆盖已实现的档案、材料元数据、当前故事及买方订单索引等明确类别；文件清理限定适用的AVATAR_MATERIAL，历史版本、备份和所有资料类别尚未形成完整清理证明。页面展示保留项与未完成项，申请关闭不冒充全部删除。
- 自动内容处理目前支持约定的文本长度和PNG/JPEG、MP4等范围；未知格式走人工处理，不能宣称所有格式和恢复动作已齐。media规则选择缺口同上。
- 共创到期后仍需明确“按截止条件核定人数”，尚无自动关闭工作程序。20人只产生原约定服务额度，不使整笔主订单免费；个人片段仍独立审核和受控领取。
- R8钱包的历史 `redemption_enabled` / `lottery_enabled` 为false，不替代R11独立权益规则和实际接口；前端没有改写这些服务端标志，也没有据此永久关闭合法R11入口。
- 评价和分享的免费奖励按用户决定关闭；评价本身、已配置注册/签到规则和原批次分别读取，不新增奖励数额。
- 支付/短信、实名、电子签、私有存储、长期模型、真实作品质量、旧库迁移样本、容量、Android/iOS实际手机分别保留验收。合成成人、隔离回执和色条视频只用于接线验证，不代表正式服务已经开通。
