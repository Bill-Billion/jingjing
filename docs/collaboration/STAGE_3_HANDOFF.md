# 第三阶段交付：合同历史与双端阅读页面

本阶段通过[第12份申请](https://github.com/Bill-Billion/jingjing/pull/12)一并交付后端历史保存与读取，以及 App、网页合同阅读页面和统一界面基础。后端原有检查与本批前端本地验收均有记录；最新上传版本和 GitHub 检查以申请为准。另一方审阅、合入共同版本和正式上线尚未完成。

## 现在可以做什么

1. 有指定权限的人员录入规则草稿，分别提交审核、批准、启用；内容有变化必须新建版本。
2. 有指定权限的人员录入合同来源版本，明确业务引用、修订号、当事方、采用的规则、承诺和读取人员。复核后才允许保存历史合同内容；新承诺不能覆盖旧承诺。
3. 获准的用户通过接口读取该合同及当时的规则。每次检查登录、所选身份和独立读取授权；普通机构成员不自动看到合同。
4. 页面查询合同后续操作所需的支付、实名、电子签或数字人服务是否就绪。当前正式运行入口没有这些业务服务绑定，所以明确返回“未启用”。

保存的始终是**未签署内容**。不会标成已签、已付或已取得许可。后台复核表示获授权人员完成内容核对；填写依据编号不自动证明外部订单、法律事实或材料真实性。

## 调用与维护

页面按[只读调用说明](STAGE_3_READ_API.md)使用三项GET。写入通过[后端操作说明](STAGE_3_COMMANDS.md)，不是公开自助审批接口；需真实有效会话和数据库逐项授权。授权维护见[谁能审批](GOVERNANCE_OPERATOR_ACCESS.md)。页面不读取数据库，不依赖内部函数。

后续订单/报价模块应在自身验证交易条款后调用合同来源保存能力，使用自己稳定的业务引用和不可变修订号。当前录入/复核工具提供了可运行的合同来源，但不生成商业订单、不校验任意JSON的全部商业含义。真实下单、收费、合同签署、授权生效仍属于后续业务阶段。

外部服务检查只验证必要的服务条件；通过后仍须业务权限、金额/授权/签署等各自校验，真正调用时仍经Provider Adapter再次检查，不能把页面查询结果缓存成永久放行凭据。服务状态变化不删除历史验证记录或历史合同。

## 怎样验证

沿用[账号服务器启动说明](STAGE_2_ACCOUNT_API.md)，必须明确配置MySQL及稳定登录密钥，不用旧npm start。数据库迁移全部应用后再启动API；本阶段新增0020–0028，旧迁移未修改。没有新增npm依赖。

仓库根运行完整测试：`node scripts/backend-check.cjs all`。须先准备指定的本机隔离MySQL，设置JX_MYSQL_TEST_ENV_FILE；缺配置会失败，不允许跳过数据库后报通过。仅检查本模块时，在backend_server运行`node scripts/test-mysql.js governance`。

此前后端交付（2026-09-24）的本机完整回归203通过、1项缺脱敏旧库样本跳过；合同规则专项55通过，账号接口19通过。各组有重叠，不相加。测试使用真实MySQL、会话和本机HTTP，人员、合同、供应商验证证据均是隔离合成数据，没有真实短信、支付、签署或制作。

实际返回格式另外用`python scripts/validate_contract.py --runtime-fixtures <文件>`检查。测试产出三份文件：`.local/account-api-http-fixtures.json`、`.local/governance-http-fixtures.json`、`.local/governance-service-http-fixtures.json`。Python需按contracts/requirements-lock.txt准备环境。远端自动检查执行同样测试。

## 升级与出错恢复

升级前先在获准环境备份数据库，并在隔离副本验证。数据库采用MySQL8/InnoDB；本阶段含合同历史表、权限历史表和来源版本表，应用编号0020–0028，0027扩展权限动作枚举。重复迁移不会重复建表；从认证表0019升级及空库建表均已测试。

没有自动删除数据的降级脚本。测试失败先停用新进程，保留失败日志和备份；若要退回旧代码，使用与该代码匹配的独立数据库副本，不能删除线上迁移记录后重跑，也不能改写历史合同。新接口暂不接页面即可暂停接入，不能用演示成功兜底。本轮没有生产升级，正式备份恢复和迁移仍需发布阶段演练。

## 审阅时重点看

- 数据库迁移和历史内容是否不可覆盖；重复请求、并发版本检查及操作记录是否一起提交。
- 逐项运营权限是否与合同读取名单分开；人员撤权和账号停用是否拒绝操作。
- 合同来源是否明确经过复核；业务引用只是引用，不能被认定为真实订单或签署证明。
- 三项GET及0.3.0-rc.2格式是否适合页面；新状态不能翻译成付款/签署成功。
- 默认未启用、环境隔离、配置版本和验证证据是否均检查。

第三阶段后端与本批双端页面可一并交付审阅，不代表整个产品完成。下一阶段建议先做作者、作品版本和权利材料，为选本与许可交易提供真实资料来源；开始前再登记一个范围清楚的小阶段。
