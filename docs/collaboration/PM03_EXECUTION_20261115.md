## 第一条怎样交给前端

前端先反馈：本机分支/HEAD、未提交UI是否保留、App/Web构建版本、现货页面已接动作、PR15/17脚本认领，以及联调机器/访问方式。后端实际环境回执放在原W10记录引用的证据位置，沿PM03的[环境字段](../sources/pm03-20261115/dashboard-data.json)填写；未填写不得称可用。凭据只放本机忽略上传的受控文件，不写Git、普通聊天、日志或看板。

前端最小验收：以所分买家登录，读取本人权限与已审商品，提交一次下单/最小写入；运营/独审用自己的权限找到同一业务记录，记录前后端版本及结果。后端API自验只记后端自验，不代前端签收。前端独立电脑优先本地同候选复现，既有受控连接按实际授权使用；本轮不开放公网。

已知网页阻断仍是当前PR15卖方缺有效实名、历史PR17买方前提待复验。后端源码使用既有当前身份准入，正常资料应准备真实的合成身份事实；不得直接改业务库伪造审核成功。前端修自己的准备脚本，后端对确证的环境/helper问题修复，另一人按新版本复验。
