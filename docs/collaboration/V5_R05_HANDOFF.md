# 第五轮交接：直接买现成视频，取得个人使用许可

本侧负责服务器、授权判断、订单和测试；队友负责 App 与运营网页。本轮完整分支 `core/v5-r05-stock-video`，起点 `17e1b6d`；依赖第2轮商品/交易和第3轮真人/授权的未合入代码，保留第4轮同一交易文件的改动。现货流程本身不调用故事或定制制作。实际上传、检查和合入状态看[当前进度](../status/CORE_CURRENT.md)，不以本文代替验收。

## 用户怎样办成这件事

买家：在广场看视频预览 → 阅读价格和个人使用许可 → 确认购买 → 真实付款核实 → 在“已购视频”下载正式文件 → 确认取得文件，或提出故障、延期、争议、退款。无需填故事、等待制作、先创建自己的数字人或办理企业身份；本轮购买人为已核验的成年个人。

卖家：选择具体艺人和现成文件 → 确认价格、许可和全部出镜人的同意 → 提交内容及权利审核 → 两项通过后公开销售。机构代售须明确旗下哪位艺人，且有其实际受托授权；不把机构名称当人物。用户已确认 **L1 可销售现货，不强制先购买 L2**。L1 和同意均核对实际记录，不只相信勾选声明。

|---|---|---|

## 已确定规则和实际限制

- 仅限已完成视频的个人收藏及个人社交分享：非独家、全球、永久、非商用。广告、改编、发行、独立声音、重新生成、模型/源文件及独家买断均不包含。需要其他权利应另走相应业务，不从本页面悄悄扩权。
- 商品规格、报价和合同保存历史版本；验收小时数及售后文字明确填写并独立审核。合成示例的金额、72小时及30分钟支付窗口不等于正式商品参数。文件限50MiB是当前技术上限，普通资料上传仍限8MiB。
- 全部出镜人的许可需覆盖现货销售及公开展示；审核人员检查实际作品、水印和适用AI标识。代码核对文件与审核记录，**不声称自动生成水印或自动完成法律审查**。
- 普通下架不撤销历史许可。权利暂停会让旧收件计时失效，恢复后需重新查看/通知/确认；退款后平台停止再下载，无法远程抹去买家已下载文件。
- 不开放私人联系卡。售后走订单内记录/通知；后续积分、榜单和返佣引用履约与退款事件，本轮没有提前发放。
- 真实收款必须满足已有交易服务的商户归属校验。当前实现是卖家直供订单；支付配置须对应实际卖家，不能拿平台商户配置冒充任意个人卖家。真实个人/MCN收款路径、退款、结算仍按支付服务开通与正式审阅验收；不绕过这一限制。Apple还要求商品明确已审产品编号及真实商店配置，否则报未就绪。
- 本轮不改前端文件。2026-10-19已看到 Bill-Billion 的 `ux/v5-r01-story-frontend`，版本 `8e77ff0`，含第一轮故事/运营页面；尚未由本侧复验或合入。第2—5轮页面仍待队友确认接手。不能再写“队友完全没推前端”。

## 页面调用顺序

统一格式见[接口文件](../../contracts/openapi.yaml)，版本 `0.18.0-rc.1`，新增20个操作。以下均为已实现接口；演示资料仅用于隔离环境。

|操作|接口（前缀 `/api/v1`）|身份及注意事项|
|---|---|---|
|浏览、详情、预览|GET `/stock/catalog`、`/stock/catalog/{id}`、`/stock/catalog/{id}/preview`|登录账号；不带操作主体头；列表支持cursor/limit/city/person_id|
|上传正式/预览视频|POST `/stock/files`|卖家主体，二进制上传；两份内容必须不同；证据继续用既有私有资料接口|
|提交、查看上架材料|POST/GET `/stock/listings`，GET `/stock/listings/{id}`|卖家传操作主体；审核人员不带主体，按权限读取|
|内容与权利审核|POST `/stock/listings/{id}/reviews`|独立审核人员；RIGHTS和CONTENT分别提交；卖家不能审自己|
|普通下架|POST `/stock/listings/{id}/status`|卖家，action=UNLIST|
|权利暂停/重新审核|POST `/stock/reviews/{id}/status`|独立审核人员，RIGHTS_HOLD或REVIEW_AGAIN；重新审核保留暂停直至两项均通过|
|审核文件/证据|GET `/stock/listings/{id}/files/{preview或full}`、`/stock/listings/{id}/evidence/{asset_id}`|卖家或有权审核岗；不返回可公开转发的地址|
|直接下单|POST `/stock/checkout`|个人买家；listing_id、offer_sha256、channel；返回既有TradeRecordResponse|
|付款/查询/退款执行|既有 `/trade` 接口|原支付/退款校验保留；页面不能上传“付款成功”证明|
|已购列表/详情|GET `/stock/purchases`、`/stock/purchases/{order_id}`|买家主体；详情允许独立售后审核岗按权限查看|
|下载正式文件|GET `/stock/purchases/{order_id}/content`|每次核对本人、实际付款、许可和文件完整性；当前完整文件下载，不是分片流媒体服务|
|确认收件/确认验收|POST `/stock/purchases/{order_id}/receipt`、`/acceptance`|取文件后刷新版本；收件前还需通过既有通知接口标记已读|
|提出/解决售后|POST `/stock/purchases/{order_id}/cases`、`/case-resolution`|买家提，独立售后人员解决；退款决定不等于实际退款|

修改请求带 `Idempotency-Key`；已有记录的修改带 `If-Match`。普通列表和详情返回 `object_version`；下载会记录实际文件可用观察，随后修改前应刷新详情。未付款、暂停及撤权不能取正式文件。遇到版本冲突先刷新，不能无脑自动重发付款。

上架输入还包括 seller_person_id、spec_id、rule_id、participants、rights_evidence_ids、qualification（minimum_halo_level固定1及来源）、payment_window_minutes、apple_product_id（未开通填null）。规范中的原字段名保留，页面用可理解的标题。合同封存不等于电子签已完成。

## 双方怎样取代码与合作

1. 队友先保留自己未提交改动并更新远端；在独立后端目录取本轮完整分支。不要把几份零散文件复制到旧后端，也不要覆盖自己的第一轮页面分支。
2. 本侧维护接口、数据库、规则及测试；队友接上述App/运营页面。优先在自己的本地界面连接下方合成服务，凭据只留本机。
3. 第一轮前端已有上传，下一次共同联调先复验其实际页面和少量服务器改动，再逐轮接第2—5轮页面。不得直接把前端整条分支强行合进后端交付，也不得声称已替队友审阅。
4. 接口差异记录在同一交接及问题记录中；共享授权、支付、数据库与合同规则须对方实际看过。按阶段集中上传，不每聊天一次就开一个申请；延续当前不新增重复串联合并申请的做法，原申请和提交保留。
5. 第6轮本侧可继续通告/投稿/客服转单；须先接可信发布资格，不能用普通实名假装具备发布资格。此工作不要求队友先做完第5轮页面，但最终验收要同版本走通。

## 可以立即跑的检查与六类资料

在仓库根目录，显式提供本机隔离数据库配置：

```powershell
$env:JX_MYSQL_TEST_ENV_FILE='<本机隔离配置文件>'
node scripts/backend-check.cjs stock
node scripts/stock-sandbox.cjs
```

启动只监听127.0.0.1，创建随机独立测试库。终端给出本地 access.json 路径，内有随机卖家、买家、审核和无关账号凭据，以及未付款、已付款、下架后已购、争议、退款、待审六类资料。禁止将 access.json 入Git；没有公开网址，没有收费接口。测试文件是不可播放的合成字节，不能作为真实水印、播放器或手机验收证据。

```powershell
node scripts/stock-sandbox-smoke.cjs .local/stock-sandbox/<本次实例>
```

检查后自动请求关闭；正常Ctrl+C、输入quit或60分钟到期也会清理本次数据库和凭据。确认本实例 status.json 的 database_removed 与 credentials_removed 都为true，才能报告清理完成。后台自动验收单独受 `STOCK_WORKER_ENABLED=true` 控制，正式服务未启用。
