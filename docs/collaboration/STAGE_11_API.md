# 队友怎样接业务通知、留言和报表页面

本侧提供服务器；队友负责 App、运营网页和合作方网页。下面 11 项接口已接入实际服务器并完成隔离测试；页面接入、双方审阅与正式启用尚未完成。本阶段没有新增需要调用收费供应商的操作。

统一前缀 `/api/v1/operations`，完整字段与错误格式见 `contracts/openapi.yaml`，候选版本 `0.11.0-rc.1`。原有 148 项接口保持；队友账号权限与安全重试修复也已接入。

|页面上的事情|调用方法|关键要求|
|---|---|---|
|看当前个人或机构的通知|GET /notifications|带当前身份；可筛未读；返回业务类型和对象编号|
|标记本人已读|POST /notifications/{event_id}/read|空正文；重复点击安全；不会替机构其他人标已读|
|看订单、项目或制作版本内的留言|GET /objects/{domain}/{record_id}/comments|服务器每次检查当前业务权限|
|留言或回复|POST /objects/{domain}/{record_id}/comments|正文 body 和 reply_to；不回复时 reply_to=null；最多4000字符|
|撤回本人留言或隐藏不当内容|POST /comments/{comment_id}/actions|action=WITHDRAW/HIDE，填写reason，携带看到的版本号；隐藏另需运营权限|
|查留言和报表的操作记录|GET /audit|明确授予运营审计权限后才可用；可按object_id筛选|
|查原有业务的历史操作|GET /objects/{domain}/{record_id}/audit|还需原业务读取权限；直接读取原模块历史，包括本次升级之前的记录|
|申请生成统计报表|POST /reports|kind、environment、period_start、period_end都必填|
|看报表生成结果|GET /reports/{report_id}|只有申请人以申请时的身份可读；重新检查每个来源的权限|
|下载表格|GET /reports/{report_id}/content|只有生成成功才返回CSV；包含统计口径、环境、期间和行数|
|修复条件后重试报表|POST /reports/{report_id}/retries|填写reason；只对失败或待处理任务生效；重复同一请求不会再加次数|

写入沿用登录凭据、请求编号和重复请求编号；留言状态变更还须带 If-Match，例如 `"1"`。身份用 X-Acting-Party。无身份的留言、报表操作只向具有相应原业务审核权限/报表权限的运营账号开放，不因为账号名称叫“管理员”就自动获准。

业务类型：TRADE=交易、PRODUCTION=制作、PROJECTS=项目发行、FINANCE=结算、SUPPLY=作品与供给、LICENSE=许可、GIGS=商单。留言仅支持交易订单、制作项目、制作版本、项目四类对象；不能把任意两个用户的聊天塞进留言。回复必须在同一对象里。正文按纯文本显示，不能作为HTML执行；没有附件上传、通用联系人、私聊、语音通话或推送短信。

通知只返回事件和业务对象定位信息，页面按业务类型跳转现有详情接口，详情再次检查权限。事件名称建议显示成用户能理解的中文；收到旧事件不代表现在仍待处理，待办操作以详情页当前状态为准。被移除成员、退出项目或失去审核授权后，旧通知、留言和报表也不能继续访问。隐藏/撤回留言仅显示状态，接口不返回原文；原始内容留在数据库供受控保全，本阶段没有授予网页查看被隐藏原文的接口。

通知按编号倒序翻页；cursor是继续看更早记录的位置。每次刷新从不带cursor开始，再按id去重。不能把cursor当“从此编号以后绝不再有新消息”的同步水位，数据库事务可能晚提交。过滤无权或已读记录后允许空页但仍有next_cursor，页面继续翻页；没有虚构全站未读总数。留言和业务审计按稳定编号翻页，显示created_at排序时由页面处理；不是实时聊天流。

通知从本次升级后的业务变更开始，覆盖供给、许可、交易、制作、商单、项目、结算；不补造过去已读历史。文件上传内部状态、账号邀请和短信不混入这里；账号邀请仍使用既有邀请接口。制作通知包括制作方，项目通知包括当前受邀/参演者和需要确认的各方，真正读取仍以原业务权限为准。

|报表类型|能看到什么|不能怎样解释|
|---|---|---|
|CASH：收退款明细|期间内已核实的收款、退款分列，金额单位为分，带订单和来源编号|不是利润、可提现余额或旧单“申报已付”|
|SETTLEMENT：结算份额|本人份额的计提、调整、已付和退回分列；运营须具备额外权限才可汇总|不能把付款方和收款方金额相加当平台收入|
|WORKLOAD：制作情况|期间内创建的制作项目，在生成时处于什么状态|不是历史时点状态或人员剩余产能；无工时/实际成本资料时不虚构利润|

期间按UTC，起点包含、终点不包含，最长366天；每份最多2000条来源。超过上限明确返回 REPORT_LIMIT_EXCEEDED，应缩短期间重新申请。通知每页最多100条。测试与正式环境严格分开。制作报表只计入存在已核验收款且没有混合环境付款的订单；未付、环境不明和混合环境项目不计入，页面必须显示返回的限制说明。

申请成功先显示“等待生成”；需独立后台程序处理。不要把HTTP200当生成完成。成功后结果不再被后来的业务改动改写，返回内容校验值、口径版本、来源及生成时间。需要最新结果应重新申请。下载表格与JSON使用同一份已保存结果；表格的文字有防公式执行处理。已生成但失去来源权限时，整份拒绝下载，不返回残缺的“成功报表”。

前端验收建议：用两个账号分别登录、切换两个机构，验证未读隔离；进入同一订单留言、跨订单回复失败、撤回后不显示原文；申请测试环境报表、等待后台结果、下载并对比JSON金额、撤销权限后再次下载失败。暂不要求真实支付；这些属于隔离验收，不能据此宣称正式业务可用。
