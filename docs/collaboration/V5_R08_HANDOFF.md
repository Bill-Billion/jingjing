# 第八轮首批：先把余额、晶钻和成长记录算清楚

本阶段共12轮。当前正在做第8轮，这一批是账本和积分的基础部分，**不是第8轮全部完成**。本侧负责服务器；队友负责App和运营页面，尚未代其认领第8轮。实际目录 `worktrees/full-flow`，分支 `core/v5-r08-wallet-points`；包含前七轮未合入依赖，共同版本仍为 `28662ab`。

## 这一批已经写了什么

|用户要办的事|服务器目前能做什么|队友页面应怎样显示|
|---|---|---|
|看余额与晶钻|本人接受已由另一人审核的规则后，建立个人账本；分别展示余额记录、可用晶钻、待冲回晶钻和消费成长|只显示当前本人；不能把机构经营收入当个人充值余额|
|看星探资格|从核实的充值记录、消费成长和六级独立审核计算期限、等级与冻结原因|未达到资格、到期、还差审核要分别说明；当前通告仍走第6轮资格机制，未切换新账本|
|消费后获得晶钻|新订单保存当时的积分规则；核对实际付款、交付和售后期后发分；只付款不发分|订单详情可请求核对；缺履约、缺售后规则时展示具体原因|
|订单退款|核实退款后撤回成长与相应晶钻；不足部分以后新发晶钻先抵扣，暂停积分用途|把“退款已到账”和“晶钻待冲回”分开，不显示负余额或现金欠款|
|花晶钻|内部已支持预留、释放、确认扣除以及到期处理；并发不能超扣|尚无通用扣分按钮；必须等投票、兑换、抽奖各自接入真实业务对象|
|充值|只有经过核实的托管回执才可在内部记账；重复回执不重复加钱|公开充值接口目前明确返回“资金托管服务尚未接通”，禁止展示充值成功|

积分规则快照明确记录“按累计实付净额计算并向下取整”，避免先退款再发分与先发分再退款出现差异；每日充值限额按北京时间换日。身份验证失效后保留本人账本历史，但不继续显示有效星探资格。

用户2026-10-19确认：退款不足晶钻按“以后新发先抵扣，期间暂停积分用途、不追收现金”实施。现金退款不会因为晶钻已经花掉而被这项规则阻止。消费成长与可用晶钻分开；花掉或过期不降低成长，退款才撤回对应成长。

## 真实可调用的接口

全部在 `/api/v1/wallet` 下，需要登录。本人操作还需要 `X-Acting-Party`；不能用机构身份开个人账本。写操作使用 `Idempotency-Key`，审核还需 `If-Match`。

|事情|请求|状态|
|---|---|---|
|看核准规则|GET `/rules`|已实现|
|创建及独立审核规则|POST `/rules`、`/rules/{record_id}/review`|已实现，需对应运营权限，不能自己审核|
|接受规则开个人账本|POST `/accounts`|已实现，成年人本人、规则编号和校验值必须一致|
|看本人概况和记录|GET `/summary`、`/records`|已实现，记录按类型分页|
|核对订单是否可以发晶钻|POST `/earnings/sync`|已实现；只能核对本人订单且须有下单时保存的积分承诺|
|六级资格提交及审核|POST `/level-six`、`/level-six/{record_id}/review`|已实现；审核通过也不能代替成长门槛|
|请求充值|POST `/recharges`|仅实现明确拒绝，503；真实充值未实现|

完整字段在 `contracts/openapi.yaml`，版本 `0.21.0-rc.1`。前九项功能路径可以本机调用，不是页面已完成；积分预留和托管记账是内部模块，没有允许客户端自行提交“已付款”“已履约”或任意加钱加分的接口。

## 第八轮还要继续做什么

1. 本侧补齐消费者余额的订单扣款分配、原路退款、差异对账及相应异常处理。当前只是充值回执记账边界，尚未实现完整余额支付。供应商结算账不能代替消费者账本。
2. 本侧接自动发分和到期任务，补齐各交易类型的履约证据及免费积分来源。当前现货已验证真实订单至积分路径；定制/试镜已有读取接点，仍需对应专项；商单缺完整履约接点。其他交易的售后天数必须由已发布规则提供，未明确时不发分。
3. 本侧让通告发布使用新资格，并处理第6轮历史外部凭据如何转入；不能在用户打开新账本时悄悄丢失旧资格或重复计算。
4. 队友接余额、晶钻、成长、会员期限和六级审核页面；双方用同一版本验收。PR24当前只证明第一轮故事页面；用户要求等队友下午确认其他页面，本侧不据此停止开发。
5. 本侧补第7轮保留事项：商单专属会话、已付款试镜补差合同。未因开第8轮删除。
6. 内部能力和交付说明齐备后按阶段集中推送，核对远端检查，再由双方实际审阅。真实托管机构、商户和服务权限齐备后另做真实资金验收。
