用户已确认退款不足晶钻用未来奖励抵扣、不追收现金。用户补充早期口头倾向支付宝；具体资金托管产品和开通状态仍未确认。普通支付宝订单支付不直接代替消费者充值托管。评价/分享奖励是否暂不开放已询问用户，不能自行视为批准。

## 队友按什么接口接

全部在 `/api/v1/wallet` 下，需要登录。本人操作需 `X-Acting-Party`，机构不能开个人账本；写入需 `Idempotency-Key`，审核另需 `If-Match`。完整结构见 `contracts/openapi.yaml`，版本 `0.21.0-rc.2`。

|页面动作|接口|说明|
|---|---|---|
|看可接受规则|GET `/rules`|不公开运营审核备注|
|运营建立和独立审核规则|POST `/rules`、`/rules/{record_id}/review`|不能自审|
|本人接受规则开账本|POST `/accounts`|传规则编号和校验值|
|看概况和明细|GET `/summary`、`/records?kind=...`|按本人权限和类型分页|
|每日签到|POST `/check-in`，内容 `{}`|北京时间每日一次；未配置返回明确原因|
|核对某订单晶钻|POST `/earnings/sync`|手动补查，自动任务不依赖打开页面|
|六级申请及审核|POST `/level-six`、`/level-six/{record_id}/review`|私人证据、独立审核；不能代替成长门槛|
|充值|POST `/recharges`|目前503，资金服务未接通，不展示成功|

金额用整数分。`recorded_balance_minor` 是账面余额；`reserved_balance_minor` 是付款中暂不可用部分；`available_balance_minor` 才是可以再次预留的金额。可用晶钻与消费成长分别显示，花掉或过期不改成长，退款才撤对应成长。

明细新增 `CASH_SPEND`、`CASH_REFUND`、`CASH_RECONCILIATION`，保留原充值、积分、积分预留和资格审核记录。免费积分不一定有订单号。规则新增可选 `free_awards`，注册、签到、评价、分享分别配置；`null` 或缺整个字段均不自动补奖励。

现货下单、报价、试镜下单支持 `CUSTODY` 余额渠道。试镜省略渠道仍为 `ALIPAY`，旧订单不改。付款仍调用 `/api/v1/trade/payments`；真实服务未开通时返回 `CUSTODY_PROVIDER_NOT_CONNECTED`。不要另造“已付款”按钮。积分扣用仅供具体投票/兑换/抽奖内部调用，不能让客户端随意提交扣分数额。

## 双方怎样验证

本侧提供 [合成HTTP返回](../testing/evidence/v5-r08/FRONTEND_FIXTURES.json) 及隔离数据库检查。全部编号和资金为测试数据，不能直接查询另一台数据库，也不证明真实充值、媒体或资质有效。队友可先据此接页面，再统一版本联调。

建议顺序：接受规则 → 空账本 → 充值与待付款状态 → 预留和可用金额 → 核实付款明细 → 履约与售后结束发分 → 退款撤成长、不足冲回 → 新奖励先抵扣 → 到期资格与通告限制。另检查别人账户、机构身份、实名失效、服务未开通、奖励未配置和重复点击。

队友负责页面和实际审阅，本侧负责后端与测试。PR24后续范围按用户要求等队友确认；现有证据只证明第一轮故事页面，不代表本轮页面完成。

## 内部接入和运行说明

- 消费者余额与供应方应付账分开。余额扣款、订单入账、退款恢复与审计使用同一事务。超时未知保留预留，明确关闭才释放；人工复核中的付款不能被后续成功回执部分更新。
- 只有签名核验或主动查询后的托管回执可记账，客户端和运营表单不能自报充值。不同机构、测试/正式环境或商户不能混账；河南换北京须单独核对旧余额与未完订单，不能只换密钥。配置版本变化也不得自动混用旧凭据。
- `WALLET_WORKER_ENABLED=true` 注册自动任务，启动时为旧账户补缺失任务。已有失败/阻塞任务保留，不擅自无限重试。每小时核对，积分来源每页100条；到期清理与成长分开。正式运行未开启时，不声称已经自动发分。
- 评价/分享的 `createRewardService` 需要真实业务模块核实事件、归属和时间，默认拒绝。这只是受信接入能力，尚不代表评价/分享奖励已开放。
- 旧资格与新资格各自完整计算，选择有效且等级较高的一份；同等级选有效期较长的一份。绝不累加两边的充值、成长或现金；旧退款待复核仍阻止发布。
- 对账只记录双方余额、时间和凭据摘要，差异可能包含到账时间差或未知付款，需核对后处理；没有自动补余额接口。

独立检查：`node scripts/backend-check.cjs wallet`、`node scripts/backend-check.cjs auditions`、`node scripts/backend-check.cjs trade`。接口检查：`python scripts/validate_contract.py --runtime-fixtures .local/wallet-http-fixtures.json`。只使用仓库隔离测试数据库。结果见 [测试证据](../testing/evidence/v5-r08/RESULTS.json)。
