# 队友如何接商单、MCN合作、佣金和榜单页面

本侧已实现服务器接口，队友负责App/Vue页面，尚未确认接手或完成联调。接口前缀 `/api/v1/gigs`，全部需要登录；涉及个人或机构操作携带 `X-Acting-Party`。当前写入限有效OWNER，离开机构后即失去权限。审核使用单独授予的GIG_REVIEW，不能由当事人、供给方、需求方或获佣MCN自审。

所有POST带 `Idempotency-Key`；修改已有记录另带 `If-Match: "版本号"`。同一请求重试返回当前记录，不重复产生佣金；412表示版本已变化，应重新读取。字段定义以 `contracts/openapi.yaml` 为准，页面不直接操作数据库。

## 页面按这个顺序开发

1. 商单列表：GET catalogue返回已审核、未暂停、未过期商单的摘要，以及当前可用规则。规则由运营提交并独立审核，价格、禁入品类、佣金比例和榜单权重没有产品默认值。规则为空时提示尚未配置，不伪造成功。
2. 发布商单：以实际需求方身份提交用途、地域、截止日期、品类和证明。只能声明商业用途，私人定制或发行项目另建对应业务，不改写已有订单。代理办理须使用有效的需求方成员身份，真实委托材料仍需独立核验。
3. MCN合作：MCN发邀请，艺人本人或获准代表确认后生效。独家期间冲突会拒绝；普通合作不建立上下级。终止后不能给新商单套用旧关系，历史订单中的关系和佣金约定保持。
4. 接商单：供给方选择已审核商品规格、自己的数字人、商用脸声同意，明确条款和单笔佣金。需独立审核，再由需求方确认精确版本。愿意进入公开榜单须显式选择 `ranking_opt_in`；不默认勾选。
5. 报价下单：原POST `/api/v1/trade/quotes`新增可选 `commercial_offer_id`。填写它后服务器核对双方、规格、数量和当前授权，将商业约定写入报价；买方按原接口确认报价后封存到订单。一份接单约定只能生成一笔订单。当前商业连接限一项商品、数量1、供给方直接履约；拆分采购先明确各笔合同，不伪装平台总包。
6. 佣金明细：POST commissions读取真实收退款再计算，返回待结算金额；GET entries查看每次增加或冲回。MCN佣金从约定的平台佣金中分出，不重复扣艺人收入。整数分计算、向下取整；退款按累计净实收重算，记录差额。这里没有“已打款”按钮，不是提现或自动分账。
7. 榜单：运营按日期生成快照，用户读取公开摘要。热度=窗口内交易笔数×权重+净实收分×权重；新兴=当前与前窗口笔数差×权重+新人奖励；地区按委托中约定的地域分组，不声称是艺人居住地。仅纳入同意上榜、正式环境、已核验的商业收款；重复支付异常单转人工，不计榜。无足够数据返回INSUFFICIENT_DATA。公开结果不含订单ID或原始收款明细。

## 接口清单

|页面操作|请求|谁可以做|
|---|---|---|
|提交规则|POST /rules|获授审核权限的运营人员|
|停用旧规则|POST /rules/{record_id}/retirement|独立运营人员；不改旧合同|
|审核规则、商单、接单约定|POST /records/{record_id}/reviews|独立审核人员|
|邀请MCN合作|POST /relations|具有有效MCN能力的当前负责人|
|接受、拒绝或终止合作|POST /relations/{record_id}/decision|被邀请方确认；任一方可终止|
|提交商单|POST /requests|需求方负责人|
|暂停违规商单|POST /requests/{record_id}/suspension|独立审核人员；同时留下站内通知|
|提交接单约定|POST /offers|供给方负责人|
|确认接单约定|POST /offers/{record_id}/acceptance|需求方负责人|
|计算本笔待结算佣金|POST /commissions|订单双方或原约定直接MCN|
|生成指定日榜单|POST /rankings|获授权限的运营人员|
|查询记录列表/详情|GET /records、GET /records/{record_id}|当事方或授权审核人员|
|商单列表和规则|GET /catalogue|已登录账号；摘要最多100条|
|业务通知|GET /notifications|当前身份负责人；最近100条|
|读取公开榜单|GET /rankings/{record_id}|已登录账号|
|佣金增减记录|GET /commissions/{record_id}/entries|订单双方或约定MCN|
|读取证明文件|GET /records/{record_id}/evidence/{asset_id}|记录当事方或授权审核人员，且文件必须属于该记录|

## 状态不要混淆

商单PUBLISHED是通过发布审核，不是已成交；OFFER ACCEPTED是需求方确认接单条款，不是已付款；COMMISSION CALCULATED是按核实收退款计算的待结算金额，不是实际支付。手工审核必须真的查验原始材料，勾选框不能代替身份、签署、广告内容及标识的核实。

本阶段不实现真实成片制作，制作接口在第16份独立分支；订单样片/最终验收付款节点在本分支仍保守拒绝，须合入第七阶段才能使用。其他数字人、支付和前端真实启用条件也没有被本阶段自动解除。
