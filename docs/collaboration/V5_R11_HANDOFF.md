# 第11轮交接：兑换、抽奖得到的权益怎样真正用起来

2026-10-20。总计划12轮，本轮第11轮。本侧负责服务器、数据库、业务规则和主要测试；队友负责App与运营网页，接手和页面进度待本人确认。完整分支 `core/v5-r11-redemption`，工作目录 `worktrees/full-flow`。本轮需要第8轮晶钻账、第9轮奖励及第10轮共创额度；完整依赖已放在本分支，不能只摘本轮提交放到旧integration运行。上传、检查和合入状态统一看[当前进度](../status/CORE_CURRENT.md)。

## 用户怎样完成业务

|用户要办的事|按什么顺序操作|怎样才算真的办成|
|---|---|---|
|用晶钻兑换制作金|看兑换目录、价格和范围，确认兑换，进入我的权益|服务器扣分并发放同一张券；余额/库存不足则都不发生；反复点击不能多扣|
|用制作金定制|先取得平台已审报价，选券查看抵扣后的金额，再确认订单|合同保存原金额、抵扣和新分期；按实际到账核销券，不按点击付款核销|
|用免单或共创额度|查看适用服务、剩余有效期，确认免付金额后下单|显示“权益全额抵扣，现金实付0元”；开工才核销，开工前取消释放|
|使用面试卡|选本人真人及数字人，提供对应授权，等待运营排期并确认|有明确项目/批次、时间、处理记录；完成面试不等于获得出演权|
|使用曝光权益|选本人的公开艺人资料，运营安排资源位和7天日期，独立审核后本人确认|公开曝光列表只在有效期间出现；撤回公开授权后立即隐藏；实际页面展示仍需队友接入|
|抽奖|查看审核后的规则、实际概率、库存条件，选单抽或十连|服务器一次性扣分、扣库存并保存结果；前端动画读取结果，不生成结果|
|处理未兑现权益|本人申请处理，运营核对证据|面试按已公布规则延期一次或返积分；曝光兑换退原积分，抽奖曝光按预先审核的补救积分处理；不能临时编数|

## 本轮已确认的三个规则

1. 制作金先只用于平台人工定制片和做剧；不用于现货、人工样片、数字人创建/托管。允许的具体商品版本必须提前审核登记。
2. 普通抵扣按抵扣后应付现金计算30%首款、60%中款和10%尾款，尾款吸收分币余数。首次真实付款确认后核销；退款最多退实付，已核销券不返。付款结果未知时先核对，不能取消释放后重复使用。
3. 全额抵扣不生成0元付款假回执。用户确认具体服务和免付金额后生成独立状态的订单；开工核销、开工前取消释放。开工后取消走已有售后审核，现金实付0就不退现金。基础款对应哪款商品及规格由甲方配置，不默认采用冲突的1800/3000元。

共创服务额度仍是一份不可提现权益。第10轮发的额度，按原服务编号、金额、有效天数和服务提供方对应审核后的模板；领取不会重新延长有效期，也不能反复换成多张。原活动取消或退款后阻止继续使用；已经发生的现金回执如实保留并记录异常，不撤销或伪造。使用这份额度的订单不再叠加同笔推荐佣金。

## 队友怎样接页面

统一文件 `contracts/openapi.yaml`，版本 `0.24.0-rc.1`。本轮27个操作，全部在 `/api/v1/redemption` 下。公共返回仍是 `meta + data`，通用记录详细内容在 `data.data`。身份操作传当前 `X-Acting-Party`；运营审核与目录读取不传身份头。写请求沿用 `Idempotency-Key`，修改已有记录沿用 `If-Match`。不要直接读服务器数据库或复制内部函数。

|页面|可调用接口（省略上述前缀）|操作注意|
|---|---|---|
|兑换目录、我的券包|GET `/catalog`、`/grants`、`/grants/{record_id}`；POST `/exchanges`|提交目录的stock_id和template_sha256；先显示适用范围、门槛和到期时间|
|共创额度领取|POST `/service-credits`|传第10轮benefit_id和对应stock_id；额度已关联时返回原记录，不再多发|
|收银选券|POST `/grants/{record_id}/checkout`；POST `/holds/{record_id}/release`|先显示服务器返回的adjusted_quote；用户确认后沿用trade报价确认接口，加reward_selection：hold_id和adjusted_quote_sha256|
|订单取消|沿用 `/api/v1/trade/orders/{id}/cancellation`|已下单不能仅释放占用；须取消订单。已开始付款且结果未知先核对；开工后通过制作售后处理|
|面试/曝光报名|POST `/grants/{record_id}/bind`|本人person_id与avatar_id；面试另传cast，曝光传profile_id。机构不能替艺人确认本人面试授权|
|排期、确认、兑现|POST `/grants/{id}/deliveries`、`/deliveries/{id}/review`、`/grants/{id}/confirmation`、`/grants/{id}/finish`|先运营提出、另一人审核、本人确认；到期并有证据才能记已兑现；不把审核通过当完成|
|未兑现处理|POST `/grants/{id}/remedies`、`/remedies/{id}/review`|本人申请；独立运营依据事先规则选择拒绝、延期一次或返积分。不得重复补偿|
|曝光展示|GET `/exposures?city=...`|读有效公开名单，不从中奖记录直接展示；本人关闭公开资料后不再展示|
|运营库存|POST `/stock`、`/stock/{id}/review`；GET `/queue?kind=...`|真实证据、容量、有效期、价格、商品及批次先登记。审核员不可自审；队列按cursor/limit分页|
|审核证据|GET `/records/{id}/evidence/{asset_id}`|只读取本条记录关联的私有证据；持有审核权限且不得自审。正文为文件字节；无关文件/权限不足/内容损坏不放行|
|运营奖池|POST `/pools`、`/pools/{id}/review`、`/pools/{id}/retirement`|创建设规则和成本，规则审核与财务审核由不同人员执行；两类都批准才公开。修改规则须新建版本|
|抽奖和历史结果|GET `/pools`、`/pools/{id}`；POST `/draws`；GET `/draws`、`/draws/{id}`|提交pool_id、rules_sha256、count为1或10；同一个请求重试返回同样结果；请求未知先查记录或用原键重试，不能换键再抽|

操作权限是 `REDEMPTION_REVIEW`；奖池财务审核另需 `FINANCE_REVIEW`，两项批准不可同一人完成。图库、作品、授权、文件仍走原来的私有权限，不增加公开文件链接。

**必须处理的兼容变化**：订单新增 `REWARD_FUNDED`，显示“权益全额抵扣”，不要显示“已支付现金”；这类订单的应付为0、付款分期为空。旧订单返回和请求保持兼容。报价确认的reward_selection可选；普通不用券的订单仍按原方式操作。新建商品和人工报价仍必须为正价，不能提交0元绕过权益检查。前端解析新状态、0元和空分期后才能验收这类页面。

券的 `HELD` 是正在占用，`USED` 才是核销；面试的 `BOUND` 是绑定本人，`SCHEDULED` 是排期已审核，`CONFIRMED` 是本人确认，`FULFILLED` 是已登记实际兑现。读券时有效期也要显示；占用未下单可以释放，已下单走取消订单。过期不删除历史记录。

## 抽奖怎样保证结果可核对

单抽300晶钻、十连2700。前九次按整数权重抽取；若前九次没有面试卡/制作金/免单，第十次只在这些奖项里按相对权重抽取。因此不能把十连写成十次独立概率。公开返回同时列出单次概率、触发保底分支的概率、第十次概率、十次期望数量及成本。概率计算值用十进制文字保存（方便页面格式化百分比），整数weight才是服务器抽取依据。

权重总和必须10000，使用服务器安全随机数；不使用前端传中奖项。返回保存当时奖池和奖品承诺，停用/改版不改变历史。库存不足不把概率偷偷分摊给其他奖：任一非空奖库存不足本次抽数就暂停该次抽奖（十连至少预留每项10份），整批失败不扣分。此方式较保守但不会承诺无法兑现的奖；不是生产容量测试结论。

面试卡实际批次、光环条件和授权在使用时再次检查；终面直通卡不开放。无法兑现的面试卡按公布条款延期一次或返预定积分；暂未做自动降级换卡。曝光抽奖模板必须预先填写补救积分；未填写不能发布奖池。返积分优先冲掉待冲回晶钻，原兑换积分的到期时间不会借退款重置。

奖池配置可登记需求中权重，但**没有预置自动启用的正式活动**。本轮测试中的商品、价格、库存、开奖和积分全部是合成资料，不能直接发布给用户。真实概率、成本和活动条款须由业务、财务及法务核验；后台技术权限通过不代替这些实际审阅。
