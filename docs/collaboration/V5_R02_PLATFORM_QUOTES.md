# 平台报价到未付款订单：本批怎么用、还有什么没做

本侧已把第二轮的故事版本、平台报价、独立复核与未付款订单接到同一套交易接口。本批在 `core/v5-r02-story-quote` 本地继续，起点c0ec464；尚未推送、审阅、合入或启用。第二轮还剩新版分账、财务核对和相关付款条件，不能把这批交接当第二轮全部完成。

## 已确认的业务安排

用户2026-10-16确认：先由平台签约主体报价，操作人同时具备故事受理权限和该主体报价权限；外部制作机构暂不直接读取私人故事。当前报价权沿用该主体OWNER，不把普通员工或受理员自动变为报价负责人。没有配置平台组织，或缺少任一权限，都拒绝报价。

需求创建人可以是机构成员；这只表示提交制作意向。确认机构订单仍要求机构OWNER。机构OWNER能按既有权限查看机构交易，但不会因此获得其他成员的私人故事正文。报价和订单只新增故事ID、正式提交ID和内容校验值；没有把故事正文复制到交易列表。

## 用户实际会经历什么

1. 用户提交故事，运营受理；若需补充，走已经实现的补件流程。
2. 资料再次受理后，平台报价人选择当前正式故事版本，填入已经批准的商品规格和规则。这里没有默认真实价格、片长、权利或改稿次数。
3. 独立复核员检查报价。报价人及买卖双方成员不能给自己这笔报价作独立复核。
4. 买方有权负责人确认后，生成一笔原交易系统中的未付款订单；合同内容已固定，但没有签署，没有到账，也没有开工。
5. 用户从原需求找到报价和订单。重复确认不建第二单；同一需求的两张报价同时被确认，也只留一笔订单。

故事有待补充项、未重新受理、正式版本已更新时，旧报价不能通过复核或被确认。已形成订单的需求不能再用补件改写；包括订单后来取消的情况。取消后的修改/重签流程还没有新增，不能悄悄解锁历史承诺。

## 接口与兼容说明

统一版本为 `contracts/openapi.yaml` 的0.14.0-rc.1。原调用不带新字段时保持原行为；旧报价和旧订单没有被回写。需要生成客户端的伙伴应更新可选故事引用字段，以及分期节点枚举，不能把未知节点当“样片已验收”。

|动作|接口与变化|
|---|---|
|创建关联故事的报价|原POST /api/v1/trade/quotes新增可选customization_source，包含request_id、submission_id、content_sha256；其他报价字段仍按原接口|
|独立复核|原POST /api/v1/trade/records/{id}/reviews；故事报价批准时再次核对当前版本与补件状态|
|确认生成订单|原POST /api/v1/trade/quotes/{id}/acceptance；仍传quote_sha256、If-Match及Idempotency-Key，买方主体由X-Acting-Party指定|
|从故事找到报价及订单|新增GET /api/v1/customization-requests/{id}/quotes；支持limit、cursor；本人带原责任主体，运营不带主体头且须有受理岗位|

列表按报价ID升序分页；返回必要摘要，不返回价格明细或故事正文。详细报价沿用trade读取权限。source_is_current只表示故事版本一致，不能据此推导“已审核、可确认、已付款”。order_id有值表示存在关联订单，其付款状态须读取原订单。游标不能跨账号、主体或需求使用。

同一未知结果重试沿用原请求键、正文和版本。旧成功请求重放仍重新检查当前权限；412应重读后让用户核对，409应提示补件中、故事已变、报价状态不符或已有订单，不能自动用新键重建。

后台配置 `CUSTOMIZATION_MERCHANT_PARTY_ID` 为实际平台签约组织ID；默认空，禁止关联故事报价。这只是报价主体配置，不代表已实名、已获生产批准或付款服务可用。配置变更及真实账号授权由维护者按真实组织依据执行，本次没有设置真实值或开生产服务。

## 付款规则和本批边界

新定制报价按首款30%、再补至累计90%、尾款10%保存三步计划；各明细首款和累计90%向下取到分，差额放在尾款，确保总额严格相等。中间一步是新增CUSTOMIZATION_INTERIM_CONFIRMED，不能用SAMPLE_ACCEPTED冒充。旧订单原有分期保持。

这批新定制订单的实际收款统一拒绝并返回CUSTOMIZATION_PAYMENT_RULES_PENDING。新版分账与财务核对尚未完成，首次预览和90%补款先后也仍按既有待确认点处理；没有用一个假成功按钮替代。其他旧订单的付款入口保持原行为。正式规格、权利、改稿次数和新分账批准版本未齐备时，不向真实客户发出正式报价。

本批约束适用于带customization_source的故事报价。旧通用报价入口仍为原业务保留，尚未完成V5商品分型与强制分流；不能仅靠前端约定防止新商品走旧入口。因此正式开放前必须补商品版本标记及服务器路由限制，这也属于下一批，不把本批当全平台报价改造完成。

## 队友怎样重建合成资料

沿用第一轮的本机隔离MySQL准备，再执行：

```powershell
$env:JX_MYSQL_TEST_ENV_FILE=(Resolve-Path '.local/mysql/runtime/test-env.json').Path
node scripts/backend-check.cjs customization
node scripts/customization-sandbox.cjs
```

工具现在生成6个合成账号、3类模板、4份故事，以及一张待独立复核报价。access.json新增trade字段（平台组织、规格、规则和报价ID），requests.quote定位待报价故事。用merchant账号并带trade.merchant_party_id读报价，用reviewer不带主体头独立复核，再由buyer确认。token仅在本机.local临时文件，不要上传或贴入聊天。

只监听127.0.0.1；付款、短信和其他未列入白名单的接口仍关闭。停止方式仍为Ctrl+C、quit或stop文件，最多60分钟自动关闭。本批已实际走通9项本机接口联调并检查停止清理；这不等于App页面操作验收。
