# 第十二阶段交付：旧材料保留、数据恢复和上线检查

本阶段的目标是验证数据能否保留下来、发生故障后能否安全恢复，并把正式启用前的缺项列清楚。本侧负责服务器和数据工具；队友继续负责App/Vue、页面联调和实际审阅，未代其认领。

|---|---|---|
|旧材料保留|SQLite只读盘点；MySQL保存来源、原结构、原值并对账；重复导入和并发导入保护|真实旧库已迁移、旧订单已确认到账、历史账号和许可已获准启用|
|加密备份与恢复|备份加密、防篡改、防覆盖；同版空库恢复并检查所有行、微秒时间、大整数、生成列和已使用编号|私有文件本体已恢复、生产大数据量可承载、任意历史时间点可恢复|

|安全和有限并发|真实隔离MySQL与HTTP检查权限、伪造付款、重复请求和并发读取|独立安全审计已通过或已经具备正式并发容量承诺|

## 怎样检查与回退

在仓库根目录配置专用本机MySQL后运行 `node scripts/backend-check.cjs release`；全套为 `node scripts/backend-check.cjs all`。接口检查仍用 `scripts/validate_contract.py`，协作材料检查为 `python scripts/collaboration_check.py`。测试在随机jx_test库进行，不访问生产；自动检查也调用同一专项入口。

旧直接导入脚本已停用，避免执行由导出文件决定的SQL及关闭外键。迁移保留表不影响业务接口；若暂不启用维护工具，保留表及其历史证据即可，不能为了回退删旧记录。恢复库的隔离标记必须保留；旧服务代码不认识该标记，因此不得把更旧的服务程序连接恢复库，以免绕过保护。

当前备份是有大小上限的应用数据演练，不是完整生产灾备产品；详见操作说明中的范围。正式运行前仍缺实际脱敏旧库及映射、对象存储恢复、实际供应商核验、页面/真机验收、独立安全与目标规模压力测试、值班人员和发布批准。自动出款、长期数字人真实供应商网络接入也不能列作已正式可用。
