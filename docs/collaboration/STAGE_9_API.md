# 第九阶段：队友怎样接项目和发行页面

本侧负责服务器、权限、数据库和测试；队友负责App/Vue页面。本页与 `contracts/openapi.yaml` 0.9.0-rc.1 对应，22项新增接口已接服务器，不是只写的示例。测试中的用户、钱、作品、凭据均为虚构材料；不能因此显示真实业务已启用。

## 页面顺序与完成标准

|页面工作|服务器已有能力|队友要做什么、怎样验收|
|---|---|---|
|项目列表和选角|列出自己参与的项目；公开目录只给开放角色摘要|展示名额、固定价或报价、用途及期限；其他人的报名详情不可见|
|报名和邀请|报名、回应邀请、筛选、本人确认、拒绝和退出|把“报名”“获选”“确认入组”分开显示；发出邀请不能直接显示已入组|
|开工条件|核对阵容、6层权利、制作来源、角色费用、人工审核和各方确认|逐项显示缺少的条件；有条件未齐或授权失效时禁止继续，不显示成功|
|版本确认|每版保存权利、责任人及确认顺序；确认绑定准确内容|先展示完整约定再确认；前一人未确认时说明等待谁；换版后重新确认|
|发行材料与送审|关联已验收且付清的最终成片；审核、补件、拒绝、新申请关联旧申请|保留历史理由；每次重提是新记录，不能覆盖旧审批|
|外部渠道结果|登记外部凭据，由无利益关联审核员核实|内部通过显示“可送出”，上传凭据显示“待核实”；核实后才显示渠道实际结果|

当前未代队友认领新页面，也没有声称这些页面已联调。队友账号页在第11份申请已有新成果，原始记录见 `docs/tasks/records/UX-PR11-account-pages-20260929.md`。

## 调用入口

所有路径前缀 `/api/v1/projects`，均要求登录。下面路径中的编号使用服务器返回的UUID。写入附 `Idempotency-Key`；对已有记录操作附 `If-Match: "对象版本号"`。以个人或机构操作时附 `X-Acting-Party`；只允许该身份的当前负责人，退出/撤销成员身份后旧登录令牌不能继续操作。

|操作|路径（相对于前缀）|身份|
|---|---|---|
|新建项目／查看本人项目|POST／GET `/projects`|当前负责人；GET也可审核员|
|可报名项目及渠道摘要|GET `/catalogue`|已登录账号|
|添加角色|POST `/projects/{record_id}/roles`|项目负责人|
|邀请／报名|POST `/roles/{record_id}/invitations`、`applications`|负责人邀请／演员身份报名|
|回应邀请／选中、拒绝、确认、退出|POST `/candidates/{record_id}/responses`、`decisions`|对应当事人；只有项目负责人能筛选|
|新方案／开工／新版成片材料|POST `/projects/{record_id}/plans`、`start`、`editions`|项目负责人|
|版本确认／查看确认进度|POST／GET `/records/{record_id}/confirmations`|指定确认人／获准查看的人|
|检查开工条件／取消项目|GET `/projects/{record_id}/readiness`、POST `/projects/{record_id}/cancellation`|获准查看的人／项目负责人|
|渠道档案|POST `/channels`|有项目审核权限的资料登记人，以本人身份提交|
|独立复核|POST `/records/{record_id}/reviews`|有 `PROJECT_REVIEW` 权限、且不是项目参与方的审核员；不带操作身份头|
|发行申请或重提|POST `/projects/{record_id}/releases`|项目负责人|
|外部结果凭据|POST `/releases/{record_id}/external-events`|项目负责人；不会自动改变发行结果|
|详情／项目内记录|GET `/records/{record_id}`、`/projects/{project_id}/records?kind=...`|当前有权查看者；无操作身份头时必须有审核权限|
|读取私有证明|GET `/records/{record_id}/evidence/{asset_id}`|项目负责人或获授权审核员；普通报名人、其他确认人不可下载所有原始证明|

详情返回 `kind/current_status/object_version/content_sha256/data`。列表支持 `cursor/limit`，项目内列表按权限过滤，可能返回空页但仍有下一页；继续使用 `next_cursor`。公开目录最多100条摘要，不返回原始文件或报名人资料。完整请求字段、类型和成功返回以接口文件为准，不要求前端读取数据库。

## 具体规则和错误提示

- 项目用途明确选 `PUBLIC_SHARE`（公开分享）或 `RELEASE`（发行），地域、语言和有效期必须填写。独家不等于允许发行；私人项目升级使用新的授权和本项目方案，不覆盖原订单。
- 角色用固定价或报名报价。金额单位为分；0元只有明确约定时才提交0，不能擅自把未知价格填0。高于0的角色需要独立已付订单明细（`OTHER`），买卖方与金额对应；制作费或剧本许可费不能再充当角色费，同一笔明细不能分配给另一角色。
- 6层权利分别是脸声、原始作品、剧本、音乐、改编、最终成片。材料先通过既有供给材料上传接口存为私有证明，再引用材料编号。必须人工复核内容，程序不代替版权律师。
- 确认人限定为项目发起方、角色所属方、权利持有人、脸声本人及制作方，不允许无关方加入否决环节。职责与前置确认人明确登记；循环等待会被拒绝。确认是对具体内容的同意，不代表平台已完成真实电子签。
- 原制作脸声逐一检查；允许角色提供同一人的新公开授权，原私人授权不被改写。原制作被撤回、暂停、退款或原许可开发资格已失效时仍暂停后续操作，须人工复核并通过有效的新制作/授权流程恢复，不允许直接改历史快照。
- 新方案、新材料版本不继承旧确认。`CHANGES_REQUESTED/REJECTED` 留存旧记录，再创建新版本；取消不表示已退款或已通知外部下架。
- `AVAILABLE` 只表示当前开工条件齐全，不等于成片可下载、已送审、外部已发行；`BLOCKED` 同时返回具体原因。
- 外部结果按“可送出→核实已提交→补件/拒绝/已发行→核实已撤下”登记。没有外部接口自动提交；凭据来源标为人工核验。补件/拒绝后重新申请并关联前一份。撤回授权后禁止新使用，已有外部成片是否已下架仍须凭据核实。
- `412` 请重新读取版本；`409` 根据原因处理缺授权、缺付款、名额已满、前置确认、旧版本、重复申请等，不应盲目重试。`403/404` 不得退回模拟数据。`503` 表示服务未可用，不能显示已成功。
