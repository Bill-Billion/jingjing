## 用户现在要走哪条路

**买家：** 找可约艺人 → 选择明确的真人/数字人、时间地点和用途 → 等待安全核查 → 确认包含交通的一口价 → 实际付款核实 → 等艺人接受 → 在这笔订单内沟通 → 查看审核通过的取样 → 确认完成，或提出争议。

**艺人：** 本人或明确受托的MCN发布试镜方案 → 选择是否公开接单、是否公开价格 → 独立审核 → 接受或拒绝已付款邀约 → 记录出发/到场 → 交取样及授权 → 等审核和买家确认。机构操作必须绑定具体真人及数字人，委托被撤回立即失权。

**客服：** 核查真实用途、正规场地与成年资格 → 按请求加入订单沟通 → 处理改期与争议 → 依据双方陈述和证据核定退付 → 原交易退款审核和支付渠道处理。不能直接把“申请退款”改成“钱已到账”。

## 队友怎样接页面

无需重新猜数据库字段。只使用 [统一接口](../../contracts/openapi.yaml)，版本 `0.20.0-rc.1`；本轮31个操作。新请求使用已有登录令牌、`X-Acting-Party`、`Idempotency-Key`，更新已有记录带 `If-Match`。运营操作不带机构身份头；服务端核对独立审核岗位。428为缺版本，412为版本过旧，应重新读取后让用户确认，不能盲重试。

所有地址以下均省略 `/api/v1`。

|页面动作|接口|注意|
|---|---|---|
|可约艺人列表|GET /auditions/catalog|不带操作主体；支持城市和分页；价格可能不公开|
|已接受邀约的方案|GET /auditions/invitation-offers?invitation_id=…|带买家主体；撤回/无关邀约不可用|
|艺人发布/审核/开关|POST /auditions/offers；/offers/{id}/reviews；/visibility|已有授权不能自动扩权；需MANAGE_AUDITIONS委托|
|发起预约、安全核查|POST /auditions/bookings；/bookings/{id}/reviews|绑定offer_id和offer_sha256；安全检查不是自动词库审核替代人工|
|订单确认|POST /auditions/checkout|传booking_id和booking_sha256；返回既有trade订单，状态未付款|
|付款、退款|沿用trade接口及已配置渠道|本轮演练不开放真实调用；付款按钮显示未启用|
|接拒/出发/到场|POST /auditions/bookings/{id}/decision、/travel|先核实付款；重复操作不重复执行；接受时锁定艺人时段|
|改期|…/reschedule、/reschedule-response、/reschedule-review|发起方、另一方、安全复核三步；不能单方改已约时间地点|
|交付与审核|…/delivery、/delivery-review|审核通过才能给买家读文件；失败返回具体原因|
|取样、收讫与确认|GET …/materials/{asset_id}；POST …/receipt、/confirm|全部文件实际读取后收讫才开始约定计时；不是上传时自动计时；明确确认可主动完成|
|取消/争议处理|…/cancel、/resolution|客服记录双方陈述在reason，证据传evidence_asset_ids；不得代替真实支付退款|
|订单列表/详情|GET /auditions/records?kind=BOOKING；/records/{id}|每页继续取next_cursor，不因空页就断言没有记录；尊重服务端权限|
|沟通和已读|GET/POST …/messages；POST …/messages/read|消息仅能引用本单取样或订单；不能传任意外链/第三人文件|
|联系卡和客服|POST …/contact；GET …/contacts；POST …/support|联系另给同意，可撤回；客服必须有岗位并明确加入|
|行程与归档|GET …/itinerary；POST …/baseplate|分享由用户主动操作；归档须艺人本人单独授权|

主要状态：SAFETY_REVIEW 等安全核查；READY_TO_PAY 可确认订单；AWAITING_PAYMENT 未付款；AWAITING_ACCEPTANCE 等艺人接单；ACCEPTED 已接单；DEPARTED/ARRIVED 已出发/到场；DELIVERY_REVIEW 等取样审核；DELIVERED 可查看取样；DISPUTED 争议暂停；REFUND_REQUIRED 等退款处理；REFUNDED/PARTIAL_REFUND_SETTLED 仅在渠道退款核实后出现；FULFILLED 履约完成。页面不能自行猜测或合并这些状态。

先前通用交易评论对试镜订单明确返回 `USE_AUDITION_CONVERSATION`，防止绕过接单和付款限制。其他订单保持原有流程。消息列表里的“is_read”表示当前读取账号已读，不表示另一方已读。
