## 新接口清单

个人申请接口不传机构身份。所有写操作带Idempotency-Key；隐私执行方案带If-Match，拟方案用申请版本，复核及执行用方案版本。

- GET /api/v1/privacy/requests/{request_id}/executions：本人的具体处理列表。
- POST 同地址：拟定PROFILE_CORRECTION、FILE_ERASURE或ACCOUNT_CLOSURE；提供target_id、policy_rule_id、details.reason，改名另提供display_name。
- POST .../executions/{execution_id}/execute：本人确认已复核方案，confirmed=true。
- 上述三个地址在 /privacy/operations/requests 下另提供工作人员入口；仅投诉限制/解除在工作人员入口执行，不能代本人改名或注销。
- POST /privacy/operations/requests/{request_id}/executions/{execution_id}/review：独立复核，提供方案摘要、decision、reason、scope_verified、retention_verified。
- GET /privacy/requests/{request_id}/data?category=PROFILE或ARTIST_MATERIALS：分页读取本次支持的副本范围。
- POST /api/v1/media/tasks：带机构/个人操作身份。task_kind为MARK_VIDEO或MODERATE_FILE；source_kind为SUPPLY_ASSET或PRODUCTION_VERSION；传source_id、variant（preview/final）、policy_rule_id。
- GET /api/v1/media/tasks/{task_id}：本人查询，不传机构身份。
- GET /api/v1/media/operations/tasks/{task_id}：具备相应内容审核权限的工作人员查看。
- POST .../operations/tasks/{task_id}/review：仅复核已经返回REVIEW的机审结果；传decision、reason及result_sha256。原机审结论保留。未返回结果、服务未启用、高风险拒绝均不能用此入口伪装通过。

完整字段及错误返回以contracts/openapi.yaml为准；12项接口不是12个已完成页面。素材和制作仍走原有人工业务审核，机审通过不自动发布。

## 必须显示清楚的边界

- 注销是停止该账号使用，不代表全部数据库记录、所有供应商副本和备份已删除。
- 自动文件删除当前仅支持本人个人主体的AVATAR_MATERIAL。合同证据、多方作品、私人故事历史正文等不能套这个接口批量擦除，仍须分类依据和具体处理设计。
- 有尚未结清的订单、退款、余额或唯一机构负责人交接时，注销会拒绝。当前不提供强制忽略这些事项的按钮。
- 媒体规则须明确启用。没有已审核的media.processing规则时，原人工审核路径保持原状态，不能对外宣称已全面机审或全面强制标识。
- 阿里云审核适配器是可选候选，默认关闭，没有替甲方开通产品、付费或代替火山做正式选型。音频独立文件、超过600字的文本和其他不支持格式明确拒绝，不能把视频抽帧或文本截断当完整审核。
- 可见AI文字和通用文件元数据已实现；正式适用范围、文案及法定元数据格式仍需审核，不构成合规结论。
- 暂停账号仍可只读查看自身停用状态；其他业务请求拒绝。已注销账号连该只读例外也不能使用。

# 个人信息申请：页面怎么接、用户会看到什么

本批在worktrees/privacy、core/v5-privacy-protection。起点65f8938，沿用0147—0150数据库迁移顺序；这属于未合入的必要依赖，完整分支包含它们。上一批样片与合同功能在PR25单独审阅，不需等待本批页面。

## 用户怎样操作

1. 在“我的—隐私与个人信息”选择查询、复制、更正、删除、注销或投诉，说明具体资料范围。此入口按登录账号访问，不随机构身份切换，不传X-Acting-Party。
2. 提交后显示“已收到，正在等待处理”，展示目标答复日期。未配置审核后的节假日日历时，明确标“按普通工作日估算，需人工核对”，不能显示成已承诺的法定截止日。
3. 工作人员处理并拟好答复，另一位有权限的人员检查材料、第三方信息是否已脱敏及剩余事项。未经复核的草稿不向申请人开放。
4. 用户查看审核后答复，下载属于这份申请的私有材料，查看暂时保留的具体资料、依据与复查日期。不能用“有订单”一概保留所有资料。
5. 用户可提出异议；旧答复与记录保留，不被新回复覆盖。

## 偏好与处理结果的边界

个性化和营销默认关闭，休息提醒由页面按保存的分钟数执行（0表示关闭提醒）。当前榜单本身是不按个人画像排序；本批没有启用营销推送。保存设置不等于新建推荐引擎或已验证系统推送退订。

RESPONDED只表示已有人工核验的答复，不能显示“所有操作完成”。FOLLOW_UP表示仍有待处理事项或需复查的保留记录。DELETION_REQUESTED、ACCOUNT_CLOSURE_REQUESTED始终带EXECUTION_PENDING和待办，不会自动删文件、删账号或伪造供应商回执。实际执行、后续回执与撤回效果仍须按对应业务核验。

正式保留说明必须引用已生效的 `privacy.retention` 规则版本，内容包含 `terms.privacy_retention.categories`；每项声明scope、basis和max_review_days。它只是明确已审核依据和复查上限，不由程序自动认定法律允许。用户确认尚缺正式依据，登记EXT-PRIVACY-20261020，不能用合成测试配置上生产。

## 怎样验收

从仓库根目录运行 `node scripts/backend-check.cjs privacy`，使用指定的本机隔离MySQL。专项覆盖本人/他人、机构头拒绝、重复提交、独立复核、草稿不泄露、附件私有、旧答复保留、删除待处理、分类留存、并发设置及审计失败回滚。真实材料与实际删除、页面、真机和正式启用另外验收。

尚需本侧继续：实际删除/注销处理与下游结果衔接、投诉对具体业务限制及解除的核验、素材机审和真实文件标识。需队友：页面和提醒实际运行。需甲方：真实联系人、投诉渠道、分类保留/删除依据。不能把三类待办混成“全部等甲方”。

## 结果通知兼容补充

审核通过的答复在同一笔数据库事务内进入既有业务通知。通知domain新增PRIVACY，页面点击后打开对应个人申请详情；只发申请人的个人身份收件箱，不发机构或其他成员。即使关闭营销，也保留这种业务答复通知。请扩展消息类型处理，不能因遇到新增类型导致页面报错。通知正文不带申请详情或附件内容，仍需本人登录后查询。

如果通知保存失败，答复与正式历史一起回滚，不会在后台显示已答复、用户却没有通知。原有通知已读和权限机制继续使用。


## 本轮补充：本人撤回授权、删除具体模型

接口候选更新至0.28.0-rc.1；原13个接口不变，新增4个本人接口。现有页面无需改服务器内部调用；队友新增以下操作与进度显示。当前在本地自验，上传情况以CORE_CURRENT为准，尚未确认队友接手。

1. 用户先提交删除或注销申请，范围包含数字人、人物素材或全部资料。这一步仍只表示提交申请。
2. 进入申请详情，用 `GET /requests/{request_id}/model-assets` 查看与本人授权关联、制作模块已经登记的长期模型。它不是完整个人资料清单；空列表不能写成“你没有任何资料”。列表支持cursor/limit分页。
3. 用户明确确认撤回哪份授权，再调用 `POST /requests/{request_id}/consent-withdrawals`，提交consent_id、consent_version、reason，带申请当前If-Match与Idempotency-Key。说明撤回会影响使用同一授权的其他业务，不只影响当前一份模型；撤回不等于历史材料已经物理删除。操作失败时整笔回滚。
4. 重新读取模型和申请的版本，再调用 `POST /requests/{request_id}/model-deletions`，提交asset_id、asset_version，带申请当前If-Match与Idempotency-Key。必须先撤回对应授权。当前删除队列不要求先付清订单，不改旧合同和钱账。
5. 用 `GET /requests/{request_id}/actions` 查询实际进展，支持分页。它会读取后台当前结果，不能只拿第一次提交的返回值一直显示成功。

|返回状态|页面应显示|下一步由谁处理|
|---|---|---|
|CONSENT_WITHDRAWN|指定授权已撤回，资料清理仍需核对|本侧和运营继续核对关联资料；不显示“全部删除”|
|QUEUED|删除任务已登记，等待处理|后台任务按供应商条件执行|
|WAITING_PROVIDER|正在处理，尚未确认删除|页面刷新查询，不重新提交新任务|
|NEEDS_ATTENTION|暂未完成，需要工作人员处理|运营检查已有制作任务失败原因及配置，使用原有受权限限制的任务重试入口；不能让用户反复点击制造新任务|
|MODEL_DELETED|该模型已确认删除|仅表示这一项结果，不表示账号、原始素材、备份或其他模型已删除|

这些接口全部按登录本人访问，不传X-Acting-Party；机构成员、平台运营也不能代用户执行。运营仍可使用原有受理、答复和独立复核接口。模型列表不返回供应商内部模型编号、其他人的合同或项目文档。

request_completion目前固定NOT_CONFIRMED，代表整份申请未获完整执行结论。新执行操作会使待审核答复失去当前状态，工作人员必须按新版本重新处理，旧正式答复仍保留。供应商结果改变时不会伪造申请整体结案；当前由页面刷新动作进度，未新增向本人推送“全部完成”的通知。

执行与配置：使用已有供应商任务和原模型保存的供应商、环境及配置版本。配置未开通、换主体或回执未确认均不得显示删除成功；失败重试沿用原任务核对，不绕过权限另造任务。本次没有调用真实供应商。

下一步仍属我方：进行中创建任务的清理、源文件及各类记录的处理范围、账号注销、投诉处置、素材机审与真实标识。需要甲方的正式依据仍只有对应外部条件清单中的内容，不能把上述代码工作都转成等待甲方。

## 制作途中撤回：本轮补充的后台行为

创建请求已经发给供应商后撤回授权，后台现在可以按原任务查询迟到的结果，不能重新发起创建。返回的模型登记为DELETE_REQUIRED，即“需要删除”，会进入原有本人模型列表；本人可继续通过已有删除操作处理。因此本轮没有新增路径、字段、数据库迁移或页面必须跟随修改的调用格式，接口仍是0.28.0-rc.1。

页面特别注意：制作任务SUCCEEDED只表示这次供应商结果已经查清。模型是否可用还须看模型状态；DELETE_REQUIRED不能显示“数字人已可用”。删除须等独立删除任务确认，整份隐私申请仍是NOT_CONFIRMED。

尚未发出的创建请求会被拦截；既有渲染仍检查完整授权。供应商配置换了、查询失败或结果不明时，保留待人工处理，不自动换账号、不重复制作。旧版本已经阻塞的任务，需要有权限的工作人员通过原重试入口核对；本轮不会批量重试历史任务。

本轮只补“明确撤回授权后，旧创建任务结果如何收尾”。进行中的任务尚未增加本人专用列表，空模型列表依然不能证明无在途任务；到期、账号关闭等其他停用原因的跨业务清理、源文件/备份、投诉、账号注销仍在剩余清单。没有调用真实供应商，也不保证供应商能瞬间取消已发出的请求。

## 本轮新增：本人查看正在创建的模型

当前候选接口为0.29.0-rc.1，原17项隐私接口不变，现共18项，新增一个只读入口：

`GET /api/v1/privacy/requests/{request_id}/model-creations`

仅由申请本人读取，不传机构身份头；申请须为删除或注销，范围包含数字人、人物资料或全部资料。支持cursor/limit分页。它返回制作模块中与本人授权相关的创建任务，包含已有结果的任务；不返回供应商任务号、模型内部编号、其他人的项目或合同。

|status|页面说明|后续操作|
|---|---|---|
|QUEUED|已登记，尚未取得制作结果|可按返回的consent_id和consent_version进入原有撤回确认|
|WAITING_PROVIDER|正在等待确认制作结果|刷新查询；撤回不会保证供应商立即取消已发出的请求|
|NEEDS_ATTENTION|暂未查清，需要工作人员核对|运营使用原有受权限限制的重试入口，不让用户反复新建模型|
