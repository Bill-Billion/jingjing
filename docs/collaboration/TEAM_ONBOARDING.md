# 我们各自做什么，现在怎么开工

**本侧做服务器和数据，队友做App和网页。两边可以同时做，不需要等一边把整个系统做完。**

这里的“本侧”指账号chengcongcong222使用的这边Codex；“队友”指负责App和网页的开发者及其Codex。仓库拥有者不自动等于任务执行者。目前还没有队友登记接手任务的记录，下面是已有方案中的建议分工。

|谁负责|具体做什么|怎样配合|
|---|---|---|
|本侧：服务器和数据|保存账号、作品、授权、订单和账目；判断谁能看或改什么；处理付款、制作、退款；连接外部服务|告诉队友每个页面能拿到什么数据、能提交什么操作，失败时怎样提示|
|队友：App和网页|用户看到的页面、按钮、五个主入口；运营和合作方网页；手机安装包和网页打包|按双方约定把数据展示出来，把用户操作交给服务器；缺少接口时列出页面具体需要什么|

**本侧已把上传代码后的自动检查做出来，并实际跑通。** 它会在所需基础代码合入后加入共同版本，查看方法见[自动检查说明](AUTOMATIC_CHECKS.md)。本轮又写好外部服务检查和私密文件保护基础，并通过本机和GitHub测试；真实服务未启用。本轮已修第一批旧付款假成功、实名自动批准和付款查询归属问题，并通过本机和GitHub测试。第二批又修好样片缺字段、加密配置、水印/存证假成功，并限制未授权阅稿，本机和GitHub检查均通过，已上传同一份第7份申请。第三批已阻止MCN未经确认的绑定和相关访问，下一步做个人/机构权限及本人接受邀请，再完善合同留存。

**队友现在可以先做这几件事：**

1. 在自己的电脑上运行现有App，记录哪些地方能运行、哪些地方报错，能不能生成测试安装包。
2. 整理现有页面，说明分别放在“首页／入戏／培育／成角／我的”哪个入口，哪些页面缺失。已有导航能用就复用。
3. 搭起运营人员和合作方共用的网页工程，先让它能运行和打包，再做登录及基础页面。

这三件事可以先开始。真正把页面接上服务器时，双方要先核对数据格式。测试阶段可以用明确标注的假数据搭页面，但不能把它显示成真实付款、实名或制作成功。

**双方什么时候需要互相检查？**

例如：服务器改了“订单金额怎么传给App”，队友需要检查页面是否还能正确使用；队友发现某页需要新增数据，应提出具体页面需求，由本侧修改服务器接口。数据库结构、付款、权限、作品使用许可和结算等重要规则，也需要另一方检查后才加入共同版本。普通按钮样式或自己负责的内部代码，不必每次找用户批准。

服务器已经有三份改动等检查：[双方交换数据的格式](https://github.com/Bill-Billion/jingjing/pull/1)、[MySQL数据库基础](https://github.com/Bill-Billion/jingjing/pull/2)、[耗时任务中断后继续处理](https://github.com/Bill-Billion/jingjing/pull/3)。可以让队友的Codex先检查，再把发现的问题用中文说明；不能只盖“通过”而不实际检查。第三份依赖第二份先合入。
