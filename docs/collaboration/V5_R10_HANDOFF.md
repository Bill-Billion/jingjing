# 第10轮交接：多人一起定制，各人只提交和领取自己的内容

2026-10-20。总计划12轮，本轮是第10轮。本侧负责服务器、数据库和主要测试；队友负责App与运营网页，尚未代其认领。完整分支 `core/v5-r10-cocreation`，目录 `worktrees/full-flow`。实际上传和检查结果统一见[当前进度](../status/CORE_CURRENT.md)。本轮依赖第3轮本人授权、第4轮报价付款和制作、第9轮推荐规则；这些依赖尚未全部进入共同版本，因此提供完整分支，不让队友自行拼接提交。

## 用户怎样办成这件事

|步骤|谁来做|做到什么才进入下一步|
|---|---|---|
|发起共创|发起人提交故事，再选择已经审核的活动规则，创建房间|确定制作方、用途、地域、截止时间；平台报价前创建房间，使规则进入报价和合同|
|邀请参与|发起人邀请指定的真人；被邀请人登录本人账号|每人选自己的形象、提交本人材料、阅读并同意本次参与条款；机构和发起人不能替别人同意|
|支付整包费用|发起人接受报价，按订单支付首款|参加人数与付款分开显示；不为每个参与者凭空创建收费订单|
|核定是否成团|截止后由发起人或有权运营核定|系统检查首款、真人身份、本人材料和授权；有效人数不少于10才进入制作；9人及以下申请延期或取消退款|
|制作和确认|受派制作人按权限读取材料；发起人验收整包成果|沿用首款30%、正式预览确认后补至90%、成片确认后付清尾款；片段不能提前下载|
|领取成果|发起人按原订单领取主片；参与者领取单独审核的本人片段|不能查看他人私人故事、素材或主片；片段必须有独立文件、内容审核、授权标识和AI标识|
|中途退出|参与者本人退出；必要时运营处理|截止前不再计入人数；截止后暂停使用相关素材，恢复须独立审核并重新制作和验收，不能继续下载旧版|

用户已确认：满20名有效参与者，给发起人**一份不可提现的服务额度**；具体服务、额度、有效期由审核后的活动规则决定。不退整包款，不等于全员免费，不与发起人同一订单推荐佣金叠加。20不是人数上限。同一真人有多个形象仍只计一人；当前技术容量为每房间21—100人、每人最多4个形象，由活动配置确定，不把合成测试的40人和测试金额当正式规则。

本轮提供额度发放、查询、取消撤回和历史依据；实际选服务、锁定和核销在第11轮衔接。页面现在可以显示“已取得服务额度，使用入口待开放”，不能显示成已经消费或提现到账。

## 谁可以看到什么

|身份|可以看/做|不能看/做|
|---|---|---|
|发起人|房间进度、有效人数、参与者是否缺条件、主订单、整包验收、延期或取消申请|其他人的私人故事和原始素材；替参与者授权；替运营批准退款|
|参与者本人|自己的邀请、资料、授权确认、退出记录、单独审核的本人片段|其他参与者的私人资料和片段、整包主片、发起人的订单详情|
|实际受派制作人|已成团且仍有有效授权的参与者资料，按页读取、受控下载|尚未分派的房间；已退出者素材；暂停或取消后继续取材|
|运营人员|按专门权限审核规则、处理房间申请、审核片段|以普通机构成员身份取得审核权；自己提出自己批准；靠修改人数绕过付款和授权|

## 队友如何接接口

统一接口文件 `contracts/openapi.yaml`，版本 `0.23.0-rc.1`。本轮新增26个操作，全库379个。下表统一省略 `/api/v1/cocreation` 前缀。登录沿用原方式；个人/机构操作传 `X-Acting-Party`。规则与审核操作不传身份头，使用运营权限 `COCREATION_REVIEW`；恢复既有制作还需要 `PRODUCTION_REVIEW`。可同时由发起人或运营执行的读取和核定允许不传身份头，此时必须有运营权限。

写操作沿用 `Idempotency-Key`；修改既有记录传 `If-Match: "当前版本号"`。请求失败不自动换键重新建订单。响应仍为 `meta + data`，通用记录详情在 `data.data`，房间概况直接在 `data`；不要从数据库字段推导接口。测试例子见[实际合成返回](../testing/evidence/v5-r10/FRONTEND_FIXTURES.json)，其中编号只属于当次临时测试库。

|事情|调用|页面注意事项|
|---|---|---|
|活动规则|GET/POST `/rules`；POST `/rules/{record_id}/review`|先建规则、由另一人审核；停用只阻止新房间，旧订单保留快照|
|创建/查房间|POST/GET `/rooms`；GET `/rooms/{record_id}`|创建传故事、已审规则、制作方、标题、截止时间、用途、地域；列表按cursor/limit分页|
|邀请/查看邀请|POST `/rooms/{record_id}/invitations`；GET `/invitations`|邀请的是person_id，不是任意昵称或形象数量；受邀不等于已同意|
|参加与个人资料|POST `/rooms/{record_id}/members`；GET `/members`；GET/POST `/members/{record_id}`|每人提交person_id（首次）、cast、private_story、material_asset_ids、sharing_allowed、participation_sha256、agreed:true；材料须本人已上传且有效|
|个人退出|POST `/members/{record_id}/withdraw`|填写原因并再次确认；退出后旧片段不可继续取回|
|核定人数|POST `/rooms/{record_id}/close`|截止前禁止；截止后检查真实条件并固定结果；反复点击不重复发额度|
|延期、取消、恢复|POST/GET `/rooms/{record_id}/cases`；POST `/cases/{record_id}/review`|kind为EXTEND/RESUME/CANCEL；延期传新截止日，其余new_deadline明确传null；审核记录版本与房间版本都校验|
|核对退款结果|POST `/rooms/{record_id}/sync`|审批取消不等于已退款；只有原付款系统确认退款后才显示已退款|
|制作方取材|GET `/rooms/{record_id}/materials`；GET `/members/{record_id}/assets/{asset_id}`|制作方分页读取；文件通过受控二进制下载，不返回可公开访问的地址|
|个人片段|POST `/rooms/{record_id}/snippets`；POST `/snippets/{record_id}/review`；GET `/snippets`；GET `/snippets/{record_id}/file`|制作方传member_id/file_id/final_version_id/note；独立审核确认四项检查；收款、成片验收和有效授权全部满足才下载|
|额度与运营待办|GET `/benefits`；GET `/queue?kind=RULE/ROOM/CASE/SNIPPET`|服务额度不进入现金余额；运营列表可分页；不要把待审核片段当可用成果|

房间返回 `joined_count` 为已参加人数，`eligible_count` 为当前满足全部条件的人数，不能混用。`cutoff` 是已锁定的成团依据，退出不会改写历史人数；继续制作使用经审核保留的人员。截止后不再接收新报名或改资料。本轮核定入口由发起人或运营主动调用，尚无自动定时关房任务；同时记录截止时间和实际核验时间，核验时已失效的授权不会算入，不能把它当精确回溯任意过去时刻的权利凭据。

`OPEN` 显示“招募中”，`UNFORMED` 显示“人数不足，待延期或退款”，`READY` 显示“成团条件已核定”，`PAUSED` 显示“暂停，待处理退出或申请”，`REFUND_REQUIRED` 显示“退款待办理”，`REFUNDED` 才是实际退款确认。`READY` 不等于已经开始制作；还要通过原有制作审核和开工接口。`allowed_actions` 为身份对应的操作类别，按钮是否可执行还需结合房间状态、截止时间和服务器错误，不可据其显示假成功。

错误处理：`COCREATION_INVITATION_REQUIRED` 提示先取得本人邀请；`COCREATION_PARTICIPATION_REQUIRED` 提示重新核对本次授权；`COCREATION_QUOTE_CHANGED` 提示平台重新出具含房间规则的报价；`COCREATION_NOT_READY` 提示人数/首款/授权未齐；`USE_CUSTOMIZATION_CASE_REVIEW` 跳至原制作售后申请；`COCREATION_SNIPPET_NOT_READY` 提示片段尚不满足领取条件。版本冲突先刷新记录，不能覆盖另一方刚做的处理。

## 与旧订单及制作接口的关系

房间必须在报价之前创建；旧报价生成后才加房间，旧报价确认会被拦截。报价自动保存房间规则和参与条款校验值，订单/合同沿用该快照，不新增另一套付款账。房间与故事、主订单、制作项目分别唯一关联。发起人是订单买家，既有推荐规则排除自购及同一实际所有人，不能给他自己的整包消费再记推荐佣金；本轮没有虚构参与者独立消费来发佣。

创建共创制作项目仍用原 `/production/projects`：`consent_ids: []`，`fulfillment: {uses_identifiable_people:true, cast:[]}`；服务器从订单绑定的房间逐人读取已锁定授权，空数组不代表无人出镜。普通定制仍沿用原cast规则和20项限制；不能让普通订单借此跳过授权。每人授权单独保存，已验证21真人、22形象，避免把所有人塞进旧20项数组或一条超长数据记录。

未建立制作项目时取消，由共创独立审核；已经有项目时共创取消申请关联原制作售后申请，由既有 `/production/projects/{project_id}/case-resolution` 审核金额，再调用房间sync。若该售后决定继续制作，sync结束房间申请后仍保持暂停，发起人再申请RESUME并独立审核。退出后恢复清除旧版当前/已验收指针，必须重新交付；旧合同和历史验收证据保留。
