# 普通通告修订：已确认缺口与下一批边界

本轮只做只读核对，以下不是已开发功能。来源：原ACC-DEL-10.04“截止、下架、修订有版本；历史申请可查询。；关键条件改动需告知已有申请人。”普通资格按PM01 W03已审新规则，旧单按快照。

已查：src/http/notices-routes.js登记创建、审核、下架、投稿、意向和客服报价，未有通告修订接口；src/modules/notices/repository.js未有修订方法。notice_records.object_version用于并发控制，notice_audit只记录版本与摘要，不能自动视为可读取的历史内容版本。本轮新NOTICE_WITHDRAWN通知仅代表下架分支。

下一批实施建议（工程方案，不冒充甲方原话）：
1. 先设计并保存原发布内容、当前修订和原申请所依据的快照；历史数据缺快照时明确缺失，不能用今天的通告正文补造过去。
2. 拟改内容须重新校验发布身份、官方权限、机构范围、时段及独立审核；审核前不得改公开内容，拒绝/撤回不能损坏原发布版本。
3. 生效后才向原申请人发布最小必要通知；已审/待审申请受众与当前权限保持，幂等、并发和失败回滚必须同案检查。
4. 关键条件变化后，旧申请/未接受报价能否继续需显式兼容或重新确认，不能无声套用新条件；已付订单和合同快照不改。
5. 新增HTTP必须更新统一接口合同、示例与版本；只提供后端能力，前端接续仍暂停。完成标准为正常修订、独审拒绝、越权/失权、重复提交、旧版本冲突及原申请/报价边界的实际接口证据。

此项是后端可独立推进的剩余工作，不归因于等待Bill-Billion或甲方；详细设计时如发现重大业务歧义及时反馈，已有规则先遵循原合同快照。
