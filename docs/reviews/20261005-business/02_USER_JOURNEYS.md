# 按每类用户重组办理流程：建议稿

这份是用来审阅并指导修改的方案，不是当前App已经如此，也不是新的业务批准。保留已确认五入口、原图册视觉基础和后端权限；按[决定清单](03_DECISIONS_FOR_REVIEW.md)确认业务变化后再施工。

## App里先让用户找到自己要办的事

|用户|默认工作页突出什么|不应堆在首屏的事|网页如何配合|
|---|---|---|---|
|个人或机构客户|开始定制、继续我的订单、待我确认的报价/样片、我的成片|供给审核、平台规则编号、分账配置、独立付款复核|需要人工协助时有对应业务编号和说明，用户不用抄编号串接流程|
|艺人/数字人权利人|我的形象及可用状态、待确认合作、待确认角色、参与项目与本人收入|他人的制作派工、整个平台财务|复杂资料或未开放服务明确在哪办理；不能把授权文档上传当真实身份核验成功|
|MCN经理|合作艺人列表、每人的形象/授权/待办、机构订单、合作事项和机构份额|个人消费者自己的私密订单、无关供给审核|批量管理和复杂合同证据可在机构网页；不能因经理登录自动代艺人确认|
|作者/版权方|我的作品、待补权利材料、审核结果、许可销售与应得收入|面向客户的全部制作步骤、无权限的审核动作|许可商品复杂范围和证据管理在供给工作台，App给清楚交接|
|制作公司/工作人员|分给我的任务、客户反馈、待交版本、明确交付人|平台总账、无关作者商品及客户私密资料|保留网页上传、指派和专业制作处理，App提供明确的通知及任务入口|
|平台审核/财务|专用网页待办与独立复核|不塞到普通App“我的”功能大全|按已授予权限办理，保持职责分离|

一个人或公司可能承担多个业务身份：作者也可能买片，MCN也可能作为客户采购。页面按“当前代表谁、获准做什么、参与哪些业务、这次想做什么”组合，不要求拆多个登录账号，也不通过界面开关发放权限。没有对应能力时，可以显示申请或解释入口；不能一味隐藏到用户不知道如何入驻。

五入口建议这样承载：

|保留入口|用户能理解的主要任务|注意|
|---|---|---|
|首页|我要定制／我要找商业服务／我要参加项目；我的待办|默认少量相关任务，不按数据库模块排所有按钮|
|入戏|私人定制；继续我的定制订单|剧本许可作为其中一环；单独采购放明确的专业入口|
|培育|商业服务、发需求、接单；按买方/供给方分别展示|保留已定入口名，可加“商单合作”解释；不把所有MCN财务混到客户发需求页|
|成角|浏览公开项目；我的报名、邀请、项目与发行进度|清楚区分我作为权利人参加和我作为项目方管理|
|我的|本人资料／代表机构、自己的形象与授权、与我有关的订单/作品/合作|角色相关入口渐进展开；合同从相关订单/许可直达|

每个提交页最少显示“这次代表谁”“这笔业务为什么做”“需要谁继续”。涉及形象时另显示真人权利人（适用时）、形象和使用范围；不在每个作者投稿、许可采购页面强制选一个无关艺人。

## 先做通两条定制路线

### 个人给自己做片

1. 点“我要定制”，显示买方是本人。选已有形象，或从明确的形象建立/授权流程继续；缺外部条件时解释未启用，不制造可用形象。
2. 选择主题、剧本、制作用途和已发布规格。选形象或选剧本可允许先后互换，但需要的关系都应在报价前汇合；不能跳进若干互不相连的“项目”列表。
3. 提交一份制作需求。页面说清制作方/平台谁接收、多久及何条件回复；未知承诺不编造时间。可保存草稿并看到还缺什么。
4. 收到报价后，在一页核对出演形象、陪演、剧本许可范围、交付内容、修改约定、付款节点、买卖双方。确认后形成该笔订单的历史承诺。
5. 后续在同一订单里查看“制作方进行中”“待我看样片”“需我补意见”“可付尾款”“可查看最终版”。具体先后采用已批准的规格和验收规则，不擅自确定新比例或时长。
6. 付款、验收、许可、文件条件满足后取得成片；私人用途仍受原范围限制，公开发行另走申请。

当前第4步之后部分存在；第1—3步及出演承诺没有完整走通。这条不是让用户拿模拟订单从半路开始的测试。

### 机构为旗下真人艺人做片

1. 机构经理进入甲公司的工作页，选择“为合作艺人定制”。页面区分公司员工与合作艺人，不能用员工名单冒充艺人名单。
2. 从已有、有效且获准用于本业务的合作关系中选张某，再选他的古装形象。展示关系有效范围、本人同意状态；合作关系不足时，进入补充授权/本人确认，不假装成为张某登录。
3. 页面明确“甲公司是买方；张某是出演人；古装形象用于本次制作”。如经理代办权限不足，只能保存需求或请有权的人继续，不直接替人确认。
4. 接入与个人相同的需求、报价、制作、验收路线。公司付款与艺人同意分别确认，避免把两者合并成一次同意。
5. 变更出演人或形象时生成可核对的变更；重查权利、本人同意、报价和分成影响，不能改写旧订单快照。

机构经理代办的具体范围、确认时点和变更细则仍待审。当前App不是只缺一个艺人选择框，相关查询、权限与订单承诺也需补。

## 其他路线怎样衔接

|路线|清楚起点|中间交接|到哪算用户这件事办完|
|---|---|---|---|
|公司先采购许可|“采购剧本使用权”，显示买方公司、用途和未指定出演状态|供应方报价/核验→许可取得→以后绑定用途项目；跳转携带原许可，不让用户重新找|取得约定许可及可查凭证；不冒充作品制作或发行已完成|
|作者供给|“投稿剧本”或“继续补材料”|作品与权利审核→范围明确的许可商品→买方交易→收入|能看自己作品状态和销售相关任务，知道被退回哪项；无需接触平台审核工具|
|品牌商单|“发布需求”，明确商业用途|收到方案→选艺人服务与已获准形象→报价→订单→制作/验收|得到约定成果并可查费用；本人脸声和商业许可与普通私用分开|
|艺人接商业服务|“我的可提供服务”或“处理收到的需求”|选具体形象→用途核验→提供方案→本人/获准代理确认→交付|明白接了谁的单、用哪个形象、赚哪一笔，机构佣金不变成新的多层分销|
|MCN推荐艺人|“为某项目推荐艺人”|按授权选具体艺人/形象→报名/报价→筛选→权利人最终确认|每名艺人的结果可查；同机构多人推荐规则审定后补后端，不混成公司自己参演|
|制作人员交片|“我的制作任务”|由订单带入获准剧本/形象/约定→上传版本→审片→客户反馈|清楚当前应交什么、谁接收、被要求改哪里；必要网页操作明确交接|
|项目发行与收入|“我的项目发行进度”|使用范围与会签核对→外部资料→实际渠道结果→实际收入/各方份额|可查证据及自己的权利/收入，不把平台内部审核通过当已在外部上线|

纯虚拟形象按自己的权利类型办理，不强制变成真人；涉及真人脸声才要求相应本人同意。各类形象可做哪些动作仍按REQ-007和真实服务条件区分，不凭页面选择扩权。

## 怎样才算新流程真正做完

|验收故事|必须能直接回答的问题|不能替代验收的方法|
|---|---|---|
|普通人第一次为自己做片|从哪里开始、用哪个形象、还缺什么、谁报价、下一步谁做？|测试脚本先创建好报价后，只测读取和确认|
|机构给一位艺人做片|谁付款签约、哪位真人/哪个形象出演、经理能代办到哪、何时需本人？|把机构切换当作切换成艺人，或手填他人编号绕权限|
|机构推荐两位艺人参与同一角色（若批准）|每个人的报名、同意、结果是否独立，是否明确一人多形象去重？|先改掉去重条件却没有确认和历史规则|
|公司先买许可再安排项目|何时仅有许可、何时补出演及项目、是否明确未获发行权？|把许可预留成功显示成整个定制成功|
|暂停、授权失效、换人、取消和成员退出|旧资料还能否用，谁能继续，旧承诺是否保留，费用怎样处理？|只测顺利通过，不测中断及恢复|

新增每一步都保存“需求依据→办理目的→当前页面/API→可重复验收结果”。用看得懂的业务名称、照片/作品名和主体名称确认对象，编号留在详情和排查记录；没有权限的对象不能通过搜索或列表暴露。
