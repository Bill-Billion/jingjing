# 全范围核对：跑完轮次，不等于全部业务可以交付

本表逐项对照V5的30个工作包，区分代码、实际页面、外部条件和验收。旧包原始验收结果不覆盖、不统一改成通过。

## 当前必须单列的遗留工作

1. **代做样片仍需开发。** V5 §2.3/§3.4明确平台真人团队承制、1000元/单、50%/50%，样片所有权归艺人。当前商品类型虽有MANUAL_SAMPLE，trade/product-policy.js仍拒绝报价；不能用现货购买或私人定制流程冒充。下一批应补受理、所有权绑定、报价付款、制作和交付测试，并保持制作金不可用。
2. **停止剧本自助供稿需专项核验。** 当前works/licensing保留历史接口；需要验证V5运营代录与普通作者写入的区别，而非只检查隐藏菜单。
3. **完整页面尚未证实。** PR24当前标题和分支仍是第一轮故事前端，未替队友宣称后续页面已完成。双方必须同版本逐条操作验收。
4. **真实服务与正式发布条件未齐。** 托管支付、外部电子签、长期数字人、OSS、发行渠道、实际到账、合同税票、完整客户端、生产容量、脱敏旧库样本分别保留待验。已通过隔离模拟不能抵消这些缺项。

本轮参演和发行新增能力可以按独立成果交接；整套V5暂不标为“全部交付候选通过”。本表发现的缺口不退出范围，也不全部退给甲方：代码缺口由本侧继续补，页面由队友接，外部材料才由甲方提供。

## 验收如何继续

先修代码明确缺口，再由双方锁定同一版本，按原验收场景逐项运行；通过、失败、缺材料、尚未做分别填。账户/权限、私人定制、现货、试镜、共创、晶钻权益和发行都必须从页面入口走到运营结果。最后再做真实外部服务、旧库迁移、手机及容量验收，不自动合入或部署。
