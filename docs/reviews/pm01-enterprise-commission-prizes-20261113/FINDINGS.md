# 原要求、已复现问题与实施边界

来源：[原验收](../../testing/FULL_BUSINESS_ACCEPTANCE_20261028.json)ACC-DEL-01.04企业代办、20.03结佣、20.04逆向、21.04真实奖品；[PM01](../../sources/pm01-20261111/03_本轮施工任务与验收.md)W10同记录验收、W17奖品兑现及W29整体验收准备。不是新增产品路线。

企业代办原文：“企业授权代表可操作订单与票据，不依靠星探等级代替代表权。；公司切换后不得继承上一主体的审批权限。”现实现限定已核准企业的成年实名OWNER，不新增普通员工的通用财务代理授权。新增四组同订单验证：无充值会员也可申请企业票据、普通员工不能代办、同人切换另一企业不能读取/办理原单、申请方不能自审、原代表权撤销后不能靠旧命令恢复访问。撤销/恢复OWNER关系和企业能力是隔离管理前提，未声称开发了法定代表变更审核或真实税务开票。

结佣原文：“售后结束且真实履约/支付成立后才可结佣。；无推荐人份额归平台，自购和虚假交易不返。”逆向原文：“部分退款按原快照冲回；追偿和实际到账独立。；MCN管理关系改变不得改旧单推荐人。”

[合同提取17（渠道KOC推广返佣协议）](../../sources/contracts-20261029/extracted/17.md)第二条规定：“乙方不得通过刷单、虚假交易、诱导付费、虚假宣传等方式套取佣金，违者取消佣金、追回已付并追责。”本批采用的流程补全是：已有RISK_ORDER排除认定阻止新的推荐佣金结算、批准和付款额度；已有结算与到账记录不删除，不把排除操作当成退款或已追回。独立申诉恢复仍用原归因和金额，不创造新推荐关系。最终追回及真实持牌出款仍单独验收。

## 已复现缺陷

1. 异常来源仍可新建佣金结算：FIRST_REFERRAL_RISK_RUN中的“Missing expected rejection”复现。来源e58696e1已在佣金同步和可支付额度读取补门禁，SECOND_REFERRAL_RISK_RUN的32项通过；之后新增部分退款场景，不能借此旧结果代替最终验证。
2. 异常标记前生成的待审结算仍可批准：PENDING_REVIEW_FAILURE使用e58696e1的外置诊断复现。诊断只在独立测试进程改编测试文本，禁写业务/HTTP证据文件，不污染正在运行的完整回归。最终修正和同版复验见REPORT，不能把诊断当通过。
3. 推荐人持运营权限可恢复自己的佣金来源：REFERRER_SELF_REVIEW_FAILURE同样外置复现。应补当前账户与原订单推荐人之间的利益关系检查；其他个人或公司身份不能绕过。最终修正和复验见REPORT。
