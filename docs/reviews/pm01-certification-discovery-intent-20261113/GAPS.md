# 原需求、实现差异和实施顺序

1. 原ACC-DEL-04.02要求“手动城市可浏览，距离仅在获准定位后计算”。现有discovery/search仅接受kind/city/q/cursor/limit；catalog-city提供城市别名，公开资料只有城市，没有受控地理坐标来源，OpenAPI无距离字段。本轮验证手动浏览及拒绝未知坐标参数，不把缺证据当缺功能，但这里代码/接口确实没有GPS距离查询。后续先核地点来源、公开精度与一次使用授权；无真实地点数据时不得把城市中心距离冒充艺人位置，不强制采集或阻断购买。后端独立设计/验证由chengcongcong222继续，设备定位及页面当前暂停。

2. 原ACC-DEL-11.03要求“同意合作生成一次客服工单，指派并补需求报价”。现有notices/repository的CASE支持WAITING_SUPPORT、独立NOTICE_SUPPORT关联报价，记录linked_by；没有明确assignee或指派/交接动作。不能把关联操作者当成预先指派。本轮已核同案并发、权限和保留原授权，下一步开发具体客服指派/交接：限制有效运营权限与利益冲突，交接后旧承办人不能继续写，关闭/撤回后不能接单，保留历史及原报价合同。具体接口方案先入API交接，新增权限不得自动授予旧岗位，前端不实施。

3. 原ACC-DEL-02.03要求到期按正式版本。本轮合成未来时钟同时使实名和认证失效，能证明有效状态与历史分开，不能证明所有单独到期/续审组合；后续补单独期限边界与重审收费核对，不自行增加第二次扣费。02.02分类收费是已有仓库有效口径，10元审核费与通过分离。

4. 原11.04期限依各自规则快照，源码使用submission_days；不得把例举72小时覆盖全部旧单。事件、收件人与重试本轮已验；真实推送和用户实际收到仍依真实通道与设备，不由数据库行数代替。

以上为原验收子项或为实现它们所需的流程补全，不新增产品路线。暂无必须由用户新决定的事项；先完成可独立后端部分，再在真实接入时提出具体材料用途。
