# 实名要求与实施边界

来源：[20261029合同00号第二条](../../sources/contracts-20261029/extracted/00.md:23)：“用户须使用真实身份信息注册。浏览可使用基础功能；发布、交易、创建数字人前须完成 L1 实名认证（免费）。”该包主体名称的后续修正仍按用户已确认昆山公司，本文不恢复旧北京主体。

实施补全而非逐字原文：机构有代管资格、被代理艺人有成年实名，并不自动证明当前登录办事人的实名。现有auditions/context.buyer已对企业办事人的个人主体调用verifiedAdultParty，故对其他经营发起操作采用一致模型；不推导额外付费光环/模卡审核义务。

本轮实际HTTP确认stock/repository.create及artists/repository.createAvatar的3类办事人状态未阻断；有效成年正例成功。源码检查显示前者在命令重放前只核机构OWNER，后者核被代理人verified与代管权限，未见独立办事人身份检查。测试是合成授权/身份/材料，未启用真实机构认证。

后续修复要求：在业务事务内检查实际账户自己的身份及有效期，并在成功请求重放之前执行；不把读取时回看原创建者的资格误当当前经办动作，从而追改旧合同或连带封锁买家历史记录。正式操作能力仍由当前机构授权、艺人同意、产品条件分别决定。待修复，不宣称已实现。

其他入口的只读线索，尚未列为已复现故障：通告个人发布已核verifiedPerson，机构发布另走资格记录；现货买方检查当前个人身份，但检查位于首次创建分支；供稿旧avatar创建入口存在，不因现代艺人入口已验就认定它满足新合同；通用交易accept/preparePayment需继续核当前实名与旧合同边界。每个确需修复的入口须先具备正常对照与实际反例，不全局修改owner来掩盖分类问题。

已知年龄限制与实名有效性是两件事：已知MINOR在失败/未知核验后保留限制；ADULT但身份过期/拒绝也不能据此满足新的经营准入。保护性资料、申诉/撤回和退款处理不自动归类为新经营。当前读路径及旧约定继续保留。
