# 首轮联测后的集中补修

四组接续、隔离环境和首轮联测已通过 [草稿 PR40](https://github.com/Bill-Billion/jingjing/pull/40) 同步。随后继续处理完整回归中确证的问题，补修 App 源码冻结为 `22b269e145209eece2cb8c13ed5d7da6a70cd66c`。本批没有改后端、API、迁移或管理网页；原环境与管理网页仍使用 `996b34417e1149f858a3804af7cc933d43c1856a` 的组件内容。源码树、构建产物、完整结果见 [补修结果](FOLLOWUP_RESULTS.json)。

实际修复和验证：

- 报价的付款节点卡片在已有 Material 内又加了不透明装饰容器，遮住 ExpansionTile 内 ListTile 的涟漪并触发 Flutter 断言。节点内部增加透明 Material，金额、渠道、原请求恢复和释放逻辑不变。
- 合同目录测试仍点击旧文字“回到原业务”。改为当前合同卡片的“查看原约定”，继续核对原参与/发行记录、不得读取失权父项目、实际详情页和当前版本。
- 收银台和未知付款测试在滚动到字段之前断言，或者固定拖动后将目标移出了视窗。改为实际滚动到待核对字段，保留精确金额、固定渠道、未达节点不能办理、未知不能假称成功等断言。

四个关联测试文件 35 项全部通过。随后又运行完整 App 回归；结果和失败逐项保存在 `FOLLOWUP_RESULTS.json`、`APP_FAILURES_FOLLOWUP.json` 和 `app-all-tests-followup.log`，没有用 35 项局部结果替代完整结论。旧 81 项失败清单及原始日志保留供追溯。
