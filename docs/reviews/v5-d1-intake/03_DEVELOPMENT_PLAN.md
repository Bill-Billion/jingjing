# 六段开发安排：先打通用户办理路线，再扩展经营与奖励

这是D1完整范围的施工安排，不另造产品版本。编号仅用于查证；本侧负责服务器、数据、权限、规则和主测，前端伙伴负责Flutter、Vue、端上调用及安装包。所有前端任务均为建议安排，尚未代认领。原60项配对任务不删减、不改号；对应开始和收口阶段见文末表及[现有任务表的V5计划区](../../tasks/board.json)。

25条原文补充细则已关联到同一任务表中的60项配对任务；它们随对应业务验收，不另建待办系统。11项代码层面的依赖与容量边界见实现差距报告。

## 当前具体执行顺序

用户补充实际Figma并要求逐轮推进后，六段已细化为[十二轮安排](07_ROUND_PLAN.md)，首两轮见[施工交接](08_FIRST_ROUND_HANDOFF.md)。六段继续表达完整范围，十二轮表达可以检查的实际成果；不是新增12个互相独立的大项目。第一段只先实现当前业务所需基础，不等全部身份/资金功能齐备才开始故事。完整演员授权在第3轮，先于第4轮正式制作。

## 首批真正可以开始的工作

1. 本侧整理共同版本证据、业务来源与规则差异，前端伙伴确认本地是否有未推送成果和实际账号。已有PR23代码不重复施工；计划材料的“合并”命令不自动执行。
2. 本侧先交六组小接口说明：谁在操作/代表谁；真人与数字人及造型授权；商品与许可类型；订单付款/分账快照；故事模板/草稿/补件；公开资料及媒体状态。每组附成功、无权、资料不足、服务未开通和重复请求例子。接口名/字段经双方实际确认并登记进既有contracts后才算双方约定，当前只是设计工作清单。
3. 前端伙伴可以先做旧路由去向、新五入口、“我的”任务分组、三端页面权限清单、动态故事表单及运营受理布局。接口没实现的页面仅使用明确测试示例，不进入正式回退逻辑。
4. 本侧优先把新分账策略、旧版重放、财务来源校验和退款尾差一起实现；同步做好不同商品付款计划。存在有效MCN、采用艺人80%/MCN20%且无推荐人时，100元样片平台18、MCN16.40、艺人65.60；商单平台22、MCN15.60、艺人62.40；有推荐人分别从平台部分再支出7.20/6.60，供应方份额不变。还须检查无MCN（供给额全归艺人）、关系失效及换绑不改旧单。自营制作不是照套这两层佣金。这是验算例，不是税后到账承诺。
5. 双方先把动态故事提交、运营补件、报价接线做通，再接已有付款与制作；公开现货可并行走独立权益链。初次对甲方演示时应能亲手完成“个人定制”和“购买现货”，同时展示失败时如何继续，不再只演示菜单。

## 把大包依赖拆成真正需要的能力

- 实名/年龄的档案和权限设计可先做；10元认证费、60元创建、29元托管的实际交易都需要收银能力。D1未列全这一费用依赖，本计划补入；不凭档案创建成功宣称真实模型已建。
- 第三段通告发布依赖星探/机构资格，因此第四段的资格计算和规则版本要提前提供，并连接可信充值/消费事件或已明确批准的机构资格依据。储值真实通道尚未开通时，可用隔离合成事实测试，不能让前端自算资格或让所有普通实名用户发布正式通告；缺实际资格事实时，相应星探发布只完成隔离验证，正式功能保持未启用。
- 第二段交易必须先产生可追溯的合格成交、退款、撤单事件；第四段积分/推荐再消费这些事实。不能只有支付成功就发分，更不能把充值当消费。
- 共创房间、本人材料和独立授权可在定制链稳定后先做；优惠和推荐费率未定只限制对应报价/奖励发布，不停止房间基础设计。
- 运营配置、受理、财务及MCN最小操作随业务交付；聚合看板后收口。不能全部后端写完再让前端接，也不能业务写好却无人能在后台处理。
- 大文件规格和私有上传方案提前约定：现代码有8MB上传限制；20人共创也可能超过旧20条同意引用上限。采用有边界的媒体/引用管理，不通过取消权限或无限抬限绕过。

## 每段怎样集中交付

默认一个明确业务成果一个集中审阅入口。阶段内双方各自在自己分支保存小提交；在约定交付点上传固定版本，由本侧整合双方提交及证据，运行联合检查，再提交阶段申请。前端伙伴真实审阅共享接口、权限、付款、授权和分账；本侧检查页面是否符合接口与用户路线。不能由两个辅助模型代替队友批准。

第二段可拆成“现货购买”和“私人定制”两个完整成果；第三段可拆“试镜”和“投稿转单”；第五段可拆“共创”和“奖励兑换”。这不是按聊天次数增开申请，也不是30个DEL各开一份申请。具体交付点在该段开工记录中约定。

共享接口若会让对方等待，就把可审阅的接口、示例及兼容检查作为提前约定的小交付点集中同步；不把尚在本机的文件当作对方已经取得。独立业务从共同版本开支；确需未合入前置时记录准确提交与获取入口，不随上一项自然串接。

## 工期与人员安排的边界

两位主要开发者各维持一条施工线，审阅/资料准备可并行；不按“两个Codex就同时做全部30包”安排。D1没有经实测支撑的新工期，本轮不沿用旧2092—3240人时或旧周数，也不把页面组数换算完成率。先完成首批接口和第一条跨端链，记录实际开发、返工和等待，再给剩余工作滚动估时。真实渠道开通、甲方规则裁决和队友可投入时间单列，不能混进代码速度承诺。

下表“收口”指内部实现与跨端检查的目标阶段，真实服务启用另列；跨段任务可先提供必要小能力，不能把大包全部完成当作唯一开工条件。
