# 当前后端能复用什么，V5还需要改什么

核对日期：2026-10-15（北京时间）。资料包标识为 `JX_V5_FULL_DELIVERY_D1_20261016`；这是材料版本日期，不是本次核对日期。代码比较基线：`25e6d29f81fd882edc203b732a48fe90d15f8c9f`，工作目录 `worktrees/full-flow`。

本报告以D1的30个交付包、121条完整范围、60项双流任务和18项待决事项为核对框架，逐包审阅后端任务，结合接口协作规范核对当前Node/MySQL运行模块。**这是开发前的静态审阅；没有执行本阶段业务测试，没有修改业务代码或调用外部收费服务。** 原有测试或模块的存在，不能记为V5已验收。

本报告只说明代码差距和技术依赖。甲方业务要求、D1整理建议及正式批准结论仍须分别记录。尤其是“接受且对应款已核验后开放会话”的AND条件，是DEC-03的拟议解释，正式门禁矩阵尚未批准；不能按一条总开关直接开放所有业务。其他冲突也只阻断相关规则发布与真实启用，不阻断独立基础开发。

## 首要判断

新阶段可以沿用登录、主体成员、MySQL、任务恢复、规则/合同快照、订单收退款、四阶段制作、项目会签、财务凭据、通知与私有文件基础。V5改变了买卖路径、艺人经营方式和资金分配，不是只换五个菜单，也不应推倒新建另一套订单、制作与支付事实。

已有代码最强的可复用部分是“不假成功、留存历史、检查权限、重复请求不重复记账”。缺口主要是：真人与数字人多造型关系、公开供给货架、现货视频购买权益、故事卡入口、正式试镜履约、业务会话、储值/积分/券、推荐归因、多人共创、抽奖与隐私请求。这些不能因已有同名旧页或旧 SQLite 服务而记为 V5 完成。

下文代码均来自当前后端 `晶晶日上工程交接包/01_源码/backend_server/`；证据链接指向仓库原文件，行号对应上述比较基线。所有交付包仍属于“未按V5验收”。

## 后端如何接入D1的六个里程碑

沿用D1六个里程碑；详细认领、前端分工、推送点和时间安排由统一开发计划管理，本报告不新增另一套阶段。一个里程碑内可按业务成果独立交接，不要求全部接口写完才让页面开始。

|D1里程碑|后端关键安排|独立交接和验收重点|
|---|---|---|
|一：共同起点和规则迁移|DEL-00，及01/07/08/24的最小接口、旧新费率分流、历史快照保护|身份与交易类型先给前端；旧新订单同跑；不得擅自合并PR或覆盖旧规则|
|二：定制与现货两条客户链|DEL-02/03/04/05/06/13/14/15的基础能力，接入已有订单和制作；收费部分依赖DEL-07|现货购买/下载/退款与故事卡/人工制作分别验收；公开供给、运营审核、MCN上架随链条交付|
|三：试镜、通告、投稿和消息|DEL-09/10/11/12，提前接DEL-17/18的资格查询所需能力|通告发布资格由服务器判；意向不自动开聊；接受/付款/联系卡/客服权限按DEC-03候选矩阵实现并隔离验证；正式开放前取得逐业务确认|

|五：共创和权益兑现|DEL-16/21/22接已经约定的权利人、主订单、积分和卡券能力|共创按真人去重与权限隔离；兑现面试/曝光和兑换权益；抽奖正式算法未决时不发布真实活动|

## 共同接口应先给哪些，怎样减少彼此等待

先小批冻结，继续使用 contracts/openapi.yaml、PROTOCOL.md、implementation.json、CHANGELOG.md，不另开第二套API真相：

1. 登录人/责任主体/权利人/数字人/造型声音/代理权限与 allowed_actions；前端先稳定当前操作身份，不用切演员来替换付款主体。
2. 媒体上传完成、审核状态、公开投影、下载权限；正常/审核中/被撤回/未接OSS四种都给实际错误样例。
3. 商品种类、报价/订单行、付款计划、各项价款及两层费率快照、退款结果；明确旧版兼容和不允许发起的新写。
4. 现货权益、定制需求/故事版本、试镜邀约、意向工单、会话成立条件与状态。每种对象由本域拥有，付款只引用trade事实。
5. 消费者现金余额、供应方应付、可用晶钻/累计成长、券、推荐归因，分别有查询与事件依据。界面不自行重算钱与权限。
6. 共创房间/权利人去重/权益锁定及个人素材授权，最后接奖励事件和财务；不能全部共享房间故事。

每份交接至少带：真实路径与身份、成功/空/错误/版本冲突/失权样例、分页过滤、幂等、敏感字段、外部未启用说明、隔离HTTP测试命令、前端能开始什么。前端确认“够实现页面”后冻结该小能力；内部实现可继续，不等所有API齐了才联调。集成入口保持一个明确成果一个阶段申请，公共文件由指定人整合；阶段不因每次聊天额外开PR。
