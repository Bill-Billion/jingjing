# 怎样证明业务做通，以及哪些材料要提前准备

D1的133项目前全是未执行的拟验收。它们可以当总目录，其中大多数前置条件是统一模板，还不是能照步骤直接执行的完整测试。每段开工时，只把该段场景展开为具体账户、数据、操作、预期账目与权限、失败恢复和证据，不一次制造大量空测试文件。

## 统一可重建的测试资料

本侧提供一套按场景重建的隔离MySQL资料及固定规则版本：普通成年买家、未核验/未成年账户、个人艺人（一真人两个数字人）、另一个独立艺人、两家MCN及失权员工、运营受理/制作/审核/财务不同岗位、推荐人、共创9/10/19/20/21人，以及旧版订单、新版订单、待处理退款和已失效券。

一条跨端测试使用同一批数据和同一接口版本，页面能从真实用户入口找到对象，不要求人手输数据库编号。合成数据可触发付款/实名/模型返回供离线验证，但必须明确只用于测试，正式代码不得失败后自动退回模拟成功。

每次记录：来源条款、场景与对象、后端提交、App/Web提交、规则与迁移版本、环境、命令、结果、跳过原因、截图/日志、操作者及审阅人。前端在真实隔离接口上完成联调后，再分别记录Android/iOS构建及真机操作；Web测试不代表手机验收。

## 分层检查，避免重演“测试都绿但不会用”

1. 业务规则独立检查：分账、权益、去重、资格、计时和退款，不要求启动无关模块或供应商。
2. 真实隔离MySQL检查：金额与流水事务、并发锁券/抽奖/退款、重复事件、权限撤销和故障恢复。
3. 接口与兼容检查：请求/返回符合既有OpenAPI；旧端读历史、新类型拒绝或引导，不能误进旧流程。
4. Flutter/Vue业务操作：从入口到结果，连对应运营或MCN处理；同时看失败后的下一步。
5. 原生真机检查：下载与权限、支付回跳查单、相册/麦克风/位置单独授权、小屏大字、退出与恢复；没有测试的系统明确写未测。
6. 外部服务分项核验：沙箱和正式产品、收付款与退款、真实模型及删除、真实标识和发布各留证据。前五层通过不能代替第六层。

## 本轮验证结果的含义

本轮做材料哈希、编号映射、依赖和链接检查，以及代码静态复审；没有执行V5业务测试。新增补充检查见[需求审阅](01_SOURCE_RECONCILIATION.md)和[技术缺口](02_CODE_GAPS.md)。所有拟验收维持未执行，历史CI结果保留各自提交；旧手机用户反馈仍是完整业务未验收通过。
