# 来源与八个资料遗漏

[00号协议第二条](../../sources/contracts-20261029/extracted/00.md:25)原文：“用户须使用真实身份信息注册。浏览可使用基础功能；发布、交易、创建数字人前须完成 L1 实名认证（免费）。”第90轮已据此修交易门禁，本轮不再改规则。

|测试范围|失败的上游事实|本轮处理与保留|
|---|---|---|
|customization-handoff|owner通过newOrder已实名，接手续付的next只有机构代表授权而无本人身份；中款失败导致后续交付和本人资料无数据|只补next身份，保留first/next撤权、各人阅读签收、原截止期限及隐私反馈原文检查|
|customization-trade|独立fixture正常buyer没有本人身份，接受旧/新报价先被拒绝|只补buyer；普通机构成员仍不能确认财务，私有故事边界和竞态唯一单不变|
|fixed-income-release|直接参演付款发生在newOrder之前，buyer尚未实名，里程碑断言收到实名错误，实收/发行派生失败|补明确buyer，仍要求里程碑后付款，保留独立项目收益/真实引用凭据的合成验证|
|participation及participation-amendment|同类独立参演付款未准备buyer身份，改价引用和退款因原付款未发生而派生失败|两个文件分别补buyer，金额/退款/旧账/换角断言不变|
|operations|在进入运营测试前创建实际订单，正常buyer接受报价被拒绝|补buyer，保留权限、通知、评论和报表实际办理，不绕过订单准备|
|release|隔离备份恢复演练的前置已付订单因buyer未实名不能创建|补明确buyer，后续恢复、格式及有界HTTP负载检查原样保留；不是生产演练|
|privacy-transaction-copy|本人、其他人和机构对照订单分别需buyer/outsider/producer正常接受，但三人都无实名|显式补三位实际办事人，仍不授予他人订单或机构订单的个人副本权限|

这些是隔离测试资料修正；不得在通用pay/注册辅助函数自动实名所有人，不得修复已有负例身份以求全绿。helper未修改。观察失败的父项和后续undefined/未付款断言不是同等数量的独立业务缺陷。完整终态及同次关联日志均保留；正常假身份不证明真实KYC可用。
