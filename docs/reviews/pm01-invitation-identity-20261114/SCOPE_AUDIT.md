# 本轮边界核查

依据：[20261029合同19号第四条](../../sources/contracts-20261029/extracted/19.md)明确“未实名用户仅可浏览”，并列实名交易和机构入驻；[00号第二条](../../sources/contracts-20261029/extracted/00.md)规定发布、交易、创建数字人前免费L1；[10号第四条](../../sources/contracts-20261029/extracted/10.md)规定“乙方完成实名（L1）后方可交易”。本轮不追改历史订单，机构当前办事人不能以机构资格代替本人实名是沿已有代办实现补全，未新增收费。

|入口|实际所核事实|本轮处理及剩余|
|---|---|---|
|企业邀约提交与成功重放|notices.repository.submit只调buyer，机构inviter只核机构资格；独立HTTP九项反例中的六项在失效身份下返回200|已确认缺口，待当前完整运行终态后在命令重放前核实际账户，不改读接口|
|邀约独审发送|review只重核代表权限及原邀约对象；三种失效实名下审核仍发送|已确认缺口，审核实际发送时核原提交人，保留独审与已发送历史，不把审核员变成艺人|
|企业授权和艺人意愿|原六步企业邀约/直达商单/支付与撤权仍通过，三个失效实名期间的本人有权读通过|不能拿机构授权通过代替个人实名；也不把本人查旧邀约当新交易封禁|
|既有商单会话|gigs.conversations.scope继续核原订单、当前代表/机构授权、已接商单、付款、退款冻结/归档|只读核查，没有新实际失败；保留既有风控/归档测试历史，不据静态缺少实名函数就直接改旧会话|
|佣金归因和结算后台|engagement.referrals.capture/bind/sync由订单快照、退款事实及独审流程驱动|系统对既有账本同步不是新的人类发布动作，不把本人准入硬塞到回调/退款/后台结算；原逆向继续按快照|
|私人项目/机构登记准备|只知道合同区别浏览、新经营及保护性权利；未逐入口取得实际反例|尚未核清，不因函数叫create就算公开发布，也不宣布全部符合|

该表是本轮六处边界的核查范围，不是另造六条产品路线，也不是所有接口审计结论。未覆盖仍留在既有任务和151标准中。冻结运行时未改源码或正式测试。
