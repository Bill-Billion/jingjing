# 恢复核对：本批证明了什么，还不能据此做什么

依据PM01 W28恢复后业务、文件和金额可核对的交付条件；本批为后端隔离预备。维护者阶段末检查本批代码，不等于批准运行生产恢复库。

|核对对象|本批实际动作|仍须另验|
|---|---|---|
|数据库业务事实|同一未知退款加密备份到新库，核原案件/任务/操作键/钱账；最后同案一笔结清回执，原库未改|实际旧库来源、业务映射和备份之后的真实外部交易|
|执行资格|逐表比较后同事务作废RUNNING旧租约；旧进程不能续期、写渠道号、完成任务或结清|恢复后独立操作人当前权限、实际渠道配置和恢复授权|
|原请求与尝试记录|新租约在隔离库内部查询同一原请求，不再发送；结清丢任务写回后不重复结清；上限不清零|真实渠道签名/查单、配置更换和实际异常回执的验证|
|隐私|合成最新登记核摘要和对象；重放关闭账号/撤会话/停材料下载，二次恢复仍保留登记并清旧重放标记|真实最新登记及供应商删除执行、OSS版本或备份字节处理|
|失败恢复|作废旧租约步骤失败时恢复行整体回滚，隔离标记仍在；原库不受影响|真实规模、回退时限、正式回退命令及运维签收|
|任务可见性|只读发布检查显示待执行、待重试、执行中、受阻和失败数量；不执行任务|实际告警投递和值班接收，不把只读数量表称为告警已接通|

当前恢复命令没有解除隔离的操作，本批也未添加审批入口。合成测试直接调用内部处理器，始终保留QUARANTINED，并检查正式HTTP/worker启动被拒绝。发布报告始终NOT_APPROVED。

最新隐私登记负责文件抑制和关闭账号，不是完整的权限同步记录；不能用它证明备份之后所有员工撤权、独审权限变更和供应商配置已核对。正式恢复前仍须按现有运维手册核这些变化。申请中的昆山材料和最后采购的OSS不在本轮重复索要。

内部restore的MATCHED表示先完成快照比较，再执行已明确列出的保护：覆盖恢复隔离状态、作废RUNNING租约、清除旧隐私重放状态。业务金额、任务关联和原渠道编号保留，运行字段不是原样可继续使用。
