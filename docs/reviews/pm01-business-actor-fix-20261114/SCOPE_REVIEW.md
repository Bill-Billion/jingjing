# 实际改动与接续边界

依据PM01 W01“分域审阅PR39，单列迁移、权限、钱账、授权、删除及发布配置”，此处为开发者准备，未代维护者审阅。本轮对应W14通告商单、W20机构代办和W10同记录证据；不是新增平行业务路线。

|领域|本轮事实|验证和限制|
|---|---|---|
|迁移与恢复|没有数据库迁移改动，仍0225|旧真实58表缺样本独立保留，不能用模拟恢复代替|
|权限|邀约提交/重放和独审发送核实际提交人；商单需求及买方接单核本人当前实名|组织资格、已接受TRADE代表权与本人实名分别检查。独审发布核原作者，审核员继续按运营权限|
|钱账|没有改支付、结算、佣金和退款算法|原商业订单/返佣及身份失效后的可信到账恢复纳入关联；模拟付款不代表真实渠道|
|授权|不改艺人邀约意愿、肖像/声音用途、机构授权、旧合同快照|允许有权人读旧记录和保护性撤回，实名恢复后原键恢复；无扩大授权|
|隐私与删除|没有隐私运行时改动|首轮正常买方缺合成实名，在建商单前失败；只补该账号明确前置，原限制/传输中撤权/多重限制/旧引用断言保留，见FIXTURE_FAILURE|
|发布与配置|仅后端准入和接口预发布版本，无新端点字段、收费或部署变化|不修补/运行前端，不启用真实服务；旧网页准备失败按旧候选证据单列|

只读接续核查：`gigs/repository.js`供给方`offer`核OWNER及`eligible`，`gigs/context.js`的`eligible`核当前主体、有效规则、机构关系、头像和用途授权。仅凭没有直接调用办事人实名函数，不能立即宣布缺陷；还须沿上游资料和交易实际入口做独立反例，区分被代理艺人与实际办事人。本轮修复及50项新测试只覆盖买方和邀约，不声称供给方首次报价/审核/重放已逐种身份验证。

`gigs/conversations.js`既有已付会话的权限、冻结与归档，和返佣按订单快照/退款事实的系统处理，不能一概套用“新发布”门槛。若需接续，先核具体用户动作及原文，再构造有权旧读取与保护性处理对照。当前完整检查冻结期间不得改后端、正式测试或合同文件；独立探针必须另用输出和测试库。
