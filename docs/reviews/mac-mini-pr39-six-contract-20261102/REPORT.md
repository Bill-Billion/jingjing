## 本轮发现并修复的问题

1. **交接 POST 返回普通关系记录，网页需要重新读取交接汇总。** 提交或原键恢复后读取同一关系交接接口，保留版本和原单。联调还发现双方已确认在网页主详情不可见，已添加逐笔状态、原订单链接和双方回执；新增失败在先的渲染回归并重跑网页→原生→网页同单。
2. **原隐私回复复核发送了错误决策枚举。** `response-review` 改用原接口 `APPROVED/REJECTED`，期限与执行复核保留各自 `APPROVE/REJECT`。真实账号关闭后的网页保留回复及结案链验证通过，未修改后端契约。
3. **监护预期使用拒绝不能当作全域权限失效。** 已关闭、分钟到期、额度/夜间限制清当前预览与错误状态，保留可核对的家庭入口和待确认原请求；真正无权仍按原访问保护清缓存。身份变更后的迟到响应不能回写。App 专项覆盖原键恢复、只读身份和预期拒绝。
4. **新财务算法被旧前端严格枚举拒绝。** Web `trade.ts/finance.ts` 和 App 交易/财务模型兼容 `LARGEST_REMAINDER_PLATFORM_MAX_ONE_FEN`，旧 `HALF_UP_PLATFORM_REMAINDER` 保留；未知算法仍拒绝。相应报价、规则、收入错误说明已接；未改财务后端。

主要位置：Web `src/business/{contractSix,guardians,infringement,handover,privacy}.ts`、`BusinessView.vue` 与 `ContractSixFacts.vue`；App `lib/contract_six/`、`account_session.dart`、`community_support.dart` 及原订单/试镜/规则页面。详情见本批 Git 差异。
