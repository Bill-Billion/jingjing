## 已实际走过的流程

1. 作者个人身份在网页选择正文、作品证明、权利人证明，真实上传后保存《林间来信 · 网页投稿（隔离测试）》第1版，再单独提交审核。草稿和待审状态分开，新稿两路均无结论。
2. 独立审核员查看机构供给申请，第1版要求补正；作者切换机构身份，补充简介与实际上传证明后提交第2版。审核员批准第2版；第1版的补正理由完整保留。
3. 《窗前来信》第2版先通过权属审核，再由内容审核要求补充结尾。两路显示不同结果，第1版的双审批准未改变。
4. App 正常短信登录并选择个人身份，读取上述作者资料和作品。接续第2版、更换为真实新正文，保存第3版草稿；草稿不继承旧意见，单独确认提交后进入等待双审。
5. App 对第3版填写理由并确认撤回；网页对另一草稿填写理由撤回。两端保留版本、材料和说明，当前状态与历史中的同一记录同步。
6. 临时关闭隔离存储传输，已有正文下载真实返回503，网页显示服务暂不可用；随后恢复。临时撤销测试审核员既有两项作品审核权限，刷新真实返回403并清空队列；恢复后重新可读。未扩大正式账号权限。
7. 普通 MEMBER 正常登录并选择机构身份，页面拒绝读取该机构供给资料；切换本人个人身份可填写自己的首次申请。
8. 390×844网页申请表实际检查，`innerWidth=390`、根节点宽度390，无页面横向溢出。桌面恢复默认视口；Flutter 使用同源390×844内容框，检查长表单滚动和必填提示。
9. 最终 App 构建重新登录后返回原投稿路径；空原作已显示空白权利人字段，标题／材料／关系未齐时保存禁用。最终构建的首次作者申请已复查：真实个人身份可见，空名称、介绍及证明使提交禁用。

记录编号仅用于查验：网页新稿 `f19272ef-84d2-4c53-b5c0-6a5df1d7d268`；机构申请新修订 `d246a447-4f59-4b4e-8a1b-84ca1288b314`；App 第3稿 `42d67512-8140-499a-976d-b1e86ddcfec6`。这些编号会随测试环境清理而失效，不是正式业务入口。

- 网页原生选文件按钮偏小：统一为44px；桌面正文／证明双列，小屏单列；初始空权利关系可见。
