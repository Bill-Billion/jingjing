# 结算约定、实付与发行收入页面方案

固定原图册acd5f99：App7张、网页20张。原PR19后端395679c、已上传17前端、16制作及18项目前端在本地整合，风格和完整导航继续保留；没有全局钱包、自动转账或新的商业默认。WEB35是单份结算约定的付款条件，不是全局上线面板。

约定需要独立核验和各方对准确版本确认；结算期次只是标签，不冒充时间筛选。冻结结算保留当时事实，事实更新须重建，旧记录不改。合作方只查看本方余额；付款方和独立核验者查看全体。前端接入时已修复详情、列表、本人确认及原键重放的后台数据隔离，27项真实财务测试通过。投影保留原快照content_sha256，不将投影JSON摘要冒充原指纹。

余额、可申请金额、已申请占用、实际已付和待追回分别表达。REQUESTED和APPROVED占额度，批准不等于到账。PAID、FAILED、RETURNED需要原金额全额凭据和独立核验；自动出款当前未实现。发行账单是应收，真实收款凭据另行登记核验，部分到账和冲减保留原关联记录。外部编号不能重复使用。

调账须明确2至30个不同参与方、正负分值合计零，并有独立依据；异议可阻止后续申请批准，但不能抹掉实际历史付款。处理完须指向批准调整或原成功退款，不能用财务决定冒充退款。App退款继续现有trade接口，对账只核对同一环境已验证事实，不产生钱。私有凭据按真实源对象读取，财务访问不意味着拥有所有材料权限。

每次写入保留原编号、内容、版本与身份。确认成功须读取确认记录核对本人、原指纹、决定及理由；未知结果先核对，再恢复原请求。412重读重新作决定；身份或授权变化清空私有资料、文件和待请求，忽略迟到结果。筛选后的空页仍可继续游标。
