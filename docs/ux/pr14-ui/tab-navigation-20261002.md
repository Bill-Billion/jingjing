# App底部栏目切换修订（2026-10-02）

五个栏目现在在同一个主页面内切换：底栏和顶部栏固定，正文立即切换，底栏选中反馈为140毫秒；开启减少动态效果时关闭该动画。暖白、铜色、图册版式和业务接口保持原有标准。详情及表单继续使用返回导航。

## 改了什么

- 取消每次点击Tab时替换整个页面；地址随选中栏目更新，切换不增加返回历史。主栏目路由没有页面推进动画，子页仍使用正常页面转场。
- 栏目第一次打开才加载，随后保留自己的滚动位置和已读取内容；再次点击当前栏目不刷新。非当前栏目不接受焦点，内部动画暂停。
- 会话或办事身份变化后销毁原栏目的状态，隐藏栏目下次打开才重新读取。受控阅读仍是独立子页，其到期、撤销、失焦清理保持原样。
- 打开公开目录详情再返回时不重新清空目录，保留已经加载的分页与浏览位置；需要新目录时使用现有“重新读取”。私有办理记录返回后的核对仍保留。
- 新地址、旧名称兼容、直接链接、登录后返回和未知地址兜底都继续使用新版页面。

## 实际验证

相关账号、许可、导航54项测试通过，其中新增5项针对切换状态、滚动位置、目录加载、身份清理与减少动态效果的检查。修改文件静态分析无问题，Flutter Web构建成功。[相关检查](evidence/tab-related-tests-20261002.log) · [静态分析](evidence/tab-analyze-20261002.log) · [构建](evidence/tab-web-build-20261002.log)。没有扩大到整仓测试，没有进行真机测试。

真实Flutter Web与隔离MySQL接口在浏览器检查，正常合成短信登录后回到入戏。390×844与320×693视口均查看：五入口齐全、地址与选中对应、六次轮流/重复切换底栏位置不变且目录额外读取0次。详情隐藏底栏，页面返回及浏览器返回均回到入戏；实际屏幕点击后返回的按钮位置为455.086像素→455.086像素。旧个人地址刷新后进入新版我的，刷新不恢复旧会话；未知地址明确报错且能返回首页。[浏览器事实记录](evidence/tab-navigation-runtime-20261002.json)。

初次位置比较使用了元素定位点击，工具先自动滚动后再点击，测量基准不一致；报告保留该次原值并标为已被复核替代。使用屏幕点击排除该影响后通过。浏览器工具另记录了一条Electron辅助脚本的MutationObserver异常，调用栈指向node:electron，未观察到Flutter应用错误；不据此修改产品。临时视口调整已恢复。

## 用户在浏览器怎么审查

[手机框预览](http://127.0.0.1:8771/mobile-preview.html)；[直接打开App](http://127.0.0.1:8771/#/home)。预览与隔离API已重新启动。按顺序检查：

1. 首页→我的→入戏→成角→培育→首页，观察底栏位置不变，正文立即切换，没有整页左右滑动或缩放。
2. 在首页和我的分别向下滚动，切走再切回；位置应各自保留。连续点几个栏目，最终停在最后点击的栏目；重复点当前栏目不回顶。
3. 我的→顶部设置与帮助→返回，应该回到原来的我的栏目和浏览位置。
4. 登录入戏后打开剧本详情，再用页面返回或浏览器返回；回到原目录位置。切换栏目不会重新加载目录；需要更新商品目录时主动点“重新读取”。
5. 直接打开或刷新`/#/profile`，应为新版我的；`/#/does-not-exist`应明确报错并可回首页。

切换栏目本身无需登录。目录联调可用合成买方13900009202，正常获取验证码；验证码仅从隔离控制面读取。当前状态文件为忽略的`.local/pr14-tabs-ui-runtime.json`，复用[环境说明](test-runtime.md)中的查询命令时用这个文件名。不会发送真实短信。
