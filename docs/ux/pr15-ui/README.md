## 已开发页面和审查路径

|办理事项|App入口|管理网页入口|重点看什么|
|---|---|---|---|
|规格和报价|私人定制说明 → 查看已有报价；我的 → 订单与报价|`/trade/specifications`、`/trade/quotes`|商家明确填写价格、服务、数量、条款及分期；审核不替代买方确认；新版本不改旧约定|
|独立审核|在管理网页办理|`/trade/reviews/specifications`、`/trade/reviews/quotes`|真实权限、独立账号、批准或拒绝理由；本人或关联人不能自己批准|
|确认订单与保存合同|报价详情 → 确认报价；订单详情 → 查看原合同内容|`/trade/quotes/:id`、`/trade/orders/:id`|提交原报价指纹，保留当时规格和分期；合同保存明确显示尚未签署|
|付款记录和核对|订单详情 → 建立付款记录 → 付款详情|`/trade/payments`、`/trade/payments/new`|建立记录不显示已扣款；未知结果恢复原记录，服务器核实后才改变到账状态|
|退款申请和结果|成功付款详情 → 申请逐项退款；我的订单付款入口|`/trade/refunds`、`/trade/refunds/new`|原付款逐项余额、明确原因；批准、执行、待核实和实际退款分开|
|退款独立复核和执行|在管理网页办理|`/trade/reviews/refunds`|另需退款权限；批准后单独执行，Apple进入等待用户申请的实际状态|
|历史订单原始依据|订单与报价 → 旧记录 → 详情|`/trade/legacy`、`/trade/legacy/new`、`/trade/reviews/legacy`|保留原金额、原报告状态和私有附件；核对历史材料不追认为新到账|
|许可衔接|关联订单 → 查看关联许可；我的许可与项目|原许可工作区和订单详情关联入口|付款门槛、签署材料、身份核验与许可生效各自办理；不把付款成功当取得许可|

App详情为 `/trade/record?recordId=实际编号`，合同加 `&section=contract`，退款表单为 `/trade/refund?paymentId=实际编号`。子页使用返回导航；旧许可地址 `/orders?kind=GRANT` 进入新版许可工作区。已有正式入口保持新版，尚未实现的制作/验收业务如实提示状态。
