## 两端共同要求

每个新增页面或状态登记当前设计来源、采用的信息结构和实际适配。先核对标题、卡片排列、字段分组和动作位置，再看字级、间距、颜色及细节。只有颜色接近，不能说明符合设计；没有完整来源时写明适配，不虚构原图页号。

- App继续使用暖白 `#F7F5F0`、白卡片、铜橙 `#B45D3D` 的已有组件，主标题24、正文16、辅助14，控件圆角10、卡片12。顶层固定广场、试镜、通告、消息、我的；故事表单、草稿详情和通知均为返回式子页。V5已存画面的信息层级用于调整入口和故事分组，不能恢复旧入戏／培育／成角主栏。
- 网页继续使用背景 `#F5F6F2`、白表面、深绿 `#335D46`，220px侧栏、64px顶栏、32px主体间距、28px主标题、16px正文及现有表格／卡片／按钮。故事收件按筛选、摘要、正式提交内容、受理记录分区，不添加营销横幅或无接口依据的数字卡片。
- 所有网页共用当前41项菜单；列表和详情保持唯一正确高亮。正常入口、登录返回和退出路径有效；不存在或无权记录按真实接口拒绝并清除旧私密内容。
- 动态问题来自绑定的服务端模板；清空即清空，已提交内容使用当时快照。长故事、标签和编号合理换行，技术编号或校验值可以折叠，不能删去验收需要的业务信息。
- 核对主副标题、卡片顺序、字段标签、日期和编号主次、按钮位置及禁用状态、图标和留白。主要操作触达尺寸至少44px。保留现有视觉语言，不增加虚构人物、案例封面、生成成功或已付款示例。
- App核对手机及放大文字，网页核对桌面和390窄屏；查看实际截图并检查返回、菜单和主要操作。共同组件可集中检查，但只实测部分页面时不得扩大为全产品通过。

## 本轮页面与验收

R01 App包含故事入口、品类动态表单、草稿列表及恢复保存、正式提交、待查看和受理中状态；网页包含收件分页筛选、正式提交快照和开始受理。逐项设计来源及适配见[页面对应关系](gallery-page-map.md)，路径及兼容映射见[导航验收](navigation-acceptance.md)。

需要同时检查空目录、读取中、校验错误、无权、版本冲突和未知写入恢复。必填附件未具备时可以保存文字，但不能伪造上传或提交成功。提交与受理不代表收款、授权通过、报价完成或制作开工；本轮不包括补件报价、实际附件、付款、共创及后续轮页面。

当前测试与截图只证明记录的合成资料和页面范围。具体通过数、跨端操作及清理结果仍归本轮交付记录；另一方实际审阅、上传合并、原生安装包和正式启用单列，不在这里增加另一份进度台账。
