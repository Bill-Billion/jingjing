# 导航与新版页面验收

用户在2026-09-30明确要求：各tab正常显示和跳转，不能出现内部404、菜单消失或跳回旧版；允许按规划新增、更换和删除入口，最终全部页面换成新版。

## 固定的导航规则

网页所有业务和审核页面共用一份菜单：账号与机构、合同与规则、供给申请、我的作品、选剧本、许可商品、许可办理、项目与绑定、受控阅稿、供给审核、作品审核、许可核验。只能有一个当前主入口；作品详情和新修订仍高亮“我的作品”，权属或内容审核都高亮“作品审核”。菜单显示不代表获得业务权限，服务端仍逐项核对。

App顶层采用已确认暖白图册的首页、入戏、培育、成角、我的五入口。入戏承接私人定制，培育承接商业委托，成角承接公开项目与发行。顶层保留底栏；表单、详情使用返回，并回到新版页面。

图册来源为提交`acd5f99`中的`design/full-ui-20260929/DESIGN.md`、`design-system.json`与`pages.json`；顶层参考APP-01、APP-07、APP-19、APP-23、APP-33。当前已实现业务使用对应账号、合同、作者作品页面，不将完整图册里后续接口冒充已在PR13接入。

## 页面如何逐批替换

|业务|目前前端范围|后续应做什么|
|---|---|---|
|账号、身份、机构、邀请|已实现新版|从新版主入口进入，保留真实权限及登录流程|
|合同原文、引用规则、服务状态|已实现新版指定读取|后续列表和签署能力随对应接口接入|
|作者申请、原作、版本、私有材料、独立审核|PR13已实现新版|与同一套导航连接，保持旧稿和旧意见|
|数字人资料、本人脸声同意及撤回|PR13后端已交付，相关页面尚需下一批|按同意范围和撤回规则接入真实页面|
|剧本许可、选本与项目许可绑定|PR14前端已本地实现新版|预留、证据、许可、额度与受控阅读使用真实接口，上传和合并单独记录|
|订单、付款与退款|后续PR15前端|接真实订单及付款状态，不采用演示成功|
|制作、分阶段确认及验收|后续PR16前端|接具体制作版本、反馈与受控交付|
|商单、经纪合作与项目流程|后续PR17及对应业务批次|按最新项目规划接入新版页面|

未开放页面是阶段过渡，必须说明当前可做什么，并提供真正可用的下一步。它不能算作该业务已经开发完成。正式导航不能复活旧生产接口、旧展示数据或旧主框架；历史源码可保留供查阅。

## 每批页面的检查方式

1. 逐项点击全部主入口：目的页面正确、名称稳定、其他入口仍存在、当前高亮正确。
2. 从列表进入详情、表单和新修订，再返回：回到同一新版业务区域，不跳回旧壳。
3. 直接打开合法地址；退出后再打开，再登录：回到允许的目标，重新鉴权读取，不续办旧交易或复用旧账号私有缓存。
4. 切换账号和个人／机构身份：导航稳定，权限和数据按当前真实身份变化。
5. 验证旧名称兼容及错误地址：已有名称映射到正确新版目的地；未知地址明确提示并可回新版首页，不能伪装成已有业务。
6. 检查桌面和手机尺寸：全部菜单可见可点，主页面不横向溢出，正文和底部操作互不遮挡。
7. 新增、更换或删除路由时更新对应测试和人工点击记录；自动检查通过后仍需看实际页面。

内部路由404属于导航缺陷；无权限、文件失效或不存在的私有记录属于业务边界，仍须按接口约定拒绝访问。不能通过公开私有材料或隐藏真实失败来满足“无404”。
