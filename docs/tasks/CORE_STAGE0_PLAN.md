# Core Stage 0执行计划

2026-09-21，用户已要求开始开发。按R0.6现有任务表推进，不再新增一套阶段或固定周数。

|顺序/并行关系|任务|本侧交付|验收与协作|
|---|---|---|---|
|当前|CORE-S0-001 首批契约|OpenAPI3.1、通用金额/错误/幂等/版本、会话/主体/Readiness/快照、旧接口映射、隔离样例与校验工具|标准验证、正反样例、兼容说明；Experience交叉review后才能进入integration|
|可与契约评审并行|CORE-S0-002 MySQL基础|本地隔离MySQL8、mysql2/promise、async访问、版本化migration runner|新库/重跑/失败回滚；生产不可退回SQLite；schema跨流review|
|数据库基础后|CORE-S0-003 旧库导入|字段映射、脱敏副本导入、数量/金额/关系对账与恢复|不把旧假付/实名未知升级真实事实；没有旧库样本明确记录缺口|
|数据库基础后|CORE-S0-004 模块与Worker|持久jobs/lease/outbox、独立Worker、幂等/恢复|多实例抢占、过期接管、重复执行和重启断点|
|首批契约和数据库后|CORE-S0-005 Provider基础|私有OSS边界、Readiness、日志与health/ready|失败拒绝假成功；无公开存储降级；不调用收费/生产能力|
|数据库基础后|CORE-S0-006 后端CI|可重复隔离MySQL测试及CI入口|实际运行证据、失败退出码、无生产依赖|

Experience可独立核验Flutter工具链、设计系统和Web骨架；契约评审通过后按切片消费，不必等待后端整项完成。金额/身份/支付/权利/共享接口不由客户端复制完整状态机。

本轮CORE-S0-001步骤：

1. 核实旧路由、旧OpenAPI与R0.3/R0.6边界，建立接口迁移表。
2. 形成有明确命名、鉴权、主体、错误、分页和版本语义的首批OpenAPI3.1候选。未知商品规格不填默认。
3. 建立本地契约验证工具，覆盖有效示例、越界金额、缺主体、未知状态、幂等/版本冲突等协议约束；不把Schema测试冒充权限/支付运行时测试。
4. 更新Task/CURRENT，commit/push并创建到integration的PR；状态IN_REVIEW，保持未合并。评审期间可启动独立的MySQL任务，不等待全项目重新批准。

本轮不启动真实登录短信/支付/AI，不访问生产，不部署；不修改Experience目录。旧API是否兼容、哪些路由已实现与哪些只有契约，分别记录。
