# 功能分类导航与现货真实封面、时长 · 2026-10-29

前端负责人：Bill-Billion。基于 PR39 的 `5ad8cae4` 组合代码，落实用户对父子文件夹式导航的纠正，并接入接口 `0.31.5-rc.1` 的现货媒体。沿原 [PR39](https://github.com/Bill-Billion/jingjing/pull/39) 集中交付；没有新增接口、迁移或依赖。

## 本批页面

- 网页工作区由弹出抽屉改为侧栏内的功能树。54 个入口归入账号与个人服务、人物与作品、影片与许可交易、商单与通告、故事与共创、制作与发行、财务与运营七类；父级有对应语义图标和展开箭头，子级缩进。点击或键盘操作展开／收起，支持全部收起、名称／分类搜索及无结果提示。当前分类自动展开，身份和草稿离开保护继续沿用。
- App 广场、全部作品、详情及网页现货目录、详情接入 `media` 和 `cover`：完整影片、预览分别显示真实时长；只展示已审核预览的首帧，保留画面比例。核对账号、版本、来源、类型、大小、SHA256、图片解码及尺寸后才显示。
- 只读取可见卡片，App 串行、网页最多两项并发；媒体仅保留在内存。换身份、换记录／版本、退出、权限失败时清除旧展示；迟到回复和旧图片错误回调不能覆盖新状态。失败显示暂不可读取，可手动重试，不写默认时长或循环请求；原预览入口独立。
- 本轮实际发现并修复：网页离开通用业务页到艺人页时，旧组件在卸载前读取了新路由的空业务定义；现在保留最后有效上下文并停止离页读取。下架／授权变化有专用提示，未读取有效商品及许可时禁用购买入口，避免引导重复发起。

## 验证

网页完整 `npm test` 411 项通过；最后购买入口保护补充后，相关业务 83 项及媒体 14 项再通过。类型检查与发布构建通过，既有大包体积提示保留。

App 按仓库 CI 清单运行 701 项通过；随后自审发现旧图片错误回调可能清掉新图，补充重现并修复，最终媒体专项 18 项通过。最终静态分析无问题；普通 `main.dart` 和隔离验收入口均构建成功。分析使用与源码逐字一致的 364 文件 ASCII 路径镜像，避免本机中文路径的分析协议错误。末尾局部修正未再次宣称已跑全部清单。

浏览器使用真实后端、一次性数据库和合成账号，未修改甲方数据。实际办理：

1. 两端列表、详情读同一作品：完整片红色 2 秒，已审预览蓝色 1 秒；封面为蓝色，分别显示 2／1 秒。
2. 注入文件损坏，重新读取后清除封面与时长；修复文件后手动重试恢复。App 原预览另行打开成功。
3. 网页媒体延迟 5 秒期间切换办理身份，旧图立即清除，随后仅显示新上下文结果；App 身份／退出／迟到响应由专项测试覆盖。
4. 创建绿色预览的新修订，未审核前公开目录仍只有旧批准版；旧记录版本变化时 App 清图并要求重读。新版本双审后两端改为绿色封面，完整 4 秒、预览 3 秒；旧记录刷新后不可继续展示。
5. 下架新版本，两端刷新后清除图和时长；网页最终构建显示“作品当前未公开销售，请返回选购影片列表查看当前作品”，购买入口禁用。
6. 桌面 1280 宽、手机 390 宽实际检查功能树、分类图标、展开／收起、键盘、搜索、无结果、当前分类及无横向溢出。最终构建从现货跳至艺人页不再新增控制台异常；App 控制台未见异常。

原导航浏览器脚本已同步 54 个入口／7 个分类及实际可见性检查，业务和权限断言保留。13 个根目录受影响脚本及独立定制脚本语法检查通过；本机未重新执行历史整套浏览器脚本，远端结果按本次提交核对。历史截图不能代替本次新图。
