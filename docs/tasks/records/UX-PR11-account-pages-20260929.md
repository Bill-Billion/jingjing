## 计划与职责

本任务负责 Flutter 与 Vue 页面、前端请求处理、相关测试和本记录。复用用户在 `jingjing-ux` 目录的网页基础工程，原目录和未提交内容保持原样。

范围：短信登录和退出、账号与身份切换、机构创建/改名、能力申请、成员邀请及接受/拒绝/撤回、成员列表与移除。旧业务页面及后续阶段接口不扩展。机构审批、所有权转移、真实短信开通不在现有 #11 接口内。

沿用 #11 的现有业务规则，不新增商品价格、佣金或商业权限决定。邀请到期时间由操作者明确选择；机构及能力申请展示实际待审状态。新会话与旧账号、旧令牌隔离；请求失败不回退演示成功。

## 已实现的页面

| 页面 | 本次接入内容 |
| --- | --- |
| App 登录页、网页登录页 | 实际申请验证码、校验登录、显示发送失败；不再通过体验令牌登录新账号 |
| App“我的”、网页账号工作台 | 账号编号、个人/机构身份选择、退出登录；清除旧身份的延迟响应 |
| 机构管理 | 创建与改名、待审核状态、五类业务能力的申请及各自状态 |
| 邀请与成员 | 本人接受/拒绝邀请；负责人填写账号编号和截止时间发出邀请、撤回本次发送回执、分页查看和移除普通成员 |

所有实际业务判断继续由 #11 服务器执行。页面不提供审批、所有权转移或商业代理功能；普通机构成员不自动获得业务能力。后端没有发件列表接口，两端明确标注本次会话/标签页的发送回执范围。

App 新账号会话只存内存，重启需重新登录；网页使用标签页会话存储。App 登录新账号后，尚未接入的旧订单、钱包、创作和消息入口显示接入提示，避免混用旧令牌及旧数据。此限制会在对应后续页面接入时逐项解除。
