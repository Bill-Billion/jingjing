# 第二阶段：账号、机构和成员邀请可以通过接口调用

第一阶段已由Bill-Billion合入共同版本7d139ff。本侧从这个版本新建core/stage-2-account-api，完成后端实现和本机检查，现在集中交付。没有修改队友页面，没有发真实短信，没有部署。整组账号权限工作仍在进行，本次不是整个产品完成。

## 这次能做什么

1. 申请短信验证码、校验登录、查询本人账号和退出。验证码错误次数、发送频率、会话过期及撤销都保存在MySQL，服务重启不会绕过限制。真实短信未配置或未验证时明确失败。
2. 查询个人/机构身份，创建待审机构、改显示名、申请多种待审业务能力。身份切换只选择操作身份，不增加权限。
3. 机构负责人邀请指定账号，被邀请人本人接受或拒绝；负责人可以撤回邀请、查看成员、移除普通成员。邀请不自动绑定，更不授予商业代理或收款权。
4. 提供可独立启动的新服务、分页、错误提示和重复提交保护。页面只依赖接口文件，不依赖数据库字段或后端内部函数。

## 实际检查结果

本机使用真实MySQL和本机HTTP，短信供应商由测试替身代替。账号接口专项19项通过；完整回归148项通过、1项因缺脱敏旧SQLite样本跳过。数据库16、后台任务21、外部服务21、账号机构18、旧问题31项专项也全部通过；各组有重叠，不能相加当成产品完成数。

检查了同时请求只发一次、验证码只消费一次、错误次数持久保存、重复登录返回原会话、过期/退出/停用限制、跨账号越权、旧令牌及伪造角色拒绝、邀请接受/拒绝/撤回、移除不删除个人身份、分页限制和隔离、审计失败整体回滚、真实启动入口及过期认证数据清理。19份实际HTTP返回通过接口格式检查，接口校验669项通过。

初次检查发现过期会话清理与登录结果外键顺序不一致，已修复为先清理关联结果；启动入口测试曾被同一测试库中已有的发送限额拦截，已让该测试明确沿用隔离测试配额，不更改运行时默认限制。通过结果来自修复后的完整重跑。

## 数据升级与出错恢复

只新增0015–0019五份迁移，不改0001–0014。会话、验证码摘要、重复登录的加密结果和限流记录独立保存；不引入新npm依赖，不把旧SQLite账号自动当成新可信账号。

正式升级前仍须备份与恢复演练，本轮仅操作隔离测试库。若接入测试出现问题，停止新的账号服务并回到已验证代码，保留新增表及数据供排查；不能直接删表后宣称账号仍可登录。旧服务不兼容新会话，代码回退不等于账号数据回退。真实环境的数据恢复方案须在部署阶段另行验证，本轮没有执行生产回滚。
