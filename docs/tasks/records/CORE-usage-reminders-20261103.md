## 本批目标与需求依据

37号材料“使用时长管理与防沉迷”原文：“提供使用时长统计、休息提醒、夜间提醒；用户可开启\"定时休息\"\"夜间免打扰\"。”原文另写：“推送可自助关闭或设置免打扰时段；营销推送不得高频骚扰，提供一键退订。”来源：[合同提取原文](../../sources/contracts-20261029/extracted/37.md)。

核查发现 rest_reminder_minutes 仅保存设置，没有服务端时长统计和到时提醒接口。此轮先完成可独立验收的休息提醒后端：本人开启后，前台定期报告仍在使用；服务端计时、跨端合并、提醒和本人确认。夜间免打扰、实际外部推送、高频消费强制确认另行列出真实缺口，不用一个设置字段冒称全部执行。

## 实施建议及边界

- 前台建议30秒报告一次；超过90秒无报告视为离开，离开时间不计入连续使用。30/90秒为实施建议，不是甲方原定数字。
- 只存本人当日累计和当前提醒状态，不保存页面、浏览内容、定位或逐次活动轨迹。当前统计不是准确屏幕使用监控，也不作为未成年人限制或财务依据。
- 定时休息关闭时停止计时并清除当前统计；旧客户端保存偏好仍兼容。账号不同、身份切换不会读到别人的记录。
- 本人确认“已看到提醒”只重置下一次提醒计时，不能冒称已经实际休息。
