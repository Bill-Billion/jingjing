# 制作途中撤回授权：补齐迟到结果的处理

本轮从0756c14继续，工作目录worktrees/privacy，分支core/v5-privacy-protection。开工目录干净，origin/integration仍为28662ab。本侧负责服务器和隔离测试；队友页面不在本轮代改。按阶段保存本地提交，不逐项推送。

问题：数字人创建已经发给供应商后，用户撤回授权，原程序会连查询旧任务结果也一并阻止。供应商可能已经生成模型，平台却没有登记它，后续无法选择删除。

本轮处理：

- 撤回后尚未发出的创建任务继续禁止发出。
- 对已经尝试发送的创建任务，只按原任务查询结果，不重新创建，不改变供应商、环境或主体配置。
- 收到迟到的模型结果后，保存为“需要删除”，不能投入新制作；保留具体模型和任务关系，接入已有的本人模型列表和删除操作。
- 撤回不直接冒充物理删除。本人仍通过已有删除操作确认具体模型；原合同、付款、其他文件和整个申请的完成状态不随之改写。
- 渲染任务仍须完整授权，不因允许查询旧创建任务而恢复渲染。

验收：首次发送前撤回、发送途中撤回、旧任务查询、配置变化、未确认结果、事务失败、重复回执与失效执行权；核对原制作和隐私测试。没有调用真实供应商。

本轮也检查PR24实际代码范围、自动检查及合并状态，另记前端核对报告。前端未上传的本地进展无法据远端判断。账号注销、原始资料清理、投诉处置、素材机审和文件标识继续保留在缺口清单，正式隐私依据仍待甲方补充。
