## 给前端伙伴的直接接法

获取原PR39完整分支，在自己的目录合并并保存已有改动；不要只取页面文件，也不要把原integration后端当作本次服务器。使用隔离测试配置执行既有迁移命令，新增表为0166销售说明；不得手动改生产数据。

|页面需要做的事|本次可调用接口（统一前缀 `/api/v1`）|主要注意点|
|---|---|---|
|卖家第一次选择商品及销售说明|`GET /stock/sales-publications`|当前办理身份；按选定规格过滤规则，保留分页。平台发布与独立复核另走同名POST及`/:id/reviews`。|
|机构逐人选择出镜形象|`GET /stock/participant-options?person_id=...`|同时核对机构经营委托与本人同意；不能用旧作品推断授权。|
|退回作品另存新版本|`POST /stock/listings/:id/revisions`|提交读到的原版本和同次操作标识；成功返回新编号，原已购承诺保留。|
|第一次选试镜规则与公开授权|`GET /auditions/offer-options?person_id=...&kind=RULE`或`AUTHORIZATION`|按具体人物查；换人物清掉旧选择；选择为空不自动借用历史方案。|
|本人选择删除原始文件|`GET /privacy/requests/:request_id/file-options?kind=FILE`或`POLICY`|本人账号，不带机构办理身份；受依赖阻止的文件说明原因。原件读取`.../files/:asset_id/content`。|
|显示本次到底删除什么|既有执行方案返回`target_summary`|显示文件名称、类型、大小和依赖；旧方案缺可读对象时不开放盲删。|
|分别显示累计与可用晶钻|既有钱包汇总增加`cumulative_points`|累计发放减撤回；旧服务器未返回就说明暂无口径，不用余额代替。|
