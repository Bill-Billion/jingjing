## 做了什么

- 订单明细对应制作项目，指定当前负责人；开工须独立核验外部签署、身份及权利材料，并核对真实付款记录。已购剧本还检查实际许可、项目绑定与制作权。
- 私有文件上传保存摘要；剧本、样片、粗剪、成片分别保存不可改写的版本。独立审核后，买方才能确认或提出修改。改动上游版本会使下游旧确认失效。
- 修改次数采用订单中明确保存的规格，统计买方要求修改次数，不把制作方内部上传次数当收费次数；不默认未知商业参数。
- 样片确认、成片验收与实际付款彼此独立；最终原件仅在尾款核实到账且当前成片已验收后可下载。退款、权限失效或授权撤回会阻断后续使用。
- 长期数字人任务持久保存、超时查询原任务、防止重复提交；创建要求训练同意，已购剧本AI处理另需许可。撤回后阻断生成并将已知资产标为待删除，不能把该标记当真实远端删除。
- 15个新增页面接口，新增数据库迁移0050至0054；任务重试可加入业务事务，旧调用兼容。旧接口结构保持，付款节点新增真实制作验收检查。

## 怎样检查

运行 node scripts/backend-check.cjs all；制作单模块可运行 node scripts/backend-check.cjs production。检查包含真实隔离MySQL与HTTP、并发反馈、上传重复请求、付款与下载门槛、审核不能自审、失效许可/同意、工作进程租约丢失和重复恢复。许可测试另覆盖实际付费组合订单中的改稿进入制作。

最终数量与七组实际HTTP格式检查保存在同目录stage7证据JSON。缺脱敏旧库样本的既有回归项仍跳过，不当作通过。
