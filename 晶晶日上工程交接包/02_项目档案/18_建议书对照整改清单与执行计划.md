# 18 · 《商业模式与技术架构建议书》对照整改清单与执行计划

> 版本 V1.0｜2026-08-31｜依据：博士朋友《晶晶日上 商业模式与技术架构建议书 V1.0》（事实基准 08-29 P0 总结）+ 08-30/31 实际开发成果（档案 13–17）。
> 本文件是后续整改的唯一任务源（SSOT）。原则：**不推倒重写、不拆微服务、不一次性大重构；每步先测试后改、保持 analyze/回归全绿、线上变更先备份可回滚；外部能力只做适配层骨架，不臆造密钥、不替用户采购。**

## 一、总判断
建议书专业、方向正确，但其"前后端未联通 / 测试少 / Mock 支付 / 无运维"的判断基于 **08-29 快照**；08-30/31 已销项其中一大批。真正剩余的是：① 数据库迁移机制与 MySQL、② OSS 私有存储、③ 实名活体/内容机审真实供应商、④ 支付退款与对账闭环、⑤ OpenAPI 契约与 Provider 可替换层、⑥ staging/告警外发/iOS。业务范围上**采纳"功能保留、真实资金交易先收敛到 C 端个性化视频、定制剧/圆梦线上只收意向线下撮合"的折中路线**（与老板"定制剧线下撮合"原话一致），去金融化口径已基本落实。

## 二、对照表
### A. 已销项（建议书担心、现已达成，勿重复做）
- 前后端联通：登录/统一订单/数字人/AI/钱包/使用报告/售后/评价均在线走真后端，断网 Mock 兜底。
- 自动化测试：Flutter 91（交互点击流+三档布局+单元）；后端 58 服务器回归+17 公网+33 支付沙箱。
- 运维底座：PM2 守护+开机自启、每日热备并实测恢复、15min 健康巡检、logrotate、脱敏日志、上线前备份可回滚。
- 支付骨架：官方 alipay-sdk、验签/幂等/服务端金额权威/重复回调不重复入账/查单补账（真实密钥待用户）。
- AI 异步：任务表、创建-轮询-转存、重启续跑、并发/重试/成本流水/日熔断、前端阶段进度。
- 去金融化措辞：settings/projects/project_detail/sample_order_detail/glow_panel/后端 projects 均已写"定制消费非投资、不承诺货币回报、席位=交付名额"。

### B. 半成品（方向对、要补完）→ 批次 1
- 资金：缺**渠道退款状态机、每日对账、账务守恒校验**。
- AI 任务：轮询有、**Webhook 端点、成片机审后交付、交付物版本化（重做不覆盖）缺**。
- 供应商可替换：火山/支付宝为唯一硬绑定，**缺统一 Provider 接口**。
- 存储：本地 uploads + 预留 UPLOAD_URL_PREFIX，**缺 StorageProvider 与 OSS 实现骨架/签名 URL**。
- 建表：db.js 启动隐式 CREATE/ALTER，**缺版本化可回滚 migration 机制**（MySQL 切换前置）。
- 契约：有手写 validate schema，**缺 OpenAPI 主链路契约文件**。
- 合规漏网：`routes/theater.js:49 tags:['可投资','可参演']` → 改"可认领"（前端标签取自后端，一处即净）。

### C. 硬缺口（依赖外部采购/账号/设备）→ 批次 2
- MySQL 8.0 实例与实际切换（先在服务器自建或买 RDS，二选一需老板定）。
- OSS 私有桶（阿里云 OSS/火山 TOS）+ 密钥。
- 实名活体供应商、内容机审（文本/图/视频）供应商测试账号。
- 支付宝 APPID/PID/公钥或三证书 + 沙箱买家账号（真实沙箱联调、退款、对账）。
- 正式域名 + ICP 备案 + HTTPS 证书（域名老板购买中）。
- iOS 构建：**当前 Windows 物理上无法出 iOS 包，需 Mac/Xcode 或云 Mac**。

### D. 路线分歧（已按折中定调，不再反复）
- 定制剧/圆梦/剧场等功能代码全保留（差异化资产）；但**真实资金交易先只开 C 端个性化视频**，定制剧/圆梦线上仅"展示+意向（可退意向金）+线下撮合"，不做线上全额成交、不做收益权/票房分成/众筹式售卖；"投资/认购/回报"统一为"认领/支持/鸣谢"消费口径。

### E. 我们额外已有（建议书未强调）
追光 UI 体系与高保真效果图、AI 成本日熔断、网络白名单收敛、服务器运维脚本固化、企业资质与火山能力实跑核查。

## 三、批次 1 任务单（纯代码、不依赖采购，立即执行；每项必须带测试/回归、保持全绿）
| 编号 | 任务 | 动作要点 | 验收 |
|---|---|---|---|
| B0 | 合规净尾 | theater.js 标签改"可认领/可参演"；全工程再扫 投资/收益权/票房/分红/众筹/年化/回报 | 仅余"非投资/不承诺回报"等否定式合规说明 |
| B1 | 版本化迁移 | db.js 隐式建表/ALTER 抽为 migrations（up/down、schema_migrations 版本表、启动幂等迁移到最新、可回滚）；现有 59 表数据平滑不丢；预留 SQL 方言层为 MySQL 铺路（本批不切 MySQL） | 全新库与现有库都能迁到同一版本；down 可回退；后端 58 回归全绿 |
| B2 | Provider 适配层 | 定义 Payment/Storage/Identity/Moderation/Avatar/SMS Provider 接口；现有 alipay/volc/volcSpeech/volcVisual/smsService/本地存储包成默认实现；业务路由只依赖接口；未配置供应商时优雅降级 | 切换实现不改业务路由；缺密钥不崩；新增对应单测 |
| B3 | StorageProvider | 本地实现=现状；OSS 实现读 env（endpoint/bucket/AK/SK/私有），putPrivate/signedUrl/delete；未配置走本地、不暴露永久公共地址方法位 | 本地链路不变；OSS 未配置时行为与现状一致 |
| B4 | 资金可对账 | 订单/支付/退款/结算状态分离核对；退款"先申请渠道、以渠道结果更新本地"，渠道未配则留痕不假装成功；新增账务守恒校验（实收=已退+待结/已结+平台+渠道税费）与每日对账任务，差异落表/日志 | 构造平账与差异用例单测通过；不改动既有金额口径（DB 分、API 元） |
| B5 | AI 交付治理 | 交付物版本表（重做新增版本、保留旧文件与原因，不覆盖）；新增 provider webhook 接收端点（与轮询并存、幂等、验签位）；成片先过 ModerationProvider（本地敏感词实现，供应商后接）才置为可交付 | 重做产生新版本；webhook 重复回调幂等；未过审不进交付 |
| B6 | OpenAPI 主链路 | 产出 openapi.yaml，覆盖 auth/sms、humans、videos、orders/all、pay、ai、samples 的请求/响应/枚举/错误码；与现有字段逐一核对修正漂移 | 契约与路由一致；列出尚未覆盖清单 |
| B7 | staging/告警 | 服务器起 3100 预发实例连独立库、不影响线上；告警做可配置外发通道（env webhook，未配只落日志），覆盖支付异常/AI 大面积失败/5xx/磁盘/进程 | 预发可访问且与线上隔离；触发一条测试告警走通通道 |

约束：不改商业价格与既定流程；不碰火山短信控制台（另有任务）；不买云服务、不臆造密钥；中文只用 Edit/Write/Node 精确补丁、禁 PowerShell 管道读写中文；Flutter  analyze=0、flutter test 全绿；后端 node --check + 服务器 58 回归；线上改动走"备份→上传→校验→重启→回归→可回滚"SOP（Node ssh2 通道，见 work/deploy/ops）；真 SDK C:\src\flutter + JAVA_HOME=C:\src\jdk17 出包。每完成一个 B 项即在本文件追加"实施记录（状态/证据/遗留）"。
