## 二、阿里云 SDK 选型（以 node_modules 内 d.ts 实测为准，不凭旧文档记忆）

本地与服务器均用 npmmirror 安装，共 71 包，核心 5 个：
`@alicloud/openapi-client`、`@alicloud/tea-util`、`@alicloud/credentials`、
`@alicloud/cloudauth20200618@2.0.4`、`@alicloud/green20220302@3.4.4`。

**关键事实：cloudauth 2.x 方法名已重构**，不存在旧文档的 Id2MetaVerify/InitFaceVerify：
- 二要素：`elementSmartVerify(req)`，结果 `body.code==='200'` 且 `resultObject.passed`（'T'一致/'F'不一致）。
- 人脸核身：`initSmartVerify(req)`→`resultObject.certifyId`；`describeSmartVerify({certifyId,sceneId})`→`resultObject.{passed,passedScore,subCode}`（本期纯 API 照片比对闭环；未来动作活体/H5 走 metaInfo）。
- 内容安全 2.0 green：统一 `{service, serviceParameters(JSON字符串)}` 模型；`textModeration/imageModeration` 同步、`videoModeration`(提交拿 taskId)+`videoModerationResult`(轮询)异步；`body.code===200`、`body.data.labels`（空/nonLabel/none/normal/pass 为干净）。

- `services/providers/faceVerify.js`：`initVerify/describeVerify`；passed 且 `passedScore≥阈值(默认80)` 才 true；**结果无 passed 字段判 null=处理中（不是不通过）**。
- `routes/faceverify.js`：`POST /init`（登录；校验 human 归属+必须先实名 approved，解密身份证号，调 init，写 face_materials 台账，未配置 503）、`GET /result/:certifyId`。已在 app.js 挂载 `/api/face-verify`。
- `scripts/aliyun_compliance_selftest.js`：32 项可复跑自测（临时库+隔离端口+mock 阿里云，不触网）。

**重写**
- `config.js`：新增统一 `aliyun` 段（一套 RAM AK/SK 共用；elementSceneId/faceSceneId/facePassScore；green 三个 service 名可 env 覆盖），兼容旧 MODERATION_API_KEY/SECRET。
- `services/providers/moderation.js`：文本=云优先+本地词库双保险（云故障回退本地）；图片=云同步否则人工；视频=云异步提交后人工；补全涉政/违法本地兜底词库；`greenReady()` 只看是否配 AK（配了即用云，`MODERATION_ENABLED=false` 可强关）。
- `utils/contentModeration.js`：由"未配置即通过"的隐患孤儿模块改为转调 providers 层的薄封装，保持 `{pass,score,reason}` 外形并补 decision/needsHuman/provider。
- `routes/identity.js`：先校验 18 位身份证格式；ready 且 passed=true→approved/`verifiedBy=aliyun_element`，passed=false→rejected"姓名与身份证号不一致"，passed=null(云故障)→pending 转人工；**未配置云维持历史"自动 approved"但标 `verifiedBy=unverified_auto`（=线上现状降级，Key 到自动升级）**；身份证号用 `utils/crypto` AES-256-GCM 加密落库，`/status` 只回掩码不回明文/密文。
- `routes/compliance.js`：`/sign` 改 async；ready 时用 livenessTxnId(=certifyId) **服务端再复验一次**——false→403、null→409、true 才放行并回写 `face_materials.liveness_verified=1`；**production 未配置仍 501（安全红线不变）**；非生产未配置保留长度≥8 演示。
- `routes/review.js`：`submitReview` 升级 async，建 content_reviews 后按类型调机审；**只有 reject 才自动打回业务表**（video/endorsement→review_status=rejected，human→status=rejected），pass/review 一律置 machine_done 进人审队列（云只拦截、不做最终放行）；机审异常 catch 成 review 不崩。

**修改**
- `routes/videos.js`、`routes/endorsement.js`：交付 handler 改 async，原手写 INSERT content_reviews 块替换为 `await submitReview('video'/'endorsement', order.id, userId,{url}).catch(()=>{})`（机审异常不阻断交付）。
- `.env.example`：追加 V12.5 阿里云段（全部空值/默认，无真实密钥）。

## 六、缺 AccessKey 时的行为对照（安全降级，已实测）

| 路径 | 无 AK（当前线上） | 填入 AK + 场景 ID 后 |
|---|---|---|
| 个人实名 | 自动 approved，标 unverified_auto（=原现状），身份证加密存储 | 公安二要素权威核验，一致才 approved |
| 授权签署 /sign（生产） | 501（红线不变） | 服务端云端核身复验通过才签署 |
| 文本审核 | 本地敏感词库 | 阿里云 green 优先 + 本地双保险 |
| 图片/视频审核 | 转人工队列 | 云机审拦截 + 人工终审 |
| face-verify/init | 503 | 返回 certifyId 进入核身 |

## 七、需要老板提供（只写服务器 .env，不进仓库/前端/聊天）

1. **RAM 子账号 AccessKey ID/Secret**：建议仅授予 `AliyunCloudauthFullAccess` + `AliyunYundunGreenFullAccess` 最小权限（不要用主账号 AK）。
2. 开通**实人认证（cloudauth）**：分别创建「要素核验（身份证二要素）」「人脸核身」两个认证方案，各拿一个数值型 **场景 ID**（对应 CLOUDAUTH_ELEMENT_SCENE_ID / CLOUDAUTH_FACE_SCENE_ID）。
3. 开通**内容安全 2.0（green）**：确认文本/图片/视频实际开通的 service 场景名（默认 comment_detection / baselineCheck / videoDetection，如控制台不同以控制台为准覆盖）。
4. 拿到后把 `ALIYUN_ACCESS_KEY_ID/SECRET + 两个场景 ID` 发我，我只在服务器 .env 回填、pm2 restart 即全量生效，并做一次真实二要素+机审联调。
