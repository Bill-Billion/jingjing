## 一、为什么升级（现状问题诊断，逐条要解决）

交互骨架已达标，本轮只解决 4 类**视觉/品牌**问题，不许以"重做"为名破坏已闭环功能：
1. 首页/列表艺人卡出现**大面积纯黑空块**（封面无兜底）——必须做到任何状态都不死黑：真人封面 / 深蓝灰玻璃骨架微光 / 品牌渐变+线性人像占位，三选一兜底。
2. **品牌不统一**：旧 Logo 是粉橙玻璃「晶」、全站却是金色、登录页场记板像第三套语言。本轮统一为「曜石 + 香槟金日出光束」一套语言，**旧粉橙 Logo 停用**。
3. **图标三套混用**（实心金圆 / 线性描边 / 第三方彩色）——统一为"线性 1.8 描边 + 玻璃圆芯"，第三方登录改玻璃描边单色圆。
4. **黑金闷、平、缺景深**——用曜石蓝黑分层 + 克制液态玻璃悬浮卡 + 顶部内高光表达 Z 轴；金色改为"配给制"，只点主 CTA/选中/关键数据/品牌。

## 二、设计总原则（视频理念 → 本 App）

1. 一屏一主角，层级靠"明度 + 字重 + 玻璃景深"拉开，不只靠字号。
2. 可点元素六态齐全（沿用 PrimaryButton：默认/按下0.97/禁用/加载/成功/失败），玻璃元素按下时**轻微提亮**（像光被触摸激活）。
3. 高频操作落在下 2/3 拇指热区；主 CTA、下单、发送固定底部悬浮玻璃操作栏。
4. 预测用户意图、统一卡片结构（上封面/主信息、中标题标签、右下操作或价格），形成"不用学"。
5. 快比炫重要：动效为引导/状态/层级服务；玻璃与动效都要克制，**绝不为炫技做大面积流动炫光**。

### 3. 关键 bug 与教训（务必记住）
- 首版在 `_FadeSlideInState.initState / CountUpText.initState` 里调用 `Motion.reduced(context)`（内部 MediaQuery.of），Flutter 禁止在 initState 依赖 InheritedWidget，导致所有挂载页抛异常、124 测试一次性崩掉 100 个。
