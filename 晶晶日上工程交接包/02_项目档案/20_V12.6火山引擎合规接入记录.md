## 4. 人脸核身（visual CertSrcFaceComp）实现要点

- **契约适配**：CertSrcFaceComp 是「姓名+身份证号+本人照片」一次性同步有源比对，而既有路由是 init→describe 两步。实现为：`initVerify` 在服务端即用实名姓名/解密后的身份证号 + 本人照片发起一次权威比对，生成一次性流水号（作为 certifyId / livenessTxnId）并把云端结论缓存 5 分钟；`describeVerify` 按流水号取回服务端已得到的结论。`/sign` 服务端复验只信该缓存结论，客户端回传不作为依据。
- **请求**：`req_key=cert_src_face_comp`、`idcard_name`、`idcard_no`、`image`（base64，**自动剥离 `data:...;base64,` 前缀**）；支持 base64 直传或 URL 抓取转 base64；纯 metaInfo 的 H5 动作活体流程（cert_h5_config_init→cert_h5_token→h5-v2.kych5.com）留后续扩展，当前显式返回未实现、不伪造。
- **响应三态判定（fail-closed）**：
  - 成功 `code/status=10000` 且 `data.result=true` 且 `source_comp_details.score ≥ 1e-4` → `passed=true`（缺分值时只信 result）；
  - `algorithm_base_resp.status_code=210207`（姓名身份证不匹配）/ `210311`（人脸不匹配）→ **优先判 `passed=false`**（真实 API 命中子码时顶层 code 可能非 10000，故子码优先于顶层码）；
  - `result` 缺失 / 未知子码 / 顶层非 10000 / 坏响应 / 网络异常 → `passed=null`（处理中或无结论），**绝不判通过**；`result=true` 但分值低于阈值 → 不通过。
