# 10 三端角色逻辑三轮走查 · 自测问题清单 · UI 提升方案（V12 改造依据）

> 2026-08-30。起因：V11 云端版真机评估仅 30 分，核心不是"没联网"，而是**四种角色被塞进同一个 APP、职责边界混乱**，叠加素材/图标/UI 问题。
> 本文先梳理对齐、经确认后再统一改造，禁止在逻辑未清时直接打包。

## 〇、一句话结论

当前是「一个 App 同时扮演 买家 / 艺人 / MCN / 平台」四种角色，入口和数据互相串线。目标是**角色分层**：C 端 APP 只服务"消费+成为艺人"，MCN 用独立 H5 后台，平台用独立管理后台，艺人是 C 端内的"创作模式"。

---

## 一、四个角色的职责定义（第 1 轮：定边界）

| 角色 | 是谁 | 核心诉求 | 载体 | 能做 | 明确不能做 |
|---|---|---|---|---|---|
| **C 端买家** | 普通消费者 | 买祝福/代言/剧场席位，收视频、复购、分享 | C 端 APP | 逛、下单、付款、私信订单、收货、评价、售后、退票 | 看不到平台抽成/AI成本/艺人到手/个税；不选"MCN身份" |
| **艺人（供给侧）** | 真人开通数字分身接单的人 | 建分身、定价、接单、制作交付、看收入提现 | C 端 APP 内"创作中心"（同一账号切换身份） | 试镜建数字人、套餐自定价(≥99)、接单、交付、钱包/提现、保证金、数据 | 不是另一套 App；与买家身份用"模式切换"区分 |
| **MCN 机构** | 签约多名艺人的公司 | 管艺人、看汇总数据、统一结算分钱、开票 | **独立 H5 管理后台**（PC/手机浏览器，不进 C 端下单链路） | 旗下艺人列表/上下架、汇总看板、批量提现、分账规则、粉丝画像、导出 | 不以"MCN 身份"去 C 端下单；不在 C 端 APP 内承载管理重功能 |
| **平台（我方）** | 晶典传媒运营 | 审核、风控、仲裁、定价规则、资金、内容合规 | **独立平台管理后台（Web）** | 艺人/内容/资质审核、订单仲裁、保证金、抽成配置、风控、数据大盘、对账、公告 | 业务逻辑不写死在前端；所有资金动作留痕 |

**关键原则**
1. 买家侧只出现"我要付多少"，分账（平台服务费/AI成本/个税/艺人到手）只出现在**艺人端与平台端**。
2. "身份"不是下单选项。个人/企业是**发票抬头类型**，且只在需要开票时收集；MCN 是后台账号类型，与下单无关。
3. 同一自然人可以既是买家又是艺人：用"我的 → 创作中心/切换为艺人视角"进入供给侧，而不是把艺人功能平铺给所有人。

## 二、三轮走查发现（第 2 轮找错位 · 第 3 轮走闭环）

### 第 2 轮：角色错位（放错了端 / 串了数据）
- **D1 下单页让买家选「个人/企业个体户/MCN机构」**（`video_order_page.dart:267-295`）。MCN 出现在买家下单身份里，属根本性错位；个人/企业也不该在下单时选。
- **D2 下单页向买家展示分账明细**（`video_order_page.dart:298-311`：平台服务费、AI制作成本、代扣个税、艺人预计到手）。商业机密外泄 + 买家困惑，必须移除，改为只显示"商品金额/优惠/实付"。
- **D3「我的数字人」跳到艺人广场**（`profile_page.dart:56` 路由 `/humans` → `HumansPage`）。买家"我的"里没有"我拥有的数字人"概念，路由错误。
- **D4 MCN 重功能嵌在 C 端 APP**（`profile_page.dart:64` 入口 + `mcn_page.dart`）。按新边界应剥离为 H5 后台；C 端只保留"机构入驻"引导。
- **D5 MCN 看板字段与后端/Mock 三方不一致**：前端读 `totalRevenue/monthRevenue/artistCount/pendingWithdraw`，mock 给 `totalIncome/monthIncome/talentCount/withdrawable` → 在线/演示都会显示 0；且艺人头像只画了 `Icon.person`（`mcn_page.dart:201`），多个按钮是假 SnackBar。
- **D6 平台端缺失**：后端有 `/api/admin/*`，但前端没有任何平台管理界面，审核/仲裁/风控无操作入口。

### 第 3 轮：业务闭环断点
- 买家闭环 浏览→下单→**支付（未接，仍是弹框）**→制作→交付→评价/售后：支付断、订单状态推进靠 mock。
- 艺人闭环 试镜建分身→**真人脸授权链（直传方舟被风控，未通）**→定价→接单→交付→结算提现：建分身/交付未真实打通。
- 资金闭环 担保交易→分账→个税→提现→开票：前端把分账错误展示给买家；微信/支付宝分账未接。
- 登录闭环：登录后 `profile_page` 用户名仍写死"体验用户/未登录"、统计写死 ¥1286.5（`profile_page.dart:116,162-166`），没读登录用户与真实钱包。
- 单位口径：`mock_data.wallet()` 用"分"（128650），下单/我的页用"元"，全局分/元不统一，易出金额错误。

## 三、自测问题清单（按严重度，含定位）

### P0 逻辑/阻断（必须改）
1. D1 下单身份三选一含 MCN —— 删除 MCN，个人/企业改为支付后"发票抬头"可选项。
2. D2 买家侧分账明细外泄 —— 删除，买家只看实付；分账迁到艺人端订单详情。
3. D3 我的数字人路由错误 —— 重构"我的"信息架构（见第四节）。
4. 在线素材是卡通：云端 `uploads/avatars/avatar1-6.jpg` 为**紫发赛博动漫风**，APP 连云后首页显示卡通；而本地 `assets/images/artist_1-7.jpg` 才是电影感仿真人。**两套素材必须统一为仿真人**，并替换云端 seed。
5. APP 安装图标未做：`android/app/src/main/res/mipmap-*/ic_launcher.png` 仅 0.4–1.4KB 默认占位，需用"追光水晶"logo 生成全密度图标（含自适应图标）。

### P1 体验/数据一致性
6. profile 用户名、统计写死，未接登录态/钱包。
7. MCN 字段名前后端对齐、头像渲染、假按钮接真接口（剥离 H5 前先修数据）。
8. 全局金额单位统一为"后端存分、前端展示元"，写一个统一格式化函数，禁止散落硬编码。
9. 沈清辞"赛博朋克/赛博少女"人设与追光真人风冲突，人设与图一并改。
10. 品牌代言从"我的"进入未带 human（`/endorsement` 无参），页面可能空。
11. 加载/空状态/错误态缺失：联网慢时无骨架屏、失败直接回退演示，用户无感知。

### P2 视觉/交互（UI 提升，见第五节）
12. 页面转场生硬、卡片层级/留白/对齐不统一、列表精致度不足。
13. 启动图标、引导页、空状态插画、品牌水印等成体系设计缺位。

## 四、目标信息架构（改造后）

**C 端 APP 底部 5 Tab**：首页 / 艺人(广场) / 【中央＋创作】 / 剧场 / 我的
- **首页**：搜索+城市、Banner、场景金刚区、仿真人推荐流、剧场彩蛋入口。
- **艺人广场**：仿真人卡片（真实头像/评分/等级/起订价/同城），筛选与排序。
- **中央＋**：买家=快速下单/上传脸试镜入口；已是艺人=快捷接单/交付（按身份呈现）。
- **我的（买家视角，重构）**：
  - 账号区（真实昵称/手机号/认证徽章，点按可"切换到艺人创作视角"）
  - 我的订单、我收到的视频、我的消息、我的收藏、钱包（买家=充值/退款；艺人视角才是收入/提现）
  - 售后服务、优惠券、邀请
  - 成为艺人（试镜创建数字人）、**MCN 机构入驻（仅介绍+留资，跳 H5）**、设置
  - 不再出现跳错的"我的数字人"；"我创建的数字分身"只在**艺人创作视角**里。
- **艺人创作视角（同一 APP 内切换）**：数字分身管理、套餐自定价(≥99)、接单队列、制作交付、收入/分账/提现、保证金、艺人学院、数据。
- **MCN（独立 H5）**：登录后看旗下艺人、汇总收益/订单/粉丝画像、分账与批量提现、统一开票、艺人上下架。
- **平台后台（独立 Web）**：审核、风控、仲裁、抽成/保证金配置、资金对账、内容机审、公告。

## 五、UI 提升方案（延续唯一视觉「追光」，不再开新风格）

1. **设计基调**：影院深蓝黑 #0F1219 + 暖金三段渐变（#FFE3A0→#F5A623→#E0911A），衬线标题+无衬线正文，克制光晕、大留白、电影海报感。废弃一切粉橙/霓虹/赛博紫。
2. **APP 图标**：深色底 + 居中多棱暖金水晶（与启动页 `_CrystalPainter` 同源），做 adaptive icon（前景/背景分离），全密度替换 mipmap，安装后桌面图标即品牌。
3. **仿真人素材统一**：全部用电影感暖光真人肖像（对标 artist_1/3 的质感），自有虚构 IP；云端 seed 同步替换；卡片用统一比例（3:4 肖像）+ 圆角 + 暖金描边等级徽章。
4. **转场/动效**：全局统一页面转场（淡入位移 200–260ms，缓动 easeOutCubic）；卡片点击轻微缩放反馈(0.98)；列表加载用**金色微光骨架屏**；下拉刷新用品牌水晶旋转；Tab 切换内容区淡入。
5. **组件体系**：统一按钮（金色胶囊主按钮/描边次按钮/文字按钮三态）、统一卡片圆角(20/24)与边框、统一表单、统一徽章（S/A/B、金/银标、热度）、统一空状态（水晶插画+一句引导+行动按钮）。
6. **层级与信息密度**：每页一个主行动点；价格用金色衬线大字；买家页不出现分账；详情页用"头图—评分—套餐—样片—评价—下单"固定结构。
7. **折叠屏/平板**：延续 `responsive.dart`，宽屏双栏（列表+详情）、限宽居中、铰链避让（已具备，补齐细节）。
8. **投资人演示观感**：首屏 3 秒内看到仿真人+品牌质感；关键路径（逛→下单→出片）每步都有真实/高质量拟真数据与流畅动效。

## 六、改造顺序（确认后执行）

1. 冻结角色模型与信息架构（本文，待拍板）。
2. 改逻辑 P0：下单页去 MCN/去分账、重构"我的"、统一金额、接登录态。
3. 素材与图标：生成/替换仿真人（本地+云端 seed）、做 APP 图标与自适应图标。
4. UI 组件化与转场、骨架屏/空状态，整体过一遍视觉。
5. 艺人创作视角整合；MCN 字段先在 APP 内修通，随后迁 H5；平台后台单独立项。
6. 真机逐角色回归（买家/艺人/MCN/平台各走完整闭环），至少三轮，再出包。
