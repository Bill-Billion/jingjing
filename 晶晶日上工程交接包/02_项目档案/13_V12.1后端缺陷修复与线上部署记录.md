## 三、防复发机制（以后每次改后端必须走，固化进 SOP）

1. **动完写库代码必跑 schema 审计**：临时空库建表 + PRAGMA 真实列 + 扫描 INSERT/UPDATE 列，输出必须 NO SCHEMA DRIFT。不能只靠肉眼看建表语句。
2. **新增/修改路由必做"挂载核对"**：`routes/` 下每个文件都要在 app.js 有对应 `app.use`；本轮 contacts 就是"写了没挂"的典型，静态扫描 SQL 发现不了，必须单独核对路由表。
3. **引用 config 段必确认该段存在**：新增 `config.xxx.yyy` 时同步在 config.js 落定义，否则请求走到才 500。
4. **本地隔离冒烟先行**：SQLITE_PATH 指向临时库 + 独立 PORT + seed + 自签 token，走真实 HTTP 覆盖写路径，绿了再碰服务器；绝不在线上库直接试。
5. **上线四件套**：先备份 → SFTP 上传并做 MD5 字节比对 → `pm2 restart` 后验证建表/接口状态码/`pm2 logs` 无新错 → 公网经 Nginx 再打一遍。
6. **中文文件只用 Edit/Write/Node 脚本改，不用 PowerShell 管道**（会损坏中文编码）；CRLF 文件大块 Edit 易失败，用单行替换或 Node 精确补丁。
7. **临时探测/补丁脚本统一 `_` 前缀，交付前清干净**（本地源码目录与服务器都清）。
