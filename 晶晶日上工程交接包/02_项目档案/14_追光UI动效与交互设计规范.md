## 一、五条总原则（来自视频，逐条对应到本 App）

1. **层级一眼可读**：每屏只有一个视觉主角；标题/正文/辅助文字三级对比拉开；主要操作按钮永远最醒目且位置稳定，用户 1 秒内能找到"下一步点哪"。
2. **每个可点元素必须有状态反馈**：正常 / 按下 / 禁用 / 加载 / 成功 / 失败，六态至少给出视觉变化（按下缩放或变深、禁用变灰、加载转圈、成功轻提示）。不允许"点了没反应"。
3. **为单手拇指设计**：高频操作（首页主 CTA、底部导航、输入发送、下单支付）放在屏幕下 2/3 拇指热区；顶部只放低频的返回/筛选。
4. **替用户省思考**：能预测的就直接给（登录后直接回来源页、下单自动带上次地址/艺人、AI 生成直接出进度而不是空白页）；同类卡片用**统一结构**（上图/标题、中信息、右下操作），形成"不用学"的心智。
5. **快比炫重要**：动效为"引导注意/表达状态/交代层级"服务，纯装饰动效一律删；任何转场不得让用户觉得"卡、等、晕"。

## 二、动效量化规范（直接写进 Flutter，全 App 统一）

### 1. 时长 Duration（对应 Material/iOS，落地为常量，禁止随手写魔法数字）
在主题/动效工具类统一定义：
| 场景 | 时长 | 说明 |
|---|---|---|
| 微交互（按钮按压、勾选、点赞、开关） | 100–150ms | 反馈要"即时" |
| 组件内变化（颜色/透明度/小位移、Tooltip、SnackBar 进） | 180–220ms（默认 200ms） | 标准短动效 |
| 卡片/弹层/底部 Sheet 入场、下拉刷新 | 280–320ms（默认 300ms） | 移动端标准转场 |
| 整页右进左出（push 详情/下单） | 320–350ms | iOS 标准 350ms ease-out |
| 模态全屏页（登录、创建数字人、支付） | 400–450ms，末尾可带极轻回弹 | 模态"盖上来"的重量感 |
| 离场/返回 | 比对应入场短约 1/3（如进 320 / 退 220） | 离场不需吸引注意 |
| Tab 切换 | 150ms 淡入+轻微滑动，或直接切换 | 不做整页大转场 |
| 骨架屏微光、Loading 旋转 | 循环 1200–1400ms | 柔和不刺眼 |
| 折叠屏/平板（宽屏≥600dp） | 同类型 +50ms（位移更大） | 大屏稍慢 |

### 2. 缓动曲线 Curves（与时长配套，全 App 仅用这 4 条）
- 入场/元素进入：`Curves.easeOutCubic`（≈ cubic-bezier(0,0,0.2,1)，快进轻落）——页面 push、卡片浮现。
- 离场/元素退出：`Curves.easeInCubic`（≈ cubic-bezier(0.4,0,1,1)，慢起快收）——关闭、删除。
- 屏内位移/尺寸/颜色变化：`Curves.easeInOutCubic`（≈ cubic-bezier(0.4,0,0.2,1)）——展开收起、进度。
- 按压反馈：`Curves.easeOut`，缩放 1.0→0.97（已有 `PressScale` 组件，统一复用，不要各页各写）。
- 模态/成功勾选可用极轻 overshoot（0.98→1.01→1.0），**回弹幅度≤1.02，禁止 Q 弹、禁止弹簧乱晃**。

### 3. 转场方向语义（页面关系要"看得见"）
- 进入下一级（列表→详情→下单→支付）：新页从右侧 8% 位移 + 淡入 easeOutCubic；返回反向。层级越深越往右，用户始终知道"从哪来"。
- 模态（登录、创建数字人、筛选、支付确认）：从底部上滑 + 背景 30% 黑色遮罩淡入。
- 浮层（ActionSheet、菜单）：锚点/底部弹出；**Alert 居中淡入+轻微缩放**。
- 底部 Tab 之间：平行关系，只做 150ms 交叉淡入，不做左右滑动（避免误导层级）。
- 全局用 `PageTransitionsBuilder` 统一，不允许个别页面裸 `Navigator.push` 默认平台动画造成风格不一。

### 4. 性能与无障碍（硬约束）
- 优先 `AnimatedOpacity/AnimatedContainer/Hero/TweenAnimationBuilder`；**避免对 Blur(BackdropFilter)、阴影、大尺寸图片做逐帧动画**，长列表里毛玻璃只在固定导航栏用一次。
- 动画只动 `transform/opacity`（GPU 层），不动 `left/top/width/height`（触发 relayout）。
- 尊重系统"减少动态效果"：`MediaQuery.disableAnimationsOf(context)` 为 true 时，转场时长降到 ≤100ms 并关闭循环/回弹动效。
- 真机（低端安卓）验证：转场期间帧率不低于 55fps，掉帧就降级（去模糊/去阴影）。

## 三、组件反馈规范（六态齐全，对齐视频"控件使命"）

| 组件 | 必须具备 | 本 App 落地 |
|---|---|---|
| 主按钮（胶囊 CTA） | 默认/按下(缩放0.97+明度降)/禁用(灰、不可点)/加载(按钮内菊花、禁重复点击)/成功(短暂金勾)/失败(轻抖动1次+提示) | 下单、发送验证码、生成、支付全部走统一 `PrimaryButton`，**提交中必须禁用防重复下单** |
| 文本输入 | 聚焦时边框转鎏金、错误时描边转暖红+下方错误文案、清空按钮 | 手机号/验证码输入；验证码按钮带 60s 倒计时（与后端限频一致） |
| 开关 Switch | 开合动画+颜色变化明确表达开/关 | 设置项、授权范围 |
| 进度 | **可量化用线性进度条**（AI 生成：排队→生成中→转存，给百分比/阶段文案）；**不可量化才用转圈** | AI 视频是异步任务，必须轮询 `/api/ai/task/:id` 显示阶段，不许让用户对着转圈干等 |
| 数值选择 | 离散用步进/标签点选，连续用滑块 | 价位区间、时长 |
| ActionSheet vs Alert | **用户主动操作的二次确认**（删除、退出、解绑）→ ActionSheet（底部）；**系统发起的提示/警告/错误**→ Alert（居中） | 撤销授权、退出登录用底部 Sheet；接口报错、风控提示用居中 Alert |
| 卡片 | 按下整体轻微缩放+明度反馈；右上/下方操作区位置统一 | 艺人卡、项目卡、订单卡统一结构与按压 |
| 骨架屏/空态/错误态 | 列表加载先出骨架（同形状微光块）；空数据给插画+一句引导+行动按钮；网络失败给"点击重试" | 首页/广场/订单/消息全配，禁止白屏和裸露英文报错 |

## 四、导航、布局与多屏适配（含折叠屏，用户明确点名）

### 1. 底部导航（修复"图标不对等"）
- 定稿 5 主 Tab + 中央创作键：**首页 / 圆梦（项目市场）/ 中央「创作」凸起键 / 消息 / 我的**；**艺人广场作为独立 Tab 或首页顶部入口**（本轮按用户要求加入，信息架构见 §六，二选一在原型里确认后固化）。
- 5 个区域**等宽、图标+文字都居中、图标统一 24px 线性、选中鎏金/未选 #8A8FA3、文字 11px**；视觉校正：线性图标视觉重量一致，方形/圆形图标做像素级对齐，不许一大一小、基线不齐。
- 中央「创作」键：圆形鎏金渐变，直径比普通图标大约 1.35 倍，轻凸起但不遮挡内容；点按 0.97 缩放 + 弹出创作菜单（祝福视频/数字人/定制剧/AI 生成）。
- 导航栏用一次毛玻璃（固定、不随列表滚动重复模糊）；安全区 bottom padding 适配全面屏手势条。

### 2. 响应式断点（一套代码适配手机/折叠屏展开/平板）
定义宽度断点（以 dp 计）：
- `< 360` 紧凑小屏：左右边距 12，字号降 1；
- `360–599` 常规手机（基准设计稿 390×844）：边距 16；
- `600–839` 大手机横屏/折叠屏外屏/小平板：内容最大宽 560 居中，或首页改 2 列瀑布流；
- `≥ 840` 折叠屏展开内屏/平板：**Master-Detail 双栏**（左列表、右详情同屏），网格 3 列，顶部导航与底部导航按宽屏重排。
- 用统一 `Responsive` 工具（列数 `gridCols`、是否双栏 `isTwoPane`、内容最大宽）判断，禁止写死宽度；图片用 `BoxFit` + 圆角统一；文字随屏宽在基准 ±1 级内浮动，禁止溢出/截断成省略号的关键信息。
- 横竖屏切换、折叠展开/合起用 `LayoutBuilder`/`MediaQuery` 平滑重排（180ms），不重启页面、不丢状态。

### 3. 单手优化
- 列表页的筛选/搜索入口可在下滑时吸附底部或支持下拉聚焦；下单"去支付"、聊天"发送"、AI"生成"固定在拇指可达的底部操作栏。

## 五、启动页 / 引导 / 开屏（修复"每次退出都重弹广告"）

1. **开屏只在「冷启动」出现一次**：用本地标志位区分冷启动 vs 热启动/页面回退；进程没死再回前台**不得**再播放开屏和引导页。
2. 按视频"启动页与首屏融合"思路：冷启动展示「追光水晶 logo + 鎏金光晕」≤1.6s，期间并行预取首页数据，光效淡出后直接落首页（首屏骨架已就位），**不做强制商业广告读秒**（演示阶段不接开屏广告）。
3. 三页引导页仅在**首次安装/大版本更新**展示一次，之后可在"我的-设置"回看；提供"跳过/立即进入"，记住选择。
4. 登录态有效则跳过登录直接进首页；未登录可游客浏览，触发"下单/消息/我的/AI 生成"时再弹登录（模态），登录完成自动回到来源操作（不丢上下文）。

## 六、信息架构与业务闭环（UI 必须服从正确的商业逻辑，配合功能闭环）

- **「定制剧」与「圆梦」是两个板块，不许混**：
  - **定制剧=以用户本人为主角**：入口在「创作/我的」，用户选样片、填需求、走 99 意向金 + 4901 制作款七步流程（含电子合同），**线下撮合，不在线上直接撮合成片**。
  - **圆梦=拿钱圆别人的梦**：独立 Tab「圆梦」，展示已定项目、可下载已定人物/剧本、空缺角色可"认领参演/出资"（席位模型，不是金额众筹）。
- **艺人广场**：真人数字人艺人列表（**只用真人暖光仿真人图，严禁动漫/卡通/赛博形象**），区县筛选要精确到区/县并正确回显。
- **三角色边界**（UI 不串角色）：
  - C 端买家：浏览、下单、私信、订单、圆梦——**不出现"个人/商户/MCN 身份选择"**；
  - 艺人：接单、交付、定价、收益、授权管理；
  - MCN：**只用 H5/独立后台看板**（管理艺人、看数据面板、分账/管理费、提现），**不在 C 端 App 里当买家下单**；App 内最多留一个"MCN 管理后台"入口跳 H5。
- **我的页**：登录后消费真实 UserProvider，买家/艺人双视图分组；"我的数字人"必须进入**我创建的数字人列表**（不是跳到艺人广场），创建成功后这里立即可见、可看审核状态。
- 价格/金额全 App 对外一律"元"（后端已统一），前端不得再对已是元的字段 /100；意向金 99、样片制作款 4901、代言 1999/19999 以 config/接口返回为准，**不在前端写死价格**。
- 自有 IP 只用：黄帝史诗·天下合、少年龙武、边境暗影（类型标签全 App 统一：古装史诗/热血成长/悬疑短剧），**清掉《雾港追凶》《那年盛夏的我们》等非自有名与"赛博朋克"残留**；剧场模块名保留「晶典剧场」（用户 8/30 拍板，不改）。

## 七、视觉与排版细节（高级感来源）

1. **字号**：基准 14/16/18/22/28，标题可奇数不拘泥偶数；正文行高 1.7，段间距 > 行间距；数字金额用等宽/半粗，对齐右缘。
2. **圆角与阴影克制**：卡片统一 22、按钮胶囊、Sheet 顶部 24；阴影只用于表达层级（浮起元素一层极淡黑阴影 + 鎏金 1px 内描边），**禁止又重又糊的投影**；深色底优先用"明度分层 + 1px 鎏金描边"表达卡片，而非堆阴影。
3. **鎏金与玻璃（吸收 Liquid Glass，克制）**：主 CTA/选中态/关键数据用鎏金渐变；毛玻璃仅用于底部导航、顶部栏、浮层，边缘可加极细高光，触控时轻微提亮（像光被触摸激活），但**不做大面积流动炫光**，避免廉价。
4. **图标视觉校正**：同一组图标视觉等大（方形略缩、圆形略放），统一线性 1.8 描边、统一圆角端点；选中态不用花哨多色，用鎏金+实心点。
5. **渐变低饱和**：背景仅用 #0A0B10→#14161F 的柔和过渡与极淡径向光晕，禁止高饱和撞色；封面/海报图自身彩色，UI 控件让位于内容。
6. **统一卡片范式**：上=封面/主信息，中=标题+关键标签，右下=操作或价格；列表里同类卡片结构完全一致，降低学习成本。

## 八、本轮（V13）逐页落地清单（功能闭环优先，UI 同步）

> 顺序即开发优先级；每项都要"数据来自后端、断网有演示兜底、状态齐全"。

1. **登录闭环**：新增手机号验证码登录页（输入手机号→`POST /api/auth/sms` 发码带 60s 倒计时→`POST /api/auth/phone` 校验→存 token+写 UserProvider→回来源页）。短信签名/模板审核通过前，开发联调走后端 dev 兜底码，UI 上不暴露兜底码；保留微信/Apple/游客入口。
2. **数字人闭环**：创建（真人照片上传 `POST /api/humans` multipart，授权范围勾选、活体检测标注"演示模拟"）→提交后"我的-我的数字人"可见（审核中状态）→审核通过进艺人广场；风格选项去掉赛博朋克/玄幻，改真实风格；全程进度反馈。
3. **AI 生成闭环**：创作页接 `POST /api/ai/image`（文生图）、`POST /api/ai/video`（t2v/i2v）→拿 taskId→`GET /api/ai/task/:id` 轮询，显示"排队/生成中/转存/完成"线性阶段进度与可取消，成片进"我的作品"并可下载/下单；需登录，未登录弹登录。
4. **统一订单闭环**：`GET /api/orders/all` 聚合祝福视频/定制剧/代言/圆梦，订单中心按状态分组（待支付/进行中/待交付/已完成/售后），下单支付后能立刻看到自己的单，不再用写死假单；`GET /api/ai/status` 展示能力状态。
5. **首页/圆梦/广场**：首页接真艺人（去掉本地写死第三套数据，统一以接口+演示兜底为准）；圆梦席位模型正确显示"已认领 x/y 席"（不是金额、不是 328000 席）；广场区县精确到区县、真人头像、分类去赛博。
6. **详情/下单**：艺人详情、定制剧七步、代言、祝福视频下单：金额取接口、协议默认**不勾选**、无艺人时拦截并提示、支付按钮防重复、支付占位清晰标注"演示环境，正式支付接入后开通"。
7. **消息/我的**：会话列表真实化；我的页双视图、真实用户数据、正确路由、设置里可回看引导、测试连接入口（服务器地址与连通状态可见）。
8. **全局**：按 §二/三 接入统一转场与六态组件、骨架/空/错误态、§四 响应式断点与底部导航等宽、§五 冷启动一次；清全部旧紫 hex 与孤儿页。

## 九、反模式（明确禁止，自检必查）

- 每次回前台都重播开屏/引导/弹窗；热启动弹"广告"。
- 按钮点了无反馈、可重复点击导致重复下单；提交中不置灰。
- AI 生成只给一个转圈、无阶段无结果、成品找不到。
- 用写死假数据当线上结果；前端再把"元"除以 100；前端写死价格。
- 动漫/卡通/赛博数字人；非自有 IP 名；旧紫/高饱和回退；硬编码 hex 绕过主题。
