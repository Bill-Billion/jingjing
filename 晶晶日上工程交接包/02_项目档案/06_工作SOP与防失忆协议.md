# 06 · 工作 SOP 与防失忆协议（以后照此执行，避免再返工）

> 这份文件专门治三类反复出现的问题：①"老失忆"（换会话/换任务就忘口径）；②"改A坏B"（价格/命名多处不同步）；③"急着打包结果一堆错"。
> 任何一次任务，严格按下面流程走。最后更新 2026-08-29。

## 一、每次开工协议（先读后做，不许凭记忆）
1. 先读 `00 主索引` → `01 价格SSOT` → `02 问题册` → `07 决策记录`，确认最新口径与未决项。
2. **读真实代码/文件现状**，不靠记忆或旧总结假设行号与内容；要改哪个文件先 Read 它。
3. 飞书在线文档/表格/幻灯片每次使用前必须重新拉取最新版，禁止用历史缓存数据回答。
4. 明确本次任务边界：只改被点名范围；发现额外问题登记到02，不顺手扩大改动。
5. 若存在待拍板项（07 中 D 编号）且会影响本次结果，先用文字列出影响、一次性问清，不擅自替老板定。

## 二、单一事实源原则（治"价格多处不一致"）
- 产品/价格/权益/命名：**只认 01 号文档**；后端集中在 `config.js`，前端集中到一个 `pricing.dart`（待建），页面只引用常量，**禁止在页面里写死金额/比例/档位名**。
- 视觉：只认 03 号文档与 `app_theme.dart`，禁止硬编码色值。
- 合规口径：只认 05 号文档。
- 改一个口径 = 一次任务内把"文档 + 前端常量 + 后端config + PPT/计划书话术"全部同步，缺一不算完成。

## 三、改动前 / 中 / 后清单
### 改前
- [ ] 全局检索同名/同值点（搜金额数字、旧命名、旧色值），列出所有要同步的位置
- [ ] 确认是否触碰 P0/合规/资金，触碰则先出文字方案
### 改中
- [ ] 一处改动，同步所有引用点；新增文案先想"用户能不能看懂"，禁用内部黑话/投资化词
- [ ] 金额一律后端用分、展示层格式化；演示数据集中在 mock_data 并标注演示
### 改后（自验，不验不交）
- [ ] `flutter analyze` 无 error（info 记录在 T-11）
- [ ] 涉及后端：`node` 语法/启动检查通过
- [ ] 价格/席位/金额逐页与01核对（尤其定制剧四条入口必须一致）
- [ ] 至少在小屏常规宽度看布局；折叠/平板按03清单抽验
- [ ] 走一遍真实用户路径（下单/支付/交付/售后），不靠单点看代码
- [ ] 回写02问题状态（含版本与验证证据）、必要时在07记决策

## 四、出包 SOP（治"急着打包出错包"）
1. 先确认 02 的 P0 是否清零；演示包可带 P1/P2 但要在交付说明里列清楚"哪些是假的/不能用"。
2. 按 04 第九节命令构建，以 "Built ...apk" 为准（PowerShell exit code 1 是 warning 误报）。
3. 包名/版本号递增（pubspec version），交付副本放项目根并带版本中文名。
4. 手机下载走飞书云盘外链（present_files 手机端打不开），注意约20MiB上限。
5. 交付说明固定四段：**改了什么 / 怎么验证的 / 还缺什么(诚实) / 版本与路径**。禁止只说"做好了/完成了"。

## 五、多视角审查法（老板要求至少审3-4遍）
每轮较大改动后，依次换视角挑刺并登记02：
1. C端普通用户：看不看得懂、信不信任、顺不顺、价格有没有歧义；
2. 艺人/供给侧：愿不愿来、到手多少、被差评怎么办；
3. B端/MCN：批量管理、对公结算、归属；
4. 平台运营：审核/客诉/退款/榜单/数据能不能管；
5. 资方：数据真不真、模式成不成立、合规有无硬伤；
6. 银行/支付：二清、反洗钱、备付金、对账；
7. 政府/监管：资质、AI与内容安全、人脸、未成年人、去投资化；
8. 技术：联调、性能、并发、异常、安全、可维护；
9. 出海：PDPA/支付/本地化/数据出境（P3）。
> 每遍只找问题、给证据(文件位置)、定级，不空谈；找完排优先级再动手。

## 六、决策记录制（ADR）
- 任何老板拍板/重要取舍，立即追加到 `07`：日期、背景、决定、理由、影响范围、谁拍板。
- 新会话开工先看07，避免"同一个问题反复问、反复改回去"。

## 七、上下文接续协议（换会话/换Agent/隔天后）
1. 第一步读 00→07→02，5分钟恢复全部上下文；
2. 再读本次要动的真实文件；
3. 用 TodoWrite 拆任务，一次只推进一个 in_progress；
4. 中途被打断，把进度写回02/07或任务清单，不留"只在脑子里"的状态。

## 八、明确禁止（出现即返工）
- 禁止没对齐文字方案就大改/出包（高客单与合规尤其）；
- 禁止凭记忆改代码、禁止跳过后端/页面现状 Read；
- 禁止页面写死价格/色值/旧命名；
- 禁止把 mock 数据当真实能力宣称；禁止静默降级后说"已完成"；
- 禁止为"规避"法律而设计明示站外导流/黄赌毒通道（合规只能做责任隔离，不能绕红线，见05第六节）；
- 禁止交付不带"还缺什么"的说明。

## 九、复盘节奏
- 每完成一个阶段：更新00的完成度判断、02问题状态、07决策；
- 每出一个包：做一次第五节九视角快速过一遍；
- 出现一次返工：在02新增"根因+属于本SOP哪条没做到"，持续补本SOP。
