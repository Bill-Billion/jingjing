# 晶晶日上 · 合作工作台

Vue 3 / TypeScript / Vite 网页。账号、机构、合同和作者作品界面统一使用暖白和墨绿。账号管理沿用 PR #11，合同读取沿用 PR #12；已接入 PR #13 的供给申请、作品资料和独立审核；本轮接入 PR #14 的选本、剧本许可、项目绑定和受控阅稿。

## 本次可以做什么

- 手机短信登录、退出；查看和复制自己的账号编号。
- 查看个人和机构身份，加载更多身份，切换当前操作身份。
- 创建机构、修改机构名称；新机构如实显示“待审核”。
- 申请作者、剧本供应方、制作方、MCN、企业客户五类能力，并分别显示审核状态。
- 本人查看收到的邀请、接受或拒绝；机构负责人通过账号编号邀请成员，并明确选择截止时间。
- 保存本标签页实际收到的发送回执，可凭回执撤回邀请。当前没有“发出邀请列表”接口，回执不冒充完整历史或实时状态，退出后清除。
- 分页读取机构成员、移除普通成员；负责人不能移除，普通成员没有管理入口。

当前不包含机构审批、账号停用、负责人转移、本人退会、商业代理授权等未提供接口的功能。机构成员关系不会自动变成经纪或商业合作。

## 合同与规则

工作台的“合同与规则”入口打开 `/contracts`；也可通过 `/contracts/<snapshotId>` 直接进入。填写获准查看的合同编号后，按当前工作身份读取。页面没有合同列表或创建、审批、签署、付款入口。

- 显示封存时的当事方、承诺、规则版本、内容指纹及“未签署”事实。开放正文递归排版，保留原键名、换行、数组和空值，所有内容按纯文本转义展示。
- 规则只能从这份合同的 `rule_contents` 选择，读取时始终带 `snapshot_id`，不替换为今天的最新规则。
- 可分别检查支付、实名、电子签和数字人所需服务。`SERVICE_READY` 只显示服务条件满足，不代表业务已完成或获得执行授权。
- 三个 GET 携带当前 Bearer 和 `X-Acting-Party`，使用 `no-store`，不带幂等键或条件缓存头。负责人身份不会自动获得合同读取权限。
- 正文与检查结果只保存在页面内存；身份或账号切换、退出、离开页面和读取失败时清空。连续查询、切换规则/服务、A→B→A 的迟到响应均不得恢复旧内容。
- 校验正文格式与固定状态，拒绝旧文件元数据、缺失字段及与当前请求不匹配的成功响应。失败显示真实错误与请求编号，不使用演示成功兜底。

三个读取接口需要 PR #12 后端；具体字段与验收条件见仓库的 [接口核对与验收](../../../docs/ux/pr12-ui/contract-review.md)。

## 作者与作品

工作台的“作者与作品”入口包含供给申请、我的作品和独立审核。页面连接 `/api/v1/supply`，不使用本地桩代替供给业务。

- 供给申请分别填写展示名称、简介和私有证明。补正从真实最新申请带入上一版编号，保留旧版审核意见；最新申请获批后才开放投稿。
- 原作投稿分别填写标题、私有正文、总体权利证明和每一项权利关系。每行主动选择主体、作者／权利人／代理角色及证明；“使用当前身份”只填编号，不替用户认定权利人。项目改稿从真实许可绑定入口进入，原作来源与项目只读，仍需上传本次新稿、总体权利证明并主动填写每项权利关系。
- 正文和证明通过私有二进制接口上传，单文件不超过 8 MiB，明确选择受支持的文件类型，只有服务器返回可用的材料才进入表单。下载使用已鉴权的字节响应并核对大小及摘要，不生成公开材料链接。
- 保存草稿、提交审核和填写理由撤回是独立操作。现有接口没有原地编辑，修改已保存内容使用新修订；作品及上一版编号来自读取结果。判断最新修订前完整读取该作品的分页记录，不把初页第一条当作最新版。
- 运营侧分别读取供给申请、权利审核和内容审核记录。轨道选择不授予权限，服务器复核审核资格并禁止自审；历史版本的意见独立保留。
- 私有资料、选中文件和待操作内容只留在当前页面内存，身份／账号／审核轨道切换、退出和失去读取权限时清空。原操作结果未核对时阻止正常页内导航，先恢复原操作；网络结果不确定或原操作仍处理中时保留原幂等键与完整内容，仅由用户重试原操作。412 刷新记录并要求重新确认；需要人工核对的 409 不盲目重放。

路由：

| 页面 | 地址 |
| --- | --- |
| 供给申请与历史详情 | `/supply/profiles/:recordId?` |
| 我的作品与详情 | `/supply/works/:recordId?` |
| 新建原作草稿 | `/supply/works/new` |
| 基于作品创建修订 | `/supply/works/:recordId/revision` |
| 独立审核列表与详情 | `/supply/reviews/:channel/:recordId?`，轨道为 `profile`、`rights`、`content` |

这些路由支持安全登录返回，仅接受站内已声明路径和小写 UUID。完整接口边界见 [PR #13 接口核对](../../../docs/ux/pr13-ui/api-review.md)，真实隔离后端启动说明见 [联调环境](../../../docs/ux/pr13-ui/test-runtime.md)。

## 选本、许可、项目与受控阅稿

本轮按图册 WEB-09 至 WEB-12 继续采用暖白、墨绿和清晰表格。全部工作区共用同一份主菜单，保留账号、合同、供给和作品入口；详情、表单、独立核验页面保持正确高亮。

| 页面 | 地址 |
| --- | --- |
| 已上架商品目录、短试读及预留 | `/licensing/catalog/:recordId?` |
| 当前供给方商品与历史关联 | `/licensing/products/:recordId?`、`/licensing/products/new` |
| 预留合同及外部材料上传 | `/licensing/reservations/:recordId?` |
| 已提交外部材料与许可凭证 | `/licensing/evidence/:recordId?`、`/licensing/grants/:recordId?` |
| 项目用途与额度绑定 | `/licensing/projects/:recordId?`、`/licensing/projects/new`、`/licensing/bindings/:recordId?` |
| 指定账号、指定身份及期限的受控阅稿 | `/licensing/readings/:recordId?`、`/licensing/readings/new` |
| 独立审核、许可发放及暂停 | `/licensing/reviews/:section/:recordId?`；section 为 `products`、`evidence`、`readings`、`activation`、`grants`；`projects`、`bindings` 为关联记录只读入口 |

- 商品引用当前身份完成双审的原作。权利、用途、地域、语言、独家条件、开始／开发／有效期限、项目及集数额度逐项明确；价格、首款、预留时长均无默认值。改价或改条款建立新商品版本。当前没有公共规则目录，表单明确要求核对已经生效的规则版本编号。
- 目录只使用已登录真实目录；短试读以纯文本显示，不提供作品原始正文下载。独家不自动包含发行权。
- 预留保存当时合同、规则及价格；用户确认范围后才提交。真实外部双边签署、身份及付款材料分别上传私有文件，合同指纹来自本次预留。上传不等于取得许可，不冒充自动支付或平台验签。
- 独立许可核验使用当前账号，不携带业务方身份。身份与双方签署三项核验初始未勾选；批准证据还须明确已签合同指纹、币种、实收、收款方及凭证。审核不能绕过自审、独家冲突或重复收款凭证限制。
- 发放接口返回 HTTP 200 也可能只是过期预留进入人工补救；页面按实际记录显示“尚未取得许可”。许可证展示范围及截止时间；暂停和日期均决定当前是否可用。
- 项目用途建立后不可原地改写。项目绑定校验用途、国家、语言、集数、改稿／制作权、开发期及额度，明确提示本阶段不支持释放再用。绑定详情核验有效改稿权、开发期及项目范围后可进入 `/supply/adaptations/:bindingId/new`，保存前再次读取许可；表单来源与项目只读，作者和权利人由用户主动填写。项目改稿新修订保留已保存的来源和项目，重新核验其许可资格。
- 阅稿需供给负责人提交指定账号、身份、期限和保密／评估依据，独立批准后供指定读者读取 UTF-8 纯文本及水印。读取前后核验授权，不执行 HTML、不持久保存正文、不提供原文件下载。期限到达、换身份、退出、离开、窗口失焦时清除；页面可见期间每 15 秒重新核验，服务端每次实际读取再次鉴权。没有撤销推送接口，不能承诺即时收回已经显示或复制的文字；不承诺防截屏。
- 许可及上传未决操作仅留页面内存，保留完整原内容、原版本、原幂等键；结果未核对时阻止正常页内导航，先恢复原操作。重试发回同一操作。确定冲突先结束、刷新再决定；412 重新读取并要求主动确认。身份／会话／页面变化丢弃迟到结果；失去读取权限清除私有合同、材料和正文。

字段依据为 [第五阶段接口说明](../../../docs/collaboration/STAGE_5_API.md) 与 [统一接口文件](../../../contracts/openapi.yaml)，不直接依赖数据库表。

## 启动

使用 `package.json` 规定的 Node 版本，首次执行：

```sh
npm ci
VITE_BACKEND_ORIGIN=http://127.0.0.1:3000 npm run dev -- --host 127.0.0.1
```

浏览器打开命令输出的本地地址。开发服务器将 `/api`、`/health`、`/ready` 代理到指定服务，默认后端为 `127.0.0.1:3000`。生产环境优先部署为同源；需要不同来源时，可在构建时设置 `VITE_API_ORIGIN`，并由后端配置允许的网页来源。浏览器地址不能包含数据库或供应商密钥。

入口为 `/login`、`/workspace`、`/contracts/:snapshotId?` 和上述作者作品路由，开发构建还提供 `/dev/status`。生产构建不注册开发自检页；网页服务器需要将前端路由回退到 `index.html`。

```sh
npm run type-check
npm run test:contracts
npm run test:supply
npm run test:licensing
npm run build
```

`dist/` 为构建产物，不进入 Git。没有真实短信配置和验证记录时，服务器会拒绝发送；页面不会采用固定验证码或切换成模拟成功。

## 数据与权限保护

接口依据为 [第二阶段调用说明](../../../docs/collaboration/STAGE_2_ACCOUNT_API.md)、[统一接口文件](../../../contracts/openapi.yaml) 和 PR #11 的真实返回。

- Bearer 令牌保存在当前标签页的 `sessionStorage`。退出和任何已登录请求的 401 会清除令牌、身份、邀请回执和未决操作；新登录不会继承旧账号内容。
- 所有写请求携带 `Idempotency-Key`。已有对象修改携带原始 `If-Match`；机构级请求携带匹配地址的 `X-Acting-Party`。
- 账号写入前将原操作保存在当前标签页。网络中断、读取响应体失败或服务器结果不明确时保留原键、原内容和原版本；刷新后仍可重试原账号操作，核对前阻止其他修改，避免重复创建。供给材料及其待操作不落入浏览器存储，仅在当前页面内存保留。
- 412 重新读取最新记录，403 重新核对权限，429 和 503 如实显示。没有自动重试写操作或模拟数据兜底。
- 身份切换及退出通过请求所属会话和身份版本隔离旧响应，防止延迟的成员数据写回新页面。
- 页面依据 `party.allowed_actions` 与成员角色显示功能；服务器在每次操作时作最终鉴权。未知权限不会自行启用按钮。

## 浏览器验收：真实隔离后端

`npm run e2e` 使用 Playwright Core 和本机 Chrome，调用真实 PR #11 HTTP/MySQL。短信适配器为隔离测试替身，不发送短信、不调用收费供应商。

先在**仓库根目录**按 [MySQL 基础说明](../backend_server/docs/MYSQL_FOUNDATION.md) 准备本机隔离数据库，并指定自己的私有测试配置：

```sh
JX_MYSQL_TEST_ENV_FILE=<本机测试配置JSON> \
PR11_UI_STATE_FILE=<绝对路径的私有运行状态JSON> \
node scripts/pr11-ui-test-server.cjs --test-only
```

启动器默认使用 API `3220`、仅测试控制 `3221`，创建随机测试数据库和临时账号，测试结束以 Ctrl+C 退出后删除该数据库。运行状态 JSON 含测试控制密钥，不能上传或公开。

在网页目录另开终端：

```sh
VITE_BACKEND_ORIGIN=http://127.0.0.1:3220 \
npm run dev -- --host 127.0.0.1 --port 5199 --strictPort

PR11_UI_STATE_FILE=<同一个私有运行状态JSON> \
BASE_URL=http://127.0.0.1:5199 \
CHROME_PATH=<本机Chrome可执行文件> \
npm run e2e
```

macOS 已有 Chrome 时可不传 `CHROME_PATH`；Linux/CI 指向已安装的 Chromium/Chrome。脚本只接受 loopback 及 `testOnly` 状态，不用于部署服务。截图默认保存在 `output/playwright/`，可以通过 `SHOT_DIR` 指定其他位置。

测试覆盖登录、五类能力、邀请接受/拒绝/撤回、成员移除、真实版本冲突、服务器写入后响应体断流并跨刷新重试、旧响应隔离、401/403/429/503、分页、退出以及 375 像素布局。其中分页及网络/权限错误为浏览器明确注入的测试场景；成功的账号写入和 412 使用真实隔离后端。

原有 `npm run stub` 和 `npm run check:protocol` 保留为**旧登录协议演示工具**，不支持本次全部机构功能，不参与正式页面的请求选择。完整验收使用上述真实隔离后端。
