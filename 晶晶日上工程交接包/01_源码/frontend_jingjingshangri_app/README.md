# 晶晶日上 Flutter 客户端

晶晶日上数字人 IP 经纪与定制圆梦平台的主客户端工程。保留原有暗色业务页面；真实手机号登录和账号、机构、成员管理已接到 PR #11 的新服务。PR #12 已接入指定合同阅读、关联历史规则和外部服务条件检查；本轮 PR #13 增加作者申请、作品版本、权利链和私有文件流程。登录、账号、合同、作者与作品区域沿用暖白铜橙样式。

完整项目背景见[仓库根 README](../../../README.md)，账号接口和服务启动条件见[账号与机构接口说明](../../../docs/collaboration/STAGE_2_ACCOUNT_API.md)。当前应用版本为 `12.3.1+22`；本轮使用 Flutter 3.47.5 / Dart 3.13.4 验证。

## 启动账号页面

先按后端说明启动隔离测试服务，再显式设置新账号服务地址。地址包含协议、主机与端口，不包含 `/api/v1`：

```sh
flutter pub get --enforce-lockfile
# 浏览器开发；后端须允许这个页面来源的跨域请求
flutter run -d chrome --web-port 8769 --dart-define=JX_ACCOUNT_API_URL=http://127.0.0.1:3000
# Android 模拟器访问本机服务
flutter run -d <Android设备ID> --dart-define=JX_ACCOUNT_API_URL=http://10.0.2.2:3000
# 打包浏览器预览；不等于部署或生成原生安装包
flutter build web --no-web-resources-cdn --dart-define=JX_ACCOUNT_API_URL=http://127.0.0.1:3000
```

未配置 `JX_ACCOUNT_API_URL` 时，登录页明确提示服务地址未配置。它不会继承旧生产地址，也不会使用演示验证码。真实短信必须已经配置和验证；服务返回未启用时，不显示“已发送”，也不启动假倒计时。上述 `3000` 是示例端口，须与自己的服务一致。PR #12 临时隔离验证使用 `3222`；PR #13 使用 `3232`。隔离服务提供正常的手机号／验证码挑战流程，没有开启真实短信供应商或访问生产数据库。

## 本轮可以使用的页面

- 原登录页：申请验证码、按服务器时间显示重发倒计时、登录；未确认的请求保留原内容重试。
- “我的 → 账号与机构”：查看并复制本人账号编号，分页选择个人／机构身份，创建机构和修改机构名称。
- 能力申请：作者、剧本供给方、制作方、经纪机构、品牌客户，按服务器显示待审核等状态。
- 收到的邀请：分页查看，核对机构及邀请人编号，接受或拒绝。
- 机构负责人：填写对方账号编号，自行选择邀请截止日期和时间，发送邀请、撤回本次登录发出的邀请；分页查看成员和移除普通成员。
- 退出：立即清空本机账号、身份和私有列表，同时通知服务器；断网时明确提示服务器退出未确认，并提供重试入口。

机构审核、账号停用、所有权转移、本人退出机构没有接口，本轮不制作能假装成功的按钮。服务器也没有历史发件列表接口，所以发送回执仅保留在本次登录内；不能把回执当成对方尚未处理的实时结论。成员身份不自动授予付款、作品使用或商业代理权。

## 指定合同与历史规则

登录并选择办事身份后，从“我的账号 → 读取指定合同”粘贴完整合同编号。也可打开 `/#/contract?snapshotId=<合同编号>`，或在应用内向 `/contract` 传入 `{'snapshotId': '<合同编号>'}`。没有合同列表、创建、审批或签署入口。

三个读取接口共用 `JX_ACCOUNT_API_URL` 和当前新账号会话：

- `GET /api/v1/contract-snapshots/{snapshot_id}/content`：合同信息、保存的承诺及关联规则版本。
- `GET /api/v1/rule-versions/{rule_version_id}/content?snapshot_id=…`：从当前合同包含的规则中选择版本，重新核对权限后读取。
- `GET /api/v1/contract-snapshots/{snapshot_id}/business-readiness?action=…`：选择支付、身份核验、签署或数字人服务，检查必要服务条件。

合同保留 `SEALED / NOT_SIGNED` 的真实含义：内容已保存、尚未签署。`SERVICE_READY` 只表示本次检查的服务条件具备，不能作为付款、签署或许可生效的依据。页面不会提供这些未接入动作。结构化条款和承诺按纯文本展示，不执行 HTML，也不生成下载文件或公开链接。

每次请求都携带当前 `X-Acting-Party`。普通成员拥有有效查看授权时可读取；负责人也必须有独立授权。权限失败统一提示“内容不存在或无权查看”。合同、规则和服务结果只在内存保存；退出、登录失效、身份变化和重新查询立即移除旧内容，迟到响应不会恢复旧数据。旧元数据格式或不完整的成功响应会显示读取失败，规则或服务检查失败也会移除此前正文。限流时按服务器 `Retry-After` 秒数等待，未返回等待时长时不编造倒计时。

## 作者申请、作品与私有材料（PR #13）

登录后，从“账号与机构 → 作者与作品 → 进入作者与作品”打开作者工作区。个人以本人身份操作；机构私有资料只对当前负责人开放，普通成员不能读取或提交。作者申请通过后才能保存作品和提交审核，判断依据是完整分页中修订号最高的申请，不能用旧版已通过的申请替代当前资格。

| 页面 | 应用路由／Web 深链接 |
| --- | --- |
| 当前申请、申请历史、我的作品版本 | `/supply` ／ `/#/supply` |
| 作者申请与补正 | `/supply/profile?previousId=<申请记录编号>` |
| 原作投稿与新修订 | `/supply/work/new?previousId=<作品版本记录编号>` |
| 申请或作品版本详情 | `/supply/record?recordId=<记录编号>` |

首次申请或首次投稿不带 `previousId`。这些参数只用来读取已有记录；实际提交时，关联申请、作品及前一版本编号由读取结果带入，不能任意编辑。补正和新修订会接续已读取的最新版本。未登录的作品深链接会先进入手机号登录，登录后清除旧路由、选择当前有效身份，再重新读取指定资料，不恢复旧账号的待提交动作。

作者申请填写展示名称、介绍与证明材料。作品表单填写标题、私有稿件、作品权利证明，并独立添加作者、权利人、代理的多行关系；每行都有主体编号和相应证据，至少明确一位权利人。首次原作直接显示一条空白权利人关系，主体与证据由用户填写；作者申请及作品必填未齐时，提交按钮禁用并提示缺失项。“使用当前身份”仅填入主动选择的那一行编号，不默认投稿人拥有版权。当前只开放原作，项目改编需等项目许可流程接入。

作品先“保存草稿”，再在版本详情核对后“提交此版审核”；两者是不同请求。详情分别显示权利审核、内容审核的实际结果和理由，不将双审通过解释为已上架或已获商业许可。撤回必须填写理由。版本冲突会重新读取并要求再次确认；结果未知时只核对原请求、原内容、原幂等键和原版本，不另建一笔操作。成功写入后会再 GET 核对当前记录，避免把旧的幂等重放回执当作最新状态。

### 私有文件怎样处理

文件按钮调用系统／浏览器文件选择器，实际读取并上传用户选择的二进制文件。使用 `file_picker 11.0.3` 以兼容现有分享依赖；`crypto 3.0.7` 用于核对授权元数据中的内容哈希。支持 PDF、TXT、JPG、PNG、WAV、MP3、MP4、BIN，每份不超过 8 MiB，流式读取也检查实际大小。只有服务端返回归属正确、大小与内容匹配的 `READY` 文件才加入表单引用；本地选择名不作为后端业务字段保存。

所有供给请求使用当前新账号 Bearer 和 `X-Acting-Party`。上传是 `POST /api/v1/supply/assets?purpose=…&media_type=…` 的原始字节；下载先读取授权元数据，再从 `GET /api/v1/supply/assets/{id}/content` 获取私有字节，并核对大小和哈希。没有公共 URL 或旧服务下载兜底。Web 将私有字节交给本地 Blob 下载，提示“已交给浏览器保存”；原生保存返回取消时不提示已保存。

上传结果未知时保留原文件和原请求，恢复操作仍使用相同内容；返回需核实存储结果时暂停继续上传。文件、待提交内容和私有记录只由本次会话持有；身份切换、退出、登录失效或撤权会清空相关状态，迟到的读取、写入或下载不会恢复旧资料。文件移除按钮只移除此处引用，不声称删除服务器文件。

## 新旧业务如何分开

新令牌只用于 `/api/v1`，不写入旧 `UserProvider`、旧 JWT 或演示服务。新账号登录后清空旧私有路由，默认进入独立 `/account` 账号页，再从那里打开合同或作者与作品；明确的供给深链接可以在登录后重新读取目标资料。新账号区域不叠加旧版主导航；“浏览旧版展示”保留为历史页面入口。旧登录守卫不会继续执行下单等动作，也不会要求已登录的新用户反复登录。

“浏览旧版展示”仅进入历史页面，不创建体验账号或伪造真实登录。旧 `ApiService` 的服务器与演示配置仍只属于历史页面，不能用于判断新账号接口是否可用；在本地验证这些历史页面前须隔离旧生产地址。

新会话、待核对的写请求和私有列表只放内存，关闭应用后需要重新验证手机号，不把新令牌明文写入偏好存储。写入失败且结果未知时，保留原请求编号、原内容和原记录版本；同一内容明确完成后，才允许发起下一次新操作。已失效的短信挑战会提示重新获取，不永久重试一个不能再发送的挑战。

dart analyze lib/account lib/contracts lib/supply lib/pages/login/login_page.dart lib/app.dart test/account test/contracts test/supply
flutter test test/account test/contracts test/supply test/interaction_flows_test.dart test/widget_test.dart
