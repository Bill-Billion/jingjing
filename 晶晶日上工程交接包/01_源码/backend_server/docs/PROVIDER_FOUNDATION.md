# 外部服务未开通时，程序怎样处理

本轮加入一套共用检查：先确认代码已实现、配置齐全、对应环境有验证记录，而且记录对应当前配置，再允许调用。只填密钥不能成为“已经能用”的证据。旧业务尚未全部接入；这份说明不能当作正式支付、实名或制作验收。

## 已有的基础能力

|能力|当前情况|
|---|---|
|实名、支付、文件存储、内容审核、长期数字人、电子签的共同调用方式|已定义六类内部接口，未实现的操作明确失败；业务输入字段仍由各任务按双方约定补齐|
|记录外部服务是否能用|MySQL保存服务、具体用途、测试/正式环境、当前状态、配置版本和历史证据引用；不保存密钥或证据原件|
|私密文件保存|已写阿里云OSS接入代码并隔离测试；实际账号、权限与效果未验证，当前不启用|
|其他五类服务的实际接入|本轮没有完成新接入；旧SDK文件不能算已符合新的检查要求|
|出错后的处理|记录请求编号和错误类型；不记录原始请求、密钥、私密链接和供应商响应正文；超时不自动重复付款等操作|
|检查服务器状态|`/health`只说明进程能响应；`/ready`检查必要依赖及表结构。可选外部服务未开通不拖垮整个服务器|

旧应用挂载上述两个检查地址，但其旧路由还在用SQLite，因此`/ready`明确返回503。以后完成MySQL应用组装时注入`mysqlReady(db)`。本轮没有声称旧应用能在生产运行。`/api/health`历史地址仅表示进程响应，不应用作正式接流量判断。

## 文件安全和对旧功能的影响

新私密存储每次上传、读取、临时链接、删除都先调用服务端权限检查。默认不授予任何权限；检查失败同样拒绝。文件键必须在`private/<归属标识>/<文件>`下面，但路径格式本身不证明归属，授权函数必须核对真实资产记录、当前操作人和操作种类。不可把客户端传入的机构号当授权依据。

上传明确指定私有权限并禁止覆盖已有同名文件；返回文件引用、大小与校验值，不返回公开网址。临时读取链接默认300秒，允许范围1–900秒；签发后到期前属于持有即可用的链接，权限撤回不会让已经签发的链接立即失效。对需要立即收回的材料，后续业务应使用受控读取并避免签发链接。权限检查和调用之间仍可能发生状态变化；已经在途的请求不能宣称一定被即时取消。

旧存储不再因OSS配置不全退回本地目录，也不再把普通公开地址叫作私有链接。本地保存仅限开发/测试，并必须明确写`isPrivate:false`。现有AI、数字人上传代码没有明确分类权限，因而会被拒绝；接下来要迁移这些调用，不能为了恢复演示而改回默认公开。生产环境也关闭旧静态上传目录。已有历史文件没有被自动移动或删除，后续须先盘点再处置。

## 接手代码的人如何使用

- `src/modules/providers/readiness.js`提供状态保存与检查；新增表结构0006、0007，旧迁移文件不变。并发更新须带上读到的版本号；状态和历史记录在同一事务保存，任一失败就全部撤销。
- 保存状态必须由服务端注入`authorizeChange`，记录验证通过还要注入`verifyEvidence`，默认全部拒绝。后者必须实际检查对应环境、用途、配置版本与材料，不能用恒定返回true替代。测试中的固定许可和假证据仅在测试文件中。
- `adapter.js`六种内部接口：实名verify；支付create/query/refund；存储put/get/sign/remove；审核inspect；数字人submit/query；电子签create/query。调用形式为`call(operation,input,context)`，context只由可信服务端填入操作人、身份、请求/任务/付款记录编号。具体支付幂等键和回调核验在业务接入任务完成。
- 状态为`NOT_IMPLEMENTED / IMPLEMENTED / CONFIGURED / SANDBOX_VERIFIED / PRODUCTION_VERIFIED / WAITING_PROVIDER_APPROVAL / DISABLED_BY_PRODUCT`。本地环境不能开启真实调用；测试验证不能开启正式调用。停用、待批准仍保留历史，但新调用被拒绝。
- `private-storage.js`读取明确的OSS环境参数，生产进程只能用PRODUCTION，开发/测试只能用SANDBOX；暂不支持自定义endpoint。配置一经加载固定，重建实例后凭据变化会使旧验证失效。使用锁定的ali-oss 6.23.0、HTTPS、V4签名、私有ACL与禁止覆盖请求头。
- `observability.js`提供请求编号及允许字段日志。服务端生成请求编号；不信任请求头自报的操作人或机构。后台调用通过context传递关联编号。本轮尚无真实领域任务接线，不能宣称支付到后台任务全链路已实测。
- `operations.js`返回首批接口约定草案的meta/data格式，含X-Request-Id和禁止缓存头。该草案仍待检查，未改写主接口文件。新运营状态读写接口暂不开放，等待账号/机构/权限任务，不能用旧管理口令绕过。

数据库内读取方法供服务端内部使用，包含审计元数据；将来给页面的响应需按批准后的接口投影，不能直接透传数据库行。新日志采用允许字段方式，旧调用携带的自由文本详情会被丢弃；诊断时按错误类型和关联编号查，不能恢复记录密钥的做法。

## 验证与限制

`npm run test:providers`要求明确的隔离MySQL配置，会检验状态持久保存、并发冲突、失败回滚、停用、环境隔离、配置变化、存储拒绝公开降级、临时链接和请求关联。`npm run test:ci`包含此项和原有检查。外部网络被拦截；OSS测试使用替身，另用真实SDK离线签名验证格式，没有上传真实文件，也没有验证云端ACL实际效果。

供应商真实验证需另取得授权和对应环境账号；经真实验证并保存证据后才能启用。旧付款直接标记已付、实名缺配置自动批准、其它旧业务假成功尚待下一项修复。

实现依据：[OSS对象访问权限](https://www.alibabacloud.com/help/en/oss/user-guide/object-acl)、[阿里云官方Node SDK](https://github.com/ali-sdk/ali-oss)。实现及验收以锁定依赖和本仓库测试为准。
