# 规则与合同内容：内部封存工具

当前只有纯函数，没有数据库保存、公开HTTP、审批入口或真实签署处理。完整阶段计划见[规则与合同阶段](../../../../../../docs/collaboration/STAGE_3_RULE_SNAPSHOTS.md)。模块只依赖Node内置crypto；可独立测试，不启动登录、数据库或外部服务。

`createRuleContent`接收明确的版本标识和条款，生成深拷贝、只读的内容及SHA256校验值。它不批准规则、不选择当前版本、不增加任何未知商业参数。`verifyRuleContent`核对读回的内容。

`sealUnsignedContent`接收合同版本标识、当事方、明确UTC时间、规则内容及当时承诺。规则的状态和生效时间必须由未来的可信数据库层读取，禁止直接信任HTTP请求中的自报状态。这里只检查是否已生效且不晚于封存时间，同一规则不能混用两个版本。这个工具不能证明合同版本存在，也不检查谁有权代表当事方，后续服务必须完成这些检查后才能调用。

输出固定为SEALED、NOT_SIGNED，包含规则内容副本；没有已付款、已签署或许可生效结果。历史校验使用`verifyUnsignedContent`，不因规则后来停用而拒绝旧内容。新增条款或证据必须创建新版本，不能改原记录；跨请求和数据库层的不可覆盖、幂等和权限尚待实现，Object.freeze本身不提供持久化保护。

内部格式分别为rule-content-v1与contract-content-v1，不是新公开接口。序列化按对象键排序，保留数组顺序和文本原样；拒绝循环、访问器、隐藏属性、无效Unicode、非有限或不安全数值。64KiB、24层、4096节点是内容处理限制，可随明确版本变更，不能拿来代替文件存储或业务规格。拒绝空条款，但具体价格/退款/授权字段的完整性仍须对应业务模块校验；本工具不保证任意JSON就是合法合同。

校验值只能发现内容与记录的校验值不一致；有权同时改内容和校验值的人仍能重新计算。它不是电子签名、公证或外部存证。私有文件、数据权限、签署证据和操作审计由后续层实现。

仓库根可执行：

```text
node --test "晶晶日上工程交接包/01_源码/backend_server/test/governance-content.test.cjs"
```

现有完整测试脚本会自动发现本测试文件；本轮只运行本模块与现有纯权限规则检查，不冒称已跑数据库全套回归。
