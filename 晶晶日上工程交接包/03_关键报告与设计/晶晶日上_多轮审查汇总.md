# 晶晶日上 APP 多轮代码审查汇总（动代码前最终整改清单）

> 审查对象：`work/app/jingjingshangri_app`（Flutter，当前版本号 10.0.0+10，主题仍是旧 V5 多巴胺粉橙）
> 审查方式：逐文件通读源码（26 个核心 dart 文件 + 全局关键词扫描），分别以「第一次打开的小白 C 端 / 想入驻接单的艺人 / 想做定制剧的 B 端客户 / MCN / 合规与真机演示」五个视角走查。
> 结论原则：**只列在真实代码里定位到的问题**，每条给出文件、触发条件、后果、改法。优先级 P0＝崩溃/合规红线/演示直接穿帮，P1＝体验硬伤与业务不一致，P2＝打磨。
> 重要前提：后端、数据库、云服务器当前都未跑起来，APK 是「纯前端」状态。因此凡是走接口的页面，**必须有本地 mock 兜底**，否则投资人一点就"加载失败/连接失败"。

## 二、P0 崩溃 / 阻断级（不修改，真机演示会直接崩或穿帮）

### P0-1　网络层：默认地址导致"全 App 功能不可用"
- 位置：`services/api_service.dart:11-21`
- 现状：`defaultUrl = lanUrl = http://192.168.1.82:3000`；另有 `publicUrl=http://8.222.213.43:3000`（阿里云新加坡）但**没有任何地方默认用它**。
- 后果：手机用移动网络或别的 WiFi 时，Dio 全部请求超时 → 艺人 Tab 直接显示"请确保后端服务已启动"、登录/下单/私信全部失败。这与你反馈的"功能不能用、连不上"完全吻合。
- 改法（演示优先，分两步）：
  1. **演示期**：`defaultUrl` 改为公网地址；同时在 App 启动时做一次健康检查，失败自动进入"本地演示模式"（读内置 mock 数据，见第五节），保证**断网也能完整走流程**。
  2. 设置→服务器设置里，把快捷芯片改成：`公网(阿里云) / 局域网 / 模拟器` 三个真实可用项，**删掉失效的 loca.lt 和需要翻墙的 Tailscale**；"测试连接"失败时只显示友好文案（"当前为演示环境，部分为示例数据"），不抛 Dio 原始错误。
  3. 公网用 `http://` 明文，需在 `AndroidManifest` + `network_security_config.xml` 放行该 IP/域名，否则安卓 9+ 默认拦截明文（这也可能是连不上的叠加原因）。

### P0-2　定制剧详情页空值强转崩溃
- 位置：`pages/project_detail/project_detail_page.dart:10`
- 现状：`(project['raised'] as int)/(project['goal'] as int)`；首页本地项目只有 `title/type/img/percent` 键，网络项目用 `raised_amount/goal_amount`，都没有 `raised/goal`。
- 触发：首页点任意定制剧卡片进详情 → `null as int` 抛异常 → 页面红屏/崩溃。
- 改法：统一数据模型字段；进度一律用 `(raised_amount??0)/(goal_amount??1)`，并对本地 mock 补齐同名字段；详情顶部海报改用 `project['img']`。

### P0-3　登录体系缺失 / 路由未注册黑屏
- 位置：`app.dart`（路由表）、`pages/profile/profile_page.dart`
- 现状：
  - 路由表注册了 21 个路由，**没有 `/login`，也没有 `/humans`**；
  - "我的"页"我的数字人"→ `pushNamed('/humans')`，onGenerateRoute 返回 null → 黑屏；
  - "我的消息"→ `/messages` 打开的是单人 `ChatPage` 且 `human={}`，`int.parse("null")` 抛错（chat_page.dart:30）；
  - 顶部"点击登录"胶囊**没有 onTap**，无法进入登录。
- 改法：
  1. 新建简洁登录页（手机号+验证码，演示期验证码任意填或固定 123456，本地直接发 token、写 SharedPreferences），注册 `/login`；
  2. 未登录点需要登录的功能统一弹登录页；注册 `/humans`（我的数字人列表，本地 mock 空态+创建入口）；
  3. `/messages` 改为"会话列表页"，不要直接打开空的单人聊天。

### P0-4　艺人 Tab 无本地兜底，与首页自相矛盾
- 位置：`pages/humans/humans_page.dart`
- 现状：完全依赖 `getHumans()` 接口，后端没起就整页"请确保后端服务已启动"；而首页却有 7 个本地艺人卡片——同一台手机，首页有人、艺人 Tab 报错，自相矛盾。
- 改法：接口失败/演示模式下回落到与首页**同一份**本地艺人数据；去掉"请确保后端服务已启动"这类面向开发的话。

### P0-5　买家端看到平台内部账（且个税算错）
- 位置：`pages/video_order/video_order_page.dart`、`pages/endorsement/endorsement_page.dart`、`pages/wallet/wallet_page.dart`
- 现状：
  - 下单页给买家列出"平台服务费 10%、AI 制作成本 15、个税、艺人预计到手"；代言页列"服务费 15%、AI 成本 500、艺人到手"。这些是**平台与艺人之间的内部结算**，绝不能给买家看。
  - `_calcLaborTax(形参 grossIncomeFen)` 把传入的"元"当"分"又 `/100`，显示处再 `/100` 一次，导致算出来的个税几乎为 0。
  - 买家身份选择里混了"MCN"选项；钱包页（本是艺人才有的提现/结算）对所有用户开放，且"服务费 10%、代扣 6%"与下单页的劳务报酬三级累进（20%–40%）是**两套互相矛盾的税模型**。
- 改法：
  1. **买家端只显示一个数：实付金额**（商品价 + 无额外隐藏费），抽成/AI 成本/个税/艺人到手全部移到"艺人端—我的收入/结算说明"；
  2. 买家身份只保留"个人/企业（是否要发票）"，删掉 MCN；
  3. 统一税务口径：买家端不出现税；艺人端用一套口径（建议钱包页的综合代征口径，并在文案注明"以实际结算为准"），删掉下单页那套错误的累进函数；
  4. "我的钱包"按角色显示：普通买家显示"我的订单/优惠券"，艺人/机构才显示提现与结算。

### P0-6　定制剧"投资/众筹/票房分账"合规红线
- 位置：`project_detail_page.dart`、`role_market_page.dart`、`theater_page.dart`
- 现状（必须清除）：
  - "票房交付 15%/8%/3%""档位起投 ¥10,000""已筹/目标金额/支持人数"；
  - 角色市场：女主角 50 万、女配角 20 万、客串 5 万、男主 30 万、男配 15 万——这是**份额化、可货币回报**的表述，触碰非法集资/变相发行证券红线；
  - 彩蛋档 price=10000 经格式化成"1.0 万"，旁边文案却写"1000 元"，自相矛盾；
  - 里程碑两处不一致：launch_page 是 30/30/30/10，project_detail 是 20/25/25/30。
- 改法（对齐你拍板的新业务）：
  1. 全站删除"投/筹/票房分账/收益率/起投/支持人数"等词，改为"**定制席位 / 出演席位认购**"，并在每个档位旁固定标注"本服务为内容定制消费，非投资、不承诺任何货币回报，交付物为视频/署名/出镜等约定权益"；
  2. 价格体系统一：**普通档 5000 起**（意向金 1000 + 制作款 4000），高端定制（好编剧/导演/明星、电影/中剧/短剧）**一剧一议、线上留痕、线下商务报价（几万至几百万）**；角色市场不再标 50 万这种"份额价"，改为"席位定制，价格一剧一议 / 5000 起"；
  3. 统一一套里程碑（建议沿用已正确的 launch_page：30/30/30/10，并在详情页保持一致）；
  4. 彩蛋档金额与文案对齐，显示统一由一个 `_fmt` 出。

### P0-7　全站数据源不一致 / 图文错位 / 违反最低定价
- 位置：`home_page.dart`、`projects_page.dart`、`theater_page.dart`、`role_market_page.dart`
- 现状：
  - 剧名四套：首页（黄帝史诗/少年龙武/边境暗影）、项目列表（长安锦帐/赛博迷城/江湖故人/都市微光）、剧场又一套、角色市场再一套；
  - 首页艺人头像与姓名性别错位（男图配"赛博少女"、女图配"武侠剑客"等）；
  - 艺人"温以凡"price=89，违反**最低 99**；评分全部写死 5.0、reviewCount 直接等于 sales。
- 改法：建一份**全局唯一 mock 数据源**（`mock_data.dart`）：7 个真人艺人、3 个示例定制剧（长安破晓/雾港追凶/那年盛夏，或换成你的自有 IP 名——待你拍板），首页/剧场/项目/角色市场/搜索全部引用它；价格 ≥99；评分、销量、评价数用成组的合理示例值，不写死满分。

### P0-8　主题与素材不符合"追光 + 真人"定位
- 位置：`theme/app_theme.dart`、`assets/images/`、`pubspec.yaml`
- 现状：主题注释写明"V5 多巴胺潮流"，主色 `#08060E`、品牌渐变 `#FF2D78→#FF6B35`，另有紫/青多彩辅助；旧素材 artist_1 是紫发赛博插画、剧场是霓虹二次元。
- 改法：
  1. 主题换"追光"：深蓝黑底 `#0F1219`、暖金主色 `#F5A623`、暖金到浅金渐变、聚光灯高光、克制的辅助色（不再用紫/青/粉多色跳）；`gold/brandGradient/glow*` 等别名在 app_theme 内统一重映射，可做到"改一个文件、全站换肤"；
  2. 素材全部换**真人写实**（已生成 11 张在 `追光真人素材/`：7 艺人 + 3 剧场海报 + 1 聚光灯 banner），复制进 `assets/images/` 并更新 pubspec；**禁止动漫/二次元/3D 卡通脸**；
  3. 启动页/引导页同步换暖金，slogan 统一为"做自己人生的主角"。

### P0-9　违禁词、技术报错、开发备注外露

  - 广告法绝对化/夸大："顶级主创团队"（project_detail 1 处、theater 3 处、onboarding）、"海量场景""一键生成大片""一键试镜"；

- 改法：统一文案过滤器——所有 catch 只给用户友好结果（"网络不佳，已为你切换示例数据/请稍后重试"），原始 `$e` 只 `debugPrint`；违禁词替换见第九节术语表；删除一切开发备注。

### 3.2 信息架构与角色混淆
- 底部 Tab：缺"消息"入口；"艺人 Tab"与首页艺人推荐内容重复；中间"+"对所有用户直接打开录制页（普通买家并不录制数字人，角色错位）。
  - 建议 Tab：首页 / 晶晶剧场 / 居中"定制"（按角色分流：买家去下单，艺人去创作）/ 消息 / 我的。
- profile：未登录仍展示全部菜单和"MCN 管理""我的钱包（艺人结算）"；"晶典剧场"暴露公司主体且与"晶晶剧场/定制剧场"命名不统一。按登录态与角色显隐。
- audition（创建数字人）六步过重，把保证金 500、版权 3 年、授权范围等**艺人侧条款**塞进普通创建流程；风格选项含"赛博朋克/玄幻"，与真人定位冲突。精简为：上传真人素材→选授权范围（一屏一授权分步）→提交；风格只保留真人写实类目；保证金改为"首笔收入冻结 500、入驻不预收"的说明文案。

### 3.3 流程闭环缺口
- **收到视频闭环不存在**：买家付完→没有"待交付/已交付/可下载分享"的完整可见路径，video_lib 永远空。补一条示例订单 + 示例视频。
- **样片/定制 5000 流程**：`sample_order_detail` 六步结构正确（意向金1000→选类型→选对标剧本→剧本创作(含2轮)→制作款4000→成片），但：①完全依赖接口，无 mock，后端没起就"订单加载失败"；②"查看项目计划书"只弹 SnackBar，不能真下载；③"剧本创作/改本是线下商务沟通"这一点要在 UI 上表达清楚（App 内只展示进度与留痕，沟通由商务对接，避免平台承制定制内容责任）。补本地 mock 订单、计划书可打开、线下环节标注"专属顾问将与您联系"。
- 身份认证 identity：企业/MCN 选中后，上传框仍写死"身份证正面/反面"，应随类型变"营业执照"；收集身份证正反面属敏感个人信息，需明示加密存储与用途、一屏一授权。
- 地区选择 region_picker：省市区县**数据本身完整**（全国 34 省级），但只在 humans 艺人端调用，C 端没有入口；你反馈"区县点不出来"应是入口没接上/或该页依赖接口没渲染。需要在用到"同城/地区"的 C 端位置真正接上 `RegionPicker.show`。

### 3.4 引导与版本
- onboarding 每次冷启动都弹（splash 固定跳 onboarding），应用 SharedPreferences 记录"已看过"，仅首次启动展示；"跳过/立即体验"要能落地。
- 版本号三处打架：pubspec 10.0.0、settings 写死 V4.0.0、splash 写死 V10.0.0。统一从 `pubspec.yaml` 读取或一处常量维护。

## 六、多视角走查结论

### 视角 A：第一次打开的小白 C 端
- 会踩：默认连不上（P0-1）、登录无门（P0-3）、点定制剧崩溃（P0-2）、一堆按钮没反应（3.1）、收到的视频找不到（3.3）。
- 达标要求：3 秒看懂"这是干嘛的"、不看说明能下一单、付完知道去哪收视频。当前不达标，按 P0/P1 修完可达标。

### 视角 B：想入驻接单的艺人
- 会踩：创建流程六步太重且混入合同条款（3.2）、风格有赛博/玄幻与真人冲突、保证金要"入驻先交 500"的旧表述（应为首笔收入冻结、不预收）、钱包税务两套口径（P0-5）、定价指导/补贴期等后端依赖无兜底。
- 达标要求：明白"入驻不交钱、首笔收入冻结 500、99 元 0 抽成、299 以上 10%、前 3 月 AI 成本补贴/前 100 名免佣"。需把这些正确规则在艺人端讲清楚且只给艺人看。

### 视角 C：想做定制剧的 B 端 / 高端客户
- 会踩：看到"起投/票房分账/50 万主角"会以为是投资盘（P0-6，反而吓退正规客户、招来合规风险）；5000 流程藏得深、计划书不能下载、改本是线下还是线上说不清（3.3）。
- 达标口径：普通档 5000 起（1000 意向金 + 4000 制作款），流程＝选对标类型→选对标剧本→专属顾问线下改本到满意→付制作款→出宣发片；电影/中剧/短剧、好编剧导演明星均"一剧一议"；角色可单独定制/可由客户指定谁演主角，其余席位可被他人认购；**全程非投资、交付的是内容与约定权益**。

### 视角 D：MCN / 机构
- 会踩：MCN 入口混在买家身份里、MCN 页有静态权益但数据看板依赖接口、"统一开票/管理费 3%/前 3 月免管理费"与钱包页口径需对齐。按角色进入、看板给 mock 示例。

### 视角 E：合规 / 应用市场 / 真机终审
- 硬门槛：①投资化措辞全清（P0-6）；②用户协议/隐私政策/平台规则必须能打开（3.1）；③人脸/身份证敏感采集一屏一授权、明示用途与加密、可撤回（identity/audition/settings 已有雏形，要补全）；④广告法违禁词全清（P0-9）；⑤品牌代言必须有"广告"标识（endorsement 已有，保留）；⑥先下单才能私信的门控正确（human_detail 已做对，保留并在 chat 顶部保留"请通过平台下单"提示）；⑦明文 http、权限、最小化收集在出包前过一遍。
