## 一、本次问题复盘：为什么会感觉"老失忆、没改"

### 1.1 现象
你 8/28 选定了"追光·电影感暖金"风格、也看过 8 张设计稿，但 8/29 装到手机上的 APP 还是旧的"多巴胺粉橙"风，看起来"完全没改"。

### 1.2 真正根因（不是记忆问题，是流程问题）
1. **三条线并行、没有合流点**：
   - 文档线（商业/法务/架构，到 V6.0）
   - 代码线（APP+后端，到 V10.1）
   - UI 设计线（追光，只做到**效果图 PNG + 方案 md + 素材**）
   追光在"设计线"里是完成的，但**从来没有进入"代码线"**——效果图和工程是两张皮，中间缺一个"把设计落成代码并回读验证"的环节。
2. **版本号/命名撞车**：风格叫"V5 多巴胺"、代码叫"V10.1"、文档叫"V6.0"，三套编号，极易误以为"V 数字变大=全都更新了"。
3. **多执行体接力**：文档、V5 换肤、断网演示分别由不同任务接力完成，上下文靠摘要传递，**没有一份持续维护的"需求台账"**来勾销每条要求是否真正落到代码。
4. **交付前缺"按需求回读"**：之前验证的是"能不能编译、有没有报错"，而不是"你要的那条需求在界面上到底出现了没有"。

> 一句话：**不是忘了追光，是追光一直停在"图纸"，没被搬进"房子"，而交付时没有拿你的原始需求逐条验收。**

## 四、以后的协作机制（杜绝"两张皮/失忆"，立即生效）

### 4.1 建立唯一"需求台账"（单一事实源）
- 本文件 `晶晶日上_需求台账与遗留.md` 作为唯一台账，你每提一条新要求就登记一行：**编号 / 要求 / 所属线(文档·APP·后端·UI·部署) / 状态(待办·进行中·已落地·待你确认) / 落在哪个文件 / 验证方式**。
- 每轮开工前先读台账，每轮结束更新台账，**不凭记忆、不凭口头**。

### 4.2 设计→代码必须"合流"，不许停在效果图
- 任何 UI 改版顺序固定为：**设计稿 → 写进代码 → 跑起来截图 → 与设计稿并排比对 → 一致才算完**。
- 只出图、没进代码的，状态只能标"设计完成"，**禁止对外说"APP 已改"**。

### 4.3 交付前"按你的原始需求逐条回读"（不是只看能不能编译）
每次出包/交付前过一遍四问：
1. 你要的每条需求，在**界面/文件里真实出现**了吗？（截图或路径为证）
2. 数值/口径（价格、比例、份数）和你最新口径一致吗？
3. 三条线（文档/代码/设计）是否同口径，有没有一处改了另两处没改？
4. 断网/折叠屏/小屏真机是否验证过？

### 4.4 改动留痕，每轮给"改了哪些文件"回执
- 每轮结束附：**改了哪些文件、新增哪些、未动哪些、还有什么没做及原因**，对得上台账编号。
- 关键数值（价格、比例、抽成）集中在一个配置文件，改一处全局生效，避免"改了 APP 漏了后端/文档"。

### 4.5 数值口径先确认再写死
像意向金、起步价、抽成这类数字，**先跟你确认一个权威值**，再同时落到 APP/后端/文档/PPT 四处，避免出现 500/1000 三个版本。

### 4.6 大改先小范围验证
换肤/流程级改动，先出 1–2 个核心页截图给你确认方向，再铺满全站，避免整包返工。
