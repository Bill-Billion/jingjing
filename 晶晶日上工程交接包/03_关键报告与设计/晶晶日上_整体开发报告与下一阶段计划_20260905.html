一、项目定位、产品边界与商业模式

1.1 一句话定位

理念主线（A-03）："让普通人做自己人生的主角"，面向大众消费者，而不是只做给投资人看的 Demo。数字人只用真人风格素材（禁动漫/二次元脸），剧集只用三部自有 IP：《黄帝史诗·天下合》《少年龙武》《边境暗影》。

1.2 四条产品线（边界严格、不交叉混卖）

产品线本质定价口径（唯一事实源 01 号档案）成交方式
① 祝福视频（数字人接单）大众走量、冲动消费艺人自主定价、最低 ¥99、上不封顶；99 档平台 0 抽成、299+ 抽 10%、通道费 0.6%、AI 成本 15 元/条（新人前 90 天补贴）在线直接下单
② 个人定制剧（"我当主角"圆梦短片）高客单、项目制重服务（非标品、非投资）固定四档：彩蛋档 ¥1,000 / 普通定制 ¥5,000 起 / 进阶定制面议 / 电影级面议（几万~几百万）普通档两段式：¥99 意向金锁档 → 定稿补 ¥4,901 起尾款；进阶/电影级走里程碑担保
③ IP 角色/席位只对应内容交付物（出镜、署名、镜头、成片、参与证明）C 端只卖 ¥1,000~数万的出镜/彩蛋；¥5 万以上主角/资方席位不在 C 端明码，收进"商务合作"认领期 45 天、达 80% 成团、未成团原路退
④ 品牌代言/企业口播（B 端）企业服务单品口播 ¥1,999 / 季度代言 ¥19,999，平台抽 15%，强制"广告"标识与授权书在线下单 + 授权书

永久红线（A-09）：角色/席位不得对应任何票房分账、收益分红、货币回报、回购、增值承诺，对 C 端禁用"投资/理财/回报/分红/众筹/定金"等词，统一用"意向金，可退可抵"。这条在前端文案、剧场说明、角色市场里被反复校验。

1.3 资金流：撮合分账，平台不碰资金池（A-18）

全部交易走持牌支付机构（微信电商收付通 / 支付宝直付通）的二级商户分账：用户付款 → 支付机构备付金 → 验收后分账给艺人/承制方，资金永不进入平台自有账户（规避"二清"）。定制剧由完成 KYB 的承制方（编剧/制作工作室）直接对客户收款、交付并开全额"内容制作"发票，平台只开"平台/技术服务费"发票，定制剧撮合佣金暂按 5%（A-26，UE 测算后可调）。艺人保证金入驻不预收、首笔收入冻结 ¥500 起、退出 30 天无纠纷退（A-11）。

1.4 三角色边界（冻结，反复校验）

  • 买家：C 端消费/定制；艺人：真人授权数字分身接单；MCN：只有独立 H5 管理后台，C 端不开放机构下单——App 内 MCN 页仅看板演示 + H5 引导，不产生 C 端机构表单/订单。

二、技术架构总览

2.1 前端（Flutter / Dart，单工程出 Android/iOS）

  • 规模实测（2026-09-05）：lib/ 下 75 个 Dart 文件，其中页面 40 个；lib/widgets/ 下 20 个统一组件；test/ 下 61 个测试文件、合计 311 个测试用例。
  • 状态管理：StatefulWidget 为主 + UserProvider（ChangeNotifier）全局用户态；离线演示由 app_mode.dart 在连不上后端时自动切 mock_data.dart（A-16：演示包断网可点，正式包默认在线、失败给明确错误而非静默假数据）。
  • 关键 SSOT（单一事实源，防止"改 A 坏 B"）：
    • 金额：唯一常量 lib/utils/pricing.dart，唯一展示 lib/utils/money.dart（对外用"元"、千分位、不 /100、不写死）；
    • 色值：唯一来源 lib/theme/app_theme.dart（曜石蓝黑 #070A12 + 冷青环境光 + 克制香槟金 + 液态玻璃），页面层禁止硬编码 hex；
    • 动效：lib/utils/motion.dart（时长全 ≤1.6s、4 条标准曲线、尊重系统"减弱动态"、宽屏 +50ms）；
    • 触觉：lib/utils/haptics.dart（零音频零权限，PressScale 单点挂载）；
    • 版本号：lib/utils/app_version.dart（零依赖常量，不引 package_info_plus 以免破坏离线构建链）；
    • 统一组件：PrimaryButton（六态+防重复）、GlassCard、LiquidScaffold/LiquidBackdrop（流光背景）、StateViews（Empty/Error/Loading）、Skeleton 骨架、AppNetworkImage/HumanAvatar（限解码保性能）、MilestoneBar（里程碑）等 20 个。

2.2 后端（Node/Express + better-sqlite3，线上 v13.0.0）

  • 规模实测：25 个路由模块（admin/ai/auth/compliance/contacts/endorsement/faceverify/humans/identity/mcn/messages/orderReviews/orders/packages/pay/payment/projects/review/samples/sceneTemplates/scripts/settlement/share/theater/videos）；9 个服务（volc/volcSpeech/volcVisual 火山三件套、alipay、paymentService、reconciliation 对账、smsService、aiQuota、alert）。

七、开发过程中遇到的典型问题与解法（重点复盘）

这一节专门回答"开发中都踩了哪些坑、怎么解决的"。分为真实功能缺陷、性能（你反馈的"卡"）、金额一致性、布局适配、视觉一致性、工程链/环境、测试方法论七类。

7.1 真实功能缺陷（不是样式问题，是会崩/会死页/会错数）

  1. 开屏每次冷启动必卡死：splash 里 Future.wait 返回的 List 被 as bool 强转，每次冷启动都抛异常 → 改取 results[0]。
  2. 选剧库恒空：getSampleLibrary 离线回退分支错配，导致无论在线离线选剧库都空 → 修正回退映射 + Hero 封面 + 播放钮。
  3. 钱包页无 try-catch 卡死：wallet 在线分支异常时整页卡死 → 补错误态可重试。
  4. role_market 失败误显空态：网络失败被当成"没有数据" → 区分错误态/空态并锁测试。
  5. projects 普通手机必崩：窄屏走 ListView，而卡片内部 Expanded/Spacer 需要有界高，触发 unbounded height → item 包固定高 SizedBox 有界化。
  6. audition 无限宽崩溃：Stepper 控制行里默认 expand 的 PrimaryButton 造成无限宽 → Expanded 包裹。
  7. HumanAvatar 小头像溢出、launch 窄屏主 CTA 被截断、review 星级 360 溢出：逐页弹性化/紧凑化修复。
  8. AI 路由 401（线上）：costGuard 注册在 optionalAuth 之前，导致已登录用户调 AI 也被 401、整个 AI 层不可用 → 调整中间件顺序热修，线上 58 项回归全过。
  9. 三个线上历史 bug：humans 16/15 列错、projects 分页 SQL 报错、samples 脏中文 JSON.parse 500 → 线上真实路径复测全部修复、测试数据零残留。
  10. 设置页版本号落后两大版本：版本号写死 → 零依赖单点常量 + aapt 交叉核对 + 锁测试。

7.2 性能专项：你反馈的"打开 App 很卡"（第 75~76 轮，已修主因、待你真机复验）

先给结论：不是"没缓存/没部署"，而是渲染层性能问题。 诊断出四个具体成因并逐一修复：

  1. 全站 0 个 RepaintBoundary：14 秒循环的全屏 CustomPaint 流光背景，每帧重绘都会牵连前景一起重新栅格化 → 给流光背景套 RepaintBoundary 隔离，背景动画不再让前景每帧重绘；
  2. 静态位图被放进 AnimatedBuilder：背景丝绸位图每帧被重建 → 移出动画 builder，只构建一次；
  3. 46 个微粒每帧 new Random()：每帧新建随机数对象造成 GC 压力 → 改 static final Random(42) 确定性缓存；
  4. 网络/头像图未限制解码尺寸：大图按原始分辨率解码进内存 → HumanAvatar clamp 到 1024、新增 AppNetworkImage 统一 6 处网络图 clamp 到 1280；创作键 IrisOrb 自绘也做隔离。
  • 另加性能契约测试（perf_repaint_boundary、app_network_image）防止回退。
  • 诚实说明：这些是卡顿的主要可定位成因，已在代码层修复并进了 +21 包；但最终流畅度需要你在真机上复验。另有"5 处 BackdropFilter 真实模糊在低端机的降级"列为观察项，若你真机仍觉得卡，下一步就做模糊降级（列表卡已用预乘半透纯色、只有固定顶/底栏/浮层用真模糊，方向是对的）。

7.3 金额一致性（商业正确性，零容忍）

  • 历史遗留：意向金三处不一致（project_detail=99 对，launch=1000+4000 错，sample_order_detail=1000/4000 错）、里程碑两套比例（20/25/25/30 与废弃的 30/30/30/10）、多处 /100、"已认领 720000 席"把金额当席位。
  • 解法：建立唯一常量 pricing + 唯一展示 money，分十几批逐页清干净，全站"¥后紧跟数字"0 命中；里程碑抽共享 MilestoneBar、比例调用处传入；加金额格式化/类型容错/千分位测试。合理保留的非定价数字（青少年单笔 500 合规限额、wallet 299 阈值/10% 服务费规则文本）逐一甄别、不擅改商业规则。

7.4 布局适配：三档屏逐页过

折叠屏/小屏 360、常规 390、宽屏 840 三档截图回归，是抓布局 bug 最有效的手段——多个"看着没问题"的页面在 360/840 下溢出或崩溃，全部有界化/弹性化修复，最终三档 38/38/38。

7.5 视觉一致性：全局顶部白边（第 84 轮，目检揪出）

scaffoldBackgroundColor 与 AppBarTheme 都透明、流光只铺 body，导致所有二级页 AppBar 后方透出一条白边（测试底是白、真机上是不确定深色）。修法是在 LiquidScaffold 内部 Scaffold 垫一层 AppTheme.background（零布局风险，不用会牵动 38 页的 extendBodyBehindAppBar），并加契约测试锁死，防止回退。

7.6 工程链 / 环境坑（沉淀成 SOP，避免重复踩）

  • release 出包：必须 JAVA_HOME=C:\src\jdk17；build 必须走真 SDK C:\src\flutter（解压副本 fsdk 只能跑 analyze/test 提速，Gradle 会校验 SDK git 仓库）；PowerShell 会把 KGP/ffmpeg 打到 stderr 的 warning 误报 exit 1，以输出"√ Built"为准；.dart_tool/.plugin_symlinks 需保持 37 个 junction，故坚持 --no-pub、不引新依赖（这也是版本号不引 package_info_plus 的原因）。
  • 中文/CRLF 补丁：Edit 工具对中文 + CRLF 容易失败，统一改用 Node .cjs 以 UTF-8 精确补丁，禁用 PowerShell 管道读写中文（线上 .env 也曾因 CRLF 被 sed 搞坏 dotenv）。
  • 正式签名核验：用 build-tools 35.0.0 的 aapt 读 versionName/versionCode、apksigner 验 v2 签名，三处版本交叉一致才交付。
  • 改 A 坏 B 的防护：任何改动后 analyze + 全量 test + 三档截图目检；升版本号后必须再跑一次全量（第 75 轮曾因 bump 后没跑全量导致 settings_version 测试红，已沉淀为纪律）。

7.7 测试方法论上的"证伪"与边界（不硬改产品迁就测试）

  • 小尺寸缩略图会骗人：8 看成 9、误判"档位标题叠字""剩余 9 席"，最终用 tester.getRect 实测坐标证伪——Flutter Row(Flex) 横排子节点不重叠（间距恰 8px，空间不足只会 overflow 报错），业务代码无需改；关键判断一律裁剪放大或实测坐标。
  • 测不了的不硬测：产品代码内真实文件 IO（MultipartFile.fromFile）、视频纹理通道（VideoPlayerController）无法在 fakeAsync 的 widget 测试里驱动，成功/失败回路与真播放留 integration_test/真机，这不是缺陷；golden 匹配在本环境不落 PNG，目检走 harness 截图；CachedNetworkImage errorWidget 时序不稳不强行断言。这些边界都记录在案，避免下一轮空转。
